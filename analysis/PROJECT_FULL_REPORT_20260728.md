# 第 2 章 · 架构:为什么是两层

## 命题

**"双均线密集启动"**:SMA/EMA 的 20/60/120 六条线收敛成一束(密集),
然后价格向一侧突破(启动)。OKX 永续 15 分钟线,做空侧。

## 为什么不是一层

一个模型同时干两件事会两件都干不好:

| | 检测层 2a(YOLO) | 判断层 2b(LightGBM) |
|---|---|---|
| 回答 | **"这里像不像那个形态?"** | **"这一次会不会赚钱?"** |
| 输入 | 200 根 K 线渲染成的图 | 信号那一刻的 28 个数字特征 |
| 训练标签 | owner 手画的框 | 三重障碍走完后的盈亏 |
| 成功标准 | 与 owner 金标的 IoU / 召回 | top-decile 扣成本后净收益为正 |

**关键设计**:检测层**故意不管赚不赚钱**,它只管"像"。因为"像"是可以被人标注的,
而"赚"不是——你没法一眼看出一个形态未来 18 小时会不会跌。
把两件事分开,每一层才有可验证的标准。

## 三重障碍标记

一笔做空开出后,三个条件谁先到算谁:

```
止盈 TP = 入场 − 5 × ATR14
止损 SL = 入场 + 2 × ATR14
超时      72 根(18 小时)按收盘价平
入场      信号 bar 的下一根开盘价    ← 绝不用信号 bar 自己的收盘价
```

**为什么入场必须是下一根开盘**:信号 bar 收盘的那一刻你才知道它被检测到,
用那一刻的价格入场是不可能的。这条纪律看似小,却是本项目最大一次事故的病因(见第 6 章)。

## 成功标准(不是 AUC)

```
top-decile 扣 0.2% 往返成本后净收益为正,且置换检验 p < 0.01
```

**AUC 不是标准,只是参考量。** v1 的教训:AUC 0.59 照样亏钱——
因为 AUC 衡量排序能力,不衡量排在前面那些的收益够不够覆盖成本。

# 第 3 章 · 检测层:13 轮训练,6 个版本

## 3.1 数据从哪来

不是我造的标签,是 **owner 在 Label Studio 里手画的 ⭐标杆**:
985 个选择 → 归并成 **528 个图窗 / 1008 个框**。

## 3.2 一个被忽略了很久的问题:⭐标杆不分方向

⭐标杆是方向无关的。渲染出来看,里面**约 2/3 是多头启动**。
早期版本拿全部 ⭐ 去评估空头检测器,等于让它跟多头样本比——**召回被系统性低估**。

修法:逐个判方向。从框的低点往后找 24 根,谁先满足条件算谁:

```python
# star_side():跌破均线束下轨 且 8 根跌幅 ≥ 1 ATR → 空头
if close[j] < ma_min[j] and (close[j]/close[j-8] - 1)/atrp[j] < -1.0:
    return -1, j
```

筛出 **206 个空头金标**。加上这个筛选,v6 的召回从 33.3% 变成 51.5%——
**同一个模型,只是量对了对象。**

## 3.3 六个版本:框锚在哪

这是整条线的核心问题。检测框的**右缘应该落在哪一根**?

| 版本 | 框怎么定 | 召回 | IoU中位 | 宽度比 | 结论 |
|---|---|---|---|---|---|
| v6 | 抄 owner 原框的位置与宽度 | 51.5% | 0.53 | 1.24 | 右缘对不齐,宽了 24% |
| **v7s** | 把密集阈值放宽到 expanded | **45.1%** | **0.261** | **2.00** | ❌ **大退步** |
| v8 | 固定 10 根宽 | **14.1%** | 0.544 | 1.222 | ❌ 只学会一个形状 |
| **v9** | **右缘锚在跌破那根,宽度用 owner 自己的** | **84.0%** | **0.596** | **1.00** | ✅ **当前最佳** |

### v7 那次失败,病因是我的

我把密集判定阈值从 strict 改成 expanded(0.0045),**改之前没有测量输出的框长什么样**。
结果框宽从 owner 的 1.24 倍变成 **2.00 倍**,IoU 从 0.532 塌到 0.261。

owner 当时的原话:**"所以这么简单的任务你都会搞错呗?"**

病因不是阈值选错,是**在一个很便宜的测量之前就动手**。这条后来写进了 learnings。

### v8:修对了宽度,修坏了泛化

v8 用固定 10 根,宽度比修到 1.222,IoU 到 0.544——**但召回塌到 14.1%**。
把置信度门槛一路降到 0.01,召回也只有 16.3%。

诊断脚本 `diag_v8_recall_vs_conf.py` 分离了两个假设:

- **THRESHOLD**:模型还认得,只是不自信 → 降阈值召回应该回来
- **NARROW**:固定宽度让它只学会一个精确形状 → 降阈值也没用

结果是 **NARROW**。owner 的框宽度分布是 9~13 根,固定 10 根等于只教了一种。

### v9:两个改动一起解决

```python
BOX_MIN, BOX_MAX = 5, 24        # 只做裁剪,宽度本身用 owner 自己的
span = int(np.clip(width, BOX_MIN, BOX_MAX))
box  = segment_to_bbox(sub, DenseSegment(start=t1-span+1, end=t1), tf)
```

- **右缘锚在跌破那根**(不是 owner 框的右缘)→ 右缘偏移 p10=p50=p90=**0 根**
- **宽度沿用 owner 每个框自己的宽度**(只做 5~24 的裁剪)→ 宽度比 **1.00**

最终:**召回 84.0%(173/206),IoU 中位 0.596,IoU≥0.5 占 71.7%,右缘偏移 0**。

### 一个差点毁掉整轮的 bug

`symbol_of()` 解析文件名时**只会加 `okx_` 前缀,不会去掉**,导致 199 个金标被静默丢弃。

发现它靠的是 owner 一句话:**"如果条数对不上 说明代码哪里有问题"**。
修完后可解析的从 329 变成 **506/528**。

**教训**:数量对不上永远是 bug 信号,不是"数据就是这样"。

## 3.4 训练纪律(铁律 5)

```
fliplr / flipud / mosaic / mixup / hsv  全部关闭
```

翻转会毁掉**时间方向**(K 线图从左到右是时间)和**红绿语义**(涨绿跌红)。
这是旧项目 180 个版本失败的病因之一。

外部调研曾建议 `fliplr: 0.5`、`mosaic: 1.0` —— **已否决**,会摧毁盘口对齐。

## 3.5 验收只认真 tip 金标(铁律 12)

**自家 val / mAP 永不作裁决。** v13 的 val mAP50-95 高达 **0.916**,

## 5.3 "542 分钟延迟"的完整误诊史

这是本项目最曲折的一次诊断,**我连错两次**:

### 错误判断一:"管道太慢"

实测:**全宇宙 344 币扫描只要 2.8 分钟**。算力从来不是瓶颈。
外部调研反复推荐 TensorRT / C++ OMS / 共置,把 tick-to-trade 从 15ms 压到 4ms——
**省 11 毫秒,对 3252 万毫秒的问题改善 0.00003%**。优化错了延迟。

### 错误判断二:"v11 把框画在窗口中部"

我用**离线全历史**统计发现 v11 的框中位偏离盘口 33 根,当成了病因。
但把 v11 放进**同一条 live 路径**重测:框距盘口 **p50=1 根**,和 v9 一模一样。

**tip-edge 门只在 live 生效**,拿 `mode="full"` 的统计推 live 行为,
等于在测一条根本没跑过的代码。

### 真正的原因

逐行看 `detected_at`:间隔是 **45 分钟一档**,且同一时刻批量出现多个币——
**每轮只扫宇宙的一小片**,一个币要隔几小时才被看一次。

而且日志尾部(07-21)延迟已自行降到 17~78 分钟。
**542 分钟是一段陈旧时期的统计,不是当前管道的属性。**

### 当前实测(2026-07-28)

```
脉冲每 15 分钟一轮,每轮耗时 2.5 分钟
全宇宙 344 币扫描 2.8 分钟
v9 信号年龄:p10=30  p50=44  p90=60 分钟
15 个开火中 6 个在 30 分钟门内 → 已推送 TG
```

# 第 6 章 · 被证伪的东西(本章最有价值)

## 6.1 PF 6.61 —— 前视偏差

**曾有一个 PF 6.61 / 胜率 77.1% 的回测。**

**推论**:外部文献里出现 PF 6.92 / 胜率 74% / CAGR 276% 一类数字,

## 6.2 "12.5% 胜率崩塌" —— 我从 16 笔里读出来的

我从 **n=16** 笔交易(12.5% 胜率)得出"策略崩塌"的结论。

**此后所有小样本结论一律带 Wilson 区间。**

# 第 7 章 · 2026-07-28 的三个新结论

## 7.1 障碍在扣分 —— 但"8.5 倍"这个说法是我的错

训练池 5802 笔:

| 方案 | TP率 | 超时率 | 净@taker |
|---|---|---|---|
| 基线 TP5/SL2 | 27.3% | 8.3% | +0.0312% |
| 只止盈无止损 | 41.3% | 58.7% | +0.1711% |
| 只止损无止盈 | 0.0% | 31.3% | +0.0756% |
| **无障碍纯持 72 根** | 0.0% | 100% | **+0.2645%** |

我当时说"8.5 倍"。**这个说法有问题:那是两个都接近零的数相除。**
0.0312% 只有 3.1bp,乘 8.5 得到的还是小数。**绝对差是 23bp,不是"八倍收益"。**

### 止损下限的单调陷阱

给止损加"最小距离下限",净收益随下限**单调上升到扫描边界**(4.0% 时 +0.1336%)。
第一版脚本的判读模板还写着"TP率没塌 = 没砍长尾",直接报成了改进。

**诊断的那一列是超时率**:基线 8.3% → 下限 4.0% 时 **69.6%**。
障碍推得越远触发得越少,"最优下限"其实是在逼近"根本没有障碍"。

**通用规则**:任何单调到扫描边界的 sweep,**先加对照组,不要加宽区间**。

### 完整网格扫完,中间地带不存在

SL {2,3,4,6,8,12,无} × TP {5,8,12,20,无} × 持仓 {72,144} = 70 个格子。
看**近期块**(2026-02-20 起,1456 笔):

```
止损2x 止盈5x (现行)   全池 +0.0312%  |  近期 +0.0067%  PF 1.007
止损4x 止盈5x          全池 +0.0987%  |  近期 -0.0933%  PF 0.934
止损6x 止盈5x          全池 +0.1073%  |  近期 -0.1700%  PF 0.897
止损8x 止盈20x         全池 +0.3942%  |  近期 -0.3365%  PF 0.838
无止损 无止盈          全池 +0.2645%  |  近期 +0.0452%  PF 1.032  ← 唯一为正
持仓144根:35 个格子近期全部为负
```

**70 个格子只有 1 个在近期为正。放宽止损全池越好看、近期越差——这是过拟合的形状。**

**结论:出场不是问题所在。** 不管怎么平仓,这批候选在最近三个月就是不赚钱。

## 7.2 判断层是反的(见 4.3)

## 7.3 【最重要】样本量根本不够 —— 这解释了前面所有的"样本外失效"

功效计算(p<0.01,功效 80%,方差取自训练池,**不读 holdout**):

```
每笔净收益标准差:现行障碍 2.531%   纯持 4.802%   两者之差 4.112%

n=1739(holdout 候选数)能分辨的最小效应:
   单样本 ≥39.4bp        配对 ≥33.7bp

近期块里要证的效应:
   裸池净收益   +4.5bp   ← 差 9 倍
   去障碍的增量 +3.8bp   ← 差 9 倍
```

**要在 p<0.01、功效 80% 下证明 +3.8bp,需要 133,495 笔配对样本。holdout 只有 1739 笔。**

### 这直接解释了 holdout #9 为什么失败

**它测的效应本来就在 holdout 的分辨能力之下。不是配置不行,是尺子不够精。**

### 更狠的一条

```
判断层顶档要比全池高  5bp 才能证实 → 需要总候选 2,154,730 笔
                    20bp          →          134,671 笔
                    40bp          →           33,668 笔
现在的候选池                       →            5,802 笔
```

**整个池子的毛收益才 11.7bp,却要求筛选层做出 40bp 的提升才能被证实。**

**所以那个反复出现的"样本内有效、样本外不复现",很大一部分其实是
"样本外没有足够的样本去复现"。** 这是一个统计学问题,不全是过拟合问题。
