# 检测窗为什么是 200 根 K 线？合理吗？如何提高检出准确度

**日期**：2026-07-31  
**对应当晚问题**：`为什么训练/检测用 200 根 K？合理吗？如何提高模型检出准确度？`  
**状态**：研究结论（**未改 WINDOW**；改窗 = 单变量实验，需 owner 批）  
**相关代码**：`src/judgment/yolo_candidates.py` `WINDOW=200`；`src/detection/render.py`；`scripts/check_symbol.py` / 实盘 tip 扫描同窗。

---

## 1. 一句话

**200 根 × 15m ≈ 2.1 天**，是为了在一张图里同时装下：

1. **六条均线形态**（SMA/EMA 20·60·**120**）——EMA120 至少要 ~120 根才「看起来像」稳定曲线；  
2. **密集簇的时间宽度**（规则侧 dense 常 ≥5 根，金标框中位宽约 **16 根**，见 p2a）；  
3. **与实盘一致的因果右缘**——窗末 = 信号 bar / 盘口 tip，无后文。

它是**工程约定 + 与旧项目对齐**，不是贝叶斯最优窗长；**合理作为默认**，但**不是神圣常数**。拉长/缩短都要重新训、重新 tip-smoke，且 pad200 类「只改几何」已证伪。

---

## 2. 200 根到底覆盖什么

| 量 | 值 |
|----|-----|
| 时间框架 | **15m**（主线 SWAP） |
| 窗长 | **200 bars** |
| 物理时长 | 200 × 15min = **50 小时 ≈ 2.08 天** |
| 图上 MA | SMA/EMA **20 / 60 / 120**（六条） |
| 实盘扫描 | `scan_series_with_yolo(..., window=200)`，与训练同几何 |
| tip 语义 | 窗**最后一根** = 当前可见最新 bar（live）；金标训练曾用「框右缘 = 窗末」 |

```
时间 →
|←———————— 200 bars 因果窗 ————————→|
[更早历史只进指标预热，不进 YOLO 图]
                              右缘 = tip / signal bar
```

指标预热（WARMUP 等，常 288 根≈3 天）在**进窗之前**就算好，避免图上 EMA 还在乱晃；**进 YOLO 的像素窗固定 200**。

---

## 3. 为什么当初定 200（设计动机）

### 3.1 均线尺度（主因）

形态是「**双均线密集启动**」——六线粘合后再分离。  

- 最短关注 ~**20** 根量级；  
- 中期 **60**；  
- 最长展示 **120**。  

若窗长 **≪ 120**（例如 64），图上 EMA120 几乎是一段「还没收敛的短绳」，密集/发散的相对几何会变形。  
**200 ≈ 120 × 1.6+ 余量**：足够让最长均线「站稳」，又不会把单图拉成一周行情（信息过载、框变小、分辨率稀释）。

### 3.2 与标注框尺度匹配

p2a 冒烟数据（优化 padding 后）：

| 框维度 | 中位（归一化） | 约合 |
|--------|----------------|------|
| 宽度 w | 0.080 | ~**16 根** K 线（在 200 窗内） |
| 高度 h | 0.125 | 价格方向 |

密集簇本身往往只有十几根；**窗 = 背景上下文**，框 = 局部事件。200 给了「前后各大约 90 根」的上下文量级，而不是把事件撑满整图。

### 3.3 训推一致（铁律级）

| 路径 | 窗 |
|------|-----|
| 训练渲染 | 200 |
| tip-smoke / 盘口检测 | 200 |
| 纸面 live_signal_tg | 200 |
| tip-replay | 200 |

**一旦训练 200、推理 128/256，等于换任务。** 历史失败（v13/v14 pad200）很大程度是「训练分布的窗貌/右缘语义 ≠ 盘口 tip」，不是「200 这个数字算错了」。

### 3.4 与旧项目 / 渲染分辨率

- 渲染画布约 **1280×742**（无坐标轴文字，只留蜡烛+均线）。  
- 200 根 → 每根约 **6 px** 宽量级，YOLO 小目标尚可学（smoke3 mAP50 曾到 0.8+ 量级，**仅自家 val**）。  
- 再拉长到 400/500：每根更细，框更小，需更高 imgsz 或更重 backbone。

---

## 4. 合理吗？利弊

### 合理之处（保留 200 的理由）

1. **覆盖 EMA120 + 余量**，形态语义完整。  
2. **训推同窗**，延迟预算与 tip-edge（A′ 只认窗末 N 根）可算术对齐。  
3. **已有大量金标/实验**都建在 200 上；改窗 = 废旧权重 + 重标/重渲成本。  
4. 物理上 ~2 天，符合「短线密集启动」叙事，不是日线级别结构。

### 不合理 / 风险点

1. **不是数据驱动搜出来的最优**——无系统做过 128 vs 200 vs 300 的单变量 tip-smoke 网格（若做过应在报告里，目前主线仍钉 200）。  
2. **框只占窗宽 ~8%**：模型容易学「右缘附近」捷径，而不是「形态」；pad200 把框焊死在右缘后，tip 迁移失败（见 `p_v14_failure_rootcause.md`）。  
3. **长于密集本身 10×**：上下文有噪声（更早无关波动）。  
4. **短于多日结构**：若「真信号」要看 5 天粘合，200 根装不下——但那已不是当前 15m 启动定义。

### 结论（是否合理）

| 问题 | 答案 |
|------|------|
| 作为 **默认工程窗** 是否合理？ | **是**——均线尺度 + 训推一致 + 历史资产。 |
| 是否证明 200 最优？ | **否**。 |
| 应否今晚就改成 256/300？ | **否**——无 tip-smoke 门前的单变量证据；且会破坏与现权重对齐。 |

---

## 5. 已证伪：别用「改窗几何」当银弹

| 实验 | 做法 | 结果 |
|------|------|------|
| **v13/v14 pad200** | 把金标右缘裁到窗末，制造「无后文」正样本 | tip-smoke **0/27** 级失败；H-DET-1 发现级未过 |
| 结论 | 「只要窗右缘=盘口就行」**不够**；pad 后的训练分布 ≠ 真 tip | **禁止再同构 pad200** |

因此：**提高准确度优先改标签/任务定义/评测协议，而不是先拧 WINDOW。**

## 6. 如何提高检出准确度（优先级）

### 6.1 确认级门（项目铁律）

成功不看自家 val mAP，看：

1. **真 tip 金标**（盘口右缘、无后文）上的 tip-hit / 人工认框；  
2. **tip-smoke**（实盘同几何小样本开火）；  
3. 最终 **前向新鲜 100 笔**（与判断层解耦的确认）。

### 6.2 高优先级（比改 200 更值得做）

| 方向 | 为什么 | 注意 |
|------|--------|------|
| **A. 真 tip 小金标** | 分布=生产；pad200 失败的反面 | owner 标盘口图；`label_live_tip_*` |
| **B. 训推渲染字节级一致** | full-MA 再切 vs 先切再 MA 曾害 tip_hit | 一条管线；回归测试 |
| **C. 难负例 / hardneg** | 降假阳，提高可用精度 | 单变量加包 |
| **D. conf / tip_edge 校准** | 不改权重，改工作点 | 生产 conf=0.30；TIP_EDGE 与延迟预算同改 |
| **E. 判断层挑单** | 检测池可为负，L2 仍可抬顶档 | 已有 v10 池 +17bp 量级研究结论 |

### 6.3 中优先级（单变量窗实验——仅当 A–D 不够）

| 候选 | 假设 | 评测 |
|------|------|------|
| **WINDOW=128** | 更少噪声、框更大 | tip-smoke + 真 tip；**禁止**只报 val mAP |
| **WINDOW=256/300** | 更长粘合上下文 | 同上；注意像素变细 |
| **多尺度双塔**（两窗两图） | 短窗细节+长窗结构 | 训练与脉冲耗时翻倍；脉冲预算 &lt;15min |

协议建议（若 owner 批准开窗实验）：

1. 固定权重族 / 或同一底座重训一版；  
2. **只改 window**；  
3. 报告：tip-smoke 开火、真 tip 召回、假阳/币·日、延迟；  
4. **不**自动 promote；  
5. 不碰 holdout 除非批准。

### 6.4 低优先级 / 易踩坑

- 只加大 imgsz 不改标签；  
- 打开 YOLO 增强（fliplr/mosaic 等）——**铁律禁用**；  
- 用回测 PF 或 val mAP 代替 tip-smoke。

---

## 7. 与延迟 / 新鲜度的关系

- 窗长本身不直接等于「信号年龄」；年龄由 **检出时刻 − 信号 bar 时间** 决定。  
- 但 **更长窗 + 更大图** → 单币推理更慢 → 脉冲更容易顶满 15min 预算 → 结构性挡 tip。  
- 故「加窗提准」必须同时报 **discover_wall / phase2_wall**。

当前新鲜度三门 **30min**（执行器 / TG / 看板）由管道算术推导；**改窗不自动改门**，若推理变慢需重算预算表。

## 9. 风险与诚实声明

1. 本文**不修改** `WINDOW`；结论供决策。  
2. 200 的「合理性」是 **工程自洽**，不是样本外最优证明。  
3. 提高准确度的主路径是 **真 tip 监督 + 训推一致 + 工作点**，不是再 pad 一次。  
4. 当前 L1 为 short_star_v10 **临时**；L2 为 v10 池回归；**检测层因果边仍可能为负**（HANDOFF），准度问题与「窗长」纠缠时，先分清是 **召回** 还是 **排序/成本** 问题。
