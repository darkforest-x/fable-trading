# 2. 三天做了什么

## 检测层:v9 → v10

**v9 被证伪(2026-07-28)**:
- owner 逐张审 277 个非金标开火,**否掉 276 个 → 精度 0.4%**(95%CI [0.1%, 2.0%])
- 开火密度 48.8 条/币·月,是 owner 标注密度(0.18~0.36)的 **137~274 倍**
- 「召回 84%」是在 `SCAN_CONF=0.05` 下测的,**生产跑 0.30,该门槛下真实召回 19.5%**
- 调门槛无解:压到 owner 密度需 conf≥0.50,那时召回 0%

**v10 修了三处数据污染**:

| 污染 | 规模 | 修法 |
|---|---|---|
| 窗口未精确还原 | **19.3%** 的金标 | 要求 `resolve_win_start` 的 MAD<0.5(**该返回值此前所有调用点都丢弃**) |
| 方向按「先触发」判 | **9.8%** 的「空头」48 根内涨超 2% | 改为取窗口内**较大**位移 |
| 负样本教不会边界 | 采样器 `if passes(): continue` 排除了「像的」 | 加入 v9 自己的误开火 612 个 |

**v10 结果**:生产门槛下召回 19.5%→**72.2%**,金标置信度中位 0.235→**0.644**,
但**开火密度仍是 115 条/币·月**(owner 是 0.18~0.36)→ **仍未通过验收**。

**v9 vs v10 只有 8.6% 重合**(Jaccard,`scripts/diag_detector_fire_overlap.py`),
v10 的开火里 **76% 是 v9 完全没看到的**,连共同开火位置上的置信度也几乎不相关(+0.040)。
→ **v10 不是 v9 的改进版,是一个几乎不同的检测器。**

## 出场规则:九种同候选对照

**首次把九种出场在同一批候选、同一入场、同一持仓上标注**,以前每种都在各自的脚本和池子上测,互相不可比。

## 判断层

**病因找到了**:生产用二分类器学「这单赢不赢」,但

```
ATR 五分档   胜率 36.2~37.7%(持平)   每笔净收益差 5 倍
```

**边在幅度不在胜率,而分类器学的正是没信息的那一维** → AUC 0.4962 是必然。

**但「改回归」在 v10 上不值钱**:三种目标都是 +14.7~17.8bp,回归比分类只差 **-0.53bp**。
昨天在老池上测出的 +21.46bp(t=3.21,13/15 折)**没有在 v10 上复现**。

**`models/ACTIVE`(v11 判断层)在别的候选上是反选的**:顶档 -32.91bp,底档最好。
病因是同源 —— 它在 v11 自己的候选分布上训练。**这个病三天内出现三次。**

## 经济性:加了匹配随机对照

**此前所有收益数字都没有对照组。** 加上(同币 × 同月 × 同 ATR 桶的随机做空)之后:


**置换检验抓不到这个** —— 它打乱行,而 beta 在每一行下面都一样。

## 一个决定性的负面结果

**在 owner 自己的标注密度下,因果特征一个金标都定位不到。**

**边界**:这测的是表格特征,YOLO 看像素,不完全等价;不证明金标是前视的,
