## 1. 现场复核（今天跑的）

### 1.1 最重要的一条：接到 live 的 L2 无法表达"顶十分位"

```
$ PYTHONPATH=. python3 scripts/diag_active_artifact_resolution.py

artifact          frozen_tp5_sl2_swap_yolo_v10_reg_20260731.json
  best_iteration  1
  trees in file   1                      ← 一棵树
  features        28
  pool            data/judgment_yolo_swap_v10.csv  n=18379

distinct scores   15 for 18379 candidates
  modal score     -0.00043971  covering 15427 rows (83.9%)     ← 84% 候选同分
  threshold       -0.00043971   <-- equals the modal score     ← 门正好落在并列块上

gate pass rate    pool 89.0%   val 91.1%
  a decile gate would pass 10.0%

verdict: this artifact CANNOT express a top decile on its own pool.
```

**这不是"阈值调松了"，是模型没有分辨率。** `best_iteration = 1`：LightGBM 在近噪声目标上
早停，而近噪声目标的 val RMSE 恰恰由"常数预测器"最小化——所以第 1 轮被选成 best，
存进文件的就是一棵树、15 个可能取值。q90 阈值是 val 分数的 90 分位，
当 84% 的行共享同一个分数时，这个分位数就落在那个并列块上，`score >= threshold` 于是放行整块。

**这和 ETH 3m 分类器的死法是同一种**（`(top1+top5)/2` 选 best、epoch 1 被存成 best，
见 HANDOFF 07-30 节）。同一个病在两个不同的框架上各犯了一次：**选择指标不是业务指标。**

**接到 live 的东西，和报告里 +19.4bp 的东西，不是同一个模型：**

| | 研究模型（`p_judgment_maker_cost_on_regtop.md`） | `models/ACTIVE` 的 frozen artifact |
|---|---|---|
| 树 | 400 轮 | **1 棵** |
| 特征 | **47**（28 基础 + 19 alpha） | **28**（0 个 alpha） |
| 选顶档 | 每折分位数，分值 100% 唯一 | 固定阈值，落在 84% 并列块里 |
| 验证 | CPCV 15 折，15/15 正 | 单点冻结 |

07-31 owner 批准的是"L2 切到 v10 池回归"（`642e37b`）。**批准的意图没有被这个 artifact 实现。**
