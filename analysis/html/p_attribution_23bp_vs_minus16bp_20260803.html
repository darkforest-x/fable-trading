解读

主因:CPCV 高估了 22bp

15 折 CPCV(6 选 2,带 purge/embargo)在测试块的两侧取训练样本。

这是 de Prado 的标准做法,purge 也确实挡住了标签窗泄漏 —— 但它挡不住制度泄漏:

模型见过测试块之后的市场状态。

实盘只有过去。 walkforward 只用测试块之前的数据训练,是唯一与实盘同构的切法。

所以这 -21.93bp 不是"哪一方算错了",而是 CPCV 的乐观程度在这个问题上的实测值。

我 07-30 那个 +23.49bp 没有算错,它回答的是"如果模型能看到未来制度,顶档值多少" ——

那不是一个可交易的问题。

次因:19 个 alpha 因子值 17bp,但它们不在 P1 池里

去掉 alpha,顶档绝对从 +30.76 掉到 +13.68。这些因子确实携带信息,

但 P1 immutable dataset 只有 28 个 schema 特征,所以 P2 从一开始就没有它们。

这不是 P2 做错了 —— 是数据合同里没写。

这条是可行动的:若 alpha 因子经得起 walkforward 检验,把它们并入 P1 schema 是有据可依的提案。

但本报告不构成那个提案,它需要单独的预注册(见"下一步")。

数据本身没问题,甚至更好

+5.80bp 说明 P1 的重建(side_aligned_v1 语义 + immutable 合同)没有损害信号。

我原先的假设是"我的数算在了 legacy 语义上所以虚高",这个假设被否定了。

成本那 5bp 是算术

加 5bp 滑点压力线,顶档绝对少 5.00bp。这一级不含任何发现,列出来是为了让它不混进别的解释。

模型配置只值 6bp

P2 的模型退化(1~2 棵树、15 个不同分值)看着触目,但在已经用 walkforward 且加了成本之后,

它只再拿走 6.03bp。换句话说:即使模型不退化,P2 也过不了门。
