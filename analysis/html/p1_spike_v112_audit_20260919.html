3. 最容易误读的收益：后来有突破，不等于当时就知道该买

逐笔报告中，“后来框内出现突破”的 V9 路径平均 +0.491R（15m）/+0.532R（1h），而等联合信号再入场是 −0.095R/−0.092R。前者筛掉了没等到突破就结束的 V9 框；筛选条件发生在 V9 入场之后。

Pine 在“仅显示突破+spike”模式下先隐藏 V9 盈亏框，直到后来出现联合才 reveal；显示的入场价仍是原 V9 确认收盘，绿色框先画 3R 观察位，之后按峰值扩展。这些框不能代表从联合提示时刻入场的已实现收益。 此行为不等于联合信号计算存在前视，但会让事后看图产生筛选偏差。

证据：Pine 1978–2010、2048 附近和 2130–2175；逐笔报告 §3。要回答“看到提示能赚多少”，只能对照联合确认时间、其后可成交价、该笔实际止损及出场净 R。监控端新模拟账本已采用联合后次根开盘，是朝这个方向的改进；它和原 V9 参考框仍然是不同交易。

4. 已确认的源码分流：上级专用预警仍是旧规则

默认框内规则的绘图取 v112HtfShow，任一来源联合预警取 v11AnyJoint。但 Pine 1912 行“突破+spike（上级突破）”专用预警仍取 v11HtfJointEvent，它受旧 6 根窗口和第二事件过滤限制；1905 行事件码的联合位也仍取旧事件。

可证伪的反例：V9 多头框仍开着，首次上级突破晚于 6 根且期间没有新 V9。框内标签可以出现，旧窗口上级预警不满足。反方向也不能假定等价，因为旧规则允许“先突破再 SPIKE”。任一来源预警已跟随新规则，不能笼统说所有预警都错。

本次通过源码追踪确认逻辑不等价，未在 TradingView 实际触发这个场景。建议修正最终事件路由后，以同一事件 ID 核对图上标记、两类预警和导出码；本次审查没有擅自改脚本。

5. 仍欠缺的一致性与样本边界

  • Pine 与 Python 的逐根对账尚无完整验收证据。 原 V9/V10.4 账本复现 0 差异，只能证明 Python 结果连续，不能替代 TradingView 编译、运行和事件对账。39 个相关单元测试本次全部通过。
  • 未发现可以直接判为前视的上级取值写法。 当前 Pine 使用各输出 [1] 加 lookahead_on，符合 TradingView 官方说明的已确认上级 K 取值模式；仍需核对图表收盘门和实际通知延迟。不能仅因看到 lookahead_on 就说作弊。
  • 回测还未覆盖当前最近数月。 loader 仍固定截止 2026-05-01。Owner 已在 2026-09-19 取消历史 holdout 限制，5 月以后可以直接研究；旧文档“不许看 HYPE 9-17”的说法不再是当前限制。最新行情复查仍不是未经看过的独立前向。
  • 版本和周期不能混用。 本轮 V11.1 框内入场和 V11.2 管理实验只测 15m/1h；V10.4 的六周期测试不能证明新版 30m/4h。新监控已提供 15m/30m/1H/4H，数据为 OKX，旧收益统计主要为 Binance，需同源对账或明确跨源适用边界。
  • “没画出手画线”已有具体诊断。 SOL 例子涉及相等高点、B→C 19 根小于 24 根、C 离线 0.58ATR 超过 0.35；ETH 中间触点不是规则 pivot。见 docs/learnings/a-missing-hand-drawn-line-needs-each-rule-measured-on-that-triple.md。这是形态定义差异，不再只是“可能只显示一条线”；若改规则，原回测不能直接继承。

6. 统计优势和账户可实现性仍未成立

  1. 旧 V10.4 1h 相对随机 p≈.009，但六周期 Bonferroni 校正约 .054；相对 V9 的每笔改善 +0.093R，区间 [−0.046,+0.223]。不能从“胜过随机”跳到“趋势线硬过滤已有效”。
  2. 原 V10.4 1h 去掉最好 14 笔后为 −0.070R/笔。趋势策略依赖尾部并不自动构成错误，但它要求验证资金约束下能否真实接到尾部赢家。
  3. 框内主臂历史最大同时持仓 15m 121、1h 82 个。每币串行不等于账户级风险受控；将每笔 R 相加不能解释成资金曲线。
  4. 0.2% 往返成本已经计入，但滑点、资金费率和可成交容量未建模；币池有幸存者偏差。旧增量审查明确“含浮盈的逐时账户验证尚未完成”。本次没有新增账户验证。

新监控仍有三个具体边界

  • 默认总账混合历史回放与启用后记录。 Worker 冷启动补录最近 200 根内的历史事件；API 已正确区分 history/live/late，但页面 liveOnly=false 默认取 scope=all。因此看到的已实现 R 不能直接叫独立前向成绩。即使选择 live，当前分类容许发现延迟最多一个周期加 5 分钟，盈亏仍按理论次根开盘回放，没有改用实际首次发现之后的可成交价。证据：spike_lines_worker.py:178,260，spike_lines_api.py:45,88，static/app.js:423。
  • 冷启动和滚动窗口的状态未与研究历史对齐。 主扫描器冷启动取 720 根，增量合并后可增长；日线冷启动最多约 400 根，而研究预热 1,500 根、线搜索范围/存活各 600 根。联合监控再将输入裁为最近 1,500 根。analyze 最低只检查 200 根，没有表达“与长历史状态尚未核对”。尤其 4H←1D 与日线突破存在漏线或状态不同的风险；本次未量化其频率。证据：v9_worker.py:113、okx.py:140,159、spike_lines_worker.py:199、spike_lines.py:65,176。
  • 跨窗口旧仓占用没有延续。 positions 每次从 flat_from=-1 开始，仅回放当前窗口；旧 active 事件离窗后改成 unknown，但旧仓可能仍未退出，后续信号却可以在重放中开仓。触发条件是持仓超过可保留的历史窗口且其间没有权威退出；这破坏连续的“每币每周期一笔”语义。证据：spike_lines.py:55,144、spike_lines_worker.py:87,270。这是静态边界风险，未证明当前真实账本已经发生。

已做对的部分应保留：独立 SQLite、只读主 K 线检查点、首次发现时间不被历史回放覆盖、显式区分启动前/实时/补录，以及活跃模拟仓位持续刷新。不能把这些问题描述成“没有监控”。
