1. 规则（按 Owner 原文逐字落地）

Owner：「v10去掉 重新做 用spike v9 和我这个趋势线指标 只有当我的趋势线指标出现 突破信号 然后v9也有信号才行 支持先突破 然后最多7根k出现v9信号 我们v10才做多 不需要做空信号」。

  • 突破：Owner 指标的向上收盘突破（下降压力线，参数全用 Owner 默认值，未调）。
  • V9 多头确认在第 s 根，最近一次突破在第 b 根，0 ≤ s−b ≤ 7 才开多。突破当根算第 0 根，第 7 根仍准入，第 8 根起拒绝。 V9 先出、突破后到的不算（那一刻突破还没确认）。
  • 不开空。V9 空头确认仍按 V9 原规则结束已持有的多单——这是 V9 的出场，删掉它是在「不做空」里藏第二个改动。
  • 数据缺口清空突破记录：缺口另一侧的突破不算「7 根之内」。
  • 其余（V9 入场过滤、止损、追踪、0.2% 往返成本）与已发布 V9 逐字相同。

第一版 V10（多空双向、≤0/12/48/200 根四个窗口）按 Owner 指示撤回，报告 analysis/p1_spike_v10_trendline_gate_20260918.md 原样保留为历史，不再叫 V10。

4. 两步归因：V9 → V10 的差额从哪来

V9 → V10 同时改了两件事，所以拆成两步。每一步都只删入场、不改出场；程序核对两臂共有事件的结果逐笔相同， 且「避开的亏损 − 错过的盈利 + 新增入场」等于总净 R 差额。

10. 风险与诚实声明

  • 不是盲测：两段数据都被看过多轮，前段 p=0.032 不构成样本外证据；新规则的窗口落在撤回版已看过的范围内。
  • Pine 与 Python 的一致性只在 Python 侧验证过：Python 移植有逐字 Pine 对照、截断无前视、两份独立移植互校； TV 端未编译、未逐根对照。
  • 右侧确认延迟：关键点要 8 根后才确认，线在图上「早就画好」，实盘要晚 8 根才看得到。这不是前视，但目视回看会高估。
  • 叠加 ≠ 账户：3,531 流同权叠加、无共同资金与仓位上限，净 R 合计与回撤都不能读成账户收益。
  • 成本：固定 0.2% 往返，未含资金费率与滑点分布。
  • 未训练、未 promote、未改仓、未动真金、未接实盘。
