结论一句话：门把每笔净 R 从 +0.0553 提到 +0.1028（≤12 根窗口），PF 1.083→1.155，配对随机超额 +0.0699→+0.1018，事件回撤降 66%，但准入笔数只剩 42%，总净 R 从 +3,400R 降到 +2,685R。改善几乎全部来自前一段；2025-09 之后所有臂仍然亏，而且三个较宽窗口的配对超额在后段转为负——这道门没有修好 V9 的病。不建议 promote，holdout 仍然是完整的 4.2 个月盲样本。

附带一个反直觉结果：多头侧有 47.7%~55.7% 的「突破」其实是那条下降线自己走到价格上，价格根本没涨；而这一类反而更赚（+0.0822 vs 价格真冲上去的 +0.0399 R/笔）。「再加一道只要真突破」的直觉被数据推翻了，见 §6。

1. 本次做了什么

Owner 给出 Pine v6 指标「主下降趋势线 · 关键高点 V1」，提了两件事： 「把这个趋势线突破 加入我们的spike v9 写一个v10」，以及 「对v10做回测 要求v9出了信号 同时 或者信号处于刚好趋势线突破 或者突破了一会的」。

V10 = V9 + 一道入场门。门的定义：V9 原始确认那一根，本方向的趋势线突破要么就发生在这一根 （年龄 0），要么发生在最近 N 根之内。多头看由关键高点连成的主下降压力线被向上突破， 空头看由关键低点连成的主上升支撑线被向下突破。

门只会删掉 V9 的入场，不会新增入场，也不碰任何出场。 原始反向 V6 确认照旧结束已有参考， 串行引擎收到的反向事件流与 V9 一字不差。所以 V10 与 V9 的差额只有三个来源：避开的亏损、 错过的盈利、以及删掉入场后腾出仓位带来的新入场。三者相加必须等于总净 R 差额，程序强制核对。

TradingView 脚本：yoyo/evaluation/pine/spike_burst_v10.pine（「SPIKE V10 · 趋势线突破确认」）。 这份 Pine 没有在 TradingView 上编译过——见 §7。

2. 移植的忠实度：四道验证

趋势线逻辑是 Owner 脚本的逐行翻译，包括一根 K 线内部的操作顺序（①检查已存在的线是否被收盘 突破或到期 → ②压入刚完成右侧确认的关键点 → ③只有在「本根确认了关键点且本根没有刚突破」时 才寻找新线）。这个顺序本身就是因果性的一部分。

因果性：关键点在 p 根出现，但要到 p+8 根才确认，所以 b 根建立的线不读 b 之后任何数据； f_isClean 只走 x1..b；突破判定只读当根收盘和当根 ATR。右侧确认的 8 根延迟是画法本身的 延迟——回看历史时线看起来「早就画好了」，实盘要晚 8 根才看到。这不是前视，但必须记在账上。

6. 门筛的到底是什么：一半的「突破」是线自己降下来的

并行会话的笔记 docs/learnings/a-descending-trendline-break-is-a-crossing-not-a-breakout.md 证明了一件事： 这个指标的信号是一条向下移动的阈值线被跨越，而跨越有两种完全不同的成因——价格涨上去了， 或者线自己降到价格上。本次对全池 3,531 流每一次跨越做了精确分解 （price_move + line_drop 等于建线到跨越之间闭合的全部差距，两项都换成跨越当根的 ATR）：

所以「V10 是突破过滤器」这句话是不准确的。 多头侧接近一半的准入事件，价格在建线到跨越 之间根本没涨（中位数还微跌），是那条陡峭的旧线走下来碰到了价格。ETH 4H 的目视图 （results/trendline_check_eth_4h.png）就是这个形态：所有压力线都锚在同一个远处高点上， 呈扇形降下来，420 根里出了 10 次「突破」。

这把「加一道『只要真突破』的条件会更好」这个直觉直接推翻了。 在这段历史上， 价格真的冲上去的那一类反而更差。一个说得通的机制：V9 里本来就有 V8 的过热门 （收盘离六线超过 3ATR 不入场），而「价格主导」按定义就是建线到跨越之间价格走了 2 个 ATR 以上，两者指向同一件事——在一段猛冲之后才进场是更差的。线降主导的跨越中位存活 44 根、 价格几乎没动，那是盘整后的状态，不是追涨。

所以 §9 里原本最自然的下一步（「只保留价格主导的跨越」）按本数据是反方向的。 真要做这个单变量实验，它检验的是「只保留线降主导」，而且要先接受它与已有的过热门高度重叠。 本轮不做：按成因过滤是改入场规则，属于新实验、新的单变量（铁律 4）。

7. 风险与诚实声明

  • 两段都不是盲样本。 2024-09 → 2026-05 已被 V8/V9 研究反复观察，前一段最久。 「前一段 p=0.004」在这种曝光程度下不能当作显著性证据。holdout 消耗 0， 2026-05-04 → 2026-09-10 仍是完整的 4.2 个月盲样本。
  • 多重比较。 5 个臂 × 3 段 × （周期 / 方向）切分。表里最小的 p 是 0.0040， 按最保守的方式看这些 p 全部不过项目的 p<0.01 门。
  • 这份 Pine 没有在 TradingView 上编译过。 做了差分标识符检查（V10 里所有未声明标识符 都出现在已在 TV 上跑过的 V9 里，无一例外），但那不等于编译通过。Owner 首次粘贴时若报错， 把错误发我。另外 max_bars_back=1300 是为 600 根扫描窗留的余量，V9 原来没有这一项。
  • Pine 与 Python 的一处已知细微差异：非法价格那一根，Python 把新连续段起点设在该根之后， Pine 的 segmentIndex 把该根本身算作段起点，差一根。本池的冻结缓存已验证过价格合法性， 这条路径在本次回放里不可达，但如果换到未验证数据源上会显现。
  • 截断使切点附近的样本被删失。 入场在切点前、出场在切点后的仓位记为删失（a12：153 笔）， 不把未知收益算成 0；配对随机对照里出场跨切点的也同样删失、不计入配对分母。
  • 「净 R 合计」不是账户收益。 3,531 条流叠加，没有共同资金、没有仓位管理， 事件回撤不是账户回撤。每笔净 R 与配对超额才是信号质量的读数。
  • 4H 的 PF 1.258 是 beta，配对超额 −0.1313。不要只看 PF。
  • 方向切分是事后的。 「空头后段 +0.1534R、p=0.027」不能作为「V10 只做空」的结论。
  • 两个 bug 是被这套检查抓出来的，不是事后发现的：① 用 Series.equals 比较列会连 dtype 一起比，两边都为空时 CSV 空列与回放空列 dtype 不同，22 条流误报；② 出场时间戳记的是出场 那根的开盘，所以「时间戳 == 切点」意味着这笔在 holdout 第一根出场，对照窗口右端必须 取最后一根保留 K 线的开盘而不是收盘。详见 docs/learnings/truncation-parity-boundary-is-the-last-kept-bar-open.md。
  • 未训练、未 promote、未改仓、未动真金、未接实盘。 models/ACTIVE 与 frozen 默认配置 没有变化；experiments/registry.yaml 里本实验 production_eligible / training_eligible 保持 false。
  • AUC / top-decile 不适用：V10 是规则门，不是打分模型，没有连续分数可以排序取前 10%。 对应位置用的是「准入率 + 按年龄分桶的每笔净 R」（§6 末表）与五个臂的对照， 以及方向性实验必须的匹配随机对照组（每张结果表都带）与整月块符号翻转检验。
