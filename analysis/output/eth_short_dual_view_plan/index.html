标注语义必须拆成两问

否则“形态像不像”和“后来赚没赚钱”会再次被塞进同一个标签，检测层会被迫学习一个可能根本不可从盘口预测的结果。

问题 A · 形态标签（给检测层）

shape_short_start这是你认可的空头密集启动；画/调整框
shape_no不是目标形态；删除预框
uncertain看完未来仍不确定；不当负样本
bad_data缺 K、异常针或渲染问题

问题 B · 后续结果（给判断层/审计）

clean_drop启动后出现清晰、可交易的下跌
weak_or_late方向对，但太弱或太晚
failed假启动、反抽或先触发风险
visual_uncertain肉眼不能稳定裁决
最重要的风险：如果规定“只有后来大跌的密集才算形态正例”，YOLO 实际学的是未来成功事件。这不是天然错误，但必须先通过 tip-only 可学习性实验；若因果图无法区分，继续堆标签只会得到事后识别器。

完整流水线

每一步只接受前一步的结构化事件，不靠人工记忆，也不靠“训练时别看右边”的口头约定。

① 候选发现v10 causal-tip、因果数值规则、未来结果发现、分层随机背景。来源对你隐藏。
② 双视图生成同一 event_id 生成 proposal_tip.png 和含未来 review.png；预框由前者映射到后者。
③ 人工验真你看未来，回答形态与结果两问；最终框落到时间和绝对价格坐标。
④ 因果重渲染按最终框右缘重画 train_tip.png；未来区域从物理文件中消失。
⑤ 分层训练YOLO 学形态；LightGBM 用 as-of 特征学经济结果；时间切分、匹配对照。
PHASE 0

先冻结定义，不先重画 2000 张

  • 确认未来观察窗的绝对时长；不同周期用相同墙钟时间，不用相同 bar 数。
  • 确认“形态正例”和“结果好坏”是否按两问保存。
  • 确认判断层 TP / SL / 超时与成本；这些参数仍需 owner 明确批准。
PHASE 1

补齐原生近两年微周期数据

  • 目标开发区间：[2024-05-04, 2026-05-04)，3m 与 5m 用原生 OKX 数据；10m 只由两根完整、UTC 对齐的 5m 聚合。
  • 由 VPS 拉取并作为唯一写者；本机只同步读取，不在本机另造一份历史。
  • 任何 review 图都必须满足 future_end < 2026-05-04，不能为了看未来跨入 holdout。
PHASE 2

先做 240 张校准包（每周期 80）

  • 候选源目标比例：v10 ≤30%、因果数值 25%、未来跌幅发现 20%、分层随机背景 ≥25%；v10 不足时不放宽 exact-tip 条件。
  • v10 候选内部 50% 显示预框、50% 隐藏；另放入 10% 盲重复任务，测你自己的标注一致性。
  • 你先标这 240 张，分析各来源正例率、预框锚定偏差、框宽/右缘分布和重复一致率。
GATE A

先回答“盘口是否可学习”，再扩标

  • 把 240 张的正例重渲染为 tip-only，做一次小模型时间外验证。
  • 同时用相同时间块、相同波动桶的随机背景测精度和开火密度。
  • 若模型只能在含未来 review 图上表现好，而 tip-only 无法定位，就停止扩大标签；这说明目标仍是事后语义。
PHASE 3

通过 Gate A 后分批扩到 2000

  • 建议节奏：240 → 840 → 2000；每批后检查形态定义是否漂移。
  • 当前 2000 张 causal-tip 图不删除，可作为候选/模型侧快照；靠近 holdout、没有足够未来窗口的事件需替换。
  • 最终生成 3 套独立数据：human_review、detector_causal、judgment_asof。
PHASE 4

三周期分别训练，不先混模

  • eth_short_3m_det_v1、eth_short_5m_det_v1、eth_short_10m_det_v1 分开训练与报表。
  • 先用 COCO yolo11 底座做基线；v10 初始化只能作为单变量 A/B，不能因为它会画框就默认更好。
  • YOLO 增强继续全关：flip、mosaic、mixup、HSV 均不允许。
PHASE 5

每个检测器配自己的判断层

  • 判断层候选必须来自对应周期的检测器，不能拿 3m 判断层给 10m 候选打分。
  • 特征全部 as-of cutoff；未来只生成 realized return / barrier outcome。
  • 方向性结果必须带同一 ETH、同时间块、同波动桶的匹配随机做空对照。
PHASE 6

冻结后才申请最终验收

  • 开发与 accept 全通过后，列出完整配置并向 owner 申请一次 holdout 消耗；未批准不读。
  • 任何模型不自动 promote，不改 ACTIVE，不接实盘。
  • 最终确认仍靠新鲜前向裁决；三个周期分别报告，不能用合计样本掩盖某个周期失败。

事件与文件契约

坐标转换是整个方案的防火墙。人工框不能以“review.png 上的百分比”直接进入训练。

event_id/ ├── proposal_tip.png # v10 输入；200 bars；end = proposal_ts ├── human_review.png # 人工输入；历史 + proposal + future ├── annotation.json # shape / outcome / 框的时间与绝对价格 └── train_tip.png # 标后重画；200 bars；end = final_cutoff_ts canonical_event.csv event_id, symbol, timeframe proposal_ts, review_start_ts, review_end_ts shape_decision, outcome_decision box_start_ts, box_end_ts, price_low, price_high final_cutoff_ts, candidate_source_hidden prebox_visible, labeler_revision, split_time

坐标转换

  1. 利用 review 图的 bar 时间表，把框的 x 百分比还原为 bar 起止时间。
  2. 利用该图渲染时保存的 y 轴上下界，把框 y 百分比还原为绝对价格。
  3. 令正例的 final_cutoff_ts = box_end_ts；负例沿用 proposal_ts。
  4. 从原始 K 线重新计算截至 cutoff 的均线并重画 200 根。
  5. 用新图的时间/价格尺度重新计算 YOLO normalized bbox。

机器验收断言

  • max(train_bar_time) == final_cutoff_ts
  • max(feature_source_time) <= final_cutoff_ts
  • review_end_ts < holdout_start
  • 框时间映射误差为 0 bar；价格映射 round-trip ≤1 px
  • 所有重叠事件按 UTC 时间同侧切分，切点周围做 purge
  • 任务数 = 事件数 = 图片数 = 标签记录数
为什么不能直接裁掉 review.png 的右半边？
未来大跌或反抽会改变整张图的 y 轴范围；直接裁像素后，K 线高度、均线位置和人工框 y 坐标仍携带未来缩放信息。重新从原始 K 线渲染，才能保证模型看到的是当时真实会生成的画面。

v10 的正确位置

候选提议器和可选初始化对照。它是 15m OOD 且密度未过，不能定义标签全集。

验收门：每层回答不同问题

mAP、AUC 和回测收益都保留，但任何一个都不能单独宣布成功。

Gate A · 标签可学习性

  • tip-only 时间外样本可区分
  • 对匹配随机背景有真实增益
  • 预框显示/隐藏不改变标签语义
  • 盲重复标注一致

Gate B · 检测器

  • 真 tip owner 金标召回/精度
  • ETH 每月开火密度
  • 框右缘 = 0 bar 偏移
  • 自家 val/mAP 只作诊断

Gate C · 判断层

  • top-decile 扣 0.2% 后为正
  • 置换检验 p<0.01
  • 匹配随机对照后仍有增量
  • walk-forward 各折稳定
诚实边界：人工看未来能提高“你想要的形态”定义质量，但不能保证盘口存在足够可学习的先验信号。这个方案的第一目标不是承诺更高精度，而是用 Gate A 尽早、低成本地回答这个前提到底成立不成立。
