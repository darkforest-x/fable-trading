## 2. 逐层拆解：这个指标究竟量了什么

### 2.1 原料只有价格，没有成交量或订单流

src=(high+low+close)/3。open、volume、持仓量、主动买卖量、资金费率均未参与。
因此它不能直接证明“主力进场”“资金流入”“多空真实成交量反转”，也不判断K线本身是阳线还是阴线。

### 2.2 上下轨是SMMA，不是34根普通均线

hi=SMMA34(high)，lo=SMMA34(low)。首个值由34根SMA播种，之后：

```text
SMMA[t] = (33 × SMMA[t−1] + price[t]) / 34
```

alpha=1/34，旧状态影响每根乘33/34；影响半衰期约23.2根，记忆并不在第34根突然归零。在4h图上，23.2根约3.9天。
同样的有效输入与播种下，这对应Wilder/RMA形式。两个calc_smma调用各自持有独立历史，不会因局部变量同名而把high和low混算。参见[TradingView函数作用域说明](https://www.tradingview.com/pine-script-docs/language/user-defined-functions/)。

### 2.3 所谓zlema，实际代数公式是DEMA

```text
ema1 = EMA34(hlc3)
ema2 = EMA34(ema1)
mi = 2 × ema1 − ema2
```

这正是DEMA公式。命名沿用旧脚本，不影响公式执行，但“零滞后”不能理解为提前知道未来，也不保证转折零延迟；差分补偿会在突然反转时产生超调。它也不同于先对price做滞后补偿再EMA的另一类ZLEMA写法。参见[TradingView DEMA公式](https://www.tradingview.com/support/solutions/43000589132-double-exponential-moving-average-ema/)。

### 2.4 md是“带死区的偏离”

| 条件 | md | 准确含义 |
|---|---|---|
| mi > hi | mi−hi > 0 | 快速平滑价格在上轨外 |
| lo ≤ mi ≤ hi | 0 | 快速平滑价格位于带内 |
| mi < lo | mi−lo < 0 | 快速平滑价格在下轨外 |

也可以写成：

```text
c = (hi+lo)/2 = SMMA34(hl2)
w = (hi−lo)/2 = SMMA34(high−low)/2
d = mi−c
md = sign(d) × max(abs(d)−w, 0)
```

这个等价式说明：通道宽度是平滑单根高低幅度，不是ATR，也没有计入跨bar跳空的true range。
md=0只证明mi在通道内，不能单凭它证明“市场低波动”“六均线密集”或“即将突破”。持续宽幅来回波动也可能进入带内。
LazyBear原作的目的就是削弱均线带内摆动；目的不能自动当作盈利效果。参见[原作](https://www.tradingview.com/script/qt6xLfLi-Impulse-MACD-LazyBear/)。

### 2.5 sb、sh与箭头不是三票独立证据

sb=SMA9(md)，sh=md−sb。
金叉严格等价于sh本根>0、上根≤0；死叉等价于sh本根<0、上根≥0。
因此“md金叉 + 蓝柱翻正”完全重复，“死叉 + 蓝柱翻负”也完全重复。

SMA9是均值，不是动量的一阶导数。其每根变化是(md[t]−md[t−9])/9，旧高值离开窗口也能让信号线下移。
甚至当md本根下降时，也可能发生金叉：用md序列100、−10、−10、−10、−10、−10、−10、−10、−1、−2，最后两根的md从−1降至−2，而sb从29/9降至−73/9，仍然金叉。
“相对近期基线改善”比“价格上涨加速”更准确。该序列是代数示例，不是交易案例。

## 3. 应当怎样读图与信号

### 3.1 先看主线正负，再看蓝柱

| 状态 | 优先解释 | 不应直接推导 |
|---|---|---|
| md>0，sh>0 | 上轨外偏离高于近期均值 | 必定继续涨、适合追价 |
| md>0，sh<0 | 上轨外偏离低于近期均值 | 已进入空头趋势 |
| md<0，sh<0 | 下轨外偏离低于近期均值 | 跌幅一定还会扩大 |
| md<0，sh>0 | 下轨外偏离相对近期修复 | 已经转成多头趋势 |
| md=0，sh≠0 | 已回带内，信号线还记着过去 | 已经向箭头方向突破 |
| md=0，sh=0 | 两者都在零点 | 一定马上启动 |

若md连续9根为0，sb也为0；在继续为0期间，严格交叉不会凭空重复产生。
但从负md回到0时，旧sb可能仍为负，可以出现金叉；从正md回到0则可能出现死叉。这是回到中性区，不是自动完成相反方向突破。

### 3.2 同一种箭头至少包含三类事件

- 金叉且md<0：空头偏离修复，属于逆势转折候选；金叉且md=0：回到/处于带内；金叉且md>0：多头区域的相对增强候选。
- 死叉且md>0：多头偏离减弱；死叉且md=0：带内事件；死叉且md<0：空头区域的相对增强候选。
- 这些是描述分类，并非某类必赚或必亏。过滤成“金叉且md>0”会减少逆势事件，也可能错过最早一段反转；必须另做单变量对照，不能口头宣布改善。

### 3.3 四种颜色实际在比较src，不在比较md与sb

| 颜色 | 代码的精确条件 |
|---|---|
| lime | src>mi 且 src>hi |
| green | src>mi 且 src≤hi |
| red | src≤mi 且 src<lo |
| orange | src≤mi 且 src≥lo |

颜色不直接检查md斜率、sh、交叉或K线实体方向。红柱不等于死叉，绿柱不等于金叉；深绿/橙色也不能简单翻译为固定的弱多/弱空级别。
md与sh两组直方图叠画会遮挡，尤其半透明蓝柱可能干扰读色。主线改线图或给蓝柱独立视觉层可改善阅读，但不会改变信息含量。
顶/底部三角形只是绘图位置，不代表已经识别出价格顶部/底部；大小也不代表信号强弱。

## 6. BTC与ETH永续：归一化、结构与成本

### 6.1 不跨币比较绝对柱高

md的单位是价格（USDT），不是百分比。BTC的md=100和ETH的md=10没有直接可比性。
正价格倍乘会把md/sb/sh同比放大，但不改变理论交叉。这也解释了“BTC柱子大”本身不代表更强。
若做跨币排序，可以另研究md/close、sh/close或md/ATR、sh/ATR；分母必须只使用当前已收盘及之前的数据。ATR长度和实现需明确；本次没有新增、训练或优化这些特征。
不要把`md/ATR`再做SMA当成原指标的等价显示：分母随时间变化时，这会改变信号定义。

### 6.2 按市场结构区分用途

- 持续趋势：反向交叉经常先表达偏离减弱，适合研究减仓/退出提示；直接反手则是在押注趋势反转。
- 回踩后延续：价格结构仍有效时，同方向恢复事件可作为候选，但IMACD不是独立于均线的新数据源。
- 横盘震荡：死区能减少事件，却不能辨认所有区间；通道边界附近仍可能反复切换。
- 快速V形反转：DEMA响应较快，但SMMA与信号线仍记着旧行情；确认可能落后于价格，且补偿可能超调。
- 高波动单根冲击：高低点同时影响src与通道，柱体变化不能简单归因为买卖力量；应分辨冲击与持续结构。

BTC和ETH应分别报告这些状态下的结果，再考察共同性。不能只用币种名称作为状态替代。若同时开同向BTC/ETH仓位，也不能默认两笔风险互相独立。

### 6.3 永续的可交易性不由箭头决定

代码没有仓位、杠杆、保护止损、退出、资金费率、点差、成交量或成交价格模型。
每次往返净收益须至少扣除双边手续费、滑点/点差及持仓期间资金费用；资金费用也可能为收入，应按实际方向、持仓与结算时间记账。OKX可能调整资金结算频率，不能把固定8小时写成永恒事实。参见[OKX资金费用机制](https://www.okx.com/en-us/help/perps-funding-fee-mechanism)与[交易费用说明](https://www.okx.com/en-sg/help/trading-fee-rules-faq)。
本仓统一0.2%=20bp往返成本只是既有研究口径，不是查过你的账户后得出的实际费率。本次没有改变成本假设，也没有计算净收益。
例如仅讨论代数：毛利15bp、往返成本20bp，则净值为−5bp；杠杆不改变该单位名义本金上的正负号。
图表成交价、标记价格、指数价格也应区分；止损触发与强平机制不是这个指标所模拟的内容。

## 7. 代码审查与最小改进

### 7.1 没有明显未来函数，但有盘中变化

这段代码没有request.security、负向偏移绘图或未来pivot确认引用。固定已收盘OHLC下，计算是因果递推。
但当前bar的high、low、close一直变，原crossUp/crossDn未加收盘确认，因此盘中箭头和背景可能出现后消失，警报也可能与收盘后图形不一致。严格说不能宣传“完全不重绘”。参见[TradingView Pine v5重绘说明](https://www.tradingview.com/pine-script-docs/v5/concepts/repainting/)。

如果你的意图是收盘后才确认，可将原交叉定义替换为下面的语义修正；这里没有加入零轴过滤、趋势门或修改34/9：

```pine
rawCrossUp = ta.crossover(md, sb)
rawCrossDn = ta.crossunder(md, sb)
ready = not na(hi) and not na(lo) and not na(sb)
crossUp = ready and barstate.isconfirmed and rawCrossUp
crossDn = ready and barstate.isconfirmed and rawCrossDn
```

随后plotshape、bgcolor、alertcondition共同引用修正后的crossUp/crossDn；UI创建警报选择“每根K线收盘一次”。历史已收盘信号原则上保留，改变的是盘中输出与早期未就绪输出。
这段是建议片段，没有代你修改TradingView或配置警报，也没有宣称原生编译已通过。警报保存的是脚本和参数的快照；改脚本后需按平台机制重建相应警报。参见[TradingView警报文档](https://www.tradingview.com/pine-script-docs/v5/concepts/alerts/)。

### 7.2 输入、初始化与命名

- input.int至少加minval=1，避免0/负周期运行错误。lengthSignal=1会使sh恒0；lengthMA=1时mi=hlc3位于high/low内，md恒0；合法输入也可能退化为完全无信号，应在说明中写明。
- 预热期间hi/lo为na，原三元表达式可能把md显示为0；不应把刚加载图表的这些零当成真实盘整。上面的ready改善初始显示语义，但递推收敛仍需足够历史。
- calc_smma里可把`seed=ta.sma(src,len)`移到每次调用都执行的位置，再用seed播种，便于静态检查与维护；不要随手替成普通EMA或pandas默认ewm初始化。
- 警报文案“买入信号/卖出信号”容易使相对交叉被理解成交易指令，建议写“IMACD收盘金叉/死叉，需结合主线零轴位置”。
- 粘贴内容包含Markdown的`**`、转义下划线及`&#x20;`；如果这些字符确实进入Pine Editor，要恢复成纯文本。不要把展示格式当作可编译源码。
