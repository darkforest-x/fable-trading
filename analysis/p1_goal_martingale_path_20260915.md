## 先看结论

1. **ETH × V8 在 3m/15m/30m/60m/240m 全都没有可信的毛 edge。** 10 个格子的毛 R
   95% 下界全部 < 0，单侧 p 全部 > 0.10。其中 3m 有 1453 笔样本，毛 R = **+0.0045**、
   p = 0.468 —— 样本量足够大，可以判定 3m V8 信号本身没有方向性。
   **即使手续费为零，ETH 3m 倍投也不赚钱。**
2. **成本是 3m/5m 的第二个独立死因。** cost_R（手续费折算成 R）随周期单调下降：
   3m 0.49 → 5m 0.35 → 15m 0.21 → 30m 0.125 → 60m 0.091 → 240m 0.041。
   3m 有 **49.3%** 的交易手续费超过半个 R，一次完整止损实际亏 1.49R 而不是 1R。
3. **全市场 V1 池的正收益是两个月的行情，不是 edge。** 6170 笔**全部是多头**，
   25 个月里 19 个月净 R 为负；总净 R +838.2 中，2026-04（+1188.5）与 2026-08（+709.3）
   合计 +1897.8，**去掉这两个月整池是 −1059.6**。
4. **因此本轮没有找到可以承载倍投的配置。** 已验证配置上倍投必然亏损，不是参数问题。

## 解读

- **3m 的两个死因是独立的**：毛期望 ≈ 0（信号没有方向性）＋ cost_R ≈ 0.5（成本吃掉半个 R）。
  修好任何一个都不够。倍投在负期望上只是把"很多小亏"换成"偶尔一次归零"。
- **15m 是 ETH 里最接近的**：毛 R +0.174 是所有周期最高、cost_R 也已降到 0.21。
  但 p=0.153，269 笔仍不足以断言。它是下一轮唯一值得投入的 ETH 配置。
- **全市场 V1 的 +0.136 净 R 不能当 edge 用**：全是多头、19/25 月为负、收益集中在两个月。
  这正是 CLAUDE.md「报池子的绝对收益不带对照组」那条铁律警告的形态。Owner 在 09-13
  问过"我们的策略比较适合普涨行情？"——月度表直接支持这个直觉。
- **对倍投的直接含义**：倍投在连续 19 个负月里会不断加码，活不到 2026-04。
  这不是模拟推断，是月度账本直接读出来的。

## 零假设对照说明

本轮是**诊断性实验**，检验的是"某配置的期望是否 > 0"，不是排序模型，因此
AUC / top-decile / 单特征基线按字面不适用。同等严格的零假设对照用的是：
月块 bootstrap（保留月内序列相关）+ 单侧 H0: 均值 ≤ 0 + 家族内 Holm 校正。

**匹配随机对照本轮未做**，因为两个源账本都没有附带对照组，而本轮不重跑回测。
这是本轮最大的口径缺口：全市场池 +0.136 净 R 中有多少是普涨 beta，本轮无法回答，
只能证明它高度集中在两个月。**补匹配随机对照是下一轮第 1 项，不是可选项。**

## 风险与诚实声明

- **本轮 holdout 消耗 0 次**，未读取任何 ≥2026-05-04 的数据，未读取原始价格。
- 成本基准固定为项目假设的 0.2% 往返，**未改动**。脚本里的 0.10%/0.05% 列只是
  敏感性展示，改动成本假设需 owner 批准（CLAUDE.md 升级规则），本轮未用于任何结论。
- 全市场账本的 `available` 窗口（2024-09 → 2026-09）**包含 holdout 期之后的月份**。
  本轮只用它做描述性月度集中度诊断，未用于任何配置选择或参数调优；若下一轮要
  用它做选择，需要先按时间切分并取得 holdout 授权。**这一点必须在下一轮前确认。**
- 毛 R 检验"不显著"不等于"已证明为零"。60m/240m 样本量太小（65/15 笔），
  它们的 CI 宽到无法排除真实 edge，也无法支持它。
- 月块 bootstrap 假设月与月之间可交换。收益集中在 2 个月时，这个假设会让 CI 很宽，
  这是正确的行为，不是缺陷。
- 本轮未做视觉验收，HTML 仅静态转换。

## 下一步选项

1. **（推荐，需 owner 确认数据授权）给全市场 V1 池补匹配随机对照** —— 同币 × 同 UTC 月 ×
   同前 120 bar 波动桶的随机入场，同障碍同成本。这是判断 +0.136 是 alpha 还是 beta 的
   唯一方法。先确认账本里 ≥2026-05-04 的部分怎么处理。
2. **把方向问题正面做掉** —— 池子全是多头，必须加做空样本或做多空对称检验，
   否则任何"赚钱"结论都可能只是 beta。
3. **重新界定"倍投"** —— 月度表显示收益集中在普涨期。若 (1) 证明存在真 alpha，
   那么放大收益的正确形式是**在识别出的普涨窗口内顺势加码（anti-martingale）**，
   而不是亏后倍投。本轮不预设结论，但两者应在同一破产概率约束下正面对比。
4. **修既有产物口径** —— 5m 账本窗口与其它周期不一致（2025-12 起），
   `p1_spike_v8_ict_multitf_20260915.md` 的横向比较受影响。需告知 Codex 那条线。

**需要 owner 决策的**：第 1 项的数据授权范围；第 3 项是否接受把 anti-martingale
纳入对比（owner 原始要求是亏后倍投）。
