## 为什么只有多头：配置冻结，并非空头被证明无效

此前是按当时 TradingView 选中的多头配置验证，没有补做空头及多空合并账户。它不说明做空无效，也不是“找不到空头机会”的统计结论。昨晚保存到 TV 的展示派生版 `spike_burst_v1_display.pine` 已默认双向并增加反向确认结束参考，但这些变化没有回写冻结原版，也没有自动重跑旧账本。

## 真正的退出机制：收盘触发、ATR跟踪，并非固定比例回撤

原 Pine 多头的规则是：先检验上一根收盘已确定的保护线；若未触发，收盘浮盈达到2R后开启跟踪。之后每个收盘更新：

```text
多头下一根保护线 = max(当前保护线, 向外取整(本根收盘价 - 4 × 本根ATR))
空头下一根保护线 = min(当前保护线, 向外取整(本根收盘价 + 4 × 本根ATR))
```

原函数没有“固定吐回56%”这个参数，也不是用最终峰值算止盈。ATR随行情变化，保护线只收紧。样本里的平均兑现比例是路径结果，不能反过来当代码机制。只知道最终MFE，也不知道是否曾在某根**收盘**达到2R。

另有必须明确的两把尺：Pine用信号收盘价及其风险画参考线；两年账本下一根开盘入场，以真实开盘到初始止损的距离计算净R，但继承的是Pine参考轨迹。这可以定义为“成交后跟随指标保护线”，却不能称为“成交价浮盈2R后才激活”。加强版需要明确选择并分别显示参考R和成交R，不能静默换掉旧报告的定义。

历史OHLC不能保证知道同一根K线内先冲高还是先下跌。新保护线只能在触发条件已经可见后生效；若要盘中保本，需更低级别真实数据验证，并记录覆盖不足。[TradingView 官方策略文档](https://www.tradingview.com/pine-script-docs/concepts/strategies/) 同样区分模拟成交时钟、盘中路径假设和更细粒度回测。

## 建议的 V1+：四层改动，分开验证

### 1. 保留启动核心，补齐双向

MA34/9、近零12根、0.10ATR、密集12根、量比至少4、TR至少3、实体0.55、方向收盘位置0.75和6根机会窗，暂时全部保留。新 Python 回放支持真正的多头/空头/双向，空头镜像检查高低价、箱体边界、止损取整、跳空和保护线方向。

原版多头作为不可改的基线；原规则空头、原规则双向分别出表。空头不是把多头收益取负，多空合并也不是两张收益表相加。独立资金预算与重叠仓位必须模拟。

### 2. 防过热层：先检查“爆发已过头”

第一候选仅添加 `量比>50 且 TR/前ATR>10` 联合标记，在影子结果中比较通过/拒绝及原版大赢家保留。单独的量比上限与风险宽度上限另起一项比较，暂不和联合条件打包优化。

风险宽度过大时优先减少仓位或放弃该笔，**不要把止损硬缩到允许宽度以内**；否则会重现之前用户指出的“几根K线就扫损”。跨币流动性、稳定币类型与成本占R应独立展示。不能仅因价格便宜就认定是meme，不能用后来涨幅排名选择历史交易池。

### 3. 趋势保护层：让小失败更早结束，同时给赢家留空间

先把已完成的“相反确认信号结束旧方向”单独做事件时钟回放，保留原保护止损先触及的优先级。只有该版本自己的已确认反向事件可触发，普通金叉或另一脚本的箭头不能混用。

更早保护作为下一项独立实验：比较原2R/4ATR与收盘浮盈达到0.5、0.75、1.0R后抬到成本覆盖保本线的候选，每次只改这一项。成本覆盖不是价格回到入场价；完整费用、资金费和滑点不可能靠写“保本”消失。先使用收盘触发、下一根生效的清晰规则，避免同根先看最高价再假定已按保本离场。

若早保本损害趋势尾部，再比较“首次盈利后仅降低部分初始风险”或“确认回踩结构后再抬保护”，不默认最紧就是最好。趋势后段仍采用单向收紧保护，不设3R固定清仓；3/5/10R只作里程碑。

退出与入场在V1内部有状态耦合：`trendSide==0` 影响能否再发箭头。第一轮退出比较要固定原版候选时点；后续再重放完整状态机并报告新增/丢失信号。不能从旧CSV删几行就宣称完成了加强版回测。

### 4. 账户层：同一行情只承担可控风险

同币跨交易所、30m/1H重复机会不应自动按多笔独立优势计算。按规范化底层资产归组，使用当时可见信号及预定优先级决定入场、补充确认或共享风险额度；禁止事后挑收益最高的交易所/周期。跨不同币种的同向持仓也要限制总风险，尤其全市场一起启动时。

这一层适合 Python 监控/组合引擎；单币 Pine 无法独自掌握全市场实际持仓。YOLO继续作为单独确认来源，其增量收益需要另做对照，不能借这份V1账本声称已验证。

## 完整候选清单：不只第一批四层改动

2026-09-12，Owner指出摘要遗漏了Notion的很多线索。上文是优先顺序，完整研究范围应覆盖下表。Notion的34个分析维度含重复结论、统计诊断和不同口径，不等于34条已验证的交易条件；以下将其转为可测模块。具体规则中“可比较/可改写”是本轮提出的实验假设，不冒充Notion已完成的收益验证。

| 模块 | Notion线索 | 可落地的候选与验证重点 |
| --- | --- | --- |
| 标的类型 | 稳定币成本损失、股票类资产混入 | 山寨研究池按实际标的属性定义；稳定币、股票类单列，不能用事后盈亏决定资产分类 |
| 上市年龄 | 新币、30–60天、成熟币表现不同 | 使用当时已知上市时间分层比较；缺上市记录时不能把缓存首日当上市日，不能直接宣布某年龄禁入 |
| 正常放量范围 | 中低量比组表现较好 | 在V1既有量比≥4候选中，比较中等放量与极端放量；4–6仅是候选范围，可能被大赢家主导 |
| 量价过热 | RV>50与TR>10联合较差 | 单独检查联合过热，不把强阳线、放量统一删掉；报被挡大赢家 |

| 启动后失效 | 许多交易很快扫损 | 延伸假设：收盘重新进入原蓄势区且动能衰减时提前结束；测是否误杀洗盘后的大趋势 |
| 分阶段保护 | 先浮盈后亏、2R之前缺少保护 | 比较提前降低风险、成本覆盖保本、原2R跟踪；分别统计救下亏损和丢失赢家 |
| 趋势后段保护 | 不同周期/风险宽度的兑现比例不同 | 比较ATR跟踪、已确认回踩结构保护及二者组合；不能把观测到的56%回吐写成固定机制 |
| 停滞与时间退出 | 7–14天后效率变化 | 将事后时长分桶改成当时可见的停滞检查，例如连续若干根不再推进；14天硬退出单独测，不强制长趋势到期离场 |
| 失败后重新进入 | 间隔1–3天再次确认可能不同 | 要求新的密集/回踩结构与再次突破；比较首笔与再入场，不因日历经过1–3天就机械开仓 |
| 同币信号频率 | 24小时内反复信号可能更差 | 用截至当时的同币信号数、是否仍属同一箱体定义冷却与重新获得资格；保留真正新结构 |
| 多周期信息增量 | 跨周期同一行情重复 | 比较高周期背景是否提供新增信息；同事件只分配一份风险，不把确认次数当独立胜率证据 |
| 全市场状态 | 某些日多币共涨，另一些日一起失败 | 将全市场信号密度与当时的上涨广度、BTC方向/波动等分开验证；信号多本身不能推断山寨季 |
| 连亏降风险 | 短期胜负可能聚集 | 只用当时已经退出且结果已知的交易更新状态；暂停/降仓也要计入错过的下一笔大赢家 |
| 时段与星期 | H15、H00、周日差异 | 先修时区，再按年度与币种交叉检验；不直接采用已误标的北京时间15点 |
| 跨所执行与总风险 | 同一RAVE跨所重复、多币同期亏损 | 在Python账户层规范资产ID、控制同币及同向总风险；按当时流动性/成本选择场所，不能事后挑最好成交 |

## 怎么证明加强，而不是看起来更漂亮

依次做：原多头复现 → 空头镜像及双向 → 仅反向退出 → 仅过热过滤 → 仅早保护 → 最后独立验证组合。先不改原始强度阈值，不做17参数同时搜索。

每项同表展示：已实现/截断笔数、多空和周期拆分、净收益、真实账户最大回撤、费用、净R、平均赢亏、原版≥5R与≥10R事件的保留及兑现变化、减少的亏损、提前离场损失。跨所同事件去重只作固定规则；同时报全样本、单事件集中度及留一事件压力结果，不能只报去极值后更好的一面。

随机入场对照保持同币、同时间块、同波动桶、同成本和退出规则；统计以事件/市场时间块聚类，防止跨所重复放大显著性。需要与同数量随机删信号比较，区分“选得更准”与“只是少交易”。一日1H最多24根、4H最多6根，不应照搬“同日抽1000个独立随机入场”的建议。
