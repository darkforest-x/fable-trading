# AI 策略工厂能否赚钱，以及怎样接入当前 SPIKE

审查日期：2026-09-13。对象为 [DaviddTech 的原推文](https://x.com/DaviddDotTech/status/2098683532570673297)。本轮是公开证据与本地架构审查，没有运行新回测、读取行情或逐笔交易文件。

## 判断

**流程有工程价值；公开证据不足以确认它能稳定赚钱。你的逻辑可以接入，但应保留原策略的信号、退出和资金规则，再借用自动编排与记录。直接采用对方默认交易模板，不应预期更好。**

对你而言，当前最需要补的是冻结后的新前向证据、统一资金下的可执行收益与同口径对照。继续扩大历史搜索，能更快找到漂亮曲线，也可能更快消耗验证数据。AI 的研究效率不能自动转化为交易优势。

## 原帖证明了什么

原文描述了 AI 通过 MCP 调用回测工具、记录候选、导出 Pine、在 TradingView 复核、最后连接执行的流程。作者称 8 小时产生 184 个策略；一个优胜者有 695 笔、PF 1.35、累计收益 +3,130%。他同时承认该策略回撤过高，建议先观察三个月前向结果。[原帖](https://x.com/DaviddDotTech/status/2098683532570673297)

附图是另外四张 Bybit 1H 卡片：收益约 125%–130%，PF 1.24–1.47，最大回撤 20%–30%。图中没有展示上述 +3,130% 策略的完整配置和逐笔结果，因此不能从这张图核实那项收益。[原始附图](https://pbs.twimg.com/media/HR9THZlWEAUOMoz.png?name=orig)

这支持“可以构建自动研究流水线”，尚不支持“该流水线已经产生可复制的实盘盈利”。此次公开审查未获得所述最佳策略的完整 Pine、测试起止日期、资金与杠杆配置、逐笔成交、费用明细或独立账户记录；也没有实际执行付费/登录后的流程。不能据此指控造假，同样不能把宣传值当成验证结论。

## 高回测收益为什么还不够

- **最佳策略是被选出来的。** 184 个策略可能还包含不同币种、参数和筛选尝试，实际搜索自由度更大。只展示优胜者会夸大可重复性；应保留全部尝试、失败和选择时点。Bailey 等人的研究解释了同一数据上反复搜索造成回测过拟合的机制。[原论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

- **PF 与账户收益是不同指标。** PF 1.35 表示按相应统计口径盈利总额是亏损绝对额的 1.35 倍，不表示胜率或年化收益。累计 +3,130% 未给时间和风险配置，无法公平比较。未覆盖成本能否吃掉优势，需要逐笔周转、平均盈亏、滑点与资金费数据；单看 PF 算不出安全余量。

- **TradingView 一致性不是独立样本。** 同一规则在另一引擎、同一段历史得到接近结果，只是在增加实现正确性的证据。真实成交还涉及次根入场、跳空、同 K 止损先后、佣金、滑点、限价成交与重绘。官方文档明确区分这些撮合假设，并提供较低周期数据帮助改善盘中模拟。[策略文档](https://www.tradingview.com/pine-script-docs/concepts/strategies/)、[Bar Magnifier](https://www.tradingview.com/support/solutions/43000669285-what-is-bar-magnifier-backtesting-mode/)

- **前向使用新价格，不必然存在真实成交。** 官方 Arena 将 forward 定义为候选进入队列之后的新时间窗重跑，并明确候选不等于已实盘。这个过程在源码和配置冻结、失败候选不删除、不开启事后筛选时有价值；仍需另验真实订单、资金占用与费用。三个月是观察长度，交易稀疏或同一行情高度相关时，不能作为自动通过线。[Arena 方法说明](https://aitradingarena.com/)

## 你的系统：最新研究与监控不是同一版本

仓库旧章程以 YOLO 检测、LightGBM 判断、回测、执行四层为总体结构；最近实际研究已经大量转向 SPIKE 的确定性 Pine/ Python 信号。HANDOFF 顶部日期落后于最新提交，所以本次同时核对今早 V8 源码和报告，不能只按旧章程描述当前工作。

| 路径 | 当前证据 | 接入时必须保留 |
|---|---|---|
| 冻结 V1 监控 | V1 仅多头；四个周期 | 双时钟、事件身份与 live/replay 隔离 |
| V7 研究 | V6 + BB200 事前压缩 | 原始反向事件的退出权 |
| V8 研究 | V7 + 六线距离不超过 3ATR | 原止损、趋势跟随与独立版本 |
| YOLO / LGBM | 独立本地推理 / 排序 | 确认可知时刻与增量收益对照 |

当前源码版本 1.14.1 支持 15m/30m/1H/4H，原始 V1 收盘信号和随后 YOLO 确认分开处理；模型最多等待九根，确认的可知时刻是其实际确认端点。历史回放不能补发成新信号。监控事件也没有直接写入 L4 的交易输入；执行器还要求有效 active bundle。把看板接到订单服务之前，必须补齐事件、账户与执行契约，不能把目前的信号通知称为自动交易成交。

依据：`yoyo/monitor/__init__.py`、`yoyo/monitor/signals.py`、`analysis/p1_spike_v7_v1_compare_20260912.md`、`yoyo/evaluation/pine/spike_burst_v8.pine`。9月11日迁移报告只描述当时的30m/1H/4H范围，不能覆盖当前源码新增的15m。这里核实的是源码与书面运行证据；本轮没有实时读取服务或券商账户，因此不声称核实了今日线上进程、订单或真实持仓。

## 直接照搬对方框架会改变你的策略

Arena 公开的统一模板固定 ATR 14×2.5、R:R 1.3、10% portfolio 与 10x leverage；候选还要满足至少 100 笔、PF 至少 1.2、胜率至少 40%。公开说明称 AI 只修改信号块。这些是该 Arena 当前模板的说明，不能据此断言帖中 +3,130% 的具体策略一定用了相同设置。[Arena 规则](https://aitradingarena.com/)

这也不表示 Trader.dev 回测接口强制所有自定义策略采用该模板：可行路线是提交保留自身退出逻辑的 Pine，并单独核对引擎如何执行。需要改造的是竞赛模板与验收目标，不能简单得出“平台完全无法接入”的结论。

你的 SPIKE 研究则以结构止损、2R 激活后的 4ATR 跟踪及反向结构退出为核心，3/5/10R 是观察里程碑，不是固定止盈；V8 源码还明确自己是指标而非可执行策略。近期各版的净胜率大约三成，目标是让少数长趋势覆盖多次试错。

因此，至少有三个直接冲突：

- 用固定 1.3R 止盈替换趋势跟随，会改变 5R/10R 大赢家的兑现路径。
- 用平台胜率门槛筛选，会排除一部分符合你原目标的低胜率策略；为了通过门槛改信号，会改变研究问题。
- 把单币信号放进不同仓位与杠杆框架，收益和回撤的变化不能再归因于 AI 找到了更好的入场。

Pine 中的 `indicator()` 也不能直接按帖中“订单成交告警”接交易所：要先形成明确的 `strategy()` 订单语义或本地可执行事件契约，再验证参考价和真实可成交价。原始信号在 t，YOLO 在 t+n 才确认时，后者的入场不能回填到 t。

## 现有结果说明瓶颈在哪里

以下只转述已有报告，不读取或重新评分原始数据。前一年为 2024-09-10 至 2025-09-10，后一年至 2026-09-10；这些历史已经被研究，不是新的盲测试。

| 后一年，V7 → V8 | 30m | 1H | 4H |
|---|---|---|---|
| 事件 PF | 0.8827 → 0.8708 | 0.9641 → 0.9761 | 1.1227 → 1.1534 |
| 平均独立账户收益 | −2.94% → −2.89% | +0.17% → +0.15% | +0.36% → +0.25% |
| 平均收盘最大回撤 | 13.16% → 12.50% | 8.46% → 7.98% | 3.71% → 3.51% |
| 原 V7 已兑现 ≥10R 交易保留 | 91.75% | 93.88% | 96.77% |
| 同资产配对 V8−V7 收益差 p | 0.6927 | 0.8866 | 0.0625 |
| 与匹配随机入场对照的原报告裁决 | 未证实优势 | V7/V8 有相对增量 | 未证实优势 |

来源：`analysis/p1_spike_v8_noise_filter_20260913.md`，首表、独立账户表及随机对照结论。PF 使用事件收益，账户按资金和仓位模拟，因此二者不必同方向；账户均值不是统一资金池收益。随机对照同流、同方向、同时期、同事前波动桶、相同退出与 0.2% 往返成本；“比随机好”也不能代替“绝对净盈利”。

V8 信号总量下降 14.55%，能说明频率和追高/追空保护发生变化；上述结果尚不能证明整体交易收益提高。原报告还披露 discovery 文件携带了验证 outcome，虽然之后屏蔽并记录勘误，既有暴露不能撤销。所有这些验证结论都只能作非盲描述性证据。

另一条 V1+ 固定默认研究中，全期 1H 事件 PF 为 1.356，但平均独立账户收益仅由 1.09% 到 1.14%；各周期全期改善只有 0.011–0.054 个百分点。它的基线是同源双向 master-off，不是冻结仅多头 V1，也不能与上表混称同一策略。[V1+ 已有 HTML 报告](p1_spike_v1_plus_backtest_20260912.html)

这些结果说明：你的系统并不缺能批量产出信号的工具。当前更需要识别哪些规则在新行情仍有增量、哪些改善只来自减少交易或换了资金尺度。

## 建议的接入方式

建议采用下面的职责划分；这是架构提案，本轮没有实现接口或启动计划任务。

```text
AI 研究编排
  ↓ 只提出有编号、预算和一个变量的假设
本地冻结的 SPIKE 源码、模型版本与数据权限
  ↓
本地因果回放 + 同规则随机对照 + 统一资金评估
  ↓
实验记录板：候选 / 失败 / 已冻结 / 前向不足 / 待裁决
  ↓
冻结后新前向影子记录（独立于现有实时扫描）
  ↓
Owner 裁决后，才可能进入既有执行路径
```

第一步先做“无变化接入”：AI 只能指定已登记版本、允许的数据范围与任务编号，不能任意传文件路径绕过 holdout 限制。返回信号可知时间、实际入场时间、退出原因、参考 R/成交 R、成本口径、配置指纹和完整失败原因。外部看板可以展示这些结果，但本地记录是审计依据。

接入成功的验收是同一配置下候选、入场、退出和账户结果没有静默漂移；不是平台上终于出现绿色曲线。Python 与原生 Pine 的逐 bar 一致性尚未全部确认的版本，应先把这一缺口补齐，不能用迁移到新引擎掩盖。

第二步才做单变量增量。当前已有 V7/V8，可冻结后并行记录新的影子结果；新增假设中，市场状态/广度门、早期失败退出、同事件资金占用是值得研究的方向，但每项都可能错失大赢家，不预先宣布有效，也不把它们打包成新的最优版。任何使用 ≥2026-05-04 数据的新配置评分，仍须按仓库纪律取得明确授权。

研究编排应独立于实时脉冲：连续八小时试验不能占用扫描窗口或拖慢确认。通知、模型确认、回测和执行分别记录时延，新增工具本身不改变现有三道 30 分钟门。

## 怎样判断“更好”

| 改善目标 | 要看的证据 | 不能代替它的指标 |
|---|---|---|
| 研究效率 | 候选耗时、成本、失败可追溯 | 生成策略总数 |
| 交易优势 | 冻结后的净收益与对照增量 | 单个最好 PF |
| 执行质量 | 真实可知时刻、滑点、拒漏单 | 历史图上有箭头 |
| 趋势保留 | 大赢家保留、兑现及集中度 | 曾经最高浮盈 |
| 账户可用性 | 共享资金、重叠持仓、账户回撤 | 独立账户收益相加 |

若未来仍使用 LGBM 排序，项目原有 top-decile 扣既定成本后净收益及置换 p<0.01 的门保留，AUC 只是参考；不能把这个排序门强加给没有模型排序的纯 Pine 路径。纯规则路径应使用预注册的同风险基线、随机对照、账户曲线和前向验收。
