# V10 technical report design

## Audience and surface

Owner trading researcher; technical report, Chinese explanation and concise
English title. Local desktop / portable HTML via canonical artifact.json and
the packaged Data Analytics0.2.10 reader, not bespoke HTML charts. Markdown is
the immutable source history; HTML is the primary delivery. No Sites request.

## Evidence spine

Technical summary → population/definition → fold comparison → first-shortage
decomposition → exact examples/shared-component proof → selection-bias limits
→ causal clocks/source boundary → independent verification/null controls →
financial metric nonapplicability → risks → next decision → reproducibility.
This maps all technical-report required sections; source inventory is metadata
or reproducibility text, no invented profit claim or forecast.

## Chart contract

- Question: where does the first shortage occur among the97 unmatched mothers?
- Native comparison bar, five ordered categorical stages; counts19/1/71/3/3.
- Unit maternal requests, denominator all251 / unmatched97; no candidate counts
  mixed with mother counts. First-stage attribution follows the fixed order,
  not independent causal effects of excluding each rule.
- Single-root blue palette; visible count labels, stage names and ordering
  preserve meaning without colour. Zero baseline. Full-width mobile stack.
- Dataset includes total/matched/unmatched/required-controls/share alongside
  chart count. Source is full saved mother_audit, transformation in support_report.
- Four-fold table is retained for exact paired lookup (both allocation methods
  equal in every fold) rather than redundant identical-series charts. Examples
  and proof use exact tables because IDs and legal supply identities matter.
- No PNL chart: this experiment reads/computes no new returns.

## Verification

Canonical validate_artifact plus packaged deliver_portable_artifact. If no
compatible installed Chromium, retain semantic chart table and mark structural_only;
do not install or claim mobile/browser verification. No second HTML runtime.
Companion notebook uses saved audit evidence only. Missing Jupyter runtime is
explicitly disclosed; ordinary Python top-down checking is not a kernel run.
