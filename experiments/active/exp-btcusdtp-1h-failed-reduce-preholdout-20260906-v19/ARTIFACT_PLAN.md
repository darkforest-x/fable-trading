# V19 technical HTML evidence plan

Audience is technical: the owner requests causal execution rules, failure
patterns, matched economic differences and reproducible chronological checks.
Use one portable HTML report plus its required Markdown source, not a second
app. Keep the full narrative in the canonical artifact.

Required roles: technical summary; definitions of risk half versus profitable
half and original-notional costs; aggregate/four-half comparisons; D/I and
same154matched denominators; serial occupancy; failed/recovered/hurt paths and
two-leg decomposition; statistical uncertainty; raw-clock/lineage validation;
risks and precommitted stopping decision; next questions and reproduction.
Definitions precede figures so the data cannot imply a prospective gate.

Native visual: full251 paired net-return changes as a categorical bar chart
with fixed unequal-width bp bins, including zero and unknown. Source query
actually bins saved case_delta observations in SQLite. Single blue root,
direct labels, zero count baseline, full width. Unequal bins are counts, not
density. Source rows retain before/after means and denominators. All outliers
remain. Adjacent narrative explains what changes and what cannot be inferred.

Four-half tables keep exact sample counts, baseline/candidate means and matched
comparisons; no sparse four-point trend. Other tables require exact lookup of
fees and disjoint failure groups, so no redundant decorative plots. Primary
inference is the frozen calendar-month method; utility Shapiro/IQR diagnostics
cannot switch tests or select thresholds. Reused development is not OOS.

Build source is committed before packaging. Markdown conversion is immediate;
canonical artifact then uses the official portable delivery command. Preserve
semantic fallbacks and source paths. If no installed compatible browser exists,
state structural_only; do not install one or claim mobile/theme/dialog QA.
