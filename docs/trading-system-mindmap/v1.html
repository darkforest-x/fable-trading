系统边界与版本

先说清今天用哪一套规则、哪些尚未定稿。

来源状态

三类打法分别记

  • 周一区间：按 #49 的时间、位置、5m 企稳和分批退出要求整理；细节仍待补全。
  • 龙头延续：#50 负责候选选择，#53 提出后续共振观察；选中候选不等于已准许开仓。
  • SPIKE 人工打法：Manual-v4 的 A 回踩重启、B 突破回踩，绑定 V12.8，当前是候选草稿。

共用底层流程

  • 准备 → 背景 → 选模型 → 位置 → 确认 → 风险 → 委托 → 管理 → 复盘。
  • 同一交易只采用事前选定的模型和退出合同；重合条件作为来源记录，不临场拼凑。
  • 标明是真实交易、模拟成交、回放练习还是未成交观察；四类分别统计。

规则证据标签

  • 原始规则：Owner 已写下的内容；不代表已经验证盈利。已有草案：现存但未启用的设计。
  • 方法整理／方案待实现：学习方法与未来产品能力；不能画成当前自动交易功能。
  • 待确认：参数或定义缺失。检查建议：本导图为补齐操作流程提出，需确认后才成为个人规则。

本版不自动升级

  • 不因导图完整而启用策略、训练模型、promote 或连接真金下单。
  • 现有模拟界面的仓位倍数与杠杆是工具默认值，不是实盘风险额度。
  • 旧 BB、YOLO、历史 SPIKE 等研究另保留版本和负面结论；未选定者不偷偷进入今天的打法。

02

盘前准备与个人状态

盘前卡要让你知道：今天能做什么，也知道何时停止。

已有草案＋检查建议

身份与工具

  • 记录交易所、完整合约、现货或永续、图表种类、指标名称与版本。
  • 核对图表与成交场所；价格来源不同就重新核对入场、保护和目标，不能直接搬价。
  • 检查网络、行情更新时间、订单与持仓是否可查询；缺项先恢复信息。

时间与精力

  • 事前写可值守时段、下一检查点及离屏时间，不假设自己随时能看盘。
  • 检查建议：记录睡眠、情绪、急于回本或害怕错过的状态；不替你制定打分阈值。
  • 如果无法执行原计划，把该机会记为观察／跳过；是否以及何时恢复，由事前个人规则决定。

预算与已有暴露

  • 写单笔风险金额、总在险上限、同方向关联风险上限；数值由本人决定。
  • 把已有仓位和未成交挂单一起算入预算，不只看可用余额。
  • 写当日停止新开条件和离屏处置；没有默认连亏次数、亏损百分比或每天交易次数。

盘前输出

  • 保存日期、截止时刻、背景判断、候选、关键价位和来源截图。
  • 写主情景、反向情景和无交易情景；每个情景有推翻条件。
  • 五栏记录：事实 → 解释 → 动作 → 推翻条件 → 下一检查点。

03

时间、周期与价格地图

同一根 K 的收盘时刻、可见数据和价位锚点必须一致。

已有草案

周期分工

  • Manual-v4 示例：H=1H 背景、T=15m 机会与管理、E_tf=5m 执行；不是所有模型的强制周期。
  • 另做 1H 持有或独立 5m 单要另建规则票；成交后不偷换管理周期 T。
  • 每个周期只引用已收盘数据；5m 收盘不能让未完成的 1H 变成已确认。

K／P／L区／S

  • K：本笔论点失效区域；P：重新启动或突破必须收复的位置。
  • L区：前进方向最近已知障碍；S：当前实际生效的保护价；SL0 是原始保护价。
  • 区间低点另写 Low，入场价另写 Entry，避免与 L区、执行周期 E_tf 混淆。

锚点与确认时间

  • 每个区域保存上下界、来源周期、锚定 K、识别时间及依据；新区域另记版本。
  • Manual-v4 人工摆动口径是左右各两根已收盘 K 的严格极值；到右侧第二根收盘才可引用。
  • 同价平台用区域表达；没有事前边界的图不能事后标为预先定义的突破。

时钟与数据健康

  • 分别记录信号收盘、数据收到、人工判断、委托和实际成交时间。
  • 周一日界、交易所时区、图表显示时区分别标注；纽约用 America/New_York 随夏令时变化。
  • 缺失、过期或源错误显式保留；恢复后补到的历史，不当成当时已经知道。

04

市场背景与机会分流

先判断结构状态，再决定进入哪一个模型。

已有草案／方法整理

趋势与区间

  • Manual-v4：最近两组已确认高低点都抬高为上行，下降镜像；其余先记过渡或不清。
  • 区间需要预标上下边及可辨反应；一根反向 K 不直接把趋势改名。
  • 均线密集、展开、成交量与波动用于解释背景，记录比较窗口，不单独决定开平。

BTC／ETH 与广度

  • 同一截止时刻分别写 BTC、ETH 背景，再看山寨扩散、独立启动或退潮。
  • BTC 与 ETH 不同步就分别判断；BTC 方向不是 ETH 的自动许可或否决。
  • #53 的原数据源曾出现 451 和旧缓存；使用时重新检查健康，不把历史故障当作今日实时状态。

分流到模型

  • 周一冻结区间且处于本模型时段：看边沿偏离与收回，进入周一区间分支。
  • 市场启动且有先动、抗跌候选：进入龙头延续分支；单币独立启动单独记录。
  • 采用 Manual-v4 时：H 趋势＋T 回踩看 A；预先区间突破回踩看 B；分类事前确定。

冲突与等待

  • H 上行、T 空头：不临场解释成 A 顺势多头，另记观察或独立已定义模型。
  • E_tf 反向：若计划等 E_tf 触发则等；若计划 T 直接执行，不临场新增 E_tf 否决。
  • 背景恶化与持仓论点失效分别记录；是否退出按所选合同，硬保护始终有效。

周一区间：形成到入场

这条主线保留 #49 原始规则，确认细化另作草案。

原始规则＋待确认

冻结周一 H／Low

  • 选择并记录会话时区，统计完整周一高低；未结束前只称发展中区间。
  • 冻结 H、Low、EQ=(H+Low)/2 以及来源截图；周内不随结果移动原区间。
  • 仅周二至周五找本模型机会，星期归属沿用同一日界；其他模型不自动套此时间限制。

等待边沿与收回

  • 多头原规则：跌破后收回；空头原规则：突破后回到区间。
  • 只在事前关键 Fib 位置观察；仅触及、长影线、尚未收盘都不能直接冒充已确认。
  • 区间外持续形成新结构属于反转失败观察；接受的具体判据仍需提前写定。

5m 企稳与触发

  • 原规则要求到关键位后观察 5m 企稳才入场。
  • 细化草案：收回关键位后，局部结构转向或回测守住；要写具体确认根与实际允许价区。
  • MSB／FVG／供需回测可另研究，不擅自替换原规则；没有定义清楚的“企稳”先回放确认。

初始保护与放弃

  • 多单原规则：5m 最近低点作为止损依据；到底哪一个已确认低点要标清。
  • 空头最近高点是现有整理建议；缓冲、极值选取、重新入场次数均待确认。
  • 未到触发先到目标、过期、空间消失或区间失效：记等待终止／未成交，不补虚拟盈利。

06

周一区间：Fib 与分批退出

“0.618”必须落到实际价格，80/20 必须落到实际数量。

原始规则＋计算示例

先说明方向

  • W=H−Low；从低点量的 r 位=Low+rW，从高点量=H−rW。
  • 0.618 有两个价格，开仓前写锚点、方向及选中的那一个，不用一个标签代替价格。
  • 对侧扩展：多头 H+0.13W；空头 Low−0.13W。确认目标位于本笔正确方向。

80／20 的语义

  • #49 基线计划：0.618 平原仓位 80%，对侧 1.13 平原仓位 20%。
  • Owner 原话允许观察当周结构和走势调整；调整依据与时刻需记录，不能事后改写原计划。
  • 若先平了原仓 80%，最后剩余原仓 20%；工具若按剩余仓位计，清完应选剩余的 100%。

只作算术例子

  • 假设 H=110、Low=100：两个 0.618 是 103.82 与 106.18，上下扩展是 111.30 与 98.70。
  • 假设多头 Entry=101、SL0=99，目标 106.18／111.30；两段都成交时毛 R=0.8×2.59+0.2×5.15=3.102。
  • 这不是预期收益。实际净结果按每段成交、手续费和资金费计算；T1 后剩余止损也可能亏损。

尚需确认的退出项

  • 第一个目标到底选近端还是远端 0.618，以及哪些结构允许提前调整。
  • T1 后保护移动依据、剩余仓位何时提前退出、跨周或周五未平的处置。
  • 该 80/20 计划只属周一区间；不搬到 Manual-v4 或龙头模型作为默认退出。

龙头延续：先选谁，再等什么

ETH 启动是观察入口，候选强弱要在同一时段比较。

方法整理

固定观察时刻与池

  • 先记 ETH／BTC 启动时刻和背景；不是自动购买 ETH 生态，也不是所有山寨必涨。
  • 热搜新面孔、日线结构和空间提供候选；保存当时榜单、来源和加入时刻。
  • 冻结 t0 候选；后来加入者另记时间，不能把最终赢家倒填进原池。

首波、抗跌、再启动

  • 先看是否参与首波或提前异动，不能只因“还没涨”而认定便宜。
  • 同交易所、同回调起止窗口比较回撤、突破位保持、整理结构和相对 ETH 表现。
  • 市场恢复时观察谁先转强；同时记录头顶最近阻力，而非只看离历史高点很远。

流动性与触发

  • 检查成交活跃度、买卖价差、盘口及计划数量可执行性；热度与高振幅不能代替流动性。
  • 关注最清楚的少数候选，但数量与排名权重没有新设默认值。
  • 等待预先选定的延续／回踩模型，写触发、SL0、目标和取消条件；相对强不直接触发追价。

保留落选与错过

  • #50 的七步：时刻 → 建池 → 首波 → 抗跌再启动 → 流动性 → 入场模型 → 快照复盘。
  • PEOPLE／PEPE 的复盘包括错过更好候选；作者事后解释不等于当时喊单或完整成交证据。
  • 保留所有入选、落选和无交易机会；没有已经验证的统一“龙头买入分数”。

SPIKE：先辨认信号事件

以下按 Manual-v4／V12.8 来源整理，新版需另核语义。

已有草案

事件不是命令

  • 分清普通启动、联合确认、同向重复、滚仓候选与正式参考结束。
  • 普通信号升级联合确认属于同机会的证据更新，不自动再开一笔。
  • 滚仓候选只更新观察；不自动加仓、重置原始风险或延长有效期。

标识与关联

  • 信号ID：交易所／合约／T／方向／确认时刻；参考段另存起点和原 SL0。
  • reference_id 关联参考段；attempt_id 区分退出后的新尝试；来源列表保存所有提醒。
  • 下单前人工检索已有同参考段记录；不能把工作台保存成功理解成已自动去重。

确认与迟到

  • 分别保存信号 K 收盘时刻和通知收到时刻；当前仍有效才可作为候选。
  • 旧参考已经结束，迟到通知不能使其复活；未完成 K 不当作确认。
  • V12.8 的保护／反向／未突破离场事件要核对同周期和同参考段，不能仅看箭头颜色。

版本边界

  • 本流程不是对 V12.9／V12.10／V13.1 语义的自动认证，换版本先核事件字段。
  • TV 与 API 的零成交 K、时间轴和数据源可能不同，逐笔先看原始 OHLC 与右端。
  • 只有具体版本、参考段、确认条件都可解释时才继续进入人工五项检查。

09

SPIKE：A 与 B 两套打法

A 顺势回踩重启，B 突破回踩接受；逐事件确认。

已有草案

A：背景与回踩

  • H 已确认上行，多头选择 T 上有依据的支撑或突破后转支撑区域；空头镜像。
  • 回踩时 K 未失效；把回调中已确认且必须收复的局部高点标为 P。
  • 无可锚定 P 就等；不能用尚未确认的当前尖点填空。

A：重启与放弃

  • 同参考段 T 同向 SPIKE 已收盘，随后或同根 T 收盘越过 P；只来信号、未过 P 就等。
  • 成交仍在允许价区、空间与风险仍成立；K 失效或参考结束则原候选终止。
  • 退出后重开需要新的回踩／触发证据及新 attempt，不能以“把上一单赚回”作为依据。

B：三个顺序事件

  • 先有突破前已冻结的区间边界，再发生 T 收盘到区间外。
  • 之后 K 线回踩边界区域，K 仍有效，再由 T 收盘接受突破侧价格；空头镜像。
  • 同一根 OHLC 不能证明先突破、后回踩的内部顺序；影线越界但收回不算完成突破。

B：失败与执行

  • 关联同向 SPIKE 参考必须仍有效；旧结束信号不补条件。
  • K 内沿与失效条件委托前定好；失败时不能把 K 偷移到整个区间另一边。
  • 长 K 未回踩继续等；已接受但靠近障碍 L区，重新算空间，形态漂亮不豁免成本。

共振：证据支持、冲突与缺失

订单流是辅助证据；#53 的新监控整体尚待实现。

方案待实现

两条路径不混用

  • 趋势延续：首波 → 抗跌 → 再启动 → 自己的关键位 → 守住／站回。
  • 区间结构研究：冻结区间 → 扫过 → 收盘收回 → MSB → 回测供需区。
  • 龙头不必等区间扫掠；区间反转不必满足强势排名；这是 #53 设计，不替代 #49 原始企稳。

位置先于解释

  • 预先记录前日／前周／周一高低、EQ 或可追溯的 POC／VAH／VAL／nPOC。
  • 保存会话、交易所、粒度、确认时刻和来源；发展中剖面不能冒充已冻结水平。
  • 来自同一价格数据的多项指标不是多份独立支持；不简单数票等同胜率。

真实成交与 OI

  • Delta 为主动买减主动卖，CVD 为声明起点后的累计；单位和断流区间要注明。
  • 价格守住而 CVD 更低可记录为待检验吸收解释，不证明机构身份或必然反转。
  • OI 增长不直接证明新增多头；币量、张数与美元值分开。估计 Delta 不混作逐笔主动成交。

当前能做与不能做

  • 可人工保存背景、价位、截图和证据状态；支持／冲突／未知分别显示。
  • 自动实时 CVD／结构事件／统一观察账本是待实现范围；不能写成已经实时确认。
  • 过期、缺失或源错误时不报强共振；恢复数据也不倒改当时决定。

做、等、跳过：一单一份合同

让每个候选都有明确出口，而不是无限等待。

已有草案

五项逐一检查

  • 环境符合所选模型；位置来自事前区域；实际入口到最近障碍仍有净空间。
  • 信号与结构确认完整；预算、订单、保护和值守可落实。
  • 任何硬条件失效不能被其他加分抵消，不设置统一“总分过线”。

做／等／跳过

  • 做：条件齐全、仍在允许价区、风险卡完整；仍由本人决定和执行。
  • 等：写缺什么、在哪个周期看、哪种事件或绝对时间终止等待。
  • 跳过：不符合模型、已失效或到期；保留当时理由与后来结果，未成交不计盈利。

委托前冻结字段

  • 模型和版本、方向、Entry 允许区、初始 SL0、K 失效条件、目标实际价格。
  • 数量与金额风险、已占组合预算、退出合同、候选和委托各自的到期时间。
  • 记录触发时刻、来源快照及下一检查点；未填关键项只进入观察，不标为可执行。

提前写取消条件

  • K 失效、参考段终止、价格越区、障碍空间消失、预算被占用或执行异常。
  • 订单到期不得晚于候选期限和离屏时间；不因重复提醒自动续期。
  • 撤单是动作，撤单成功是回执；若已有部分成交，还要处理真实剩余风险。

风险、数量、仓位与杠杆

先确定可承受损失，再看数量、保证金和共同暴露。

已有草案＋待确认

由风险反推数量

  • USDT 线性、数量为基础币：预计每单位止损损失=|Entry−SL0|＋每单位费用／滑点／资金费预算。
  • 数量上限=本人单笔风险预算÷预计每单位损失，再核数量步长、最小订单及可用资金。
  • 这是预算估计，跳价或流动性冲击会突破它；不能为了固定手数扩大结构止损。

三个不同的量

  • 名义金额≈基础币数量×价格；仓位倍数=名义金额÷账户权益。
  • 简化初始保证金≈名义金额÷合约杠杆，另核账户模式、维持保证金与真实场所要求。
  • 同一数量下改变合约杠杆不再把价格盈亏乘一次；保证金也不是整笔交易最大损失。

组合与成本

  • 所有持仓加待成交委托都计入事前风险预算；同向 BTC／ETH／山寨不能当独立分散。
  • 研究比较沿用原 0.2% 往返成本；真实交易记实际场所费率、资金费和滑点。
  • 模拟盘每边 0.1% 是当前工具口径；100× 合约、10× 权益仓位默认只描述工具，不授权实盘额度。

必须由本人填写

  • 单笔金额、组合在险、共同方向风险、当日停止新开条件。
  • 可接受价差／滑点、允许订单数量、风险预算调整的条件与版本。
  • 不凭盈利临时提高额度；仓位亏损不能通过改原始风险分母看起来更小。

委托与成交核对

触价、提交成功、成交、保护生效是四件不同的事。

已有草案＋工具状态

执行方式事前选

  • Manual-v4：T 确认后允许价区内直接执行，或等 E_tf 回踩后向交易方向突破前根 E_tf 高／低并收盘。
  • 第二种仍须 T 先确认、K 有效；E_tf 不必再出现 SPIKE。周一区间按自己的 5m 企稳定义。
  • 选市价还是限价、可接受成交区及到期时间先写，不能未成交后追价补理由。

下单与回执

  • 核合约、方向、数量、杠杆、价格、初始保护、目标和手续费预算。
  • 提交后用订单标识核状态；超时先查询，避免把结果不确定当失败而重复下单。
  • 实际均价、数量、费用和时间来自成交回执；通知或图表触价不当作成交凭证。

部分成交与保护

  • 按实际已成交数量确认真实保护覆盖；未成交余量有独立状态和取消条件。
  • 修改保护后核旧单、新单和覆盖量，避免空档或多余反向仓位。
  • 已经占用平仓量的挂单纳入可平量检查；拒绝超量时先核已有委托。

模拟与真实场所

  • 模拟工具已支持限价、市价、持仓保护和按剩余比例平仓；本导图不提交任何订单。
  • 后台触价依赖服务与新鲜报价；停机不补历史触价，跳价不保证按保护价成交。
  • 模拟尚无完整深度滑点、资金费和强平模型；盈亏体验不等同真实执行能力。

14

持仓状态：动作对应事实

先查真实保护，再按管理周期和合同处理状态。

已有草案

推进／等待发展

  • T 已收盘越过事前同向极值或障碍、K 未失效，记推进；按原合同持有。
  • 尚未推进先记等待发展，不因暂时没涨就判失败。
  • 新保护候选需要已确认结构及后续推进证据；浮盈数字本身不触发动作。

正常回撤

  • 价格逆向波动但 K 未失效，未出现预标障碍拒绝，真实 S 仍有效。
  • 按原计划管理；E_tf 反向、普通阴阳交替或单影线不能自动改退出。
  • 继续持有也记录事实、理由及下一 T 检查点。

受阻／走弱

  • 例如多头触预标 L区后 T 收盘回到其下沿以下，K 仍有效；空头镜像。
  • 或尝试越过事前 P／极值却收回；没触及关键位而只收低，不等同这种失败。
  • 不追加风险；仅执行事前已有减仓计划，没写比例就不临场编比例，继续核保护。

失效／未判定

  • 多头 T 收盘跌破预写 K 下沿、空头越过 K 上沿，或合同终止条件成立，按合同结束余仓。
  • 真实保护若先成交，优先处理实际成交，不等待收盘。
  • 信息不足为未判定，不默认趋势健康；优先级：真实成交／硬保护 → 合同终止 → 可选减仓 → 观察。

退出合同、分批与移动保护

初始风险保留，退出规则事前选，剩余数量逐笔算。

已有草案＋原始规则

Manual-v4 合同 I

  • 指标保护＋结构管理：真实保护、K 失效或同 T 同参考段的正式 SPIKE 结束，按合同结束余仓。
  • 先核事件及关联段，反向候选不自动等于本段正式结束。
  • 可选障碍减仓须事前填写触发、数量、次数及余仓管理；无默认比例。

Manual-v4 合同 S

  • 独立结构管理：按真实保护、K 和事前结构条件退出。
  • SPIKE 正式结束触发立即复核，不自动终止；仅限开仓前已选 S 且独立保护有效。
  • 不得看见指标出局后临时由 I 切换 S；两种合同分别统计。

移动 S 的依据

  • 原 SL0 与初始 R 分母始终保留；新 S 要来自已确认的新结构并比旧 S 更保护。
  • 不因回撤浮盈就改保护，不放宽 S 给亏损找空间；新价已被穿越时不倒填理想成交。
  • 记录改价时刻、依据和确认回执；部分平仓后核新保护覆盖剩余数量。

周一区间分支

  • 采用 #49 的 80/20 计划或事前记录的结构调整；不混入合同 I／S 默认比例。
  • 每条成交腿记原仓百分比、实际数量、价格和费用；剩余的 20% 仍有自己的退出结果。
  • 按剩余比例平仓时，第二次 50% 只平当时剩余的一半；完整清尾核实际余额和挂单。

异常、暂停与离屏

把停止和恢复条件写进流程，避免临场猜测。

已有草案＋检查建议

行情或服务异常

  • 行情过期、时间轴缺失或来源冲突：记录当时最后可靠时刻，停止新增依赖该证据的风险。
  • 持仓先核真实场所保护及订单；屏幕图线或本地服务在线不等于保护单存在。
  • 模拟服务停止、真实场所异常分开记录，不假装本地工具会替你守所有仓位。

订单结果不确定

  • 提交超时先核原请求／订单，不重复创建；撤单未确认不视为已解除挂单风险。
  • 核成交、余量、保护、资金占用后再恢复下一动作。
  • 检查建议：事前保留可用的人工查询入口和故障处理步骤，避免故障时才找路径。

个人停手条件

  • 执行本人事前填写的金额、连亏、精力或纪律停止条件；本版不代填数字。
  • 违规盈利仍记违规，合规亏损仍保留原判断；不因回本冲动跳过检查。
  • 恢复前检查数据、订单、预算和状态，并记录恢复依据；是否恢复由本人决定。

离屏与周末

  • 到预定离屏时刻，按计划取消未成交单并核回执；现有持仓按既定保护和管理合同处理。
  • 周一区间的周五收尾／跨周持有细则尚未定，不自创一个统一清仓时间。
  • 检查建议：每日结束对账，留下一次接手能看懂的未完成事项。

记录与复盘：把所有机会留下

盈利、亏损、等待、撤单和错过共用一条证据链。

已有草案

盘前与候选卡

  • 盘前：市场／版本／日界／截止时刻／背景／关键位／预算／值守。
  • 候选：模型、参考段、当时事实、缺失项、做等跳过、允许价区及有效期。
  • 同时保留落选币和拒绝机会；事后结果另列，不能重写当时理由。

持仓与成交卡

  • 记录每次状态、动作、实际数量、价格、费用、剩余量和保护修改时间。
  • 提交日志时间与真实成交时间分别记；只有真实成交进入交易账本。
  • 净盈亏汇总所有成交腿及费用；R 用原始风险分母，部分平仓不重置。

复盘四种组合

  • 合规盈利：检查是否可复现；合规亏损：检验正常损失还是规则问题。
  • 违规盈利：不升级成有效规则；违规亏损：明确偏离发生在哪个决定。
  • 把选币／选单、入场执行、退出管理的贡献拆开，不用一个总盈亏遮住过程。

每日／每周迭代

  • 检查建议：每日核漏记、费用、订单闭环与一次具体偏差；不要求额外报告。
  • 每周按模型、方向、周期、市场阶段和版本看全部样本分母，亏损和错过均保留。
  • 只选一个最有证据的问题进入下一版，保留旧版、修改原因、开始生效时刻及后续样本。

验证与下一版：怎样才算有用

导图完成是流程交付，交易优势需要另外的证据。

验证纪律＋待确认

因果回放与重复判断

  • 先冻结规则，只显示决策时点之前的图、均线与纵轴范围；写判断后才揭示未来。
  • 隔一段时间重看同一图，比较背景、K/P/L、做等跳过是否稳定，保留不一致。
  • 连续收集预先定义时段的全部候选，不仅挑漂亮正例；同一行情事件保持谱系。

研究与交易验收

  • 按时间切分；原退出和成本不动时，比较同币×同时间块×同波动桶的随机入场。
  • 报净结果、样本量、回撤、胜率、覆盖及漏掉的大赢家；只少交易、少总亏不算增量成立。
  • 若建立排序模型，再核 AUC、top-decile 毛／净、单特征基线和置换 p；本次无新实验，不填虚构成绩。

优先定稿的参数

  • 先选主做模型与实际指标版本；定周一时区、5m 企稳定义及 0.618 方向。
  • 再填单笔／组合／共向预算、当日停手和离屏处置；决定空头保护、T1 后管理及跨周规则。
  • 最后确定是否采用 Manual-v4 合同 I／S、候选到期机制、订单流哪些仅观察；不为填满导图编阈值。

升级和版本记录

  • 本版 v1 是可追溯流程地图；Manual-v4 当前仍是 draft，#53 新监控仍属设计。
  • 每次语义变化写变更原因、旧节点、新节点、适用模型、依据与生效时间。
  • 先回放和模拟核可执行性，再独立验证；实盘准入、仓位和真金动作仍由 Owner 决定。
