# 同样根数迁移到高周期，必须同时迁移时钟与事件身份

- **问题**：把原生15m IMACD→YOLO确认规则应用于1H、4H，代码表面只需换K线，但等待时间、available_at、事件ID、匹配和置换分组都依赖周期。
- **死胡同**：复用全局BAR=15m会把4H完整窗口错误记为15分钟后可用；同币同整数索引联结会把不同周期的检测框串到一起。聚合15m均线或先裁到评价期，则改变高周期指标定义和递归播种。用0确认直接断言模型失败，也会混淆“无原箭头”和“有箭头但模型不识别”。
- **有效路径**：先将完整连续UTC15m历史按整组聚合，再重算本周期指标；显式传递周期到所有收盘/入场时钟，将周期加入候选、模型与联结身份，并隔离方向置换。保持9根预算意味着1H最多9小时、4H最多36小时；本轮1H一条确认晚5小时，沿空头方向追价约0.90%，必须使用新价格。4H的BTC无候选、ETH两条候选40张输入无框分别报告。
- **通用规则**：跨周期验证先列出每个“根数”对应的自然时长和每个联结键，确认所有指标均在目标周期历史重新计算；再核对原候选、实际推理窗口和输出框三个分母。零候选不等于模型拒绝，零模型框也不是经济失败证明。
