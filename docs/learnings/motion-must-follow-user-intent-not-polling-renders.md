# 动效应绑定用户意图，而不是每次 DOM 更新

- **问题**：交易前端只有零散按钮变色；直接给动态卡片加 CSS 入场，会让轮询重建、报价更新和恢复的说明反复闪动。
- **死胡同**：仅在路由切换时淡入，会把冷加载的占位文字做完动画，真正内容随后瞬间出现；将整个页面位移还会改变固定图表的定位参照。全局套用入场类也无法区分轮询与用户切换。
- **有效路径**：共享时长和曲线，路由只淡入；冷加载仅在当前路由短暂观察首个可用内容，出现后断开。页签和说明由点击/键盘意图触发，卡片每次进入最多六张。用代次校验、取消和动态 reduced-motion 处理快速切页与迟到结果。原生 dialog 用 display/overlay 过渡，关闭后的指针和焦点立即释放。
- **通用规则**：先区分导航、用户选择、数据更新三种来源，再决定何时播放；动画绝不能成为业务状态、提交或焦点恢复的前置等待。减少动态效果还要覆盖 backdrop/details 伪元素和 Web Animations。
- **牵连**：`workspace-motion.js/css`、`design-tokens.css`、路由/分区入口、VLM Shadow DOM。生命周期回归与真实浏览器的计算样式中间帧共同验收，不能拿静态截图或 CSS 存在当作动效运行的证据。
