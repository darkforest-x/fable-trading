# 多策略回测应缓存静态解码，不共享持仓状态

- **问题**：24个入场政策汇总约898万条路径时，每个政策都重新解析相同时间列、缺失状态和排序，静态处理成本随政策数量重复放大。
- **死胡同**：直接复用基线持仓或只筛选旧成交虽快，但规则变化后先后占仓会变，不能用于比较。保留全部逐政策静态解码同样没有必要。
- **有效路径**：共享时间戳、状态与排序数组；每个政策仍独立重排持仓。标量队列只遍历已具备入场资格且有成交的候选，它们以外的行不更新持仓。与独立核验过的smoke比较1912320个布尔决策完全一致，缓存前后2868480个有效收益／已知状态／成熟时间值完全一致；同一小样本的有效值计算由5.32秒降至0.14秒，这是局部耗时而非整轮加速比。
- **通用规则**：先区分政策不变的输入解码与政策相关的状态机。缓存前者，单独重算后者；优化须逐事件验证，不能只比总收益。
- **牵连**：`yoyo/evaluation/spike_v131_rule_summary.py`；保留两次性能重启的未完成输出和新的builder版本，不改分组、入场、退出或成本定义。
