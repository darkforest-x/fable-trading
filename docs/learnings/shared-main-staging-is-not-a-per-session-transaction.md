# 同一工作树的暂存区不属于某个会话

- **问题**：V31报告23个文件已按路径和hunk暂存，在等待测试时同仓校准线程提交，把这些暂存产物与其3个修复文件一起纳入c6ddb71。当前分支一直是main，分支检查没有发现问题。
- **死胡同**：把“自己只stage了负责文件”视为提交隔离；git index是整个工作树共享的。另一个普通git commit可以消费所有已暂存文件，自己随后空提交不代表产物丢失。
- **有效路径**：先看HEAD及提交文件清单，再逐路径比较working tree/HEAD与已有哈希收据。核实23个文件原样入库、远端main一致；与另一个会话确认，不reset、不重写历史、不重复提交。提交消息不能替代内容证据。
- **通用规则**：共享main多会话需要串行提交窗口/协作锁，并在stage之后到commit之前重查index；不应把测试等待夹在已暂存事务中。分支检查和路径级staging都不是互斥锁。遇到空index先查并发提交，而不是重新add全部。
- **牵连**：V31 support交付f8e450b/6e156a8/f57f835及最终c6ddb71；另一会话校准修复。未更改单仓main纪律，未建分支/worktree，也未回退他人修改。
