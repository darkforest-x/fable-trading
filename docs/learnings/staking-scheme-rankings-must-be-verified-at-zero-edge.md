# 资金方案的排序必须在零期望档复验，否则只是在放大一个未证实的 edge

- **问题**：在仓库最优格子（均值净 R +0.168）上比较倍投 / 固定 / 顺势加码，
  顺势加码看起来全面占优：破产率 9.5%、中位期末 2704U，比固定仓位破产率更低**且**期末更高。
  这个"支配"结论能不能直接用？
- **死胡同**：差点把它当成结论交付。问题在于 +0.168 本身 p=0.190、CI [−0.118, +0.520] 含 0，
  按本仓验收口径**没有通过**。在一个未证实的期望上比较资金方案，得到的排序可能
  完全是那个期望撑起来的。仅看"同一批数据、同一套模拟、对照组齐全"是发现不了这一点的——
  三个方案共享同一个有偏的前提。
- **有效路径**：把净 R 序列整体平移到均值**恰好为 0**，重跑同一套模拟。结果分裂：
  **"倍投最差"在 6/6 格子成立（与 edge 无关，可以定论）**；
  **"顺势加码占优"塌了**——零期望下它输给固定仓位（破产率 0.379 vs 0.333，
  iid 序列下 0.582 vs 0.109）。关键判断：顺势加码的本质是**把 edge 放大**，
  没有 edge 时它只是把方差放大。同一张表里，一个结论是结构性的，另一个是寄生在 edge 上的，
  不做零期望档就分不开。
- **通用规则**：任何资金方案 / 仓位管理的比较结论，**必须在 mean=0 的平移副本上复跑一遍**。
  在零期望下仍成立的部分才是方案本身的性质，塌掉的部分是 edge 的性质被记在了方案头上。
  这条对"某某加仓法更优"这类结论一律适用。顺带：**负期望档（本仓 ETH 3m 实测 −0.620）
  也要跑**——那一档三个方案破产率 85.8%–100%，直接封死"用资金管理补救坏信号"这条路。
