# 筛选审核页的自动下一张要基于变更前索引

- **问题**：审核页默认只显示 `PENDING`。保存当前裁决后，该项立刻离开筛选列表；随后复用普通 `step(+1)` 会先把“找不到当前项”重置为索引0，再加1，于是每次跳过真正的下一张。
- **死胡同**：把“裁决”和“下一张”当作两个独立动作，在未筛选列表上没有问题，但筛选条件依赖刚写入的裁决时，第二个动作看到的已经是结构变化后的列表。静态 DOM/JavaScript 语法检查也发现不了这种状态机错误。
- **有效路径**：裁决前记录当前项在旧筛选列表中的索引；裁决后若当前项仍在新列表，走下一索引；若已被筛掉，则使用压缩后相同索引，因为那里正是旧列表中的下一项。用真实浏览器验证全局序号从4501到4502而不是4503。
- **通用规则**：任何“修改状态后自动导航”的筛选 UI，都必须明确当前项会不会因修改离开集合；导航目标用变更前索引和变更后成员关系共同决定，不能无条件调用普通 `+1`。
- **牵连**：`scripts/build_15m_candidate_boundary_review.py` 的 `decide` / `filtered` 状态机、9,000张连续人工审核效率、Playwright真实流程验收。
