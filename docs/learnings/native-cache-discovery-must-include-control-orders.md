# 原生成交缓存发现必须同时覆盖信号单与对照单

- **问题**：2026-10-31 将八策略主单入场评分替换为排列过滤。初始实现复用了旧八账户信号单，但遗漏了另一实验已保存的同规则随机对照成交，导致前段有可避免的重复计算。
- **死胡同**：仅按“本策略的旧结果目录”发现缓存不够。入场规则实验常把信号与对照存在不同实验目录；同一个对照的标识后缀不同，也不能据此认为它是新订单。直接丢弃已完成结果来统一新版缓存口径又会制造更多重跑。
- **有效路径**：补入 `exp-v3-causal-close-entry-20261030-v1` 的原挂单对照缓存，按原始订单身份联结，并核对入场、止损、目标、方向和首成交时点。暂停后续执行、保留已完成阶段，从剩余订单继续。阶段已有原生审计时保留当时的订单清单，不能用新缓存分配覆盖旧清单。新增加仓单仍需要在原生引擎中提交其父单，这种依赖与可避免的重复对照分开计数。
- **通用规则**：排期前先列出每个原生订单的完整语义身份及所有候选缓存，覆盖信号、对照、父单和子单；完成缓存覆盖检查后再执行。恢复运行只补缺失阶段，并分别记录缓存复用、必要父单依赖和前段复用遗漏，不能通过修改收据掩盖重复计算。
- **牵连**：`yoyo/evaluation/monday_order_only.py`；`exp-monday-order-only-20261031-v1` 的 `run.log`、逐币原生收据及 `validation.json`。首次builder为 `0f0bf00c29`，缓存覆盖修正为 `a7df11dd7a`。原始结果保留；未更改成交语义、模型或生产服务。
