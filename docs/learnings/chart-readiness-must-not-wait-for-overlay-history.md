# K 线首屏不能等待历史叠加层

- **问题**：信号图表把 K 线与历史参考框放进同一个 Promise.all；任一历史请求慢或失败，已有参考计划也无法先画。切周期重复请求相同窗口，选中卡片还让整批玻璃卡片重建。
- **死胡同**：只看接口耗时会漏掉 DOM 重建与不可见云带计算；微基准更快也不能冒充浏览器首屏或帧率改善。
- **有效路径**：K 线与历史请求分别维护取消、超时、版本校验和失败状态，先画所选信号；只缓存校验通过且收盘边界一致的 K 线窗口。完成周的历史按币种、周和 TTL 缓存，未完成或失败仍重试。选中态只切换相邻节点 class；云带先按可见范围加两侧邻点裁剪，再计算交叉与缺口。
- **证据**：43 个相关前端测试通过，覆盖过期、取消、重试、跨币隔离、容量淘汰和绘制边界。公网 BTC 12H→5m→12H：返回12H的 DOM 就绪575ms，没有新增K线请求；卡片节点保持身份。该单次结果不是普遍首屏时延或FPS保证，首次打开仍有网络和图表库开销。
