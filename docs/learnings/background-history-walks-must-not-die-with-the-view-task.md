# 按需补历史的后台加载，不能跟着视图任务一起被取消，也不能在还没连上时就跑

- **问题**：owner 2026-11-09 问：“为什么K线图历史的区间线只能看到最近几周的，我需要看全历史的”。纪律 App 的往周周一区间只取了 3 页 1H（约 37 天），本机缓存又只留最后 800 根，所以只有最近大约 5 周。
- **死胡同**：
  - 一次性把 1H 全历史拉下来：每周 168 根、一页 300 根，几年下来要上百页，而每周真正需要的只是周一那 24 根。
  - 把加载挂在 `.task(id:)` 上，图表最早一根变化时换 id 重新加载：SwiftUI 会取消旧任务，新任务看到“正在加载”就直接返回，旧任务随后因为取消而退出，结果谁也没有去补新的目标。
  - 启动时立即加载：那时连接还没建立，请求失败，任务结束。而任务 id 里没有包含连接，所以连上之后也不会再触发。实测缓存文件里是 0 周（旧版本同样有这个隐患，只是被本机 1H 缓存掩盖了）。
- **有效路径**：
  - 从最新一个已完成的周一开始往前走。每次请求“到某个周二 00:00（纽约时间）为止”的 1H 一页，300 根正好覆盖这个周一和上一个周一，所以每请求一次前进两周。走到图表已加载的最早一根就停，请求到空页说明到了上市日，也停。
  - 已完成的周一永远不会变，算过就存到磁盘（按服务地址和合约分开），算不出来的周也记下来，不再重复请求。
  - 往回走的加载用独立的 `Task` 跑，每走一步都重新读取最新的目标。视图任务只负责更新目标，`connection` 为空时直接返回，并且把连接放进任务 id。
  - 绘制时只画和可见时间段有重叠的那几周。
  - 实测：12H 加载 14 周；切到 1D 后加载 42 周（2026-01 到 2026-10），覆盖了整张图。
- **通用规则**：
  - 由界面驱动的增量加载，要分成两部分：界面只负责更新“想要到哪里”，真正的加载循环独立运行、每一步都重读目标。
  - 用任务 id 触发加载时，加载依赖的每一个前提（连接、账户、开关）都要放进 id。
- **牵连**：`native/SpikeDiscipline/Fib/ChartStyle.swift`（`MondayHistory`）、`Fib/CandleChart.swift`（可见区裁剪；顺带修正往周首次触价从周三才开始找的问题：`FibRange.start` 本身已经是周二 00:00）、`FibView` / `TradeView` / `LandscapeChart` 中加载历史的任务。
