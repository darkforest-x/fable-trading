# 行情缓存的新鲜度是读取时刻的事实

- **问题**：本地监控在重启、行情请求失败或整点翻页时，旧行情计算结果仍可用于展示，但原来的 healthy/ready 标记已不一定有效。
- **死胡同**：只在请求失败时更新 markets，不更新图表缓存，会让详情继续显示健康旧状态；恢复时只比较末根时间戳又会复用 loading/error。只在写入时计算 stale，也会在下一整点继续显示“当前蓄势”。
- **有效路径**：旧图可保留，错误状态必须同步；带错误的缓存禁止走计算快路，恢复同一时间戳也重新算。图表与市场列表读取时都用交易所校准时间计算预期已收盘时间，过期观察从当前蓄势计数中移除。未来整点切换、同戳恢复和高周期恢复分别做回归。
- **通用规则**：报价值可以缓存，是否最新必须以访问时刻重算；业务状态、连接状态、计算状态不能共用一个“在线”标志。
- **牵连**：`yoyo/monitor/service.py`、`yoyo/monitor/server.py`、`tests/monitor/test_runtime.py`、`tests/monitor/test_service.py`。这项修复不改任何交易规则或既有执行器新鲜度门。
