# 每周首单必须先于筛选、分页和通知资格计算

- **问题**：同一周每根合格的 12H K 都建立参考框；只精简标签仍留下重叠交易。Owner 改为每币每周首个信号，并将确认后参考价设为触及侧 1.618。
- **死胡同**：只在画图时隐藏多余框，卡片计数、旧链接和通知仍保留重复资格；先按多空或实时过滤再取首单，会让第二个方向或较晚信号重新获得名额。没有另行尝试收益回测，因为此任务是参考语义与展示修正。
- **有效路径**：以币种与纽约周一区间作共享键，先选首次合格信号，再处理方向、时间范围、排序、分页；通知写入/发送和历史重建复用同一规则。原始记录不可改写，旧重复链接转到规范首单；混合历史响应在前端再次按周收敛，防止选中旧 ID 将框重新插回。确认收盘价单独保存，不能把新的 1.618 参考价用作 EMA/ATR 递推输入。
- **通用规则**：新增“每组只允许一次”约束时，先找出所有资格消费者和复入路径，而不是把它当作列表样式。事后参考价和真实执行价分开描述；统计窗口不因画框的锚点变化而暗中扩展。
- **牵连**：`cloud_signal_rules.py`、`cloud_signals.py`、`cloud_signal_history.py`、`cloud_signal_plans.py` 及前端合并/深链。V6 在 Notion 新建，原 V5 记录保留。旧通知 payload、渠道状态和启用时间不迁移重写。
