# 高周期事件必须携带独立的可用时钟

- **问题**：将 1h RSI 大菱形接到 5m 均线确认时，1h OHLC 的开盘索引、聚合结果的收盘索引和5m数组位置同时存在。若只按 `hour_i * 12` 取位置，会把收盘后才能知道的事件提前整整一小时。
- **死胡同**：仅查看 Pine 的 `barstate.isconfirmed`，或只验证 RSI/SAR 数值一致，不能证明跨周期回放没有前视；`confirm_time` 若实际保存确认K线开盘，也会产生误导性的审计账本。本轮在正式行情评分前的代码检查发现并修复了这两种时间标签问题，没有把提前版本作为研究结果。
- **有效路径**：输入5m按开盘标记，完整12根聚合后1h按收盘标记；1h第h根事件映射到5m位置 `(h+1)*12`。例如1h在10:00收盘，第一根完整候选是10:00–10:05，确认可用与最早成交均在10:05。账本分别保留1h开/收盘、5m确认根开盘、确认知识时间、成交时间。合成案例断言确切索引并验证前缀不受后续行情影响。
- **通用规则**：跨周期连接先画出每条数据的“何时发生、何时可知、何时可成交”，再写数组映射；指标值正确不等于决策时钟正确。
- **牵连**：`yoyo/evaluation/btc_rsi_sixma.py`；`tests/evaluation/test_btc_rsi_sixma.py`；`experiments/active/exp-btc-rsi1h-sixma5m-20260920-v1/PROJECT_PLAN.md`。退出时间仅能标记包含成交的5m K线，不假装知道OHLC内部精确成交秒数。
