# 已核对的挂单占用额度，不应锁住整个账户

- **问题**：常规限价单保持 pending 后，账户全局开仓门仍把它视为结果未知，导致 BTC 正常挂单阻止 ETH 开仓。
- **死胡同**：沿用立即成交模式的“pending 非空就暂停”判断，会把正常等待成交与请求不确定混为一谈；直接放行全部 pending 又会丢掉未知回执和未保护成交的隔离。
- **有效路径**：仅放行执行版本、限价类型、挂单阶段及 acknowledged 发单回执一致的挂单。私有同步、未保护持仓、未知 outbox 仍先拦截，之后照常校验次数、同币挂单及共享额度。回归用例必须提交 outbox 状态修改再调用另一连接的读取，避免未提交数据造成假测试。
- **通用规则**：新增长期状态时，逐个审视原有短生命周期的全局锁。已知承诺进入额度预留；未知结果进入隔离。两者不能复用一个布尔门。
- **牵连**：`yoyo/discipline_app/live_book.py`、`tests/discipline_app/test_managed_orders.py`。不撤销真实挂单，不重置计数，不改变风险上限。
