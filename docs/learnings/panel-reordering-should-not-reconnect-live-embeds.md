# 面板重排要改变布局，而不是重新连接行情图

- **问题**：交易页要在行情、下单、持仓之间切换位置，同时保留 TradingView 的周期、指标及缩放。订单区独占一行的单位控件与常态检查说明又造成空白。
- **死胡同**：现有行情/下单双栏加外层持仓的嵌套结构无法直接交换三块位置；用 DOM 搬运或重新生成整个页会重新连接 iframe，丢失图表操作状态。这条风险已有前轮图表生命周期证据，本轮未重复采用。
- **有效路径**：行情节点固定在同一父节点，为下单与持仓各留独立插槽，用持久化且校验后的 grid-area 布局切换位置。账本轮询继续只更新业务节点；单位控件进入标签栏，正常等待和检查文案省略，仅在真实异常时提示。资金摘要紧随持仓，避免短订单卡片下方留出整个下单表单的空高。
- **通用规则**：先分清有内部状态的嵌入组件与可重复生成的业务卡片，再决定可移动边界。验证应实际改变图表周期后切布局及操作表单，并检查刷新记忆、窄屏溢出和异常恢复，不能仅看 CSS 或断言节点存在。
- **牵连**：`yoyo/monitor/static/paper-desk-market.js`、`paper-desk.js`、`paper-desk.css`；前端测试 `tests/monitor/frontend_paper_desk_market.test.cjs`、`frontend_paper_desk.test.cjs`；原始证据 `output/playwright/task54/panel-layout/`。仅显示层变化，没有修改自动交易检查或账本。
