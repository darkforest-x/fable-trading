# Holdout 登记与精确集合测试必须同一次落地

- **问题**：实验注册表已经诚实登记了三个新的 `holdout_consumed: true` 实验，但精确集合测试仍停留在旧名单，导致主分支的注册表契约长期红灯。
- **死胡同**：把失败当成“测试过时所以忽略”，或为了让测试绿而从注册表删掉真实 holdout 消耗。前者让门禁失去作用，后者直接篡改审计账本。
- **有效路径**：逐条核对新增实验的 Owner 授权、报告和注册表记录，只把已存在于主分支的三个真实消费者补进精确集合；并把当前工作区另一项尚未提交的实验排除在本次改动之外。
- **通用规则**：任何新增或删除 `holdout_consumed: true` 记录的提交，必须同时更新精确消费者集合测试；测试红时先对账注册表和授权证据，禁止靠弱化断言或改写历史消耗修复。
- **牵连**：`experiments/registry.yaml`、`tests/contracts/test_registries.py`、holdout 铁律；本轮 L2 自身仍是 `holdout_consumed: false`。
