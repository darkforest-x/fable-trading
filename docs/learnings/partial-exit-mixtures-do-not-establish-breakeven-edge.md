# Fixed scale-out mixtures do not prove a breakeven-stop advantage

- **问题**: Many Monday reversal trades reached the near target or positive MFE before stopping out. Owner asked whether partial TP1 followed by breakeven should replace the existing exits.
- **死胡同**: Counting rescued losers alone overstates the benefit. A new breakeven stop can also remove trades that revisit entry before eventually reaching TP2. Maximum favorable excursion does not establish that ordering. Older ETH partial-exit failures use another signal and 20bp costs, so they cannot decide the current Monday case.
- **有效路径**: First freeze the same admitted entries, original risk, original stop, target anchors and linear per-fill cost schedule. With a fixed fraction q closed at the near target and the rest at the far target, no stop changes, identical fills and no capacity effects, each resolved trade satisfies R_partial = q * R_near + (1-q) * R_far. The same equality holds for the identical resolved cohort mean. A mixture cannot exceed the better endpoint, although it can change variance and realized cash timing. Variable fractions, changed fills/capacity, fee tiers or a moved stop invalidate this shortcut. Censored endpoints must remain separate.
- **通用规则**: Distinguish a scale-out allocation from a new exit barrier. For TP1-triggered breakeven, replay the new semantics once in the approved framework only after parameters are authorized. Compare rescued losses, interrupted eventual winners, net expectation, matched controls, chronological segments and funded drawdown if funded capital is modeled. Activate only after actual TP1 fills; specify quantity, allocated entry costs, expected remaining-exit costs, tick rounding and intrabar event order. Entry-price breakeven is not cost breakeven, and an exchange trigger price is not a guaranteed fill price.

A 50% near TP1 / 50% far TP2 with remaining-leg fee breakeven is a research proposal only, not an approved default, tested profitable policy or new parameter authorization. Existing initial pin-extreme stop is the comparison baseline, not an established optimum. See [OKX order execution and fees](https://www.okx.com/en-us/help/what-a-limit-order).
