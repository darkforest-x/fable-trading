# 原生成交价格转浮点后要允许表示误差

- **问题**：2026-10-23 的5m周一插针吞没框架回放中，BTC下一开盘69054.2被Nautilus返回为69054.20000000001，差1.455e-11，大于旧tick×1e-7容差1e-11，触发入场校验失败。
- **死胡同**：把保护价格tick一律缩小可以保存更多小数，却让绝对比较容差小于大价格的一个浮点ULP。失败不意味着成交真的偏离了入场价，也不能为让它通过而改实际交易价格。
- **有效路径**：只在成交价比较处取原容差与两边价格的2ULP最大值；保持bar索引必须一致。补上69054.2原生回放测试，继续逐笔核对止盈止损及现金费用。
- **通用规则**：十进制定点与二进制浮点互转的验收应考虑表示尺度。容差必须远小于一个市场tick，不能吞掉实际一个tick的偏差。
