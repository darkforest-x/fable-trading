# 报价缓存必须显式区分未读取与仍新鲜

- **问题**：Notion 任务 54 的手动模拟开单首次获取报价为空。固定新鲜报价的单测也失败，而直接读取 OKX 公共接口可取得报价。
- **死胡同**：最初怀疑上游时间戳过期；保留原始买卖价与时间戳后，发现它们通过独立新鲜度检查。放宽有效期不能修复缓存尚未发请求的问题。
- **有效路径**：实测新进程 `time.monotonic()` 约为 0.23 秒，缓存初始化时间为 0，`now - cached_at < 3` 误判成已有新鲜缓存。用 `None` 表示从未读取，先检查空状态，再计算 TTL；有效缓存继续校验上游时间戳。
- **通用规则**：缓存是否存在与缓存是否过期是两项独立事实。不要用 0、空字典或某个时间值同时表达二者；冷启动测试须在首次调用就返回真实缓存来源，不能先 sleep 等它“恢复”。
- **牵连**：`yoyo/research_workspace/paper_desk_api.py`、`tests/research_workspace/test_paper_desk.py`。模拟成交保留报价时效门，不因本次错误放宽行情或生产信号新鲜度。
