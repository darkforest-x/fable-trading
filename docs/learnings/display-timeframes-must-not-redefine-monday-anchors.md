# K 线周期切换必须与周一定界分离

- **问题**：周一 1.618 全屏图只接了固定 15m 上下文，周期文字是静态标签；换成日线后若按图上蜡烛重新定界，纽约周一高低点会漂移。
- **死胡同**：原有 `/api/chart` 绑定全市场扫描周期，直接增加 1m/5m 会扩大扫描负担；从 15m 拆出小周期没有真实 OHLC，按纽约周一裁剪日线又会只剩几根。没有采用这些路径。
- **有效路径**：独立按需读取 OKX 原生周期，经现有 CandleHub 复用缓存和后台限速；仅请求所选合约，最多两个加载任务、十二组缓存、720 根已收盘历史。日线明确使用 `1Dutc`，周一高低点及两侧 1.618 始终取监控服务的原始纽约周一基准。前端缓存、请求和渲染身份都包含周期，切换立即取消旧请求并拒绝迟到响应。
- **通用规则**：先区分展示周期与策略定界周期；两者不能共用一项配置，也不能因展示需求扩大扫描全集。原生数据不足就显示不足，不补造蜡烛。适配按钮名称与加载边界，本次用“全图”表示已加载历史。
- **牵连**：`monday_candles.py`、`monday-fib-chart.js`、`monday-fib.js`、`range-chart.js`；日线不画会误导纽约边界的整日背景带。官方接口：[OKX 原生周期与 confirm 定义](https://app.okx.com/docs-v5/en/#order-book-trading-market-data)。
