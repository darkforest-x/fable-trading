# 框内突破的亏损不能靠一个几乎人人已满足的支撑门解决

- **问题**：V11.2 框内突破不要求当根继续站在六均线上方，怀疑这是失败交易的重要来源，于是只加 `close > ropeHigh` 做完整串行对照。
- **死胡同**：源码缺少一个看起来合理的检查，不代表这个检查在实际样本上有区分力。回放显示 15m/1h 原候选本就有 98.04%/98.05% 满足它；5,001/1,587 笔基线亏单中只直接滤掉 103/25 笔。
- **有效路径**：先复现全部 9,287 笔基线成交，再保持首次突破消费语义与独立持仓状态。15m 全期仅改善 0.0041R/笔（95% 月块区间跨0），后段差 0.000024R/笔；1h 全期 -0.0921→-0.1090R，后段也变差。1h 少亏 23.50R，却漏赚55.01R，另释放出一笔 -1.02R 交易。
- **通用规则**：评价过滤条件时先查候选覆盖率、亏单覆盖率和误删赢家的金额，再看胜率或总亏损。低覆盖条件不是自动无价值，但本轮数据不支持把六均线支撑硬门作为改进方向。
