# 暴跌预警的提前量必须相对于首次严重分钟，而非滚动窗口结束

- **问题**：用分钟数据检验提前挂单机会时，若把五分钟最低价所属窗口的结束时点当作暴跌时点，会制造额外的预警时间。
- **死胡同**：滚动最低价可能来自更早的一分钟；用该标签所在行的结束时点匹配报警，会把已经发生后的信号算成预测。只检查报警历史位于评估期间，也会把期间边界外的事件纳入。
- **有效路径**：用当前分钟 low 相对五根前 close 定义严重阈值，保留首次达到阈值的分钟，事件时间取该分钟开盘作为保守下界。信号仅在已完成分钟结束加假定延迟后可用；事件开盘的期间归属和完整报警历史窗分别核对。以未来价格突变和跨期间边界的合成检查验证。
- **通用规则**：先画出数据区间、最早可知时点与目标发生区间，再统计提前量。此前跌势已启动的预警只能称严重阶段预警，不能称预测最初下跌；分钟数据也不能证明秒级订单来得及到达。
- **牵连**：`yoyo/evaluation/market_crash_alarm.py`、`market_crash_alarm_stats.py`、`tests/evaluation/test_market_crash_alarm*.py`，实验 `exp-market-crash-alarm-20261029-v1`。统计不涉及成交或收益，未改变任何实盘配置。
