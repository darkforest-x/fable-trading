# owner 眼中的"密集"与机械定义**反相关**——三个代理全部失败

**日期**:2026-07-27
**类型**:反直觉结论(短检测器 v3 评估时挖出)

## 一句话

用 owner 亲手标的 390 个 verdict(71 keep / 319 drop)去检验机械密集定义:
**owner 认可的框只有 31.0% 算密集,而 owner 否掉的框有 47.0% 算密集。**
方向是**反的**。我们一直在拿一个不是 owner 模式的定义去训检测器。

## 三次假设,三次被数据打掉

| # | 假设 | 结果 |
|---|---|---|
| 1 | tip 锚点晚 10 根 → 重锚就好(v2) | 重锚了,gold 上几乎没动(96.9% 仍复现误检) |
| 2 | 没有负样本 → 加负样本就好(v3) | 加到 60% 负样本,v3 变得极保守:keep 只剩 **9.9%**、drop 降到 12.5% |
| 3 | owner 判像素、规则判百分比,渲染器自动缩放导致错位 | **也错**:像素空间里 keep 反而**更散**(p=0.024,同方向) |

v3 拒绝 owner 的 keep **不是 bug,是忠实执行**——按 expanded 预设那些框本来就不算密集。

## 数字

在 v1b 的 tip 处(expanded 预设 fast≤0.0045 / full≤0.0088):

| | n | 算密集 | fast p50 | full p50 |
|---|---|---|---|---|
| **keep**(owner:是真密集) | 71 | **31.0%** | 0.00503 | 0.00942 |
| **drop**(owner:不是) | 319 | **47.0%** | 0.00291 | 0.00786 |

均线束宽度(百分比和像素两种口径)都**不能**分开 keep/drop,且方向都与预期相反。

## 那 owner 到底在看什么?

不再猜,直接用 390 个标注学:时间切分 held-out **AUC 0.667**(弱但真实,不是随机)。
主导特征**完全不是 spread**:

```
cma_20 / cma_30 / cma_60   (价格相对均线的位置)
maxret_30 / minret_120     (近期极值幅度)
volstd_120 / rngz_30       (波动率与区间 z)
skew_3 / skew_30 / skew_120
slope_10 / slope_60
```

→ owner 判的更像 **"价格在均线群里的位置 + 近期波动结构"**,而不是"均线束有多紧"。

## 教训

- **先验证标签定义,再训模型。** 三轮训练(v1b/v2/v3)+ 两次 3060 全都是在优化一个
  **没被验证过等价于 owner 眼**的目标。390 个标注早就能做这个检验,只花几分钟。
- **反相关比不相关更危险**:若只测"机械定义能不能预测 owner"(AUC≈0.5)会以为是"没信号";
  实际是**符号反了**,越"密集"的越会被 owner 否掉。
- **模型忠实 ≠ 目标正确**。v3 的保守是正确执行了错误定义。评估要能区分这两者,
  所以 keep 侧和 drop 侧必须同时报——只看 drop 下降会把 v3 当成成功。

## 下一步(需 owner 决策)

1. **别再用 fast/full spread 当检测器的正样本判据**(已证伪三次)。
2. **可用路径**:把 390 个 verdict 当唯一真值,扩到 ~1000 后直接学"owner 会不会 keep",
   用它生成正样本 —— 但 AUC 0.667 说明现有特征只捕获了一部分。
3. **或者**:请 owner 用自己的话说明判 keep 时在看什么,再据此造特征——
   这一步靠猜已经浪费了三轮。
