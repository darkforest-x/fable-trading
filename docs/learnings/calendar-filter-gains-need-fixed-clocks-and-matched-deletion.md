# 日历过滤的累计减亏必须同时固定时钟并匹配少交易对照

- **问题**：V1 的 H00、周日亏损分组看似能直接转成 V8 降噪规则，但原引用未交代时区，且删单自然会改变交易数量。
- **死胡同**：把“午夜”默认成用户本地午夜，再从不同周期里挑改善最大的结果。V8 两年 UTC H00 在30m变差55.96R，北京 H00却在4H变差130.37R；同名规则并非同一组可执行事件。
- **有效路径**：预先分别固定 UTC 和 Asia/Shanghai 的确认收盘/下一开盘时钟，保留原单归因与完整串行回放，再在同币、同月、同方向、同波动桶随机删除等量事件。UTC周日累计改善2768.72R，但原有10R只保留459/532；后一年匹配后校正p仅30m低于0.05，不能据总量宣称各周期都识别了假突破。2,000次置换乘27的p分辨率下限为0.01349，必须披露，不得临时追加次数追门槛。
- **通用规则**：先确定时区和事件可用时间，再分别问“少交易节省多少”“是否比匹配随机删单更好”“损失了多少大趋势”。时区敏感性、重复历史选择与统计计算精度都要写入结论。
