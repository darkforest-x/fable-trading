# 匹配随机对照必须在研究窗口内重新回放

- **问题**：V1/V7 已有两年期随机对照缓存、收据和汇总，但市场广度研究只允许使用一年开发期，并且需要给每个广度切片保留同币、同月、同方向、同周期、同连续段和同信号前波动桶的配对关系。
- **死胡同**：直接复用两年期 `control_cache.pkl.gz`、抽样配对表或按周期汇总。缓存会整体物化受保护窗口，抽样表只覆盖每流少量目标，汇总又丢失目标时间和广度标签；开发期目标的控制退出还可能跨过开发边界。把可匹配子集的均值外推到全部信号，会把未匹配选择偏差藏起来。
- **有效路径**：只读取开发期安全前缀与小型 `control_cache.receipt.json` 中冻结的 tick/source identity，在内存中重建每个连续段；沿用原单事件执行函数和成本，用固定 seed 在精确分层内选随机 bar，并把 `fold_end` 固定到开发期右开边界。每个目标都必须产生一条 matched 或具体 fail-closed reason，汇总的分母始终是完整目标 cohort。
- **通用规则**：对照资产只有在保留逐目标身份、匹配层、执行路径和研究窗口时才能复用。任何缓存或汇总缺少其中一项，都从本轮安全前缀重新回放；匹配不到时报告缺失，不能放宽层级凑对照。
- **牵连**：`yoyo/evaluation/spike_market_breadth_matched_controls.py`、`spike_v6_wvf_study_post.py::evaluate_single_control`、V1/V7 共同执行口径、`2024-09-10` 至 `2025-09-10` 开发窗口；对照明确禁止打开 `control_cache.pkl.gz`。
