# 隐去供应商原文时仍要保留安全错误码

- **问题**：Gemini 图片请求失败，但记录只有“请求未成功”。模型访问测试通过，两张图片均约 48KB；由于未记录 HTTP 状态，无法判断原始失败究竟是结算、参数还是其它原因。
- **死胡同**：初版为了不回显密钥或供应商响应原文，只按少量 HTTP 状态翻译错误，漏掉 402、416 等状态后统一丢入泛化提示。只通过 models.get 也不能证明图片推理、结算或配额可用。
- **有效路径**：保留数字 HTTP 状态和官方白名单中的机器错误码，用本地固定文案解释；原始 message、details 和未知代码都不回显。识别记录、导出和连接测试保留同一组安全分类，失败也记录真实耗时，不把缺失耗时显示为 0ms。
- **通用规则**：敏感信息过滤不等于删除诊断证据。单独验证模型访问与实际推理；缺失的历史状态不能事后猜填。额度不足等明确失败不应自动重试。
- **牵连**：`yoyo/vision_research/gemini.py`、`server.py`、`static/app.js` 与专项测试。官方口径：[Gemini API errors](https://ai.google.dev/gemini-api/docs/api-errors)。本次 44 项离线测试通过；原始两次失败的供应商错误码仍不可追溯。
