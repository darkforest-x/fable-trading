# 扩展通知周期不能挪动首次启用记录

- **问题**：Owner 在 15m 展示上线后明确要求推送。原有 `arm_v1_bark` 看到初次启用回执就返回，仅扩展周期常量不会给 15m 建立通知边界。
- **死胡同**：删除原回执重新初始化会改变实时/预热分类基准；继承旧周期时间则会让此前仅展示的信号获得历史推送资格。
- **有效路径**：保留最初回执和既有周期时间，幂等补齐新增周期的原始启动及 YOLO 两阶段时间。新时间取扫描前校准的时钟。测试覆盖旧箭头无通知、新箭头入队、YOLO 候选注册、重复初始化不挪动边界。
- **通用规则**：首次启用回执是历史事实，不等于当前启用范围；扩展范围时单独初始化缺失的授权边界。
- **牵连**：`notification_policy.py`、`BARK_TIMEFRAMES`；Telegram 仍关闭，历史事件及其他周期设置保留。
