# 通知订阅必须按来源和渠道独立保存启用时间

- **问题**：TG 只有“突破＋spike”多头，而 Bark 能收到普通 V12.8。原因是两类来源使用不同账本和启用策略；普通 TG 仍关闭，联合策略本身只产生多头，不能据此判断 TG 不支持空头。
- **死胡同**：只打开 TG 发送器仍不完整，普通扫描器没有给 TG 入队，历史启用时间也不能代表本次授权。整合时还发现，若 YOLO 候选依赖“原始启动通知已开启”，关闭两个原始通知开关就会意外关闭仍被订阅的 YOLO 确认。
- **有效路径**：按来源 × 渠道保存订阅，生产时及发送前应用相同规则；首次启用 TG 使用新的交易所校时时间，保留 Bark 和历史回执。重新开启以新时间为界，YOLO 同时检查原始信号时间。YOLO 候选按确认订阅独立准入。原账本继续负责原子认领与回执，统一界面只读合并；每个渠道一个循环公平处理两类账本。
- **通用规则**：排查“某渠道只发某类信号”时，先逐项追踪来源定义、入队条件、启用切点、发送循环和回执，不从前端展示或其中一条渠道的成功推断其它订阅已生效。开关重开不能成为补发历史或重试未知结果的入口。
- **牵连**：`yoyo/monitor/notification_center.py`、`notification_policy.py`、`v9_worker.py`、`model_gate.py`、`joint_notifications.py`、`service.py`；30 分钟新鲜度、原子 outbox 与未知结果不自动重发保持不变。测试使用临时账本和假发送器，不发送测试推送。
