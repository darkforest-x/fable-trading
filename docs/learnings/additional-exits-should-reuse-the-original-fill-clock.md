# 新增信号退出应复用原成交时序，避免覆盖更早生效的保护

- **问题**：2026-09-20，Owner授权在突破＋SPIKE模拟持仓上叠加RSI退出，同时保留原止损与4ATR追踪，先触发先退出。
- **死胡同**：单独计算RSI退出后覆盖原交易终点，会把早已触发的止损抹掉；先用下一根整根高低价判断止损，也可能把原本在开盘已执行的RSI退出错误归为稍后盘中止损。
- **有效路径**：将闭合bar的RSI触发作为只读临时副本中的反向退出事件，复用原回放的下一开盘机制，只有实际由RSI导致的成交才改原因标签。当前bar保护先判，下一开盘跳空穿保护优先，开盘信号退出又早于该bar后续盘中触碰；原V9同根触发保留原归因。
- **通用规则**：增加退出条件应增加触发来源，不重新发明成交时钟。关闭新增条件应与旧账本逐字段一致，并用相反先后顺序的合成路径验收。运行投影需要独立绩效版本和旧快照，信号ID不应随退出版本改变。
- **牵连**：`yoyo/evaluation/spike_joint_rsi_exit.py`复用`spike_v10_4_increment.attempt`和`spike_v1_v8_be05.replay_fixed_entry`。计数方式、周期、亏损时行为仍待Owner明确；本轮未接入前端或运行数据库。
