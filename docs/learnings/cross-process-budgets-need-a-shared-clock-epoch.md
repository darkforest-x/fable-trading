# 跨进程限流不能假定 monotonic 的时间原点一致

- **问题**：本机 Python 3.9/macOS 的 `time.monotonic()` 从各自进程起点计时，写入 SQLite 的限流预约无法被另一个长期运行的进程正确解释。
- **死胡同**：同时启动几个子进程时，原点相差很小，限流测试能通过，却掩盖了常驻扫描器与新页面进程的时钟差异。直接读取验证中，父进程约 0.35 秒时，新子进程约 0.01 秒。
- **有效路径**：持久化预算改用操作系统 `clock_gettime(CLOCK_MONOTONIC)` 的共享原点；本机验证父子读数约为 649288.84 / 649288.86 秒。跨进程测试错开启动时间，以墙钟测量实际请求间隔。普通进程内超时仍使用 `monotonic()`。
- **通用规则**：跨进程存储时间值之前，验证运行版本的时钟原点是否共享。并发测试应包含不同进程年龄，不能只同时启动。
- **牵连**：`yoyo/data/candle_hub.py` 的共享请求预算与 429 冷却；[Python 官方文档](https://docs.python.org/3/library/time.html#time.monotonic) 明确 macOS 从 3.10 才让 `monotonic()` 对所有进程共用原点。
