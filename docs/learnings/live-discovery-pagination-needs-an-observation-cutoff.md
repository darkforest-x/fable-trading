# 实时发现列表分页要固定观察截止点

- **问题**：巡检列表使用不断增大的 limit 追加卡片，越看页面越长；直接换成 offset 后，新发现插到前面又会让后续页重复或漏看。
- **死胡同**：只改“再显示”按钮的文案或在前端截断已经取回的列表都不是真分页。单独增加 offset 也不能抵御新增记录导致的位置移动。
- **有效路径**：后端先按观察截止点截取原始观察，再合并形态、筛选、排序、计算 total，最后按 offset/limit 切片。第一页返回 before_ms，后续页复用这个首次观察截止点；筛选、页大小或主动刷新回到第一页并更新截止点。每个响应仍做版本检查，失败保留旧列表并标明更新失败。
- **通用规则**：实时列表分页先定义排序与时间边界，再设计页码。不能只过滤合并后的首次观察时间：新扫描可能改变旧事件分数、跨事件合并形态，仍会打乱页码。截止点必须落在原始观察层，重启后也能还原同一列表。
- **牵连**：yoyo/yolo_workbench/discoveries.py、api.py、yoyo/monitor/static/yolo-detect.js。GET 仅查询，不触发巡检或交易。后端测试插入新发现验证连续页无重复，前端测试覆盖截止点复用、筛选后页数缩减和过期响应。
