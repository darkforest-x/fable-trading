# 外观切换必须覆盖 SVG 与首屏绘制

- **问题**：研究观察台原本仅有深色主题，颜色分散在 CSS 组件和动态 SVG 属性中；浅色还要保留历史快照与研究边界。
- **死胡同**：只替换页面背景会留下深色状态底板和过浅的走势图文字；等 API 初始化后再应用偏好会闪色，内联脚本又不符合现有 CSP。这些路径在源码检查时排除，未作为交付方案。
- **有效路径**：先把组件与 SVG 的颜色统一为语义变量，再提供浅色变量表；独立同源小脚本在样式前读取白名单偏好，存储失败仍允许当次切换。外观脚本不发请求、不参与研究配置。
- **通用规则**：主题是展示层状态，验收需覆盖首屏、系统跟随、显式偏好、存储异常以及图表；后端研究状态测试不能替代主题行为验证。
- **牵连**：`yoyo/rotation/web/{theme.js,styles.css,app.js,index.html}`。本轮静态客户端3项测试通过，独立 Node 场景验证系统变化、手动覆盖、刷新恢复、非法值与存储受限；浅色25组前景/背景对比度最低4.83:1。未修改数据或触发扫描。
