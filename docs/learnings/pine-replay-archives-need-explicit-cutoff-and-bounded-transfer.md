# Pine 回放档案必须使用明确截止点并限制跨上下文传输

- **问题**：Monday Range v1.10 在实时日线显示104周，切入历史回放后却显示0周；改变返回条件后，单步推进曾出现内存限制。
- **死胡同**：仅依赖 request 上下文的 barstate.islast / islastconfirmedhistory，回放末端并不一定返回档案；直接返回含241个周对象的数组还会放大跨上下文复制成本。
- **有效路径**：在明确可见截止附近额外发出快照，并在主上下文保留最近有效返回；周档案跨上下文传输改为有界标量文本，在最后一根主图K线上解包。低周期均线仍逐子周期计算，但只传输截止附近可能进入小图的样本对象，避免搬运数万条无用对象。
- **通用规则**：跨周期脚本至少验一次进入回放和连续推进；实时截图不是回放证据。历史价格过滤必须放在数据源上下文，输出选择和绘图截止不能代替无前视检查。
- **牵连**：`yoyo/evaluation/pine/monday_range_v1_10.pine`；1H独立周档案；低周期100000根请求上限不等于承诺所有历史都可用；分钟回放受当前Basic套餐限制，未验项目须保留。
