# 判断报价新鲜度前先核对交易所时钟

- **问题**：2026-10-18 Pro 接入检查中，OKX 报价比本机时钟领先约 1.5–1.8 秒；直接要求本机时间减报价时间非负，会拒绝新报价。
- **死胡同**：放宽新鲜度门槛或盲目重试无法区分时钟偏差与真正过期的数据。
- **有效路径**：用交易所公共时间接口和请求往返耗时建立服务器时间上下界，按保守上界验证盘口年龄；K 线闭合使用下界，拒绝发展中和缺失窗口。实际盘口读取通过后，保守报价年龄约 3.6 秒、时钟不确定度约 2.6 秒。没有更改旧执行、通知或看板的新鲜度门。
- **通用规则**：时间戳比较必须同一时基；校准不确定性过大时明确失败，不能把未知时间当新鲜。
- **牵连**：`yoyo/monitor/pro/live_venue.py`、时钟偏移与缺口回归测试；[OKX Market Data API](https://www.okx.com/docs-v5/en/)。
