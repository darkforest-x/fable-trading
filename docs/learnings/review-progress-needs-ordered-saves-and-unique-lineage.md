# 审核进度必须有保存顺序和唯一来源映射

- **问题**：审核自动保存需要防止较早的请求迟到后覆盖最新进度；评分又必须保证每个答案只对应一个来源记录。
- **死胡同**：用单线程 HTTPServer 保证保存顺序，浏览器空闲预连接却会堵住整站；仅校验答案 ID 而不校验 lineage，重复一个来源行就能让已审核数量悄悄翻倍。
- **有效路径**：HTTP 请求并发处理，保存操作单独加锁并拒绝比已保存快照更旧的导出时间；每次只追加不可覆盖的快照。评分先核对 lineage SHA、ID 唯一性、公开 manifest 完整集合和重复项指向，再计算一致率。
- **通用规则**：页面可操作、文件存在、计数有数字分别只证明局部步骤。作为证据使用前，必须验证持久化的顺序和答案到来源的一对一身份关系。
- **牵连**：`yoyo/datasets/grade_a_assisted_review.py`、`tests/test_grade_a_assisted_review.py`；用空闲 TCP 与重复 lineage 合成反例验证，测试答案不进入 Owner 包。
