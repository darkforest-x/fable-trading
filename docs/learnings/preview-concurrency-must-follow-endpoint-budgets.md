# 预览并行应按接口额度与依赖安排，不能只开线程

- **问题**：第一轮将49秒预览缩至5秒后，仍有统一210ms起步间隔及ticker之后等待时钟领先的尾延迟。不同接口实际上不共享同一额度，统一队列人为延长了关键路径。
- **死胡同**：只有4个线程加连接池仍会在共用限速锁上排队；仅把限速改成接口级，实测暖请求仍约4秒。删除挂单检查、延长行情有效期或复用上一轮余额会改变安全语义，不能作为提速方法。
- **有效路径**：按官方每接口预算分别限速，账户配置810ms、算法挂单210ms、其余读取410ms；同接口各订单类型与分页共用一桶，睡眠不锁住其他接口。ticker在本次请求内与账户读取重叠，计算时执行原0–5000ms年龄门；若预取报价已过期，再取一次，失败关闭。保留真实报价请求时刻；60秒确认期限和执行器重读不变。实测冷5.905秒、暖2.068/2.410秒，仍受网络尾延迟影响。
- **通用规则**：外部调用提速要同时画出依赖、限速桶和最后使用时点；请求顺序可以变，新鲜度与归属证据不能省。测试限速桶互不阻塞、同接口分页仍限速、慢库存查询使报价过期后必须重取、重取失败不回退旧报价。
- **牵连**：`preview_reads.py`、`Client.pace`、`manual.prepare`、`tests/okx_execution/test_preview_reads.py`。只调整手动预览读路径，连接保活120秒不是报价缓存。官方接口限速：https://www.okx.com/docs-v5/en/#overview-rate-limits 。证据`output/manual-ui-20261017/preview-latency-v2-*.json`。更新前一轮[ticker最后读取的实现选择](preview-latency-is-a-network-dependency-problem.md)，不修改其历史记录。
