# 原生 K 线本机缓存：按服务地址分键，遇断档整段丢弃

- **问题**：纪律 App 2.x 每次启动打开 1.618 / 合约都要等首屏 K 线网络返回（owner 2026-11-08“每次启动加载 K 线都很慢，不能加缓存吗”）。
- **死胡同**：
  - 只放内存缓存：App 被系统回收或冷启动后为空，正是 owner 抱怨的场景，没用。
  - 缓存键只用“合约 + 周期”：模拟器连 fixture（合成价格 ≈2000）和真机连生产（真实价格）共用同一个 App 容器时会互相污染，fixture 截图里会混入真实行情（与 [fixture 模式不能回落真实行情](fixture-mode-must-not-fall-back-to-live-market-data.md) 同类问题）。
  - 拿到新数据后直接和缓存合并：离线几天后缓存最后一根早于新页第一根，合并会把两段拼成一条连续序列，中间缺口在图上看不出来，均线、云带也会跨缺口计算。
- **有效路径**：缓存文件按 `服务 host-port + 合约 + 周期` 分键（二进制 plist，最近 800 根，7 天过期，后台写盘）。`show()` 先同步读缓存立即出图；首个网络页回来时，若缓存最后一根早于新页第一根就清空缓存再用新数据，否则按时间合并；离开页面时写回。12H 由 4H 聚合，缓存存源周期。
- **通用规则**：给行情序列加持久缓存时先问三件事：键里有没有数据来源（环境 / 地址）、合并前有没有检查首尾连续、过期时间是否短于“缺口可能出现”的时间。缺任何一项，缓存就会把错的图画得很快。
- **牵连**：`yoyo/discipline_app/native/SpikeDiscipline/Core/CandleStore.swift`（`CandleCache`、`show()`、`stopAndSave()`）、`Fib/ChartStyle.swift`（`MondayHistory` 复用 1H 缓存）。
