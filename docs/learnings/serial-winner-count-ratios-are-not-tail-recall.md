# 串行策略的赢家数量比，不是原赢家召回率

- **问题**：筛选规则改变持仓占用后，新策略可能成交旧策略没开的信号。统计函数把新10R数量除以旧10R数量命名为recall，混入了新增赢家。
- **死胡同**：独立候选筛选中，新集合是原母体的子集，数量比恰好等于召回；直接复用于串行回放会失效，例如原赢家a、b，新赢家a、d、e，数量比150%，真正保留率只有50%。
- **有效路径**：按event_key取赢家交集，分开记retained、lost、gained，并用retained/original计算召回。保留旧串行经济路径和旧报表，新建统计版本，重算并哈希绑定，不改写历史产物。
- **通用规则**：只有证明处理组是母体的真实子集，才可用数量比替代召回。凡涉及持仓、去重、排队、抑制或再入场，必须先做身份集合对照。
- **牵连**：`spike_10r_serial.py`、`spike_10r_serial_report.py`；V3的`serial_v1`保留，权威召回改用`serial_stats_v2`。10R命中率和逐笔收益不受这一统计修正影响。
