# 复用特征缓存，不等于继承生成它的实验执行方式

- **问题**：给固定 V9 补跑 ETH 3m/5m 时，完整的指标与原始信号已在旧倍投研究的缓存中；直接复用旧研究入口会同时带入资金策略、时间切分和准入范围。
- **死胡同**：不能把“同一份缓存”当成“同一项回测”。本轮没有先跑资金策略再改名：代码审查时即排除该入口；通用固定入场引擎也有与低周期历史不一致的默认时间范围，不能直接套用。
- **有效路径**：先固定源文件、缓存和准备回执的 SHA，只提取 frame/raw/mask；显式恢复原低周期分段与空仓边界。旧 V8 信号及 3,525 笔已平仓记录逐笔一致后，V9 仅修改新入场。对照引擎绕开默认时间范围，并核对每笔真实已平仓目标的出场、时刻和净 R。
- **通用规则**：缓存复用要分别证明数据身份、信号身份、执行身份和时间范围；缓存目录里的实验名称不传递策略语义。先提交新适配代码，再读取行情，不以放宽逐笔核对容差补救契约不符。
- **牵连**：`yoyo/evaluation/spike_v9_eth_lowtf.py`；`experiments/active/exp-spike-v9-eth-lowtf-20260915-v1/`；原低周期分段、0.002 往返成本、原始反向信号和 holdout 授权。对应报告：`analysis/p1_spike_v9_eth_lowtf_20260915.md`。
