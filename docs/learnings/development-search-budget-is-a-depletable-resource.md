# 开发期搜索预算会耗尽，更多回测不是更多证据

- **问题**：单次看每张表，V9、成交量门、long-only 或 trailing 都可能出现漂亮点估计；但落盘搜索已含
  12 个 oscillator 阈值、11 个 slope lag、18 个自然特征门、3 个方向策略和 21 个 trailing 组合，
  共 65 个配置、60 条独立四块收益路径，尚未计入历史代码迭代和人工选择。
- **死胡同**：每次只对当前“最佳”配置报一个普通 p 值，或继续在同一 2023/24 数据上找下一条 gate。
  普通 sign-flip 只检验固定策略，不承担“从许多策略中挑最大值”的选择费用；搜索越久，榜首越像证据的
  错觉越强。
- **有效路径**：把所有已知配置折成共同四块表现矩阵，对每个符号翻转同时取全家族最大统计量。全局最优
  会选 long-only，但校正 p=0.25；V9 在 60 条路径中均值排名 19、最差块排名 12。按历史块选下一块的
  三次测试也不稳定，因此停止继续挖 2023/24，让 V10/V11 只靠新鲜前向。
- **通用规则**：开发数据是一种会被选择过程消耗的资源。每新增一个参数、gate、方向或退出组合就登记到
  同一搜索账本；当已知家族校正失败且选择历史不完整时，正确动作是冻结候选并换新鲜数据，不是换一种
  搜索算法继续试。

  repository holdout 未经 owner 批准不得读取。
