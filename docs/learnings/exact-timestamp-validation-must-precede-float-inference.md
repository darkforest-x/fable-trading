# 精确时间戳检查必须先于浮点推断

- **问题**：CSV中的小数毫秒先经 pandas 浮点推断再转整数，可能被截断或因浮点精度直接抹掉，之后分钟对齐检查仍会通过。
- **死胡同**：在 astype(int64) 前加 Decimal(str(value)) 仍不够，因为默认 read_csv 已经可能把1735775880000.00001变成整数值的浮点数。
- **有效路径**：读取 ts 时保留原字符串，再用 Decimal 拒绝非有限、非整数及超 int64 范围的 epoch；通过之后才构造整数数组。回归覆盖0.5毫秒和低于浮点分辨率的小数部分。
- **通用规则**：严格验证原始标识或时间值时，不要先经过会损失信息的类型推断。
- **牵连**：yoyo/data/ma_profit_two_minute_sources.py。原始行情和运行中的矿工未改；该边界只在备用派生工具中修复。
