# 累计扫描图必须保持采集顺序，不能把月份和累计值一起反转

- **问题**：逐月扫描按“最新月到最旧月”推进，`global_novel_after_month` 也是沿这个顺序累计。总览绘图又把整行倒序，月份虽然变成自然时间顺序，累计值却从 5,053 回落到 113，形成与“累计扫描”语义相反的下降曲线；底层计数和审核队列没有错误。
- **危险捷径**：只把标题改成“逆累计”、把 Y 轴再反转，或在报告里不提。这会让一张本可直接表达停止过程的图继续依赖特殊解释，也可能掩盖停止边界是否确实首次越过目标。
- **有效路径**：把轴定义固定为实际采集顺序（最新月→最旧月），让每个点保留生成时的累计值，明确首点 113、末点 5,053，前一完整月边界 4,969。已有正式结果不事后覆盖，另产出来源哈希绑定的 corrected 图和 repair receipt。
- **通用规则**：累计量必须与它的采集顺序成对保存和绘制。排序展示维度时，不能原样携带另一个顺序下计算的累计列；若要改成自然时间轴，必须按新顺序重新计算累计值并重新定义问题。
- **牵连**：长跑扫描进度图、停止规则审计、按批次累积的数据采集；不影响单条检测、语义门、标签、训练或生产状态。
