# 匹配对照必须共享同一批已了结样本

- **问题**：事件组和同币、同日、同波动桶随机对照都存在尚未走满期限的样本。若分别过滤各自的已了结行再比较均值，两边实际使用的 `event_id` 集合不同，差值失去“匹配”含义。
- **死胡同**：直接计算“全部已了结事件均值－全部已了结随机对照均值”。这看似都排除了 open，但不同退出速度会改变两边分母，尤其在最近两天这种大量右删失样本中会产生选择偏差。
- **有效路径**：先按 `event_id` 联结事件与对应随机入场，只保留两侧都 `status=closed` 且净收益存在的配对，再报告两侧均值和逐对差值均值；全部事件均值只能作为单组描述，不能冒充匹配超额。
- **通用规则**：任何 matched-control 报告的第一项校验都应是两侧分母的主键集合完全相同；有删失时先做 inner pair，再计算差值。
- **牵连**：`scripts/backtest_owner_short_gold_center_recent.py`、最近窗口的 partial outcome、同币×同UTC日×ATR桶随机对照、TG与HTML报告口径。
