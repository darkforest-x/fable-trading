# 成交核算一致不等于忠实实现原始策略

- **问题**：2026-09-20，首4小时区间策略的4581笔成交通过既定close-only规则的独立核算后，仍不能回答Owner要求的“整个实体在区间外”是否正确实现。代码只检查close，不检查open。BTC485/2335、ETH543/2246笔原交易，在各自excursion开始至signal之前都没有任何完整实体越界bar。
- **死胡同**：用既定PROJECT_PLAN和同一解释下的测试证明原始需求正确；或者以扣费后亏损解释所有问题。两者最多证明实现自洽和当前版本结果，不能消除需求转译偏差。此前视频字幕被解释为close-based，不能因此把用户明确写出的whole-body约束视为已获授权取消。
- **有效路径**：先把用户原句转换成布尔谓词：向上完整实体越界为min(open, close)>H，向下为max(open, close)<L。构造区间[99,101]，open=100、close=102上穿，再open=102、close=100回归；当前代码产生空单，而整个过程没有完整实体在外，严格突破前提应拒绝。再只读原账本与冻结OHLC统计上述偏差，避免把删除旧交易当成重跑策略。
