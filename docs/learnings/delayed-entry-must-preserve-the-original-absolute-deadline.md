# 改入场时点不能悄悄延长原请求的持仓截止

- **问题**：比较立即入场与等待确认时，旧引擎默认从实际入场开始计 72 小时。
- **死胡同**：单纯后移 `decision_time` 会把截止一起后移，实验不再只改变入场。以 `end_exclusive` 截断会记为数据截尾，而不是策略到时平仓；用小数小时又有纳秒舍入风险。
- **有效路径**：冻结原 E+72h，按精确整数分钟 `4320 - delay_minutes` 调用现有 `max_minutes`，恢复原请求时点并保留实际入场时点；用合成路径检验真正的 time_exit。
- **通用规则**：延迟处理前先分清观察窗口、请求有效期、策略平仓截止和源数据可用截止，分别保存并验证。
- **牵连**：V39 `replay_delayed`、原 L3 `simulate_events`，不改成本、初始止损或退出规则。
