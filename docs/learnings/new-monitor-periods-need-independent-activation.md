# 新增监听周期需要独立的首次启用时间

- **问题**：为已运行的 1H/4H 通知服务加入 15m 后，首次抓到的最近历史 K 线可能仍在 30 分钟新鲜度内，却早于该周期启用时间。
- **死胡同**：只把周期加入扫描列表、复用原 TG/Bark 启用时间，会把近期历史当新信号；重置整个信号协议又会改变旧周期事件身份及回执语义。这是设计审查中排除的路径，未上线试发。
- **有效路径**：周期配置集中定义。新周期用校准后的交易所时间持久化独立 cutover；入队与两个通知 worker 都检查。缺少 cutover 时新周期禁止发送，旧 1H/4H 继续使用原渠道 cutover，重启不重置任何首次时间。
- **通用规则**：扩展监听范围时，先区分“数据新鲜”与“订阅后产生”。新鲜度、订阅生效时间、通道启用时间、事件唯一性是分别需要验证的条件。
- **牵连**：`yoyo/monitor/{__init__,service,store,telegram,bark,acceptance}.py`；15m 的 TradingView interval=15；前端时间轴必须显示真实分钟，不能硬写 `:00`。阈值、30 分钟新鲜度和既有协议均不变。
