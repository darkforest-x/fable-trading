# 可用时间截断必须早于价格与连续性校验

- **问题**：多周期观察器必须保证某一 `as_of` 的结果只取决于当时已经闭合的 K 线。未来尾部不仅可能涨跌，也可能缺值、未确认或包含非法数值。
- **死胡同**：先验证整张行情表，再用 `as_of` 截断，看似只是在提前做数据质量检查，却让未来的 NaN、负价格或未确认行使一个原本有效的过去快照报错。未来信息通过“程序能否成功返回”渗入了结果；只测试未来价格乘十，发现不了这个问题。本轮未采用这条路径，也没有声称它经过实盘验证。
- **有效路径**：先明确索引是 UTC 开盘时间，用 `open_at + interval <= as_of` 选择可用前缀；随后只对该前缀验证 confirmation、时间连续性和 OHLCV。已闭合前缀中的坏行仍然拒绝，不填补、不排序掩盖缺口。单测把未来价格改成 NaN、负数，把未来成交量改成无穷大，并撤销未来 confirmation，验证历史返回值逐项一致。
- **通用规则**：因果性不仅约束计算窗口，也约束校验、异常处理和状态机。修改未来数据后，过去结果的数值、状态和成功/失败都应保持一致；时间索引和列名等用于决定可用性的基础契约必须先成立。
- **牵连**：`yoyo/data/rotation_features.py` 的 `closed_prefix`，`yoyo/layers/l1_detection/rotation_setups.py` 的冻结突破状态，以及 `tests/test_rotation_logic.py`。这些测试仅用合成数据，不读取真实行情或 holdout；启发式观察结果不等于验证过的交易信号。
