# Verify the loaded chart and bind desktop links to a concrete layout

- **Problem**: On 2026-09-08 spike opened Mac TradingView, but the loaded chart reverted to USELESSUSDT.P / 30m instead of the requested card. A target symbol in the early tab title had previously been mistaken for successful navigation.
- **Dead ends**: Repeating the generic `/chart/?symbol=...&interval=...` link did not prevent saved-layout restoration from replacing the target. The stuck Automation toggle was a separate observation, not proof of this redirect's cause. A native helper was drafted but abandoned before installation once the existing service bridge operated after the owner's Accessibility grant. Reading the active chart's `AXURL` through System Events also failed with -10000 for this CFURL-valued attribute, although the separate CUA accessibility reader could display it.
- **Effective path**: Read the actual loaded chart via accessibility, preserve its verified regional host and concrete saved-layout path, and append the backend's validated symbol/interval query. Save the owner's layout preference outside source code. Invoke the existing clipboard-menu bridge through the real frontend and running LaunchAgent; verify the chart-body symbol, selected interval and chart accessibility label after layout restoration. TRUTH-USDT 15m and 1H passed through whole-card click and Enter respectively; BICO-USDT 4H passed through Space. The independent POET page preview left the native TradingView destination unchanged. The original IMACD layout remained present.
- **General rule**: Separate application activation, request dispatch, loading titles, and final chart content. A successful intermediate state does not establish the requested destination. Diagnose permissions with focused operation evidence; a settings toggle is not a substitute for an end-to-end service-context check.
- **Scope**: `yoyo/monitor/tradingview.applescript`, `tests/monitor/test_tradingview_layout.py`, the static card controls, and the local `tradingview-layout.txt` preference. The HTTP response intentionally remains `requested`, because automatic post-load chart verification is not implemented. This does not alter scanner signals, YOLO, delivery rules or execution.
