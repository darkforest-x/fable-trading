# 收益表的时间分组必须锚定成交身份，不能只互相对得上

- **问题**：V19预跑独立审计发现，把同一病例的episode、single和matched三张表的fold同时改到另一半年度，原验证器仍通过，尽管真实成交时间和trade.fold没有改变。
- **死胡同**：只核净收益算术、表间相互一致和上游trade哈希，漏掉了episode从trade继承的不可变时间分组。三张表可以一起自洽地错，随后串行检查按假fold分仓，错误会传播到验证规则本身。
- **有效路径**：在V19局部直接核episode→trade固定身份和所有共享不可变字段，候选不得删除基准已有身份；新增联合篡改三张表仍必须失败的反例。旧V16验证器和策略行为不修改；仅增强本轮证据检验。
- **通用规则**：每个派生账本的时间组、方向、决策时刻、信号身份都要锚到独立原始事件，不能只靠下游表彼此一致。用联动篡改反例测试，而不止单字段反例。
- **牵连**：`scripts/verify_hourly_impulse_failed_reduce_v19.py`、`tests/test_verify_hourly_impulse_failed_reduce_v19.py`。发现与修复发生在V19真实回放之前，无行情或收益参数改动；这不说明历史结果已经被发现算错。
