# 手动订单的交互必须让用户看清设置、确认和保护回执

- **问题**：旧弹窗字段和说明挤在一起，账户范围不明显，移动端难以找到操作，用户无法快速判断是在预览还是已提交。
- **死胡同**：只换颜色或把按钮挪到卡片末尾，不能修复确认后的可编辑错觉、报价过期和未知提交回执的不同语义。
- **有效路径**：账户条常驻入口，弹窗按设置/确认/成交与保护组织；风险金额与保证金突出，3R/5R直接切换；固定底部动作。修改即废旧预览，过期移除确认；已提交隐藏设置，丢回执只查原ID，保护核验后才显示“已挂好”。
- **通用规则**：先把资金动作映射为可观察状态，再布局；按钮名称、可编辑范围和状态提示必须由同一状态机驱动，不能仅靠视觉禁用。
- **牵连**：`manual-live.js/css`、`yolo-detect.js`；模拟账户桌面/390px浅深色验收，覆盖期限、输入、失联回执、关闭恢复焦点和历史回执。真实账户只预览，模拟保护通过不代表真实交易所成交验收。
