# 可移除数据盘必须在目录发现前校验，否则离线会被误记成删除

- **问题**：外盘数据集虽然已有明确登记，但训练图像的发现逻辑先调用 `is_dir()`。硬盘断开时，目录在后续权限与身份检查之前就被跳过，新索引可能悄悄丢失整套数据。
- **死胡同**：只在遍历到每个外盘数据集后检查挂载和 UUID，不能保护根本没被发现的数据集。软链接本身存在也不代表 `is_dir()` 会返回真。
- **有效路径**：2026-10-16，为登记的所有外盘入口先核对路径、挂载身份与实际读取，再开始目录发现及替换索引。用真正变为悬空链接的图像目录测试，确认失败时原 SQLite 索引逐字节保留。
- **通用规则**：对于可移除介质，资产存在与当前可访问是不同状态。发现阶段之前校验已知资产，离线应明确失败，不能把暂不可读变成资产删除。NTFS 的整秒时间戳不等于内容证明。本任务 Owner 随后明确取消哈希检验，登记选择 metadata 方式，仅核对大小、时间和实际读取；不能声称逐字节一致。
- **牵连**：`yoyo/data/dataset_catalog.py`、`yoyo/data/external_storage.py`、`tests/test_external_dataset_storage.py`；目录 ID 与受管视图路径保持不变。
- **Git 入口也要复查**：目录内容原本被忽略，不代表目录改为软链接后仍被忽略。`source_scans` 切换后实际出现在未跟踪列表；为本机外盘链接加入精确的 `.git/info/exclude`，再用 `git status --short -uall` 和 `git add --dry-run -A` 确认不会误提交。
