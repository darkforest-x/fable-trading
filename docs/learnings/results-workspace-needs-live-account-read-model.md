# 检测结果需要有边界的实盘读模型

- **问题**：只返回总权益的摘要让检测结果与持仓脱节；用户必须离开图表才能判断是否有仓位及订单是否成交。
- **死胡同**：继续压缩到一个账户标签会丢失任务所需信息；直接每五秒拉完整账户历史则引入无关开销。把任意 worker 异常都叫旧单对账还会误导处理方向。
- **有效路径**：提供独立 workspace 投影，返回全部当前持仓与进行中意图、最近五笔记录，以及全量本地已确认交易统计；不携带交易所历史或原始账本。已实现收益只累加完整 USDT 成交与费用回执，无法归属的平仓单独计数。区分订单对账失败与账户核验异常，但不放宽确认及执行门。
- **通用规则**：先列出当前任务必须看到的事实，再缩减传输；摘要不是越小越好。连接、核验、订单成交和收益归属分别表达。
- **牵连**：`manual_dashboard.py`、`manual_readiness.py`、`manual-account.js`；只读接口，账户隔离与逐笔确认不变。
