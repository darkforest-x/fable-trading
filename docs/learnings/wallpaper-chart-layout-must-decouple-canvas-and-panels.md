# Wallpaper chart controls must not own the canvas dimensions

- **Problem**: The patrol chart was constrained by its sidebar and document flow. Turning it into a full-screen chart also exposed inherited mobile rules: a duplicate symbol selector expanded the header, coin names wrapped at 48 percent width, and the compact period selector displayed 5m while the chart showed 1H.
- **Dead end**: Enlarging the chart container alone cannot make it a stable background. Existing responsive selectors and a separately rendered period control still affect the visible result; desktop screenshots did not reveal these conflicts.
- **Effective path**: Scope wallpaper mode to the active results tab, fix the canvas to the viewport, and position independent glass controls above it. Animate only panel transforms and opacity. Reuse the existing pointer-driven sheet controller. Drive both period controls from the same state, remove the duplicate selector, and explicitly override inherited symbol text constraints. Keep the history and model tabs in normal document flow.
- **General rule**: Separate the plotting surface from panel layout before styling. Validate the actual mobile controls and inherited CSS at 390 and 320 pixels, not only the desktop canvas. Verify gesture movement before release as well as the final open/closed state.
- **Affected files**: `yoyo/monitor/static/yolo-wallpaper.css`, `yolo-detect.js`, `yolo-preview-sheet.js`, `tests/monitor/frontend_yolo_detect.test.cjs`. Stitch source: project `8978791379095391159`, screen `d70c4b10a20f478bae161de14e5e5c49`. Browser evidence: 390 × 844 sheet measured 633px; 45px and 120px touch movement produced exactly matching transforms; a short pull rebounded and a long pull closed.
