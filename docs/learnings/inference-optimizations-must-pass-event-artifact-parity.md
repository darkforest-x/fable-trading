# 推理加速必须先过事件产物 parity

- **问题**：同一 YOLO 权重、图片、conf 和 IoU 下，Mac FP16 看似是常规加速，却把冻结 ETH 48 小时结果从 411 raw / 18 events 改成 385 raw / 15 events；阈值附近的数值变化已经改变研究结论。
- **死胡同**：只比较耗时、平均置信度或少量截图不够；“模型没换”也不能推出检测结果没换。batch=64 还会把统一内存推到严重换页，CPU 全模型推理则更慢。
- **有效路径**：固定同一快照与全部扫描参数，对候选运行时改动生成完整 `raw_detections.jsonl` 和 `events.jsonl`，逐字节比较。FP16 因 parity 失败被拒绝；CPU-NMS 因两个文件 SHA 都相同才允许采用。
- **通用规则**：影响精度、设备、batch 或后处理的任何“纯性能优化”，先在有真实触发的冻结切片比较最终事件 artifact；只要框、置信度或事件数有一处漂移，就按模型变量处理，不能混进正式对照。
- **牵连**：`torch` / Ultralytics 数值路径、MPS FP32/FP16、NMS 设备、`conf=0.25` 阈值、事件去重与 holdout 纪律。
