# 多等一次确认不等于识别了趋势失效

- **问题**：V17 全仓快退截断恢复趋势，V18 将同一分支延迟到相邻第二根原生5m反色、重新核慢15m和真实开盘后才全平。
- **死胡同**：根据救回4个赢家就认定确认过滤有效，继续盲扫3根、4根。原152条全平路径中138条依然确认全平，其增量合计−231.1857事件bp；3条等待中硬止损又损失48.8652事件bp。
- **有效路径**：完整251笔的互斥归因：196亏到亏合计增量−348.0493，4亏到盈+425.6490，51旧赢家不变，总+77.5997事件bp、均+0.3092bp，区间跨零。等待只是少数恢复与额外风险的交换，尚未提供盈利优势。
- **通用规则**：将等待时长与退出仓位拆开。先核实恢复、继续亏、等待止损的全分母贡献，不用“后来变赢家”作入口特征，不用旧退出价拼新方案收益。
- **牵连**：V18 `confirmed_case_mechanics.csv`、`PATH_QUERIES.py` 与 `path_diagnostics.json`；下一个待验证假说只能独立改变确认后全平为半仓，保持确认时钟、原始止损、慢周期和成本不动，不能宣称已测有效。
