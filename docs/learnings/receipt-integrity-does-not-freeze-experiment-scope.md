# 收据哈希完整不等于实验范围与分期正确

- **问题**：聚合器能完整校验全部收据，却仍可能把一个 smoke 子集当正式实验，或按配置里另一个 split 给固定分期的随机对照重新分组。
- **死胡同**：只验证“manifest、identity、收据、文件彼此一致”，只能防文件漂移；一组共同写错的声明照样自洽。
- **有效路径**：报告入口另验 full-universe、预先确定的币数和固定 split；用修改完整收据链的反例测试证明仍被拒绝。历史运行源码从 started.json 的真实 Git 提交逐文件核哈希，而不是要求未来工作区永不演进。
- **通用规则**：来源完整性、实验契约、覆盖范围是三个独立门；校验前两者不能用文件数量或哈希替代语义。
- **牵连**：V12.6 H1 recheck 的 runner、report 与 audit；这些守门修复没有改变本次已冻结的交易输入、条件和退出。原 run_v2 保留自己的启动源码与身份，不冒充新源码重跑。
