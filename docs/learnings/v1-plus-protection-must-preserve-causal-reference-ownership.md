# 过滤新参考不能撤销已经发生的反向参考结束

- **问题**：SPIKE V1+ 在同一根原始反向强劲爆发上增加过热、风险宽度、冷却和回踩确认时，容易把“新参考不准开”错误地实现成“旧参考继续持有”。这会让入场门控反向改变已经确认的旧参考生命周期。
- **死胡同**：先把过滤判断包在整段反向处理之外。这样过热或风险过宽时，代码既不新建参考，也没有结束原方向；随后同一蓄势窗口还可能在较晚的一根重新尝试，混淆原始确认时间和批准入场时间。
- **有效路径**：把严格 V1 原始确认、旧参考结束、创建新参考拆成顺序明确的三个动作。原始反向确认先以其收盘结束旧参考；然后每个新参考门控独立决定拒绝、直接冻结或进入回踩等待。被拒绝的原始事件消费其 pending 窗口；回踩模式冻结原始边缘、箱体和 ATR，并要求后续影线触及及更后根收盘重夺。
- **通用规则**：一个过滤器若只声称限制新仓、风险参考或显示，就不得改写已经由更原始事件确认的旧仓退出。先画出事件的因果所有权，再把每个门控放到它拥有的那一步。
- **牵连**：`yoyo/evaluation/pine/spike_burst_v1_plus.pine` 的 `rawBurst`、`reverseExit`、`pendingSide` 和 `pullback*` 状态；`tests/test_spike_burst_v1_plus.py`；本规则不授权收益、实盘或自动下单结论。
