# 共用防抖计时器会取消另一项尚未完成的自动保存

- **问题**：2026-10-14 审查 RektProof 页面时，在章节笔记输入后立即切到频道检索并输入关键词，返回章节后刚输入的笔记为空。正常停留时保存可用，快速切换才暴露问题。
- **死胡同**：只看输入框仍显示文字、点击后出现反馈，无法证明内容已经持久化；逐项慢速点击也覆盖不到两个功能之间的竞态。
- **有效路径**：通过实际 UI 连续执行“输入笔记 → 切到频道原话 → 输入搜索词 → 返回阅读”复现；核对 `rektproof.js`，笔记的 400ms 保存与搜索的 250ms 防抖都先清除同一个 `noteTimer`，搜索因此取消了保存。本次只定位并审查，尚未修改实现。
- **通用规则**：自动保存与检索、计算等功能各用独立计时器；导航和导出前显式提交待保存编辑。验收要包含快速跨视图操作，并检查返回后或重新加载后的实际内容。
- **牵连**：`yoyo/monitor/static/rektproof.js` 的 `bind()`；同一个计时器也用于周计划计算。审查临时记录已通过导入恢复清理，不把测试数据留在个人记录中。
