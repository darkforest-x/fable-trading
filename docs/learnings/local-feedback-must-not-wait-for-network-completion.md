# 点击反馈和操作结果要分开呈现

- **问题**：1R 快捷反算到网络成功才震动，再弹出必须关闭的成功窗；等待时像没点中，成功后又打断填单。
- **死胡同**：仅增加成功震动无法解释等待阶段；把所有通知统一成模态窗，会把普通输入反馈和交易结果混为一谈。
- **有效路径**：点击即轻触反馈，操作自己的按钮显示加载并防重复，结果返回后验证原账户、页面与表单身份再填入。1R 使用输入框高亮；连接与账户切换使用不抢焦点的短提示；交易异常与未确认结果保留明确弹窗。下滑关闭只从把手起手，滑块与列表滚动不复用关闭手势。
- **通用规则**：把“已响应点击”“正在等待”“业务结果”拆开。反馈可以立即出现，交易事实必须等待服务端。迟到结果不能覆盖已变化的表单。
- **牵连**：`mobile/src/App.tsx`、`Dialog.tsx`、`Notification.tsx`、`ClosePosition.tsx`。触感遵循用户开关；浏览器验收不能代替真实 iPhone 的触觉确认。
