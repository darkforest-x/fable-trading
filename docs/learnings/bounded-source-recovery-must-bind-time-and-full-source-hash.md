# 恢复短行情片段仍要绑定完整源身份和事件时间

- **问题**：v6 三窗口补图需要一些已经从本机清理的 1m CSV；3060 仍保存原始 gzip。直接重新下载全市场既浪费空间，也可能换成不同的数据版本。
- **死胡同**：只知道币名或只检查切片哈希，不能证明它来自当时的行情。旧账本的行索引属于导入后的局部区间，不能直接当完整压缩源的绝对行号。串行逐行解析全部字段也使完整源验证耗时过长。
- **有效路径**：将原 ledger 的 CSV SHA 与原 gzip manifest 关联；在归档机器核对 gzip 哈希，并对完整解压 CSV 流式哈希。按核心时间戳找唯一位置，只输出必要的均线预热、左侧上下文、原核心和已闭合确认窗，保留原始 CSV 字节。按独立源并行处理，随后核对复制后的切片 SHA；重绘还必须复现已有图片及标签哈希。
- **通用规则**：完整源身份、事件时间、片段字节和重绘像素是四项独立检查。只恢复所需片段不等于可以省略原始源校验，也不能把时间局部索引误当全量索引。
- **牵连**：`yoyo/data/ma_morphology_prefix_recovery.py`、`tests/data/test_ma_morphology_prefix_recovery.py`、`yoyo/datasets/ma_morphology_threeview.py`；保留失败或中止回执，恢复本身不改变标签资格。
