# 独立连接不代表匿名数据源的注销状态彼此隔离

- **问题**：BaoStock 四进程抓取固定 A 股历史池时，每只股票各自登录/注销，前48只中11只报 `10001001` 未登录，虽然每个进程刚刚登录成功。
- **死胡同**：把“客户端全局变量已经由进程隔离”当成“服务端会话也隔离”。多个进程仍使用同一匿名身份；逐股票退出时发出的协议 logout 可以使其他连接的后续分页或请求失效。
- **有效路径**：双进程实测先A登录、再B登录，A/B分别完整读取2015～2025的2674条两页记录均成功；只关闭B的socket后A仍成功。独立反证又显示：A读5条成功→B发送logout并成功→A再读同5条立刻返回10001001。于是每个worker只登录一次、整个批次复用连接，结束仅关闭自己的socket，不逐股票发送全局匿名注销。
- **通用规则**：多进程只隔离本地状态。并行外部客户端必须分别验证登录、请求与注销是否跨连接影响；不能仅凭库没有线程安全保证就认为换成进程已经完整解决问题。
- **牵连**：`yoyo/evaluation/ashare_data.py` 的 `_worker_client()`、`_close_worker_socket()`、`_fetch_worker()`；`tests/test_ashare_data.py`。数据源、历史股票池、日期范围和参数均未改变，旧错误日志保留，失败代码不补换。
