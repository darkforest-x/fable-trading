# 同端点多档 TP 的元数据顺序不等于余仓保护顺序

- **问题**：一分钟单调路径一次穿过多档 TP，Nautilus 的撮合队列可先回调 TP2，再回调 TP1。两档按各自价格平仓，但已平 TP2 的保本标记可能为空，独立价格路径审计原本认为应该记在同一分钟。
- **死胡同**：强求所有已平 TP 腿的保本元数据顺序完全相同，会把没有经济影响的队列差异当作错误。直接忽略全部保本时间差异则会掩盖真正的提前保护或延后保护。
- **有效路径**：仅允许 TP 平仓腿在退出当分钟的“未标记/同分钟标记”差异。退出价格、分钟、原因必须完全一致；余仓止损的保护时间和价格仍严格逐笔一致。未来或更早的保护时间不豁免，费用账本独立复核。
- **通用规则**：先区分经济结果与记录元数据。任何审计豁免都应局限于一个可证明不影响结果的事件，并有反例测试证明它不会放过真实成交差异。
- **牵连**：`monday_fib_confirmation.check_oracle`；真实随机对照 `random-60m-2026-01-12--1-1`，2026-01-19 单分钟穿越三档。新增原生成交检查点保留未经审计输出，异常不再丢失诊断证据。
