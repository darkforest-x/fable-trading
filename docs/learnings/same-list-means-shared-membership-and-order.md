# “同一个列表”必须共用成员、排序和偏好规则

- **问题**：Owner 要求模拟盘监控列表与 1.618 页面一致，第一次实现却把 507 个全市场合约按距离排序；原页面实际默认只显示已触价合约，按触价发生时间倒序。
- **死胡同**：共用 `/api/monday-fib` 数据源不等于共用列表语义。模拟成交记录确实不能定义监控范围，但这也不能推出默认展示整个合约池。
- **有效路径**：先对照原页面的 `selectRows`、历史/实时触价时间选择、每周隐藏和收藏状态，再提取为两页共用的纯模型。保留历史触价的 candle 时间，避免补录时间把旧事件推到顶部。相同标签页切回页面时重新读取偏好，弥补 storage 事件不通知当前标签页的限制。
- **通用规则**：用户要求“和已有页面一样”时，优先复用其产品规则；相同输入下逐项比对列表成员、顺序、筛选及删除撤销，而不是仅核对 API 地址或列表数量。
- **牵连**：`monday-list-model.js`、`monday-fib.js`、`reclaim-watchlist.js`、`startup-hints.js`（预热也须尊重未触价的固定币种）；修正前次 [监控范围笔记](monitor-universe-is-not-an-execution-ledger.md) 中对默认列表的推断，历史记录保留。
