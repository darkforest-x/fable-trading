# 压缩存储可以保留已冻结读取器的字节契约

- **问题**：长周期历史的并行扫描正在运行，扩展 1m 数据又需要节省磁盘；原读取器只支持普通 CSV，直接改成 gzip 读取会改变正在使用的规则依赖 SHA。
- **死胡同**：给已有扫描静默换读取器，或把压缩文件当普通 CSV 交给旧程序，会分别破坏代码溯源与输入解析。仅声称压缩“无损”也不足以证明当前机器的路径可用。
- **有效路径**：下载机器保留经官方校验和验证的归档，汇总 CSV 压成确定性 gzip，并在删除本次临时 CSV 前实际解压核对 SHA。Mac 接收后生成 APFS 透明压缩的普通 CSV，仍用原读取器。当前机器用真实 5m 数据的 20,000 行探针验证：逻辑字节 1,522,250，物理占用 507,904；压缩前后 SHA 相同，原读取器输出 DataFrame 相等。
- **通用规则**：先区分存储表示变化与逻辑输入字节变化。使用文件系统透明压缩时必须在目标机器实测物理占用、全文件 SHA 和真实读取器输出；不能将一个探针比例保证为整个语料的压缩率。
- **牵连**：`experiments/active/exp-ma-profit3r-20260922-v1/transparent_compression_probe.json`；`yoyo/data/ma_profit_archive_extension.py`；`/usr/bin/ditto --hfsCompression`。探针只是存储验证，不参与训练或市场统计。
