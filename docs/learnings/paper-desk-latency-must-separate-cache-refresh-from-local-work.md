# 开单接口耗时要区分共享缓存刷新与本地工作

- **问题**：2026-10-16 Owner 询问模拟开单接口性能。对运行中的本机服务做少量顺序只读采样，总览 6 次耗时为 10.31、7.79、1589.01、2522.52、2365.59、2516.13 ms；历史 5 次为 8.89–46.87 ms。总览约 65 KB，当前证据首先指向外部行情等待，但尚未逐段计时，不能把全部慢耗时都归给网络。
- **死胡同**：总览后紧接着请求行情，行情样本只有 1.28–2.85 ms；这组请求共享缓存，前面的总览可能已经完成刷新，不能据此认为行情始终很快，也不能用这 6 个样本报告稳定的 P95 或性能提升倍数。没有对真实账户发起下单或报价落库测试。
- **有效路径**：同时核对请求顺序、缓存和锁。PublicQuotes 与 PublicRisk 在共享锁内同步请求 OKX；前者每次抓取新建 HTTPX Client，后者使用顶层 httpx.get；风险档位冷缓存还逐币串行请求。前端成交回执后继续等待全量总览才释放 busy。建议优先复用长期连接、由独立刷新任务更新不可变行情快照并缩短持锁时间，再将全量刷新移出成交反馈等待链。本轮只诊断，未实施这些优化，也未测下单端到端延迟。
- **通用规则**：先按缓存命中、缓存刷新、首次币种分别测量，并拆出外部请求、锁等待、数据库与序列化耗时。优化后在隔离账户中验证并发和重复请求，保留原始行情时间戳、15 秒报价有效期、风险缺失拒绝开仓和幂等回执语义。
- **牵连**：`yoyo/research_workspace/paper_desk_api.py`、`paper_desk_risk.py`、`paper_desk.py`、`paper_desk_analytics.py`、`yoyo/monitor/static/paper-desk.js`；HTTPX 连接复用依据为 https://www.python-httpx.org/advanced/clients/ 。
