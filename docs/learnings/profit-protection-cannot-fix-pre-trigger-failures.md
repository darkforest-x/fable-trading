# 盈利保护不能修复触发前已经失败的交易

- **问题**：K1→K2 系统加入“收盘达到 1.5R 后，下一根移到 fee-cover 止损”，但冻结验证的 13 个止损没有一笔被保护规则改变。
- **死胡同**：看到历史上存在盈利后回吐，就直接把盈利保护当成通用修复。这样只验证了规则听起来合理，没有检查亏损路径是否先到过触发点，也没有处理触发 K 线内的先后顺序。
- **有效路径**：先按 MFE 将所有止损分层，并规定保护只能在完整收盘确认后、从下一根生效。验证中 9/13 止损的 MFE<0.5R，另 4/13 介于 0.5R 与 1.5R，零笔达到 1.5R；所以主病因是入场后无延续，不是盈利保护缺失。
- **通用规则**：测试任何移动止损前，先报告“失败单到达触发点的比例”；比例接近零时，优先修入场而不是继续优化触发点。触发当根不得事后享受新止损。
- **牵连**：`scripts/backtest_btcusdtp_1h_owner_causal_v2_preholdout.py`、`results/validation_failure_reasons.csv`、1.5R 收盘触发、0.2% fee-cover。
