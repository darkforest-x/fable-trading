# 标签目标不能借用可变执行参数

## 现象

Pine 启动标签的目标固定为 `+1.5% first-touch`，实现却把
`SignalParameters.break_even_trigger_percent` 传给标签器。当前两者同为 1.5，所有结果都正确，
但未来单独修改 break-even 策略时，历史标签会在没有显式版本变更的情况下被重新定义。

## 根因

数值相同不等于语义相同。标签目标描述研究问题，break-even trigger 描述持仓管理；二者应独立版本化。
复用字段把两个本应分离的契约隐藏地耦合起来，默认值一致时普通回归测试也不容易发现。

## 修复

为标签管线定义显式 `LABEL_TARGET_PERCENT = 1.5`，调用标签器时只使用该常量；执行层的
`break_even_trigger_percent` 保持冻结且不受影响。测试同时钉住标签目标常量。

## 通用规则

当同一个数字同时出现在标签、特征、执行或风控层时，不要因为当前值相同就共享配置键。先判断语义所有权，
分别命名和版本化；若业务要求它们同步，再写显式一致性断言，而不是隐式别名。
