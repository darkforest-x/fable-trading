# 风险预算够不等于保证金够，拒绝必须同时展示两笔账

- **问题**：Owner连续看到BEAT市价张数上限和A保证金不足，以为所有币都无法开仓；原文案只说“不足”，没有说明哪一个额度、差多少及是否用了最大杠杆。
- **死胡同**：只解释交易所上限不能解释另一笔保证金拒绝；把3%当成占用3%本金，或看总权益替代可用权益，都会误判。也不能为了使按钮成功就擅自降风险、改止损或接管Owner原仓位。
- **有效路径**：真实只读复核A：权益159.6255U、可用90.4515U、已有初始保证金67.7969U；5m低点0.11247、买价0.11302，870张×10A，最大10倍，名义983.274U、所需98.3274U，差7.8759U。BEAT同一时段需119.1272U而可用90.1906U。不是双重扣减或漏用最大杠杆；CT随后由Owner截图证明预览成功。新增结构化拒绝，保留原闸门和异常文本，显示所需、可用、缺口及最高杠杆。
- **通用规则**：先用同次余额、价格、止损、合约面值和匹配档位复算“风险→张数→名义金额→保证金”，再判断实现或约束有问题。总权益与可用资金分开，历史截图与当前复查时间分开。
