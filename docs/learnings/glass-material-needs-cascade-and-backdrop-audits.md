# 透明玻璃要同时核对材质覆盖和背景采样边界

- **问题**：共享变量已有透明色，实际卡片、菜单和设置面板仍像白卡。用户用 iPhone 的透明 Liquid Glass 参考指出差距。
- **死胡同**：只加大 blur、增加阴影，或只检查全局 token。局部 0.86–0.96 alpha 覆盖、嵌套白底与单独的夜间规则会盖住底层内容；祖先 backdrop-filter 还可能让弹出菜单采不到真正的图表背景。
- **有效路径**：先记录真实页面，再逐组件检查 computed background/filter 及祖先。收敛到共享 tint、反射渐变、双色边缘和浅内层底色；独立浮层直接采样背景，承载弹层的导航父级不加滤镜，胶囊背板放在不拦截事件的兄弟伪元素。最终以有红绿 K 线穿过的浅色/深色手机截图验收，而不是用 CSS 属性存在作为审美验收。
- **通用规则**：材质迁移先找局部覆盖与合成边界。白色背景上的透明度数字本身不能证明透光效果；还要看有内容的背景、文字对比、开合层级，以及减少透明度时是否完整退回实色。
- **牵连**：`design-tokens.css`、`glass-system.css`、Cloud Signals、1.618、导航、策略小册与 `night-mode.css`；Stitch `98a9bea6408d4a3fbe26304bfbce2128`。网页 CSS 的透色和高光不应宣称等同原生系统的实时光学折射。
