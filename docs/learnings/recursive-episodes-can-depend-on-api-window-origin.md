# 有限寿命状态机也可能依赖 API 窗口起点

- **问题**：初版突破观察器从每次下载数据的第一根开始重放状态机。Review 使用持续上涨、持续放量的合成序列发现：同一个闭合时点，只把尾窗从 100 根改成 99 根，状态就可能在 breakout/watch 之间切换；每次滚动下载 100 根时，突破时间还能随窗口起点不断向后移动。
- **死胡同**：把单个 episode 限制为 12 根，并不能消除其状态依赖。过期后是否接受下一个 episode，仍由第一个 episode 的相位决定；增加下载根数只把任意起点推得更远，并没有证明结果独立于该起点。
- **有效路径**：先独立计算每根的 raw breakout，再要求新 anchor 的前 12 根没有任何 raw breakout。去簇条件只引用原始布尔事件，不引用递归接受的 episode。当前只考虑最近 12 根内的 anchor，故完整依赖范围可明确算出：20 根平台窗口 + 12 根去簇 + 12 根活跃寿命 + 当前根 = 45 根。覆盖不足显式拒绝；覆盖充足时，45/99/100 等不同尾窗必须返回完全相同的快照。
- **通用规则**：证明状态机因果还不够，也要证明它对历史输入起点的依赖已被定义清楚。滚动 API 使用有限尾窗时，应测试同一时点、不同起点，以及连续滚动多个时点。若没有持久化状态，就必须给出有限且可检查的依赖上界。
- **牵连**：`yoyo/layers/l1_detection/rotation_setups.py`、`tests/test_rotation_logic.py`。回归序列为 `close=100*1.01**i`、`volume=100*1.08**i`、`open=.995*close`、`high=1.002*close`、`low=.994*close`；全部为合成工程测试，不构成市场效果证明。
