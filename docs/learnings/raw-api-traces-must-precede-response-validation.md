# API 原始记录必须在结构化解析之前捕获

- **问题**：视觉工作台只保存结构化结论和安全错误分类，Owner 想在模型设置检查模型实际收到与返回了什么。
- **死胡同**：由识别结果重建一个 JSON 不能叫原始响应；会丢失推理字段、缓存用量、错误正文与非 JSON 返回。把图片 Base64 混入普通历史列表也会使每次刷新加载整批大图；本地保存参考图不等于服务端会话记忆。
- **有效路径**：在 HTTP 边界捕获实际序列化请求和解析前响应正文，独立表保存完整记录、列表只返摘要，识别记录引用 exchange ID。鉴权头不记录，正文回显的当前 Key 脱敏并明确标记。超时保留输入且输出为空；旧记录诚实显示未保存。使用 MockTransport 对实际发出的字节串和包含原字段/空白的返回正文逐项核对，覆盖 HTTP 失败、解析失败、超时和重启。
- **通用规则**：调试原文是独立证据，不是业务结果的另一种排版；必须区分发送内容、收到内容、解析状态和未收到的内容。
- **牵连**：`yoyo/vision_research/zhipu.py`、`store.py`、`server.py`、模型设置原始记录入口；目前仍是独立 Chat Completions 调用，不自动启用云端会话、改变参考图数量或增加重试。
