# 修复失败交易的规则，必须同时统计它会拒绝的赢家

- **问题**：2026-09-19，Owner 问 SPIKE V11.2 应先优化逻辑还是搜索最优参数。延迟突破的亏损案例看起来支持统一缩短窗口。
- **死胡同**：只看失败单，把“等得太久”当统一病因；或用最大浮盈、未来是否止损等事后字段直接生成入场过滤。前者会漏掉被新规则删掉的大赢家，后者使用了交易当时不可知的信息。
- **有效路径**：先核对完整联合账本的 9,281 笔已平仓，按时间段同时统计盈利与亏损。用原有 6 根界限做描述性分组：15m 后段保留子集均值由全体 −0.2921R 变为 −0.1980R；1h 后段却由 −0.2278R 变为 −0.2724R。全期被删掉的 ≥10R 赢家分别有 16、6 笔。因此不能把一个延迟阈值当两个周期的共同修复。
- **通用规则**：失败路径用于提出假设；入场规则只能由当时可见变量实现。每个候选规则都报“避开的亏损、误删的盈利、尾部赢家保留、时间段一致性和匹配对照”。在旧成交账本上删除交易只是子集分析；真正换规则后需重跑串行仓位，因为被释放的仓位可能接到原来跳过的信号。
