# 模拟账本先核对资金归属，再映射展示字段

- **问题**：接入 1.618 双轨模拟盘时，信号和仓位都带 `taken`，而 `shadow_closed` 看起来像影子交易数量。直接按字段名展示，会把通过评分但额度不足的记录算成资金交易，并把全部结束数量误作影子数量。
- **死胡同**：Stitch 视觉稿还生成了接口不存在的 R 指标和方向相反的周一目标文案。字段名称、设计占位数字都不足以证明统计语义；本次在落地前阅读生产者源码发现这些差异，没有把它们接进页面。
- **有效路径**：从 SQLite 写入与结算分支确认：信号 `taken` 只是评分资格；仓位 `taken=1` 且名义本金大于零才影响账户。`equity` 仅含已实现盈亏；`stats.taken_closed/wins/mean_net_bp` 是全历史资金统计，两个最近 100 条数组只负责列表。前端分别呈现资金、影子、共享触价三种范围，60m/5m 独立统计，并对空值、额度不足、手续费和迟到响应做行为测试。
- **通用规则**：接交易监控接口时，先追到生产者的入账与聚合代码，写清对象、分母、时间范围和缺值含义，再套设计。UI 不能由资格字段推断实际资金分配，也不能由分页列表推断全历史表现。
- **牵连**：`yoyo/monitor/monday_reclaim_paper.py`、`static/monday-reclaim-paper.js`、`tests/monitor/frontend_monday_reclaim_paper.test.cjs`；Stitch 画板 `481ac4e5b140422aaa749326a582b43d` 仅提供视觉参考。后端交易规则未改。
