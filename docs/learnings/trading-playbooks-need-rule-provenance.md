# A trading playbook must preserve who defined each rule

- **问题**：Notion 里的个人周一区间规则、RektProof 教学和小册研究清单同时出现，容易把研究细化误当作已确认执行规则。
- **死胡同**：直接合成一套貌似完整的规则会掩盖 0.618 的双向含义、企稳定义和不同止损依据；成功案例也不能填补这些缺口。
- **有效路径**：逐项标出 owner 已写明的规则、作者有出处的说法、整理建议及待验证项。双向 Fib 使用实际价格和分段计算示例；保留未成交、亏损和未知结果。研究清单另标用途。
- **通用规则**：先建立规则来源与确认状态，再把它转成流程；“文档完整”与“收益验证”是两个独立结论。
- **牵连**：`yoyo/monitor/static/trading-playbooks.js`、`rektproof.js`、Notion 第 49–51 条。没有更改交易执行参数或资格。
