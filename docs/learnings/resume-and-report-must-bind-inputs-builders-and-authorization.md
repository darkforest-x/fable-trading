# 断点续跑与报告都必须绑定输入、构建代码和授权

- **问题**：V9保本回放的初版仅用结果文件SHA和builder身份控制续跑；5m/15m源前缀变化仍可能混合旧窗口和新窗口，报告也未再次核对原运行的代码与授权。
- **死胡同**：输出哈希只证明文件未变，不能证明输入、配置、构建器与授权仍匹配；把inputs清单覆盖成最新源，会抹掉旧窗口实际使用的数据身份。将“第1次holdout”写死在报告，更不能证明没有重复评估。
- **有效路径**：每周期读取后先与不可变input receipt比较，再接受完成窗口；每流同时保存输入身份。报告在读取任何逐笔结果前核对run_started、当前冻结代码/config、完整manifest、原版parity与授权。holdout使用单独保留的授权ID和消耗序号，删除输出不能重用同一授权。
- **通用规则**：读数据、恢复计算和生成报告是三道独立入口，三道都要验证身份；禁止将某一入口曾通过验证当作另外两个入口永远安全的证据。
- **牵连**：`spike_v9_cost_be2_study.py`、`spike_v9_cost_be2_report.py`、合成身份回归测试；原失败/加固前运行保留，配置未调参，最终从冻结修订版重跑。
