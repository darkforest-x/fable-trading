# 展示仓位倍数前先核对账本字段的含义

- **问题**：订单卡片把持久化的 `leverage` 标为仓位大小，但它实际控制保证金占用；100× 合约可以只有权益 10× 的敞口。
- **死胡同**：不能直接重命名字段，也不能从当前下单表单的默认倍数推断旧单。旧账本只保存合约杠杆、数量及价格，没有保存最初选择的仓位倍数与定仓权益，无法精确还原最初选择。
- **有效路径**：明确展示当前实际倍数：待成交委托金额除以当前账户权益，持仓使用当前名义金额除以同一权益。权益无效或非正时显示缺失，小于 0.01× 时避免四舍五入为零；轮询更新时同步重算。已平仓记录保留明确标注的合约杠杆，不伪造历史仓位倍数。
- **通用规则**：先区分配置值、原始下单值与当前派生值，再命名展示字段。需要精确展示历史选择时必须持久化当时的定仓上下文，不能靠当前账户状态倒推。
- **牵连**：`yoyo/monitor/static/paper-desk.js` 与 `tests/monitor/frontend_paper_desk.test.cjs`；本次只调整展示，不改保证金计算、订单数量或历史记录。测试覆盖 10× → 权益翻倍后 5×、缺失权益、非正权益、微小敞口及编辑中的轮询。
