# 保留设计稿的业务适配层也必须保留请求与回执身份

- **问题**：Stitch 导出的按钮和数值属于示例交互。简单接上接口仍可能留下假统计、错误字段或确认超时后的重复提交。
- **死胡同**：执行原稿脚本会触发模拟成功提示；每次重试生成新的 request ID 无法区分新操作和丢失的回执；用一个接口失败阻断整个账户页会掩盖另一种账户的可用状态。
- **有效路径**：原始 HTML 与 DESIGN.md 保持不可变，单独业务适配层接入共享后台。确认绑定持久请求 ID、账户及完整参数，超时后只查询或重复同一幂等请求。真实执行器维持唯一写者，Pro 网关仅存用户确认；模拟拆单先落盘子请求，再发送。
- **通用规则**：视觉保真和业务正确性分别验收。页面中的收益、延迟、状态必须逐字段匹配真实语义，未知值不能用示例补齐。
- **牵连**：`yoyo/monitor/pro/`、`yoyo/monitor/static/pro/`、`yoyo/okx_execution/manual_commands.py`。实盘操作仍要求 Owner 亲自逐次确认，旧前端继续独立运行。
