# 增量标签缓存要绑定事件语义，不能绑定整批清单

- **问题**：每追加25币就重读全部旧行情并重算收益，首五周期一次完整标注约586秒，扩样队列会重复消耗这部分时间。
- **死胡同**：要求新旧sources清单SHA相同，会使真正新增来源的批次永远无法命中；只按event_id缓存，则会忽视行情字节、核心边界、时间切分和解析实现变化。连续性审计前的旧产物也不能继续使用。
- **有效路径**：先证明旧events、sources、outcomes和实现版本各自冻结且完整一致；按源路径与完整SHA、周期、方向、核心起止和根数、plan SHA、原解析器/reader/pipeline SHA复用计算字段。新NMS和cluster元数据来自新清单，不从旧结果覆盖。每轮仍重哈希当前事件所用的全部源文件。
- **验证**：扩展到第二个真实CSV来源后，与全量原labeler逐字节比较outcomes和错误清单；另测hit/miss/hit顺序、新cluster保留、plan/实现/源漂移、旧lineage错误、旧事件缺失和重复。旧原labeler缓存跨批使用必须显式提供旧events与sources路径；新增模块输出记录这些路径和SHA。
- **通用规则**：复用的单位是有证据的计算语义，不是批次ID。缓存拒绝要记录原因并重算，不能把缓存命中率当作正确性证据。这里没有改变形态、盈亏门槛或训练数据准入。
