# 共享 K 线必须同时共享数据身份、互斥和请求预算

- **问题**：主监控、图表、YOLO 和市场共振各自缓存同一行情，跨进程仍会重复补数；多个局部限流器不能限制总请求量。
- **死胡同**：把已有监控 OHLCV 直接当完整原始行情会丢失 base/quote 成交量；只缓存相同 URL 无法合并不同窗口。实际多进程冷启动测试还发现 SQLite 的首次 WAL 初始化会争锁，普通 busy timeout 不足以解决。
- **有效路径**：以数据源、合约、原生周期和开盘时间建立独立公开行情读缓存，保留 OKX 九字段及确认标记。每个序列用进程间文件锁合并请求，数据库用短事务共享总预算与后台额度，建库另加初始化锁。只请求缺失范围；失败、缺口和未收盘数据不能冒充成功更新。消费者保留原来的均线起点、交易新鲜度和时间截断。
- **通用规则**：先确认时间边界、成交量单位及原始观察语义，再做共享；用真实多进程、跨窗口和失败重试测试证明去重。缓存容量和同步状态不能替代交易准入判断。
- **牵连**：`yoyo/data/candle_hub.py`、`yoyo/monitor/okx.py`、`yoyo/monitor/market_sync_okx.py`；本机公开读缓存不写 VPS OHLCV、模型、交易账本或实盘配置。每组最多保留 4096 根，形成中 K 线只保留 2 秒并与确认序列分开。
