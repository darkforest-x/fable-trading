# 盘中限价成交必须在同一次行情推进中获得保护

- **问题**：把已验收的收盘市价适配器扩展为盘中限价入场时，合成路径102→104→97→101在100买入、98止损，却到后续数据边界才退出。Nautilus1.231.0默认命令队列将成交回调内的新保护单延至整根OHLC结束，不能沿用收盘入场的时序假设。
- **死胡同**：只补一个limit订单并在on_order_filled里发止损，会漏掉同根亏损；仅关闭队列则又把OHLC从高直接跳低误作真实跳空，止损落在97而非98。不能靠排除同根触价、取消已应成交的单或忽略失败测试制造盈利。
- **有效路径**：仅限价入场模式同步处理命令，并允许当前已越过触发价的保护单立即执行。复用现有FillModel模拟盘口接口，入场当根止损按触发价成交，真实开盘越过则保留不利开盘价；成交时刻仍由原生内核决定。每根on_bar清除该价格覆盖，后续跳空完全沿用原生逻辑。限价成交价保守固定在挂单价，入场当根不贡献MFE。
- **通用规则**：从收盘入场切到盘中入场，先用同根成交止损、真实开盘跳空、后续跳空、到期边界和多单同时成交检验保护生命周期，再跑研究。OHLC假定路径不是逐笔事实，必须保留成交区间与模型边界。
- **牵连**：`yoyo/layers/l3_backtest/nautilus_independent.py`、`tests/evaluation/test_nautilus_limit_entry.py`。隔离Nautilus运行`python -m unittest discover -s tests/evaluation -p 'test_nautilus*.py'`，34项通过；旧市价模式队列与价格逻辑不变。仅离线研究。
