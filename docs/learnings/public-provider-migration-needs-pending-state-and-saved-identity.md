# 公网提供商迁移必须保存待激活状态和隧道身份

- **问题**：Owner 买好自有域名后，注册局实名审核仍在进行。新隧道可以先配置，但公网 DNS 尚不能解析；旧管理器只认识 ngrok，后续 start 会恢复到错误的提供商。
- **死胡同**：用购买成功代替域名上线，或先覆盖固定地址并移除临时隧道，会在实名审核、DNS 委派或证书签发期间切断唯一入口。只手工启动一个 cloudflared 进程，也无法保证后续管理命令沿用该身份。
- **有效路径**：保存正式隧道 UUID、精确主机名及仓外凭据路径，由独立 LaunchAgent 托管；增加 pending_activation 状态。start/status/stop 路由到已保存的提供商，仅真实公共域名返回应用健康响应后才更新固定入口并退役旧连接器。新配置允许保留旧主机名过渡，未改变原网关同源规则。
- **通用规则**：把“配置完成”“公网可达”“旧入口可退役”当作独立状态；配置文件写成功、供应商已注册或本地进程运行都不能替代最终 HTTPS 验收。凭据内容不能进入服务参数、代码或状态输出。
- **牵连**：`yoyo/monitor/named_tunnel.py`、`yoyo/monitor/public_tunnel.py`、`tests/monitor/test_public_tunnel.py`。58 项检查覆盖真实 Caddy 自有主机访问、cloudflared 精确 ingress、身份不匹配拒绝和待激活保留旧入口；本笔记记录配置实现，不代表 `spikeok.com` 已上线。
