# Partial exits need an immutable entry and a serialized tranche ledger

- **问题**：原模拟盘只会整仓退出。新增手动减仓若直接改原始本金，会改变历史交易分母；若自动退出继续使用原本金，又会重复结算已减掉的部分。
- **死胡同**：仅减少前端数量或覆盖 `notional` 都无法同时解释历史开仓、已实现盈亏与剩余敞口。按钮禁用也不能处理响应丢失后的重试、进程重启和自动退出竞争。
- **有效路径**：保留原本金，单列余仓和逐笔退出。每次成交只结算该份额并分摊开仓费，余仓继续遵守原目标与已启用止损；整笔结束后按原本金汇总收益。手动与自动写者串行，持久化请求 ID 与仓位版本；重试返回原回执。过期报价、未完成的较早确认结算拒绝手动成交，同分钟自动退出不得倒置在已发生的减仓之前。
- **通用规则**：分批实现不是把一次结算乘比例，而是引入可重放的成交事实和剩余状态；先明确不变量，再处理并发和界面确认。
- **牵连**：`monday_reclaim_paper.py`、`reclaim-close.js`、`reclaim-chart.js`；18 项后端测试覆盖多空、部分后自动退出、并发、容量释放、重复请求及新鲜度。浏览器端使用独立临时账本验收，不能用运行中的模拟持仓试平仓。
