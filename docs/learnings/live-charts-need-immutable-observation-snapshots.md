# 实时图表与识别记录必须使用不同的生命周期

- **问题**：研究工作台永久缓存信号收盘图，后续走势不可见；简单解除缓存后，识别端重新抓取最新数据又会与浏览器点击时的截图不一致。
- **死胡同**：只轮询被冻结的图表端点不会推进行情；用最新行情重新校验旧截图的 hash 会把正常价格变化当成冲突。把未收盘 bar 的预计收盘时间当观察截止时间，也会虚构尚未发生的观察。
- **有效路径**：信号收盘历史图保留原语义，实时研究图显式使用新的 observation endpoint。读取相同 OKX 公共行情，在内存从 SPIKE 确认均线种子推进；每个 provisional tick 都从确认种子重算，避免重复递推 EMA。每次 GET 创建短期不可变 snapshot ID，识别绑定该 ID、行 hash 与像素，另记信号时间、真实观察时间和未收盘状态。提交时重新检查快照年龄与窗口到期，不再取最新行情替换。
- **通用规则**：先明确图表是可变视图还是不可变证据，以及截止时间究竟指什么。轮询只更新视图；已发出的判断必须能恢复当时确切输入。数据陈旧、断档、确认价格冲突必须显式失败，不能用成功抓取时间替代行情新鲜度。
- **牵连**：`yoyo/vision_research/live.py`、`source.py`、`server.py`、`static/`、`tests/vision_research/test_live.py`。默认信号后12根只约束手动研究识别；不修改生产新鲜度门、扫描、通知、训练或实盘资格。上传图片仍不声明已验证时间边界。
