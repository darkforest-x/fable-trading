# Owner 取消可续传交付后回执必须变成终态

- **问题**：逐文件 Telegram 交付本来支持断点续传；Owner 在发送过程中改为“不需要发”，进程虽能中断，但普通未完成回执会让以后一次重跑自动发送剩余文件。
- **死胡同**：只按 Ctrl-C 停进程、保留 `delivery_complete=false`。这能停止眼前请求，却把“网络故障待恢复”和“Owner 明确取消”混成同一状态；后续操作员或自动化无法区分，可能违背最新授权继续外发。
- **有效路径**：先立即中断并核对进程消失，再在不可变动作 ledger 上记录已发送 ID、未发送数量、取消时间和 `delivery_cancelled_by_owner=true`；发送器在任何 contract/hash 检查前先识别该终态并 fail closed，报告如实写明无法撤回的已发送部分。
- **通用规则**：所有可续传外部交付至少要有 `in_progress / complete / owner_cancelled` 三态；Owner 取消优先于重试、合同漂移和完整性恢复，除非 Owner 之后重新明确授权，否则绝不自动续传。
- **牵连**：Telegram/邮件/批量上传发送器、断点回执、外部不可逆动作、最新用户指令优先级与审计报告。
