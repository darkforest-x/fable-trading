# 行情缺失不是撤销已受理挂单的依据

- **问题**：常规限价挂单在等待成交时消失。只读核对交易所订单回执与本地 outbox，确认服务端发出了撤单请求；实现把行情缺失、过期或时间戳超前的异常统一转换成了撤单。
- **死胡同**：只看 App 列表无法区分漏显示、成交与撤销；交易所“用户撤销”也无法区分用户点击和服务自动操作。旧 outbox 只有撤单指令，没有触发分支，不能把静态发现的 bug 当成每笔历史撤单的确切原因。
- **有效路径**：先用有状态假交易所复现断行情、重启及部分成交场景，确认错误路径实际发送了 cancel-order。修复后缺失行情继续阻止新开仓，但保留已受理挂单及其额度；只有新鲜价格触及止损、原持仓结束或保护异常等已有条件才能撤单。撤单原因与 outbox 原子落库，重试保留首次原因，旧指令不补造历史原因。
- **通用规则**：缺少证据可以阻止新增风险，不能直接当成修改已有交易指令的事实。排查“订单消失”先联结原订单编号、交易所最终状态、本地写请求和触发原因；撤单受理回执不等于最终零成交，退还开仓次数必须等待最终成交核对。
- **牵连**：`yoyo/discipline_app/managed_orders.py`、`live_book.py`、`execution_journal.py`；回归见 `tests/discipline_app/test_managed_orders.py`。保持既有行情新鲜度、风险上限与保护性撤单条件，不通过放宽阈值掩盖网络问题。
