# Repeated-touch return counts require event order and a fixed deadline

- **Problem**: The owner asked how many of 859 repeated BTC 15m touches returned to the Monday range within the same NY week. A return label can silently include a price that happened before the touch or after the week expired.
- **Dead end**: Testing only the touch candle's high and low cannot establish which boundary traded first. Counting eventual returns until the end of the archive gives older events longer follow-up. Treating every successful touch as a separate winning trade also mistakes repeated observations of one return for independent outcomes.
- **Effective path**: Freeze the 859 episode starts and the original data cutoff. Check later candles against the original Monday edge and the next NY calendar Monday. For same-candle returns, use an OHLC ordering proof or the already available 1m data, retaining any unresolved ordering bounds. Keep unfinished current-week events pending. This study has 410 observed returns and one pending event, without remaining label ambiguity.
- **General rule**: Before interpreting a repeated-event success fraction, define its reset, chronological order, deadline, and censoring. A completed price return is an event label, not a stop-aware trade outcome or an independent trial.
