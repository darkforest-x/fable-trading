# 零交易账本是已观察的空仓账户，不是缺失市场

- **问题**：V7 全池汇总遇到一个完全没有进场的市场时，账户统计在排序 `entry_time` 时失败。冻结的零交易 CSV 有合法表头，但没有只在真实成交后才生成的执行字段。
- **死胡同**：只用有交易的首个市场做 smoke，无法覆盖零交易账本；直接要求补齐成交字段又会把合法空仓误当成坏数据，或迫使改动已经完成的回放产物。
- **有效路径**：账户汇总先处理空账本：零进场、零已平仓、零收益与零已平仓余额回撤。非空账本继续严格要求真实执行字段。全池原始交易文件不改，汇总修复使用新版本输出目录。
- **通用规则**：数据缺失与策略没有行动是两种状态。消费事件流之前先定义空事件集的业务含义，并用没有事件专属字段的空 schema 验证它。
- **牵连**：`spike_v7_v1_report.py::independent_account` 及其回归测试；此修复不改变信号、风控、费用、原始交易或冻结样本。
