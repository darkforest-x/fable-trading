# Owner审核只应暴露不可自动推导的主裁决

- **问题**：候选审核页同时放“真目标、延续重复、框偏、明确负例”四个按钮，虽然诊断信息丰富，却把事件级去重分析和单图语义判断一起压给Owner，导致操作慢且含义重叠。
- **死胡同**：把每个下游诊断维度都做成同级按钮。按钮越多不代表标签越精确；当一个维度能从时间邻接和核心重叠自动推导时，人工重复选择只会增加认知负担和不一致。
- **有效路径**：主界面只保留三个无法替代的裁决：形态和框都对、形态对但框偏、形态不对；用`1/2/3`直接分类并自动前进，`Z`撤销。延续/重复移到后续事件聚类诊断，只对歧义组二审。
- **通用规则**：设计人工审核面时，先把问题拆成样本语义、几何质量和可计算的关系诊断；只让人判断前两者，关系特征先自动计算。高频审核的主按钮最好不超过三个，并为每项提供单键操作、自动前进和撤销。
- **牵连**：`scripts/build_owner_short_hardneg_canary_review.py`、`analysis/html/p2_owner_short_gold_center_hardneg_canary_review331_20260811.html`、Owner导出的review protocol V2；不会改变训练图像、标签、阈值或模型权重。
