# 月首个完整周不能用月初七天或一根图表周线代替

- **问题**：把周一区间扩成月首周区间时，“第一周”可能指每月1–7日、含1日的周或当月首个完整周。Owner 2026-11-02 明确选择当月第一个周一至周日，沿用纽约时区。
- **死胡同**：未采用直接读取第一根图表周线的捷径：交易所周线边界与所选纽约日历不同。固定加168小时也不成立，包含夏令时切换的完整日历周会有167或169小时。视觉验收另发现向右展开的末端标签会被价格轴裁切，改为在线段右端向左对齐。
- **有效路径**：用所选时区计算首个周一及下个周一，固定60m源上下文遍历窗口内已收盘OHLC，再给各显示周期提供快照；仅在完整源数据覆盖整个窗口后固定价位。原生Pine直接调用生产函数的7组断言覆盖月初星期、闰年、DST、缺首根、缺中间根、外部极值与冻结时点；BTC的15m/1h/1D/1W同月锚点一致。
- **通用规则**：先确认日历窗口定义，再区分采集粒度与显示周期。形成中、已确认与向左回画的复盘含义分别标明；不把缺失窗口补成看似完整的区间。
- **牵连**：`yoyo/evaluation/pine/month_first_week_1618_v1_0.pine`；`artifacts/month-first-week-v1-20261102/delivery.json`；原生校验证据 `output/pine/month-first-week-v1-20261102/`。继承[固定源上下文原则](calendar-price-anchors-must-use-a-fixed-source-context.md)，该版本针对24/7加密货币数据，遇源小时缺口跳过整月。
