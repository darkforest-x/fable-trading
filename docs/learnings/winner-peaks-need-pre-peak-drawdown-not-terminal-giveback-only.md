# 盈利峰值必须同时审计途中回撤与最终回吐

- **问题**：ETH15m＋ICT盈利单峰值均值6.09R、最终平均净3.10R，是否能把看起来损失的近一半浮盈拿回来？
- **死胡同**：只算最终峰值减兑现，或从“达到4R的19笔最后都盈利”推出4R启动紧止盈。16.36R赢家在最高收盘5.019R之后仍出现1.861R不利价，要求立刻保留50%峰值会遇到这次回落；更不能从最终赢家身份反推开仓时可识别的持仓类型。
- **有效路径**：以原成交区间重建MFE及4ATR单向保护，排除退出后的极值；对止损根只给可能上界。32赢家上/下峰值一致，唯一有歧义的是亏损单0—0.356R。再对原2R收盘激活之后、最终峰值根之前的完整bar，用此前峰值减后来不利价算顺序确定的回落。14笔峰值≥5R的赢家有7笔途中回落>2R，最大7.23R。分开报告早期保护和趋势后段锁盈，而非假设全部回吐可追回。
- **通用规则**：提出追踪止盈之前，先找一笔足以反驳它的完整盈利路径；检查触发口径是盘中极值还是收盘、保护何时生效、多少样本真的触发。若晚启动只剩3笔，诚实称假设，不把事后参数叫优化完成。
