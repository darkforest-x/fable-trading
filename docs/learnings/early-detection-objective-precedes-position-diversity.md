# 先减少发现延迟，再判断位置增强是否符合任务

- **问题**：Owner 要解决均线密集启动发现太晚；指出正框全在倒数第五根后，我把任务改成了均匀分散框的位置，增加到核心后 5/8/11 根，反而增加等待。
- **死胡同**：把位置分布本身当目标，先围绕错误方案造图再检查文件一致性。上一轮元数据模板能复现横向框的结果，只说明数据可用位置模板解释，不能证明贴近右端的目标不合理，更不能证明应增加未来确认。此前 FIL 案例已经证明，后置过滤无法把模型首次发现时间提前。
- **有效路径**：撤下 R5/R8/R11 当前入口，保留历史资产。以逐案例的最早可识别观察时点裁图，使真实核心靠近右端；框投影原始核心，每事件最多三种，不强行凑三种或给所有案例固定框后根数。更早的图要核对当时可见证据，不自动继承事后正标签。
- **通用规则**：先明确首次发现要发生在行情的哪个阶段，再设计输入右端及标签。验收必须同时量首次识别延迟、当时已走价格、漏检和误报；宽位置覆盖、mAP 和文件完整性均不能替代它。真实时间边界不能靠平移框、补空白或回填时间修饰。
- **牵连**：`ma_morphology_training_package.py` 现在要求显式数据目录，当前无选定训练集；历史审计不再给 ready 状态或训练命令。新入口 `early_detection_contract_v1.json` 不创建新标签、数据或模型。此前 [FIL 模型首次提案分析](../../analysis/p1_1h_filusdt_model_first_breakout_gate_20260904.md)、[因果可用时间](pattern-hit-must-be-timed-at-causal-availability.md)、[确认区依赖](candle-color-dependence-must-be-localized-by-causal-region.md) 是本次依据；本文纠正 [上一轮审计](asset-integrity-does-not-validate-a-learning-design.md) 将位置多样性过度提升为目标的解释，历史数字不变。
