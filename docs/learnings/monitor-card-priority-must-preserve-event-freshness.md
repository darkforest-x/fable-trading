# 监控卡片的视觉优先级必须跟随事件时效

- **问题**：IMACD 首页用大统计卡和长表格展示所有事件，最新确认的启动点位不醒目。改为卡片后，如果只把列表第一条高亮，旧信号或断网缓存就容易被看成刚启动。
- **死胡同**：仅给每条表格记录套上卡片边框，仍然没有区分新鲜事件与历史记录；沿用表格的直接子节点焦点恢复，也无法找到新分组网格中的按钮。
- **有效路径**：先按实际使用顺序分配信息权重：币种、周期、方向、原收盘点位、启动前蓄势根数在主层，回执在次层。新鲜分组必须同时满足 API 标志和服务已有时限，并用服务校准时间加接收后的流逝时间过期；同步失败保留记录，但取消新鲜高亮。卡片用原生按钮，刷新后按事件身份在后代节点中恢复焦点。观察结构与已确认启动分开呈现。
- **通用规则**：重做监控视觉前，先定义每种强调样式依赖的事实、有效期与失效表现；不能用列表位置、推送成功或醒目的颜色代替新信号身份。筛选、键盘和移动端看图回返应与排版一起验收。
- **牵连**：`yoyo/monitor/static/`、`tests/monitor/frontend_cards.test.cjs`。不改变 `tv_start` 协议、30 分钟门限、扫描、通知及交易配置。
