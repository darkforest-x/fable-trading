# 随机对照回放应缓存一份已验证的数据源前缀

- **问题**：同一币种的 30m、1H、4H 随机对照按周期和连续段分组回放，每组都重新解压、解析并哈希同一份 30m 开发期源，边界正确但重复 I/O 显著。
- **死胡同**：把所有币种或全部派生周期缓存进内存会扩大状态面，并增加跨币、跨周期串用数据的风险；跳过前缀哈希则会破坏冻结来源契约。
- **有效路径**：利用 `(venue, symbol, timeframe, segment)` 的稳定分组顺序，仅保留当前 source path 对应的一份 raw 30m 前缀；首次读取时校验开发期 digest，各周期与连续段从这份只读 raw 数据重新聚合和生成特征。source 改变时先释放旧值，替换校验失败时保持空状态。
- **通用规则**：重复回放先缓存最靠近来源且已完成身份校验的不可变层；派生特征、参数和执行状态仍按实验单元重建。缓存键必须覆盖来源身份与内容 digest，切换时先清空再加载。
- **牵连**：`yoyo/evaluation/spike_market_breadth_matched_controls.py` 的 `_ActiveSourcePrefix`、receipt/tick 逐流校验，以及对应的 source 切换和单次读取测试。
