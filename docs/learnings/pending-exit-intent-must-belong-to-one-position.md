# 待执行的退出指令必须随所属仓位结束而清除

- **问题**：V8 退出敏感性核对中，原串行回放和固定同一笔入场的回放在跳空止损后的下一笔出现退出差异。原引擎先执行开盘保护，再仅在仍有持仓时清理预定反向退出，可能留下旧仓指令。
- **死胡同**：为了让逐笔对齐，给固定入场回放补入旧仓的残留状态。这样可以复现归档，却把历史模拟缺陷继续当成交易规则。
- **有效路径**：归档基线只用于证明来源和定位差异。先单列修正指令归属后的基线，再在两边都使用同一修正引擎测试保本。仓位无论因开盘跳空、盘中保护、反向退出或数据中断而结束，其退出意图必须同时失效。
- **通用规则**：预定退出应绑定唯一仓位 ID；清理不能依赖仓位仍然存在。历史复现与可执行行为是两个检验，前者通过不能代替后者。测试至少覆盖“预定反向 → 先触及保护 → 新入场 → 旧指令不得影响新仓”。
- **牵连**：`yoyo/evaluation/spike_exit_policy_study.py`（归档来源，保持原文件）、`spike_v1_v8_be05.py`（本研究修正与归档对照）、`experiments/active/exp-spike-v1-v8-be05-20260914-v1/PROJECT_PLAN.md`。影响限于此次历史回测结论，不据此宣称线上持仓受到同一问题影响。
