# 待执行的退出指令必须随所属仓位结束而清除

- **问题及纠正**：V8 退出敏感性核对中，本次新写的串行回放和固定入场回放在跳空止损后的下一笔出现退出差异。初步错误归因于归档引擎；逐行查源代码与 86 笔失败流后确认，归档 `replay_policy` 已清理 `pending_exit`，出错的是本次自定义新增的开盘止损分支，漏清 `pending_reverse`。
- **死胡同**：为了让本次串行与固定回放内部对齐，给固定入场回放补入旧仓残留状态。内部一致不能证明归档一致，更不能证明交易生命周期正确。
- **有效路径**：归档基线只用于证明来源和定位差异。先单列修正指令归属后的基线，再在两边都使用同一修正引擎测试保本。仓位无论因开盘跳空、盘中保护、反向退出或数据中断而结束，其退出意图必须同时失效。
- **通用规则**：预定退出应绑定唯一仓位 ID；清理不能依赖仓位仍然存在。历史复现与可执行行为是两个检验，前者通过不能代替后者。测试至少覆盖“预定反向 → 先触及保护 → 新入场 → 旧指令不得影响新仓”。
- **牵连**：`yoyo/evaluation/spike_exit_policy_study.py`（正确处理该生命周期的归档来源，保持原文件）、`spike_v1_v8_be05.py`（本次引入并修复的问题）、`experiments/active/exp-spike-v1-v8-be05-20260914-v1/PROJECT_PLAN.md`。不能据此声称旧 V8 或线上持仓存在同一缺陷。
