# 放大图表必须检查实际包含块和最终画布高度

- **问题**：2026-10-18 浏览器验收发现，手机主图放大后只剩约 277px 画布；持仓图的固定定位区域被原订单弹窗裁剪。
- **死胡同**：给图表加 `position: fixed`、`100dvh` 或放大 class 不等于充满屏幕。普通手机卡片的高优先级高度规则覆盖了放大高度，原生弹窗也可能成为固定定位的包含块。
- **有效路径**：单独定义放大状态的高度优先级；嵌套订单弹窗放大时同步扩展宿主弹窗，退出时恢复。保留图表节点原位，避免重接 TradingView iframe 导致重载。背景隔离遍历 Shadow DOM 宿主，退出恢复 inert、焦点和滚动状态。
- **通用规则**：放大功能按浏览器实际 bounding box、画布高度、可见边界和退出后的状态验收，不能只看 class 或按钮状态。普通卡片、原生弹窗、Shadow DOM、外部 iframe 必须分别检查。
