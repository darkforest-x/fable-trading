# 推理几何必须从该权重的训练 manifest 反推

- **问题**：替换 YOLO 权重后，扫描器仍需要窗口长度、核心根数和确认根数才能生成模型输入与把框映射回 K 线；这些参数不是通用的“项目配置”，而是每个权重自己的训练合同。
- **死胡同**：沿用上一版探针的 W14/W18/W22、核心 4–7 根、确认 3–5 根。代码可以正常推理并出图，但会把新权重放进训练时从未见过的几何，还会用错误规则解释框；运行成功不能证明输入语义正确。
- **有效路径**：在读取 holdout 前逐行扫描新训练 manifest 的正例，从 `window_start_i/window_end_i`、`core_bars`、`post_core_context_bars` 反推真实支持集，并同时锁定 manifest SHA。预注册、扫描器和独立 verifier 都只接受这个支持集；本例得到 W18–25、核心 4–5 根、确认 4–6 根，任何漂移都 fail closed。
- **通用规则**：更换检测权重时，第一步不是复制旧推理参数，而是用该权重对应的不可变训练 manifest 生成并验证推理几何合同；没有 manifest 或身份哈希对不上，就不要运行正式探针。
- **牵连**：`datasets/*/manifest.jsonl`、推理预注册、窗口生成、框坐标回映、事件去重、结果 verifier；也关系到 holdout 单次消费纪律，因为用错几何后再重跑会额外消耗数据。
