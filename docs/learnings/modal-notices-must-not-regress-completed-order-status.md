# 通知改弹窗时，成交终态不能被迟到的提交响应覆盖

- **问题**：独立交易 App 的内联通知推挤主页；改成模态后，提交请求和成交轮询并发完成时，错误的状态顺序会更醒目。
- **死胡同**：仅将横幅改成 `position: fixed` 没有解决焦点穿透、多弹窗叠加以及晚到“已提交”覆盖“已成交”的问题；未采用该方案。
- **有效路径**：复用受控 Dialog 的背景 inert、滚动锁与焦点约束；通知在确认/错误/选择弹窗之后展示。明确区分信息、核对中和成功；记录已经收到终态的请求编号，忽略该请求迟到的提交提示。关闭通知不取消后台核对。
- **通用规则**：展示层也要尊重终态单向推进；测试应让提交响应故意晚于成交核对，而不是只验证顺序响应。
- **牵连**：`mobile/src/App.tsx`、`Notification.tsx`、`Dialog.tsx` 与隔离 UI fixture。浏览器已检查焦点循环、Escape、背景不可操作、页面位置不变和延迟响应后的唯一成交弹窗。
