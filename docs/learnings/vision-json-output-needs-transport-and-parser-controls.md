# A JSON prompt is not an output-format contract

- **Problem**: NEIRO and BX vision runs failed at `json.loads` despite HTTP success and a JSON Schema in the prompt. Their historical raw responses were not saved, so the exact syntax failures cannot be reconstructed.
- **Dead end**: Calling this a bad key, assuming it was definitely a Markdown fence, or treating a later successful retry as proof of a fix would go beyond the evidence. The provider's model guide advertises structured output, but its generic API guide labels `response_format` text-only.
- **Effective path**: Replay the saved image/reference hashes and criteria, preserve the fresh exchange, then test the exact multi-image `json_object` combination. The four-image GLM-5.3-Flash probe returned HTTP 200 and complete JSON. Restrict the parameter to that tested model and accept only a whole bare JSON document or a single enclosing JSON/unlabelled code fence.
- **General rule**: Separate HTTP completion, JSON syntax, strict result schema, and task accuracy. Remove presentation wrapping only; never repair truncation or extract an arbitrary object from prose/reasoning. Keep the raw transport response immutable and old failures unchanged.
- **Scope**: `yoyo/vision_research/zhipu.py`, `tests/vision_research/test_zhipu.py`; raw probe in ignored `runtime/diagnostics/neiro-json-mode-probe.json`. No change to model, reasoning effort, criteria, or production/training eligibility. Official sources: [model guide](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash), [API reference](https://docs.bigmodel.cn/api-reference/模型-api/对话补全), [structured output](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output).
