# 页签分区必须同时控制布局、加载与轮询

- **问题**：信号中心已有记录与账户页签，但总览仍堆放余额、筛选、指标、图表、明细；进入记录页也要加载约 1.12 MB 图表脚本并轮询隐藏账户。
- **死胡同**：仅增加页签或缩小字号并未减少用户面前的任务数量，也没有降低隐藏内容的运行成本。全量导入 UI 框架还会引入重置规则与无用资源。
- **有效路径**：记录、分析、账户各有独立可见内容；页签写入 URL，账户页暂停信号查询，离开账户停轮询，分析首次进入才加载 ECharts。同样信号行不重复替换 DOM，时间标签按分钟刷新。Bootstrap 只编译 scoped 表单/导航/按钮，沿用产品主题。
- **通用规则**：划分界面时同时标明各区域数据来源、加载时机与离开后的生命周期；验证刷新恢复、快速切换的过期响应、主题和窄屏布局。
- **牵连**：`yoyo/monitor/static/app.js`、`signal-workspace.js/css`、`module-loader.js`、`okx-execution.js`、`tools/signal-ui/`；实盘执行器与策略不受展示页签控制。
