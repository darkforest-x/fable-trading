# 默认账户只用于新草稿，待核对委托必须保留原账户

- **问题**：首页挂单面板要默认选择「梭哈账户」，而账户列表接口的 active_account_id 只是最早创建的账户；同时面板可能恢复上一笔尚未收到回执的委托。
- **死胡同**：继续使用列表首项不能表达用户指定的默认值；直接把新默认值套到恢复中的委托，会让账户选择框与实际查询的订单归属不一致。修改服务端通用默认值也会影响其他工作台，本次未采用。
- **有效路径**：首页传入明确的账户名称偏好，只在唯一匹配时解析为真实 ID。缺失或重名时要求手动选择，不静默切到别的账户。恢复待核对委托时，以原草稿的账户 ID 和标的展示并查询原回执；切换账户会作废旧预览，新打开才重新应用偏好。
- **通用规则**：修改默认选择前，区分“新草稿偏好”和“已提交操作身份”。默认值不能覆盖后者；验收至少覆盖列表顺序不同、缺失/重名、手动切换及待核对回执恢复。
- **牵连**：home-ticket.js、monday-live.js、frontend_monday_live.test.cjs；纸面预览和实盘预览仍需第二次明确确认，浏览器验收使用合成报价且不发送交易写入。
