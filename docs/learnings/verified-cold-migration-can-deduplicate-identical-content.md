# 冷文件迁移可按内容去重，但恢复身份必须逐文件保留

- **问题**：Notion #52 要求整理 Mac 磁盘并迁移大文件，本机最初仅剩约 887 MiB。重复的临时 Git 路径清单占用大量空间，外置盘为可写 NTFS。
- **死胡同**：把每份清单直接等量复制，会把重复占用搬到外盘；仅凭文件名删除，又无法保留可恢复证据。初次筛选因每份临时文件都有 `com.apple.provenance` 而全部跳过，不能把带属性等同于不可归档。历史上整份行情外移还曾触发应用路径与权限限制，普通软链接可读不能替代应用验收。
- **有效路径**：限定稳定且未打开的冷文件，记录 dev/inode/size/mtime/ctime、模式及扩展属性，完整计算 SHA-256。同摘要共用一份压缩副本，解压重算 SHA 后逐文件保留原路径映射；释放本机副本前再次核对文件身份、摘要及占用。231 份清单的 23,185,529,519 字节由 58 份压缩内容保存，占 261,482,091 字节。补查发现末尾截断的旧清单，因此保留其全部原始字节，不把所有临时文件认证为完整可再生清单。实际运行行情与数据库继续留在本机。
- **通用规则**：区分“原路径身份”和“内容副本”。内容可以去重，路径、时间和恢复信息不能合并丢失。冷归档与热依赖分开迁移；可用空间前后差受其他进程及 APFS 管理影响，不能全部归因于本轮。归档解决容量压力，不证明临时文件持续生成的问题已根治。
- **牵连**：操作脚本、逐文件收据及恢复工具在 `data/_storage_migrations/20261016-task52/`；外盘目录 `/Volumes/Elements SE/MacData/zhangzc/storage-migration-20261016-task52/`。参见 [路径与应用信任边界](storage-links-must-preserve-catalog-trust-and-identity.md) 和 [临时清单的生成与清理归因](workspace-diff-temp-producer-is-not-cleanup-failure-cause.md)。
