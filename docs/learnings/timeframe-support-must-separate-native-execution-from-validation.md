# 周期支持必须区分原生执行能力和收益验证

- **问题**：Pine 指标原先用 1h 门禁阻止 15m 信号，但同一 K1→K2 形态需要在 15m 图上运行；直接说“支持 15m”容易混淆代码能运行与参数已验证两件事。
- **死胡同**：彻底删除周期门会让任意周期都悄悄生效；用 `request.security()` 把 1h 结果投到 15m 又只是显示 1h 信号，并没有实现 15m 形态。两种做法都会模糊 bar 间距和 SMA/ATR 的真实语义。
- **有效路径**：用 `timeframe.in_seconds()` 明确放行 900 秒和 3600 秒，默认模式写成 `15m + 1h`，并继续直接使用当前图表的 OHLCV、SMA40、ATR14 与 2–8 根距离。这样 15m 与 1h 各自原生重算，同时保留仅 15m、仅 1h 和 Any 的显式选项。
- **通用规则**：增加周期时先定义它是“原生本周期策略”还是“高周期信号映射”；再把周期门做成可见契约。代码可运行只证明执行支持，不等于该周期已有独立收益验证。
- **牵连**：`timeframe.in_seconds()`、`allowedTimeframes`、状态芯片、15m/1h 图表布局；没有读取 holdout、调参、改变 TP/SL 倍数或作盈利声明。
