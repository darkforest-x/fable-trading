# 多周期管理必须把颜色时钟与风险时钟分开

- **问题**：1h入场策略从5mSMA40改为15mSMA40管理，底层仍逐5m执行。只放宽参数校验不足以实现原生15m退出。
- **死胡同**：沿用每5m必有管理bar及相邻间隔必须5m的假设，会把+5/+10的正常静默当作数据缺失，反复清空翻色状态；只验管理bar边界又会漏掉其内部raw5缺口。将整条执行循环放慢则漏验中间硬止损。
- **有效路径**：每5m继续处理真实开盘、跳空和硬止损，只在应有的完整15m收盘更新翻色edge。入场初态取floor(entry,M)刚完成原生bar，核验它的全部底层raw5及入场前已完成间隔；入场当前bar仅读open。独立数据helper与L3交叉验证，旧5m全字段parity作为回归门。
- **通用规则**：先写清每类事件应到达的时钟，只有“该到却没到”才是missing；不能将正常静默当成状态失效，也不能让慢管理降低风险检查频率。
- **牵连**：`yoyo/layers/l3_backtest/hourly_impulse.py`、`yoyo/data/hourly_impulse_management_context.py`、V8研究driver及三个新测试文件。两种SMA40记忆长度也改变，结果只能解释为管理规格替换，不能声称孤立频率因果。
