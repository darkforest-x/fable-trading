# 自动龙头榜必须同时固定比较窗口与首次观察时间

- **问题**：把“首波参与、抗跌、先恢复”的人工流程自动化时，逐币取各自最好看的起止点会制造排名；首次上线又天然能看到启动之前的历史，容易把现在恢复的背景误记成当时已经选中。
- **死胡同**：设计时排除“按每币最近高低点比较”和“启动即回填历史候选”两条路径。另一处实现核对发现全局内容哈希去重会吞掉 A→B→A 的真实状态恢复：最后一个 A 复用旧 ID，重启再读最新记录反而得到 B。它是存储语义错误，不是行情实验结论。
- **有效路径**：按 BTC／ETH 已闭合的共同小时窗确认阶段，冻结首波结束与本轮首次观察的候选池；不满足同窗的数据保留在缺失分母内。初次加载仅恢复行情背景，独立保存首次观察时间。相对表现、回吐、回撤和恢复次序用偏序分层保留并列；当前位置等待另列。只与最新快照去重，状态改变时追加新版本，历史不改写。
- **通用规则**：先定义“当时看到了什么、什么时候真正记录”，再定义谁更强。内容相同与事件相同不是同一件事；去重必须保持状态变化的时间顺序。候选池、数据覆盖、来源与规则版本也是排名的一部分。
- **牵连**：`yoyo/monitor/altcoin_leaders.py`、`altcoin_leader_service.py` 及自动观察页。1H、此前24收盘突破与120小时上限是本次明确展示的新研究规则，未证明交易优势。只读复用现有 OKX checkpoint，独立保存派生观察，不改 VPS 行情、forward、通知或真实交易。相关测试覆盖未来扰动、缺口、未知资产分类、并列、退市／新加入、A→B→A 历史与过期暂停。
