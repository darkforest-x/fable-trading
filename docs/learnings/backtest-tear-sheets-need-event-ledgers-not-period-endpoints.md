# Backtest tear sheets need event ledgers, not period endpoints

- **问题**：策略小册有许多区间柱状图，却无法展示资金演变；旧研究有原生成交，但部分仓位核算只保存汇总。不同年份独立重启、同刻随机顺序的中位数、补充本金和当前规则差异又容易被混为同一条曲线。
- **死胡同**：继续堆汇总图不能补足资金路径；拼接区间终值或平滑插值会伪造走势。把候选交易胜率、资金成交胜率和前向胜率混用，也会让默认账户和小册数值看似矛盾。
- **有效路径**：保留原生框架成交和成本，给既有资金核算函数加无副作用观察器，预先固定原研究首个种子，仅补出缺失的结算账本。先提交导出代码，再生成新路径；逐事件验证资金=初始本金+交易盈亏+补充资金，验证原5m结果和各账户样本数。以完整事件序列绘制阶梯资金/收益与回撤，再生成月度、年度和逐笔分布；补款前低点保留，梭哈月度使用净盈亏而非含充值的收益率。
- **通用规则**：做收益图先明确账本、资金分配、时间轴、费用、补款与版本；一条曲线只对应一个完整路径。无每日盯市数据不添加伪精确的夏普指标，无有效基准不添加装饰性基准线。默认值同时检查主入口、页面路由与预加载，显式书签继续优先。
- **牵连**：`strategy_booklet_paths.py`、`strategy_booklet_metrics.py`、原资金核算函数的可选trace、`reclaim-strategy-book.js`、`app.js`、`startup-hints.js`；历史BE0/当前保护价及v3add加仓金额口径保持明确区分。
