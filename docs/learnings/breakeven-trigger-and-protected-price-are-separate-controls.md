# 保本触发条件与保护价必须分开研究

- **问题**：Owner认为V8大量浮盈回吐，要求比较5m、15m、30m、1H、4H并重新考虑止盈。原版保护偏迟，而最新费用保本又产生大量保本小单，二者不能混称为同一个退出方案。
- **死胡同**：原版收盘达到2R才启动close±4ATR跟踪；把它口头简化成“浮盈2R就保本”，会把影线触价、收盘确认、次根生效混为一谈。另一极端是把保护价设在入场±0.2%，同时用“超过该保护价一tick”作为触发条件，这实际上绑定了保护位置与激活时点，不能代表“净浮盈达到1R以后再保护”。一旦把保本比例当成盈利比例，就会漏看被提前截断的赢家。
- **有效路径**：先保持信号、初始SL、成本、时段及数据来源一致，分别记录激活所需净浮盈、安装后的净保护收益和执行时机。以原版和已有费用保本版为两个明确对照：先只改激活条件，再只改锁利水平，最后才比较部分兑现与残仓跟踪。每次都重算同入场损失减少、大赢家利润损失和完整串行重入，不能仅截断原MFE列。
- **通用规则**：保本价回答“退出时保住多少”，触发条件回答“何时愿意把止损移过去”。净浮盈门槛要先计入费用；在成本约0.5R的示例中，费用保本价约是毛浮盈0.5R，而净1R目标约是毛浮盈1.5R，两者之间的空间会被过早保护截断。该示例是代数关系，不是新回测结果或推荐参数。
- **牵连**：原版`yoyo/evaluation/pine/spike_burst_v8.pine:77`及`spike_v7_fast.py:455`；费用保本`yoyo/evaluation/spike_net_recovery_exit.py:57`；既有13组分批实验`analysis/p1_spike_eth3m_partial_tp_20260914.md`。2023-08至2024-12原始744笔中，保守MFE记录≥1R的374笔有207笔最终净亏、105笔初始止损；这不证明这些亏损都能被新规则救回。核对来源是`experiments/active/exp-spike-eth-martingale-20260914-v1/results/pre/ETH_3m_OKX_development.csv`，没有读取新holdout，也没有执行新的参数优化。不同周期、交易所和日期的既有结果不能当成同条件周期对照。
