# 已确认反向必须先冻结旧参考

- **问题**：趋势参考把反向确认排除在持仓外，导致旧方向只能等待初始保护；若直接覆写状态，旧框的峰值、里程碑和结束原因又会泄漏到新框。
- **死胡同**：仅移除“持仓中禁止信号”的门会让同向重复事件重置 entry/risk，也会在同根把新状态写进旧绘图组。
- **有效路径**：先以旧保护跑完 `f_path`，保存旧 side、peak、路径值和结束价格；仅已确认的反向事件终止旧组，再在新风险有效时分配新组。绘图层先封存旧组，随后创建新组。
- **通用规则**：状态机允许同根替换时，把“旧状态结算”和“新状态分配”拆成两个明确步骤，并为画面和告警保留旧状态快照。
- **牵连**：`spike_burst_v1_display.pine`、`spike_burst_v6.pine`；冻结的 V1 监控/回测不随该衍生参考退出修订改变。

## 验证边界

- 本地生命周期小模型只能验证设计，不足以证明实际 Pine 执行正确。`yoyo/evaluation/build_reverse_reference_probe.py` 直接提取实际状态块，以合成输入驱动；只有收盘布尔门由显式 fixture 替代，用来检验未收盘事件。
- 2026-09-11 TradingView 原生执行：V6 `REVERSE QA 16/16`，V1 `V1 REVERSE QA 12/12`。覆盖双向反转、止损优先、同向不重置、新风险无效、未确认事件；V1 另走真实蓄势和量价资格。截图在 `output/qa/reverse-reference-20260911/`。
- 同根先触及旧保护，再出现合格反向信号：旧参考仍按保护价结束；新参考可以从本根收盘开始，不能用新方向的状态改写旧参考结果。
- V6 原生运行曾报 67 plots 超过 64 上限。去掉三项重复的 Data Window 输出后恢复；`alertcondition` 和动态绘图参数也会占预算，不能只数 `plot()` 调用。
- 这些是逻辑与显示检查，不是盈利回测或实际交易成交验证。原生探针执行后已恢复正式指标，不保留临时测试段。
