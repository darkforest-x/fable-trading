# 叠加标记的过滤边界必须与画线共用同一份区间

- **问题**：把旧区间翻身勾叉移入云带指标时，旧模块固定用30m周一，新指标优先5m并回退30m/1h。再请求一次30m，即使公式一样，也可能出现勾叉筛选边界和眼前画线不一致。
- **死胡同**：最初草稿给勾叉新增独立30m请求；代码审查确认在缺源或来源冲突时会漏标或错用边界，因此在交付前弃用。不能把正常行情下高低点通常相等当成所有历史都一致的证据。
- **有效路径**：当前图表只记录可见范围的Stoch候选（时间、方向、影线极值）；末端绘制时按时间倒序合并匹配已有WeekRange，统一使用它的ready/expires/hi/lo。普通var回滚保留形成中K线的预览，已收盘标记固定；不会额外请求行情。价格严格越界、纽约周末门与12H交易逻辑保持独立。
- **通用规则**：加入参考线相关的标记前，先确认参考线的实际数据来源、可用时点和回退规则；复用已画线的快照，而不是只复制同名公式。显示范围与业务状态分别存储，缩放后重建可见标记。
- **牵连**：`yoyo/evaluation/pine/spike_signal_cloud_v1_7.pine`；旧勾叉源`monday_range_v2_43.pine`；Pine的绘图对象上限仍适用，密集视图给出放大提示。官方说明：[文字与形状](https://www.tradingview.com/pine-script-docs/visuals/text-and-shapes/)、[执行模型](https://www.tradingview.com/pine-script-docs/language/execution-model/)。
