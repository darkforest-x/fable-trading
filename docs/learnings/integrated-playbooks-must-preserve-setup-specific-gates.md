# 整合交易观察流程时，共用证据但保留各模型的确认顺序

- **问题**：Notion 任务 53 希望把订单流、机构框架和 RektProof 共振监控，与任务 50 的 ETH 启动选龙头流程整合。两者共享市场背景，但龙头趋势延续与区间扫掠反转的必要条件不同。
- **死胡同**：若把所有条件压成一个共振分数，反转机会会被强势排名误删，延续机会会被迫等待扫掠；同一价格变化的多周期表现还会重复计票。这是本次设计排除的路径，未运行新实验。已有相关失败证据见 [共振票数不是信息量](confluence-votes-must-add-independent-information.md)。
- **有效路径**：共用数据来源、可用时钟、关键位版本与事件账本；分别维护趋势延续和区间反转的状态机。每个候选展示支持、冲突、缺失与下一确认条件。订单流证据和数据健康独立记录，缺失数据不能变成中性票，等待更久也不等于证据更强。
- **通用规则**：整合前先画出各流程的必要条件与失效条件，只合并相同的事实和基础设施。保持模型身份、确认顺序和失败样本，之后以单轴消融检验新增证据是否有价值。
