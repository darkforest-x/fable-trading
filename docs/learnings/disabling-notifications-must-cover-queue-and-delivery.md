# 关闭通知通道，需要同时封住新入队、旧队列和发送入口

- **问题**：Owner 要求全部周期提前发 Bark，并移除本机 Spike 的所有 TG 通知；旧 TG 配置、待发送项和启动测试入口仍存在。
- **死胡同**：只藏起前端 TG 徽章不会停止后台发送；仅去掉一个线程，模型还可能继续生成 TG 队列；删除共享凭据则会牵连其他服务。重启前旧进程也不会自动使用修改后的代码。
- **有效路径**：先停止旧监控，Telegram worker 和模型 TG 支路默认关闭，不读取凭据；生产不创建 TG 线程和配图。启动时只退休旧 pending，保留已发送与未知回执；探测入口同样禁用。新15m直接通知单独记首次启用时间，旧1H/4H与Bark队列保持。用禁止网络/读取凭据的替身验证默认关闭，以及假Bark收据验证正常推送。
- **通用规则**：用户说关闭一个通道时，沿“事件→入队→重试/恢复→实际发送→探测→页面”逐段核查；保留审计历史，别把删除凭据当作通知开关。
- **牵连**：`yoyo/monitor/service.py`、`model_gate.py`、`telegram.py`、`store.py`、前端与临时数据库测试。仅本机监控，不修改VPS/其他服务、模型规则或交易执行。
