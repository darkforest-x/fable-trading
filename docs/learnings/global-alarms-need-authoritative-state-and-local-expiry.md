# 全站报警用事件状态驱动，声音和过期由页面独立管理

- **问题**：全屏报警要跨页面持续、跨标签页同步确认，又不能为等待报警轮询后台；浏览器还要求声音由用户操作启用。
- **死胡同**：把报警放进页面轮询会增加接口负担并在切页时重复连接；只等待推送清空会让六小时过期的报警滞留，因为服务的空闲心跳不重新读取数据库。断线也不等于已有报警已经确认。
- **有效路径**：文档级单一 EventSource 接收完整 active 快照，确认携带明确 ID，失败不乐观关闭；服务器重启后的版本归零不能丢弃。客户端按服务器时间加单调时钟安排最近一次过期，不补轮询。Web Audio 仅在点击启用后循环，确认、过期和页面离开都停止；新报警到达时取消关闭动画。
- **通用规则**：报警存在、连接健康、音频许可、确认请求和动画生命周期是不同状态。不要用连接断开代替已处理，也不要用本地存储中的“声音开”冒充浏览器实际播放许可。
- **牵连**：`yoyo/monitor/spike_alert.py` 的 SSE/ack/六小时约定；`static/spike-alarm.js`、`spike-alarm.css` 和全站启动入口；全屏工作区需要为全局报警保留可交互区域。只确认本次创建的测试报警，不动交易或外部推送配置。
