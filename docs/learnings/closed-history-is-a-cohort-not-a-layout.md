# 历史开单是已结束记录集合，不是卡片的表格布局

- **问题**：初版“历史开单”只切换显示形式，沿用卡片的全状态集合；Owner 明确历史开单必须全为已结束记录、不分输赢，并需要针对这批记录详细统计。
- **死胡同**：只隐藏状态控件仍会展示运行中记录；在当前页过滤已结束记录会漏掉其他页，统计也会跟随翻页变化。沿用信号收盘日还会漏掉此前入场、今天结束的记录。
- **有效路径**：后端增加 `outcome=closed`，在分页前选取盈利、亏损及保本退出，按退出记录日过滤时间。全部已筛选记录用于统计及分组，之后才排序与分页；前端切换卡片/历史必须更新查询代际并清空旧结果。净 R 直接取已有退出投影，不再次扣成本。按同刻退出合计净 R 计算累计 R 回撤；同刻结果异号时无法确认连胜连亏，诚实显示缺失。
- **通用规则**：先确认一个页面名称所定义的记录集合、时间归属及统计分母，再决定是否能复用其他视图的查询。所有按顺序计算的指标都必须处理同时发生与缺失记录。
- **牵连**：`yoyo/monitor/signal_analytics.py`、`static/app.js`、`static/index.html`、`static/signal-history.css`、`tests/monitor/test_signal_history.py`。累计 R 是等风险参考，不能写成账户收益率或权益回撤。未修改模拟执行、成本或准入规则。
