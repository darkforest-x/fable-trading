# 增加锁利档位时，原保本价必须保持同一个开仓价

- **问题**：测试“0.5R保本，再在1.5R锁0.5R”时，新实现复用一个tick取整函数，把第一档的实际开仓价也重新floor/ceil。浮点除法即使对应真实整数tick，也可能略低于整数，让原保本价漂移一跳。
- **死胡同**：认为所有保护价统一取整更规范，并据此直接比较结果。这悄悄同时改变了旧第一档和新第二档，收益差不能全归给新增档位；合成测试只用100这样的整数容易漏掉。
- **有效路径**：第一档直接保留已验证的actual entry；只有新增的entry±0.5R价格需要按方向保守量化。已有跟踪止损算法保持原语义。添加实际小数价格、第二档未触发时与旧BE05逐笔退出完全一致的回归，修复后换新目录重跑，保留旧尝试记录。
- **通用规则**：单变量退出实验不仅冻结阈值，还要冻结旧价格的量化过程。为新功能抽象通用helper前，先证明未触发新功能时的经济行为与旧版相同。
- **牵连**：`spike_v1_v8_tier_lock.py`、`spike_native_v1_tier_lock.py`、对应测试，以及 `exp-spike-v1-v8-tier-lock-20260914-v1`。这是本次研究实现的修正，不能据此指称旧Pine或线上止损存在同一错误。
