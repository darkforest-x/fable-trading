# 有原始界面代码时，渲染原码比重新描述视觉更可靠

- **问题**：Owner 要求 Pro 完全采用指定 Stitch 项目，截图重画与重新解释 DESIGN.md 会持续改变布局和主题。
- **死胡同**：把设计文档里的另一组色值当成原稿实现，或按截图重新组织组件，都无法保证与实际导出的 HTML 一致。Stitch 画布还注入了自己的脚本与视口换算，不能把运行时 srcdoc 整体当作导出源文件。
- **有效路径**：保留 10 屏原始 HTML 与原生 DESIGN.md，直接编译各屏自带的 Tailwind 配置；独立行为适配，不改变原稿 DOM 与 utility classes。按相同宽度核对实际颜色、字体和组件坐标。原始源码与当前画板主体核对一致；画布把 vh 固定为 1024px 而 iframe 高度随内容变化，导致两页底部空白高度不同，不能为追逐画布注入行为篡改源文件。
- **通用规则**：有可导出原码时，原码是视觉实现契约。先逐字节保存，再区分外观、演示行为和真实功能；演示成功提示不能进入实盘验收。未验收的数据接入保持关闭，原稿预览明确为设计样例。
- **牵连**：`yoyo/monitor/pro/source/`、`yoyo/monitor/pro/build.mjs`、`yoyo/monitor/pro/delivery.py`；当前前端不替换、不启动第二套扫描或执行服务。原始项目：<https://stitch.withgoogle.com/projects/8978791379095391159>。
