# 持仓管理必须以当前价格和剩余仓位为准

- **问题**：开仓时可附带止盈止损不等于支持持仓管理。已有持仓需要修改/取消保护，也需要按当前剩余仓位的百分比平仓。
- **死胡同**：直接复用开仓价方向校验，会拒绝把止损移入盈利区间；只在前端用浮点数乘百分比，容易受过期持仓、挂单冻结和尾差影响。把百分比改算成“可平数量的百分比”又会悄悄改变 Owner 的持仓比例含义。
- **有效路径**：修改保护时用新鲜可平仓 bid/ask 校验，写入独立生效时间，仅允许之后的报价触发；清空保护不依赖行情。修改、撮合与平仓共用账本事务和幂等回执，导出保留修改及报价证据。后端按剩余仓位用 Decimal 计算比例，100% 保留精确剩余量，确认固定数量且重新核对挂单冻结；超量拒绝，不静默缩减。部分平仓保留剩余保护，自动触发时撤销同仓位限价平仓单。
- **通用规则**：开仓设置、持仓修改、部分退出是一条完整生命周期，不能只实现开仓表单。区分成本基准、当前触发基准、剩余数量和已冻结数量；用锁盈、部分平仓后再次取比例、修改与自动/手动平仓竞争及断网重试验收。
- **牵连**：`paper_desk.py`、`paper_desk_api.py`、`paper_desk_limits.py` 与前端 `paper-desk.js/css`。导出 schema v5 增加 `protection_updates`，旧仓位生效时间默认为空、原保护不变。本轮 152 项账本/API/保护测试、71 项边界和 61 项前端检查通过；隔离实测修改/取消保护、25% 市价平仓、剩余量的 50% 限价挂单及 100% 尾仓平仓，原始证据 `output/playwright/task54/management-*`。未改费率、真实交易接口或用户已有保护价。
