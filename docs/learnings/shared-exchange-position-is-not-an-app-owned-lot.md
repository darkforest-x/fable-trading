# Shared exchange positions do not identify an App-owned lot

- **Problem**: Hiding external trades did not remove same-symbol entry blocking. The old reconciler copied the exchange's combined quantity, average price and realized PnL, and could wait forever for a lifecycle close total equal to the original App entry.
- **Dead end**: Removing only the UI card or same-symbol guard would permit entry but immediately fail reconciliation. A combined stop sized before a partial App close could also exceed the remaining App lot. Exchange position IDs are not unique App trade lifecycles.
- **Effective path**: Inherit current cross leverage without a set-leverage request. Persist exact owned entry, close and protection-child fills, sort by execution time, and rebuild remaining average cost and fee-inclusive realized PnL from those fills. Keep every protection generation. Use the exchange position only as coverage/liquidation evidence, cap outstanding protection to the App remainder, and reject unknown reductions rather than fabricate App fills. Terminal receipts survive restarts and exchange retention.
- **Legacy boundary**: Old repeated App close requests could include external quantity after the App lot had already closed. A fixed migration cutoff allocates historical close fills only up to the then-remaining App quantity, prorates that fill's fee, and audits the excess separately. This exception never applies to new intents or future fills. A read-only cloned ledger recovered the observed stale close with zero exchange writes.
- **General rule**: Identify ownership by persisted exact order identities before interpreting account-wide aggregates. Display filtering, leverage scope, lot accounting and exit sizing must be reviewed together. A shared cross account still shares collateral and exchange liquidation; a virtual lot does not create exchange-level isolation.
- **Affected paths**: `yoyo/discipline_app/owned_lots.py`, `live_book.py`, `managed_orders.py`; stateful fake exchange acceptance in `tests/discipline_app/test_owned_lots.py`. Primary contracts: [OKX API v5](https://www.okx.com/docs-v5/en/) and [leverage scope](https://www.okx.com/docs-v5/trick_en/).
