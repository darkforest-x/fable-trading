# 递推指标的监控种子必须连续，确认值必须冻结

- **问题**：12H EMA20/50 同时用于新信号判定和多周期图表。监控每次只读最近300根，图表读取另一长度的历史；窗口左端变化会改变首值播种后的整条递推路径，云带接近交叉时可能改变方向。
- **死胡同**：只保证“读已收盘K”并不足够。每轮从滚动窗口首根重新计算虽然没有未来数据，却不能保证同一确认点在重启、轮询、图表缩放后仍是同一个指标值。缩短或加长窗口只改变误差，不能定义稳定契约。
- **有效路径**：监控持久化最后已确认K的时间、EMA20/50及连续根数；只续算新闭合K，断档重新预热。信号保存确认时的EMA和完整周一区间、入场、止损、目标。12H图表在信号点采用已保存EMA并向右续算；其他周期只改变显示，不改变信号计划。
- **通用规则**：跨扫描窗口、跨服务或跨图表消费递推指标时，先明确种子、递推状态、断档规则和不可变确认值，再讨论触发条件。用前缀不变性、重启续算和断档测试验证，而不是仅比较一张漂亮的图。
- **牵连**：`yoyo/monitor/cloud_signals.py`、`yoyo/monitor/static/cloud-signal-chart.js`、`tests/monitor/test_cloud_signals.py`、`tests/monitor/frontend_cloud_signals.test.cjs`。本次只是信号工程验证，不构成收益证据。
