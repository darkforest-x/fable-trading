# 整表读取后再按时间过滤不能保护 holdout

- **问题**：市场广度研究虽然只汇总开发期行，但初步试算先完整物化了包含开发期与 holdout 的合并交易账本，再按时间筛选。边界后的收益没有进入输出，也仍然构成一次 holdout 访问，试算数字不能作为开发证据。
- **死胡同**：把“没有打印、评分或保留未来行”当成“没有读取未来”。`pandas.read_csv()` 已经解析并在内存中构造整张表；事后的布尔过滤只能改变下游样本，不能撤销上游数据访问，也不能证明没有观察到边界后的字段。
- **有效路径**：废止初步试算，改为逐个按时间排序的 gzip 流读取。边界行先只解析承担截止时钟的字段，发现时间达到右开边界后立即停止，不再构造该行的 OHLCV、退出收益或 R 字段；跨边界退出的开发期入场也只读取退出时钟并跳过结果。用边界 poison row、跨边界入退场和追加未来后前缀不变测试固定这一合同。构建器先提交，再从该提交启动不可覆盖的新目录构建。
- **通用规则**：先证明 loader 的物理读取边界，再谈 DataFrame 的样本过滤。只要源文件混装开发期与受保护区，就必须用可审计的时间前缀读取器或预先冻结的物理安全前缀；任何整表加载后的筛选都按 holdout 已消费记录。
- **牵连**：`yoyo/evaluation/spike_market_breadth_study.py`、`tests/evaluation/test_spike_market_breadth_study.py`、`analysis/p1_spike_market_breadth_20260913.md`；开发边界为 `2025-09-10T00:00:00Z`，本轮 manifest 必须保留 `holdout_consumed=true` 与污染说明。
