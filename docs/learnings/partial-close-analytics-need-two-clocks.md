# 分批平仓的资金统计与整笔交易统计使用不同时间

- **问题**：一笔交易可以先减仓盈利，再在另一统计周期完全平仓；按最终退出时间搬移整笔盈亏会扭曲期间资金曲线，按减仓次数算胜率又会重复计算交易。
- **死胡同**：直接汇总前端最近 100 条已结束记录，既漏掉开放持仓的已实现收益，也截断历史。已结清订单与逐笔退出同时求和则会双计；同一时刻成交按任意数据库顺序更新峰值还会制造虚假的盘中回撤。
- **有效路径**：从一致性读取事务取得完整账本。资金、手续费和退出原因按每批实际平仓时间计入；胜率与盈利因子按完全结清时间及整笔最终盈亏统计。历史无分批记录的已结清订单只作一次只读会计回填。相同时间先合并净额，再计算曲线与回撤；绘图压缩保留极值，统计仍使用全部事件。
- **通用规则**：实现额回答“这段时间资金变了多少”，胜率回答“这段时间结清的交易结果如何”。分开标注时间归属和分母，并核对累计实现额与账户净值差额。缺失报价、手续费和账本缺口不得伪装成零。
- **牵连**：`reclaim_analytics.py`、`ReclaimPaper.analytics`、`reclaim-analytics.js`；27 项后端测试覆盖跨周期减仓、历史兼容、145 笔交易、同刻成交、缺失行情及只读接口。
