# 首次识别时间必须区分提前见到核心、启动时可用与完全漏检

- **问题**：v6 低延迟模型回放中，部分事件在规则启动前已经框到原核心，真正满足启动条件时却不再输出。把首次框出现直接当成可执行启动，会掩盖时间语义差异。
- **死胡同**：只在有命中的事件上报平均延迟，会删掉漏检分母；把启动前命中一律记作提前成功，或把启动后未命中都叫全程漏检，也都会误导。此次159个test事件中，3个在启动至核心后8根之间未匹配，但其中2个在更早时点匹配过，只有1个全程没有匹配。
- **有效路径**：先冻结每事件的规则可知时点，再逐闭合K线跑完全相同的输入和阈值。分开记录任意首次匹配、启动后首次匹配、仅启动前匹配、全程未匹配；没有命中的事件保留在总分母。原始逐图框和逐事件账本让这些分类可以复算。规则启动锚点仍是研究候选，不冒充人工时点金标。
- **通用规则**：先写清检测层输出的是形态核心还是启动确认，再定义首次命中。提前框到核心既不自动等于可以开单，也不自动等于误报；禁止通过事后锁存把启动时已消失的框补成模型当时仍在确认。需要锁存的状态机必须单独验证。
- **牵连**：`yoyo/evaluation/ma_early_evaluation_summary.py`、`tests/evaluation/test_ma_early_replay.py`；原始证据位于 `experiments/active/exp-ma-morphology-v6-threeview-20260925-v1/early_evaluation_summary_20260926_v1/`。本次没有变更模型、阈值或线上锁存逻辑。
