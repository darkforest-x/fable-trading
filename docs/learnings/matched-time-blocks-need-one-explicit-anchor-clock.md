# 匹配时间块必须统一使用同一个事件时钟

- **问题**：核心末根、确认收盘、下一根入场是不同时间。若匹配随机对照时混用它们的周号，跨周信号会找不到自己的分层。
- **死胡同**：以核心末根的 ISO 周创建目标，却只枚举确认 bar 处于该周的随机候选；周日晚核心、周一确认会被漏掉。另一个陷阱是从完整未来窗口的随机池推导目标波动桶，错误排除已提前止盈但源尾不足 12h 的真实目标。
- **有效路径**：明确本实验按核心末根 UTC ISO 周匹配；目标波动独立从其确认 bar 及之前连续 TR14 计算，随机池仍要求完整时间戳覆盖。完整候选账本只提供排除锚点，模型的已冻结 val/test 账本提供匹配目标，逐 ID 校验身份和标签一致；训练行不成为评估目标。新增跨周、尾部已解析事件、标签漂移和目标子集测试。
- **通用规则**：匹配键必须声明具体时间字段及其时区；不能依赖“同一事件的几个时点通常相近”。目标特征可计算性与对照候选资格应分开处理，缺样按原因记录，不换池补齐。
