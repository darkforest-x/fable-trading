# 排除新增信号不能切断已有持仓的行情

- **问题**：Owner 将历史表现较差的十个标的及非 USDT 线性永续移出扫描池，但已有参考持仓和真实持仓仍依赖同一批收盘 K 线计算退出。
- **死胡同**：直接在合约列表中过滤后停止抓取，会同时切断退出数据；只隐藏前端卡片又不会阻止后台产生新信号。这两种做法都混淆了新增准入与存量管理。
- **有效路径**：用共享规则约束新增信号，保留历史事件。扫描前读取现有参考状态和只读执行账本，为尚未结束的排除标的保留行情刷新，禁止其新增事件和通知；无法确认执行账本归属时保守保留行情。执行器新增入口另做相同拦截，管理入口继续可读。监控源规则可以单独重载；不能把磁盘上的执行器修改说成已加载到旧进程。
- **通用规则**：缩小交易范围前，先分别列出“允许新增”的集合与“仍需管理”的集合。历史展示不等于新增准入，删除历史也不是停用规则的方式。
- **牵连**：`yoyo/contracts/signal_universe.py`、`yoyo/monitor/signal_universe.py`、`v9_worker.py`、`v130_worker.py`、执行器 `source.py` / `engine.py`。只读执行归属失败不可静默当成空仓；现有 cutoff、策略参数及资金配置保持。历史负收益筛选是 Owner 的范围决策，不因此成为验证过的收益改进。
