# 原始 API 记录需要独立的可读对话层

- **问题**：模型设置把提示词、Schema、图片 Base64 和响应 JSON 当作主要阅读界面，用户无法快速理解发了什么图、模型回答了什么。
- **死胡同**：仅折叠 Base64、把输入输出分栏，仍然迫使用户从协议字段中寻找业务结论；把所有可解析 JSON 都显示成成功结论，还会掩盖服务端已经拒绝的响应。
- **有效路径**：从当次保存的请求提取真实识别要求和图片，从响应提取回答；按对话顺序展示。长要求、参考图、思考过程与技术正文逐层展开。只有已完成且符合结果约束的记录显示结构化结论，失败状态保留。原始记录和导出不改写。
- **通用规则**：可审计不等于默认展示底层协议。先提供符合用户任务的阅读层，再给原始证据入口；展示层不能变成另一条宽松的识别验收路径。
- **牵连**：`yoyo/vision_research/static/conversation.js`、`app.js`、`index.html`、`styles.css` 与 `tests/vision_research/conversation.test.cjs`。该对话界面展示独立识别请求，不意味着模型已获得多轮会话记忆。
