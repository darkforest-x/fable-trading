# 参考监控面板的密度时必须保留指标语义

- **问题**：把 NodeFlare 这类紧凑监控面板的视觉语言移植到交易信号中心时，连续统计条、细进度线和密集卡片很容易被直接照搬，但两种产品的数据含义并不相同。
- **死胡同**：按截图数量补齐统计格、给没有明确分母的交易指标添加进度条，或一味压小卡片，都只能得到外观相似的假仪表盘。第一次把卡片最小宽度压到 236px 后，常用桌面宽度出现五列，R 状态被挤窄；同时过浅的辅助文字在白色卡面上失去可读性。
- **有效路径**：先提取可迁移的视觉关系：冷灰画布、连续的真实指标条、低阴影、紧凑筛选、规则化卡片网格和克制状态色。再把现有 API 数据映射进这些关系，不增加虚构指标。最后用真实运行数据同时检查桌面、390px 手机、浅色和深色主题，并用对比度与卡片最小宽度修正视觉判断。
- **通用规则**：参考另一个领域的仪表盘时，先复用层级、密度和节奏，再逐项确认每个视觉编码是否有真实业务量支撑；没有分母就不画进度，没有新指标就不补空格。
- **牵连**：`yoyo/monitor/static/styles.css`、`design-qa.md`、主题 token、信号卡 R 状态、整卡 TradingView 点击层、桌面与移动端断点。
