# 原始过滤字段必须跟随交易账本跨越信号分页

- **问题**：spike 已把触价时的 `ema_order` 存在信号表，但持仓/历史交易接口只联结入场评分。前端即使新增账户选择，也无法稳定解释每笔交易为何计入资金或成为影子单。
- **死胡同**：只添加账户名称，或从最近 100 条触价记录临时查排列分，都没有补齐历史交易的契约。交易仍在账本里时，原信号可能已离开触价分页；现场重新算分又会把后来的行情当成当时的依据。本次在实现前排除了这两种捷径。
- **有效路径**：在既有只读 SQL 联结中一起返回原始 `score` 和 `ema_order`，由交易的 `taken/notional/note` 解释实际资金分配。零分显示 `0/4`，旧记录缺失保持未知；`order_*`、`order_missing`、`no_slot` 分别展示原因。用原信号退出最近 100 条后仍可读取历史排列分的行为测试验证。
- **通用规则**：新增账户前先沿“原信号 → 交易记录 → API → 路由/启动预取 → 统计/操作预估”检查身份和语义。原始过滤值、实际分配结果与当前行情是三种不同事实，不能相互推断。新账户独有的结算封顶也要进入前端预估，参数从后端配置读取。
- **牵连**：`yoyo/monitor/monday_reclaim_paper.py`、`static/monday-reclaim-paper.js`、`static/startup-hints.js`、`static/reclaim-analytics.js`、`static/reclaim-close.js`。只读字段与前端适配不改变策略门槛、账户资金或执行规则。设计来源：Stitch `f56301aa72694cb58f4450afb088c191`。
