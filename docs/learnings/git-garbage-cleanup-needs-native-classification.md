# Git 清理必须以原生垃圾分类为准，不能按大小或修改时间删 pack

- **问题**：2026-09-22 磁盘再次接近满载，`.git/objects/pack` 同时存在约 32.73 GB 的有效 pack 和三个各约 1.21 GB 的 `tmp_pack_*`。有效 pack 的近期修改时间不能证明它是本次新增占用。
- **死胡同**：只找最大的文件、最新修改的 pack，或把整个 `.git` 当缓存，会混淆可清理的中断残留与不可丢弃的版本历史；文件时间也不能代替此前实际占用的基线。
- **有效路径**：先用 `git count-objects -vH` 获取 Git 明确报告的 `garbage found` 路径，再限定为具体的 `tmp_pack_*` / `tmp_obj_*` 文件。核对没有 Git 写入进程和打开句柄，文件超过一小时未修改，删除前 inode、大小、mtime、ctime 与记录一致。本轮删除五个已核实垃圾文件，分配空间合计 3,681,316,864 字节；有效 `pack-*` 文件的身份与时间快照保持一致。事后 Git 仍为两个有效 pack、30.51 GiB；其余三个约 852 KiB 的垃圾文件未在本次删除清单内。
- **通用规则**：原生分类确定对象性质，文件身份与使用状态确定当下是否能删。按明确清单清理，不能将规则扩展为所有临时前缀或所有大文件；也不能用一个近期时间戳解释完整磁盘增量。
- **牵连**：本机审计在 `/Users/zhangzc/.local/state/disk-cleanup/20260922/git-garbage-cleanup.json`；本轮没有改写 Git 历史、分支或提交。重复出现的工作区路径清单残留是另一项已清理占用，应用产生并保留它们的根因尚未修复。
