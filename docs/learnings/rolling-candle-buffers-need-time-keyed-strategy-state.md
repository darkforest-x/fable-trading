# 滚动 K 线缓存里的策略状态必须按时间存

- **问题**：VIDYA 回踩实时模拟盘每轮把新 K 线并入内存数组，数组超过上限后会截掉最旧的部分。策略状态（等待确认的碰线、待成交单、持仓的信号/碰线/入场位置）最初沿用回测里的数组下标，截断或重启后下标整体平移，状态会指向错误的 K 线。
- **死胡同**：每轮从头回放全部历史可以避开下标问题，但会把启用前的确认当成实时信号重新开仓，也让重启后的结果依赖当时取到的历史长度。
- **有效路径**：持久化时把状态里的下标全部换成 K 线开盘时间，下一轮读入时按当前数组重新映射；不在内存里的时间对“等待确认”直接作废，对持仓只影响展示字段。每轮只处理晚于上次处理时间的新 K 线；补算时收盘超过 30 分钟的确认只记录不开新仓。测试 `test_live_worker_reproduces_offline_engine_bar_for_bar` 逐根推进实时进程，与同一数组上的离线引擎逐笔对比入场、出场时间和 R，完全一致。
- **通用规则**：任何会滚动、截断或重新拉取的行情缓存，状态主键用交易所 K 线时间而不是数组位置；实时与回测共用同一个逐根步进函数，并用逐根推进的对照测试锁住两者一致。
- **牵连**：`yoyo/monitor/vidya_retest.py`（`Strategy.on_bar`、`State`）、`yoyo/monitor/vidya_retest_worker.py`（`state_to_times` / `state_from_times`、`step_symbol`）、`tests/monitor/test_vidya_retest.py`。
