# Closed-candle refresh should follow the data boundary

- **Problem**: The Monday wallpaper fetched 720 closed candles every 15 seconds even on 1H/1D. Quote polling rebuilt hundreds of list rows; chart refresh recreated price lines and rewrote the viewport, adding interaction work without new information.
- **Dead end**: A series-level diff alone was already present. It skipped identical candles but did not skip surrounding DOM replacement, price-line creation, axis options, or viewport writes. Making the poll faster would multiply those costs and would not remove public-network latency.
- **Effective path**: Keep the live quote cadence separate from closed-bar cadence. Schedule candle reads from server time and the actual last closed candle, retry lagging tails, merge new pages only after a real overlap with cached history, and retain per-symbol chart views. Patch volatile list values in place and cache formatters. Cache overlay indices outside pointer/scroll callbacks and coalesce drag writes per animation frame.
- **General rule**: Before tuning a refresh interval, identify which facts can actually change at that interval. Measure request counts, DOM replacements, and viewport writes separately from HTTP latency. Never label a successful but old upstream response fresh using the request time.
- **Scope**: `yoyo/monitor/monday_candles.py`, `monday_fib_service.py`, `static/monday-fib*.js`, `static/range-chart.js`. Compact GET preserves quote/anchor/touch semantics; the full endpoint remains compatible. Closed candles stay closed, NY Monday anchors remain monitor-owned, and scanner/trading parameters are unchanged. Measurements: `output/monday-perf-20261023/`; Node DOM-stub timing is not a browser frame-time claim.
