# 负结果的报告必须允许稀疏分组

- **问题**：冻结阈值在最终验证段可能只保留不足六个候选，但 overview 构建器硬要求六张 KEEP 加六张 REJECT。模型越差，报告反而越无法生成，交付链路会系统性漏掉最需要保留的负结果。
- **死胡同**：把 overview 的固定版式当作数据完整性门。固定十二宫格只验证了排版方便，并不能证明样本充分；为了凑满格子而复制、放宽阈值或换入别的样本还会污染预注册结果。
- **有效路径**：把“至少有一张已交付且哈希匹配的图”作为完整性门，每组最多取六张并按真实数量动态缩排。某组为零时仍诚实展示另一组；只有整个图清单为空时才 fail-closed。
- **通用规则**：结果报告的呈现基数必须由冻结实验结果决定。版式应适配零散、单边或失败结果，绝不能要求实验结果反过来满足版式。
- **牵连**：`scripts/build_15m_ma_launch_l2_global_context_report.py`、`tests/test_build_15m_ma_launch_l2_global_context_report.py`；不改变模型、阈值、扫描数据或任何收益指标。
