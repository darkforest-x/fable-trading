# 历史图层要同时更新信号集合与文字层级

- **问题**：历史交易框已经补载，确认 K 线仍为灰色；目标价和 R 在大阳线上被盖住。历史风险填充还与云带叠成红色阶梯。
- **死胡同**：只把历史框调亮无法修复确认 K 的单条信号判断；把文字放在同一个底层 primitive 的最后绘制，也只能盖过自己的填充，仍会被随后绘制的蜡烛覆盖。
- **有效路径**：从当前合约的已存与补载信号共同生成关键时间集合，每次历史回调触发已有 renderer 重绘。复用已包含颜色的同步快照，实体、影线、边框和成交量一起更新，不改变 OHLC 或视口。底层画云带与参考区，上层独立画价格/R 标签并避让。历史风险区取消填色，只保留止损边界。
- **通用规则**：遇到“框存在但高亮缺失”，先追踪两者是否消费同一个事件集合；遇到文字遮挡，先查跨 primitive/series 的绘制顺序，不能只看一个绘制函数内的先后。
- **牵连**：`cloud-signal-chart.js`、`range-chart.js` 及两者的前端测试。参考框仍固定在确认时目标；后续行情高点不是计划目标或已实现收益。
