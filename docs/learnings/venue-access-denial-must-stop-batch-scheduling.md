# An exchange-wide access denial must stop batch scheduling

- **问题**：The public Binance funding batch returned its first HTTP 403 on ATOMUSDT's second page. The per-symbol worker caught the error and continued to other symbols, eventually preserving 128 separate denied requests before the process was stopped. Other venues remained healthy.
- **死胡同**：A shared 0.8-second request budget and per-symbol exception handling do not contain an exchange-wide denial. Treating each subsequent symbol as an independent recoverable failure continues the same denied operation. The response was only an HTML “403 Forbidden”; it did not establish whether the cause was regional policy, a WAF, rate limits, or another restriction.
- **有效路径**：Stop only the affected venue process; retain immutable successful pages, normalized market manifests, denied-response receipts, and an explicit partial/blocked manifest. Preserve the distinction between a completed empty API response, a partly fetched symbol, and a symbol never attempted. Continue unaffected venues and report funding coverage as incomplete.
- **通用规则**：A batch collector should share a venue-level stop flag across workers. A non-retryable access denial must stop new scheduling and cancel pending work without changing domains or retrying every symbol. A stop flag is separate from a rate limiter. Missing funding remains unknown rather than becoming zero cost. Do not change a collector's on-disk source while running jobs use its source hash as provenance; introduce and validate the containment fix after those jobs finish.
- **牵连**：`yoyo/data/altseason_funding.py`, `yoyo/data/altseason_sources.py`; evidence is in `experiments/active/exp-altseason-multivenue-20260910-v1/data/funding/binance_funding_partial_blocked_manifest.json`. The first denial occurred at 2026-09-09 17:55:34.096 UTC. The interrupted Binance batch had 71 completed symbol manifests, including 60 nonempty and 11 empty responses; no complete funding-cost claim is supported.
