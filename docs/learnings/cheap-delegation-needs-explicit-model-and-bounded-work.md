# 节省主模型额度，要同时控制子模型继承和委派粒度

- **问题**：Owner持续使用Astra Ultra，要求保留主模型，通过轻模型分工降低消耗。原全局配置没有子代理默认模型，未指定模型的委派可能继承昂贵的主模型；已有角色又各自固定不同模型，不能只看主会话选择。
- **死胡同**：把“多开代理”直接等同于省额度，或只安装角色而不设置模型、档位与适用工作范围。委派还会增加背景说明、工具调用和整合成本。没有做过的节省比例不能从API单价或角色数量推算。本轮没有采用修改主模型或整包安装174个上游角色的路径。
- **有效路径**：保留Astra Ultra，明确默认子代理为Luna Max；新增三个Luna Max读取角色和三个Terra High工程角色，限制两个并发子代理，每个新角色禁用继续委派。用全局路由指令和skill区分简单本地工作、可独立委派阶段与主模型决策，并保留Sol使用可见Luna Max任务的owner约定。逐字段确认原配置未被改写，用原生app-server的config/read核验有效默认值，再用独立Luna Max进行五个决策场景演练。当前会话尝试新角色名返回unknown agent_type，因此明确记录需要新任务/刷新发现；没有把文件安装等同于会话热加载。
- **通用规则**：验收分为配置结构、宿主识别、实际模型/档位与真实任务成本。先消除昂贵继承与无效重复，再讨论节省多少。按整段有用工作委派，明确文件/数据范围和证据要求；不要为了省额度放松holdout、生产授权或必需质量门。
- **牵连**：[使用说明](../ops/CODEX_DELEGATION.md)；本机 `~/.codex/config.toml`、`~/.codex/AGENTS.md`、六个 `budget-*.toml`、`quota-aware-delegation` skill。配置变化不等于既有运行会话自动刷新；五场景演练验证了分工判断，不是成本benchmark。
