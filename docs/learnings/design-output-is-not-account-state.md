# 设计稿决定信息层级，真实接口决定账户状态

- **问题**：首页实盘露出只有等权重的小指标和长脚注，Owner 要求通过 Stitch 重新设计；设计生成器又在稿件中添加了执行就绪、实时推送和不存在的比例字段。
- **死胡同**：仅根据“生成成功”的文字就认为图与代码齐备，或直接复制生成代码，会同时漏掉不可下载的桌面稿，并把示例状态当成真实账户事实。
- **有效路径**：先核验实际图片和 HTML 导出，缺失时在 Stitch 修复；取得桌面与手机稿后，接入主权益、次指标和手机账户切换层级。资金、数据新鲜度、执行状态、结算归属分别映射已有只读接口，两个账户独立展示；加载、过时和未授权不显示为已同步。
- **通用规则**：UI 设计工具产物是视觉来源，不是业务数据契约。先对照可用字段删掉设计稿的虚构项，再核对真实数值、权限丢失、手机切换、刷新焦点和详情入口。
