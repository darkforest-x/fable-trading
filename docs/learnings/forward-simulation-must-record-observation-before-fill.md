# 前向模拟必须先记录观察，再决定可成交的时间

- **问题**：统一策略和前向模拟时，原信号卡已有按历史下一根开盘计算的收益，很容易直接拿来充当新模拟账本。扫描收到信号时，那个开盘通常已经过去。
- **死胡同**：直接复制信号卡的 `performance`、把旧影子观察重命名为模拟实盘，或者仅在页面隐藏历史信号，都不能证明当时有可执行的订单意图；重启后补入旧信号也会污染前向边界。
- **有效路径**：把策略版本、运行、订单意图、成交模型和结果拆开。先持久化实际观察时间，再安排严格晚于该时间的开盘；旧回测次开单独保留。复用原退出内核，固定成本，冻结代码及已消费行情，暂停/恢复设置新准入切点，停止仅截断观察而不编造平仓。
- **通用规则**：设计任何前向验证平台时，先检查 `signal_close <= detected_at <= observed_at < scheduled_entry_open`，再谈收益。未观察到的成交、资金费、盘口和账户容量，必须与已实现的模拟范围区分。
- **牵连**：`yoyo/research_workspace/strategies.py`、`paper_source.py`、`paper_store.py`、`paper_worker.py`、`paper_api.py`；既有 20bp 成本、冻结退出、新鲜度与生产准入门保持原义。架构参考 Freqtrade 的策略/run、Nautilus 的独立成交模型及 LEAN 的模块拆分。
