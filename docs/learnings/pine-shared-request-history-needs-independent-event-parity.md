# 跨周期一致仍可能一起漏信号，必须用独立原始数据核对事件

- **问题**：V2.2 的 5m 状态机在 1m、5m、1H 图均给出相同的 7 次入场，且源起点显示 2026-07-07。但已有 OKX 分钟数据独立重采样后，同一窗口有 25 次合格入场，遗漏集中在 9 月中旬之前。
- **死胡同**：只验证不同图表周期的签名相同，不能发现它们共享的错误；把嵌套 1H/15m 请求的 `calc_bars_count` 单独提高到 30000 无效。怀疑 `bar_index` 暖机门并改成实际历史值有效性检查，也没有恢复遗漏。不能把这两次尝试写成已证实的根因。
- **有效路径**：分钟原始数据按完整 5m/15m/1H 收盘聚合，用同一时序但独立实现的 Stoch 与观察逻辑定位缺口。检查整份脚本，发现更早的区间模块已有 3200 根 15m 请求，约对应缺口边界。只把该共享周期的较短请求在交易参考开关开启时扩大到 12000 根，原生结果立即从 7 恢复为 25；最近入场价、止损价和方向与独立数据一致。关闭时仍用原来的 3200。此结论是本脚本的原生实验证据，不把未文档化的行为推论成所有 Pine 请求的一般保证。
- **通用规则**：跨周期签名相等只证明显示一致。多模块合并时，先盘点全脚本同品种、同周期的请求范围，再用独立来源逐事件核对时间、方向、价格与路径；计数异常不能只调新增请求。显示保留数也不能替代持仓退出规则，超出显示数的未结束参考仍继续跟踪。
- **牵连**：`yoyo/evaluation/pine/monday_range_v2_2.pine`，`yoyo/evaluation/monday_range_v2_2_reference.py`，`tests/evaluation/monday_range_v2_2_native_checks.pine`。证据在 `output/pine/monday_range_v2_2_native_shared_history_fix.txt` 与 `output/pine/monday_range_v2_2_reference.json`。这是工程正确性检查，不能据此认定交易系统盈利或准入实盘。

补充边界：切到 5m 图时，同周期请求的源起点变为 2026-09-13，属于图表实际可用历史较短；指定 indicator calc_bars_count=30000 也未扩大。此时 7 次入场与该较短源窗口的独立计算一致，不得把不同覆盖范围的总数宣称完全相同。数据窗口保留真实源起点，并在设置提示中说明历史上限不是保证。
