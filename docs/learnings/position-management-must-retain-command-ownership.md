# Position management must retain command ownership through lost replies

- **问题**：A quick ticket can display account positions without owning them; a close or stop button needs stronger evidence than a matching symbol. A lost confirmation or exchange reply must not create another mutation.
- **死胡同**：Routing every row to a symbol-level close endpoint would merge externally owned and strategy-owned positions. Treating every API error as rejection would also unlock a retry after OKX 50004, whose outcome is explicitly unknown.
- **有效路径**：Keep strategy lots on their original command queue. Free-manual previews bind account, original order, position quantity/side and exact protection; revalidate before execution. Persist each exchange mutation phase before POST, then reconcile by its original order identity after timeout/restart. Browser pending identities survive sheet reopening. Amend only stop fields; paper TP preservation reads the latest TP in the same transaction.
- **通用规则**：A management surface must reuse the record's existing owner, then prove the mutation outcome with a receipt. A timeout is not permission to send a new command. A backend revision gate prevents rendering enabled controls before the worker supports them.

Synthetic tests cover ownership drift, separate confirmation, lost replies/restart, exact protection, preserved TP and blocked duplicate requests. [OKX API FAQ](https://www.okx.com/en-us/help/api-faq) confirms 50004 can mean success or failure (checked 2026-10-24).
