# Immutable replay pages need status-only polling

- **问题**：历史回放首页已成功后，15 秒刷新仍重取同一页；它会与所选卡片的同源 OHLC 图并发，并在浏览器中止后继续占用服务端同步 JSON 工作。
- **死胡同**：把实时与历史列表共用一个定时刷新入口，认为客户端 `AbortController` 足以限制负载。中止不会取消已开始的同步服务端序列化，因此下一次定时刷新仍会叠加。
- **有效路径**：给刷新调用标注手动或定时来源。已加载的回放 family 在定时 tick 只读取轻量运行状态；首次失败仍会由 tick 重试，手动刷新、进入回放、筛选变化和游标翻页仍读取相应历史卡片。队列保留手动操作优先级。
- **通用规则**：先区分内容是否会变化，再决定轮询范围。不可变浏览内容完成加载后轮询状态，不轮询相同内容页；查询失效和显式用户动作必须继续走真实读取路径。
- **牵连**：`yoyo/monitor/static/app.js` 的回放/实时刷新与游标序列化；`tests/monitor/frontend_cards.test.cjs` 保护定时、手动、失败重试和实时刷新边界。该调整不改变信号、通知或服务端数据。

- **验证边界**：静态源码匹配不能证明轮询分支。使用 Node `vm` 截取绑定前的客户端闭包、最小 DOM 与 fetch mock，实际执行 `refresh`，断言已加载回放、手动刷新、实时刷新、首次失败重试和游标排队的请求集合。事件监听器必须显式调用 `refresh()`；直接传递函数会把 `MouseEvent` 当作触发类型，破坏手动操作的队列优先级。
