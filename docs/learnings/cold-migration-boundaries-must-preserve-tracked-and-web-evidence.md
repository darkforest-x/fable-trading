# 冷数据迁移的边界必须保留 Git 摘要与网页证据入口

- **问题**：继续迁移大文件时，同一个实验结果目录同时包含未跟踪的大型交易明细和已提交的小型摘要；目录大小不能决定是否可以整体替换成外盘软链接。
- **死胡同**：按目录体积直接搬迁会把受 Git 管理的摘要一并移走。只验证本地软链接也不够：网页数据集和实验证据各有自己的路径许可规则，磁盘可读不等于 HTTP 可读。
- **有效路径**：先按具体候选检查 `git ls-files`、数据集索引与产物登记。完整未跟踪的冷目录可整体迁移；混合目录只迁未跟踪的大文件，保留父目录及摘要。网页行情沿用已登记外盘机制，保留数据集 ID、路径、计数，并在释放本机副本前验证实际后台与 HTTP 读取。此次压缩明细不属于现有网页证据下载范围。
- **通用规则**：迁移粒度服从文件的使用边界。先确认写者、Git 和消费者，再选文件或目录作为迁移单位；本机软链接应使用精确的本机排除规则，避免被误提交。
- **牵连**：Notion #52 追加批次记录位于 `data/_storage_migrations/20261016-task52-more/`；Owner 明确取消哈希检验，本批仅核对复制结果、路径、数量、大小、时间及实际读取，不声明内容逐字节一致。有效 Git 对象、运行数据库和当前行情写入目录保留本机。
