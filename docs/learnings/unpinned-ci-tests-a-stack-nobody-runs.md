# CI 不锁版本，测的就不是产出数字的那套栈——而且两个方向都会骗人

**日期**：2026-08-20（PR #1 第二次 CI 失败）
**结论**：`requirements.txt` 全是 `>=` 无上界，CI 因此装到
pandas **3.0.5** / numpy 2.4.6 / torch 2.13.0，而 Mac 与 3060 跑的是
pandas **2.3.3** / numpy 2.0.2 / torch 2.8.0。

## 现象

修好依赖漂移之后，CI 只剩一个失败：

```
ValueError: OHLC start is not aligned to the frozen holdout boundary
tests/test_build_eth3m_short_pilot_dataset_v2.py
```

本机跑同一个测试：通过。CI 复刻环境（当时是 3.9）：也通过。

## 根因

翻 CI 日志里的 `Successfully installed`：

```
pandas-3.0.5   numpy-2.4.6   torch-2.13.0   opencv-python-5.0.0.93
```

本机是 pandas 2.3.3。差了一个大版本。

出事的那行是测试自己写的时间戳换算：

```python
"ts": times.view("int64") // 1_000_000     # 假定纳秒
```

pandas 3.0 起 `date_range` 的默认时间分辨率不再必然是纳秒。
分辨率一变，这个手工除法就算出错误的毫秒时间戳，
于是被测函数读到一个 1970 年附近的起点，判定「未对齐 holdout 边界」——
**报错信息指向 holdout 对齐，真正的原因是一行单位换算。**

全仓同样写法共 4 处，都改成显式的 `as_unit("ms").astype("int64")`：
把分辨率写出来，而不是假定。改写前后在 pandas 2.3.3 上数值逐位相同（已验证）。

## 真正的问题比那个测试大

**浮动版本让 CI 两个方向都在骗人：**

| CI 结果 | 你以为 | 实际可能是 |
|---|---|---|
| 绿 | 代码没问题、数字能复现 | 只说明代码在**另一套库**上没问题 |
| 红 | 代码有问题 | 只是新版库改了个 API，与代码无关 |

对这个项目尤其致命：整套纪律建立在**数值可复现**上。
一个跑在 pandas 3.0 上的绿色 CI，对「这些数字还是不是当初那些数字」一个字都没说。

而且项目**早就有**一份跨机版本契约：`scripts/train_on_3060.sh` 在 Mac 与 3060
版本不一致时直接拒绝开训，理由写在脚本里——「结果无法与历史曲线对照」。
CI 是第三台机器，却一直被排除在这份契约之外。

## 处置

`constraints-ci.txt` 锁到 Mac 实际跑的版本，CI 用
`pip install -r requirements.txt -c constraints-ci.txt`，Python 版本也从 3.11 改回 3.9
（不同解释器会解析出不同依赖集，这本身就是漂移的一个来源）。

`requirements.txt` 保持 `>=` 不动——它声明的是**依赖**；
`constraints-ci.txt` 记录的是**契约**。两者角色不同，不要合并。

守门：`tests/boundaries/test_ci_installs_from_requirements.py` 断言
①CI 用了约束文件 ②每个声明的依赖都被锁 ③**锁的版本 == 本机装的版本**
④Python 版本是 3.9。第 3 条最有用：本机 venv 一漂，CI 立刻不再代表现实，测试当场红。

## 可迁移的判断

- **区分「依赖声明」与「版本契约」。** `>=` 回答「至少要什么」，锁文件回答
  「产出这些数字的是哪一套」。任何以数值可复现为前提的项目，两者都需要，且不能互相替代。
- **CI 用和生产/研究不同的解释器版本，等于给自己开了第二套依赖解析。**
  它不会报错，只会在某天以一个看起来毫不相干的断言失败的形式出现
  （本次是「holdout 未对齐」）。
- **报错信息指向的位置，和根因的位置，可以隔着好几层。** 先看环境差异
  （版本、解释器、平台），再读代码——本机通过而 CI 失败时尤其如此。
- **凡是手写的单位换算（`// 1e6`、`* 1000`、`.view("int64")`）都是一个待爆的假设。**
  用能把单位写进代码的 API（`as_unit`、`astype("datetime64[ms]")`），
  让版本升级去改语义时能直接报错，而不是静默算错。
