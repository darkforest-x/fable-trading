# 通知必须绑定用户实际看到的图表标记

- **问题**：用户说“出信号才通知”，上一轮把“刚突破零轴”直接解释为md前根等于0。规则本身通过了测试，却仍不是图上可见的箭头。
- **死胡同**：根据中文术语和本地代码里的候选变量推测用户指什么；继续加精确零轴契约，只会更可靠地发送另一种事件。原系统longSignal也不是答案，因为用户当前把普通系统标记关闭了。
- **有效路径**：先读取真实TradingView参数与可见标签，再回到Pine的绘图分支。当前showFocus=true/showMarks=false，目标是focusRelease价格标签。ETH4H实际“44根/1922.23”在公开OKX数据完全复现；原始离轴1911.20比它早两根4H，8小时。这个正反例才足以确定通知语义。
- **通用规则**：用户说“箭头/提示/信号”时，先查所用脚本、输入与显示开关，找一根实际可见标记，核对生成时刻、位置和数值；把该绘图条件绑定到通知，禁止用视觉上接近的内部状态替代。
- **牵连**：当前TV参数为快照，不会自动同步未来手动修改。前两轮报告保留历史，其中零轴定义的语义验收已被本次可见标记证据取代。生产、收益结论和下单权限不变。
