# Pine 绘图预算必须通过图表实际运行验证

- **问题**：IMACD V2.1 新增影线回踩高亮与信号收盘价后，源码通过 TradingView 编译并保存为云端第 5 版，图表实际执行却报 `RE10140`：生成 66 个 plot counts，超过 64 上限。编译和保存成功没有证明指标可以正常运行。
- **死胡同**：实现时手算为 52，把颜色参数的实际限定符与绘图资源计数判断得过于简单，并据此错误宣称仍有余量。绘图调用数不是 plot counts；同一个调用可因多个 `series` 参数占用多份名额，颜色、蜡烛影线与边框等参数也可能贡献计数，`alertcondition` 同样占用预算。只数源码里的 `plot` 或看到编辑器保存成功，都不能代替图表运行结果。此轮实际错误明确为 `66 > 64`，初次 52 的估算应保留为失败记录。
- **有效路径**：将多空方向与有无文字组合出的 4 条普通入场 `plotshape` 合并到现有普通系统标签队列。价格显示开启时用两行收盘价标签；关闭时用小三角标签，可选“多／空”文字。原系统确认时点与同根去重规则不变，2 个退出叉保留，原核心、警报、近零状态和回踩判断不动。标签对象与 plot counts 使用不同资源预算，因此必须同时保留队列回收：80 个蓄势段最多 240 个标签，加上最多 80 个普通系统标记，稳定上限 320，先创建再回收的瞬时上限 321，声明 `max_labels_count=350`。父任务记录修复版于 2026-09-08 00:19 保存为云端第 6 版，并通过官方编译与图表实际运行，双线、清晰零轴及 `2488.00` 收盘价标签均已显示。修复后的具体 plot counts 没有被运行界面显示，不能继续编造一个“精确剩余预算”。
- **通用规则**：Pine 交付至少拆成源码／编译、图表执行、目标场景三层证据；编译或保存只能证明前一层。静态绘图估算用于预警，不能当作运行验收。遇到资源超限时，应从官方运行错误确认实际数值，再将互斥或重复的视觉表达合并；改用对象后必须另外计算对象上限、瞬时峰值与回收纪律，不能把一种资源泄漏换成另一种。参见 [TradingView 官方绘图限制](https://www.tradingview.com/pine-script-docs/writing/limitations/#plot-limits)：多个 `series` 参数与警报可累计 plot counts，而标签、线和框对象不产生 plot counts。
