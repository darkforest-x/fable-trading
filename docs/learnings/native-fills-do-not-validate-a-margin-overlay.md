# 原生成交账本不能替资金和强平后处理提供验证

- **问题**：解释1m模型AUC提升、162组资金结果全部亏损时，之前把“1000U最终约612U”直接表述为账户结论。源码显示逐笔成交使用Nautilus，但最终资金倍数、强平和回撤由`frac()`另外计算。
- **死胡同**：根据“用了框架”或“逐笔平均收益为正”就认定后续账户计算可靠，再直接归因于模型无用、杠杆或市场。原摘要中59/162组逐笔平均为正，资金结果却均为负，说明必须区分评价对象，不能仅看最终数值讲故事。
- **有效路径**：分层核对源码：1m模型标签是近端退出净收益是否大于0，未学习远端收益或亏损幅度；`frac()`每笔使用已实现资金的1/10作保证金，3倍杠杆，满额跳过；按整段MAE是否达到32.333%判断强平，却在原退出时刻才扣保证金并释放名额，回撤也只在已实现退出时更新。`load_symbol()`的MAE来自5m区间极值，非原生逐时点强平事件。此处已确认是简化近似，尚未量化它对结果的方向和幅度，不宣称修正后一定盈利。
- **通用规则**：明确模型标签、逐笔净收益、资金分配、逐时点保证金和回撤的各自来源。原生交易引擎通过不等于后处理账户也通过。解释原因先引用可复现分解；不能从简化资金结果推出模型彻底无效，也不能把降低杠杆当成已验证补救。
