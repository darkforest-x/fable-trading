# Latency ceiling is not a training distribution

- **问题**：Owner曾说最多可接受10根延迟，这个风险上限被错误展开成0-10根训练与验收分布，甚至保留6-10根样本；同时输入窗口20-30根也被写成固定合同。
- **死胡同**：把“可以忍受”当成“应该覆盖”，再靠多位置、多延迟均匀抽样增加所谓鲁棒性。这样会主动训练模型依赖更长后文，并让检测窗口持续偏宽，违背尽早、精准识别的目标。
- **有效路径**：把三个量拆开：核心边界由语义决定；确认延迟收紧为3-5根（3优先、5封顶）；输入上下文从最短充分窗口动态扩展，首轮只试约14-22根并继续按precision向更短收缩。旧delay6-10和固定W20-30只保留为失败证据。
- **通用规则**：上限只负责淘汰不可接受方案，不应自动变成采样目标。任何“最大可接受X”都必须另写preferred、hard ceiling和搜索方向，避免训练分布向最坏容忍值漂移。
- **牵连**：`AGENTS.md`、`CLAUDE.md`、`HANDOFF.md`、`PROJECT_PLAN.md`；delay3/4/5验收；动态14-22根首轮窗口；Stage A复用边界；后续hard-negative匹配。
