# 模型状态提案之后的代码门不应强迫同一根发生状态切换

- **问题**：模型先提出一个持续数根 K 线的密集/启动状态，但后级代码要求提案端点恰好完成均线首次穿越，导致已经站在目标侧的全部提案被拒绝。
- **死胡同**：把“当前处于有效状态”和“当前刚从无效切换到有效”写成同一个两 bar 谓词。模型提案存在检测延迟时，转换事件早已发生，后级再精确也只能稳定得到假阴性。
- **有效路径**：按层拆语义。模型负责何时存在候选状态；代码只验证提案端点的当前方向性约束，并把重叠 proposal 去重成事件。首次穿越若仍有业务价值，应作为独立时间戳记录，不能成为状态提案的必要条件。
- **通用规则**：先判断上游输出是“状态”还是“事件”。状态 gate 检查当前成立；事件 gate 才比较前后两根。删除事件条件会改变接受率，但不会让信号早于上游首次输出。
- **牵连**：`yoyo/layers/l1_detection/model_first_standing.py`、`scripts/diagnose_1h_filusdt_model_first_standing.py`、P2 causal-onset 门、holdout 单变量纪律。
