# 固定金额和仓位倍数必须共用同一套成交校验

- **问题**：模拟开仓新增 USDT 金额输入，需要与已有权益倍数模式一致；合约杠杆仍只决定保证金。
- **死胡同**：直接把输入金额当保证金，或在前端先换成整数仓位倍数，会改变用户要开的敞口。验证金额失败后若已经置 busy，也会把整个表单锁住。
- **有效路径**：两种模式互斥提交。固定金额除以实际报价得到基础币数量，向下舍入，再进入原有保证金、费用、风险档位、止盈止损与报价时效校验；成交仍使用冻结报价和幂等回执。输入校验在置 busy 之前完成。
- **通用规则**：增加输入方式不增加第二套账务逻辑；区分权益倍数、名义金额与抵押杠杆，回执使用服务端实际数量。
- **牵连**：`paper_desk.py` 的 `size_by_notional/_size_entry`、`paper_desk_api.py` 的 `open-preview`、`static/paper-desk.js`。1000 权益、10000 敞口、100× 合约杠杆对应 100 保证金与 5 Taker 费；扣费后实时仓位倍数自然变化。
