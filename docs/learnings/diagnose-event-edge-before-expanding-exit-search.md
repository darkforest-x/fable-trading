# Diagnose event-level edge before expanding an exit search

- **Problem**: Owner challenged the slow one-parameter-at-a-time research loop on 2026-10-20. The four-coin 5m-entry search produced no positive full-history arm among 52 combinations. Changing management from 15m to 5m increased win rates but reduced the current-buffer count of final gross20R trades from205 to106. These results do not establish that entry signals lack all conditional value, nor identify a profitable exit.
- **Dead end**: Treating each exit result as a prompt for another threshold test leaves the source of edge unresolved. Changing initial stop distance also changes the R denominator: the prior buffer study shows that much of the apparent improvement came from lower fee-R, and ZEC's later fixed-notional result worsened. Many entries during one move may share the same underlying opportunity, so trade count is not independent-event count.
- **Effective path**: First separate observations from hypotheses. Reuse existing ledgers and market data to construct bounded event paths and matched controls; group correlated entries for inference without silently changing the requested multi-entry strategy. Diagnose favorable/adverse excursions and first-passage order, including stop-then-recovery within prespecified horizons. Future paths are outcome labels only; hypothetical recovery does not erase an actual stop loss. Test a small declared set of entry-time context variables, such as completed4H/1H state, causal range location and MA compression, before selecting conditional exits. This workflow is proposed, not yet executed or validated.
- **General rule**: Compare net basis points at fixed notional alongside initial-risk R, cost-to-risk and clustered outcomes. Require repeatable, time-ordered evidence versus matched controls before expanding optimization. Preserve all tested variants and inspect nearby parameter stability. Use the existing cached screening implementation for supported semantics and Nautilus for execution validation; add bounded tests when semantics change. Do not substitute faster optimization for evidence of edge.
