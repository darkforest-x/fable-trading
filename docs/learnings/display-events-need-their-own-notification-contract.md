# 展示账本里的信号不会自动进入已有通知链

- **问题**：突破+spike 页面有实时联合信号，却没有 Bark/TG 通知；右上角 Bark 的累计未知回执又让人误以为整个通道失效。
- **死胡同**：只打开 TG 开关，或只排查 Bark 设备，都不能补上断链。联合信号写在独立的 `spike-lines-v1.sqlite3`，已有发送器消费的是主库 V9 队列，其协议校验也不接受 `joint`。直接复用旧激活时间还会把历史重算当作新消息。
- **有效路径**：先从 UI 所用事件反查所属数据库、首次插入点、队列和发送边界。为联合信号建立独立双通道队列，首次插入与入队同一事务，每个通道保存新启用边界；发送时再次校验收盘后30分钟，复用已有明确失败/429/未知回执语义。每条事件显示两份真实回执，累计未知用数量说明。
- **通用规则**：信号展示、信号准入、入队和外部回执是四份不同证据。看到卡片不能推断已通知；已有通知通道正常也不能证明新事件类型接入。新类型启用必须独立去重、切点和新鲜度约束，不借用历史显示激活时间。
- **牵连**：`yoyo/monitor/spike_lines_worker.py`、`joint_notifications.py`、`notification_policy.py`、`service.py`、`spike_lines_api.py`、Bark/TG 发送器与前端。原 V9 通知、模拟收益、Pine、执行和生产准入没有因此改变。
