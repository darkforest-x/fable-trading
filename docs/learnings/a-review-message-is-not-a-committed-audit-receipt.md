# 预审通过消息不等于预审收据已经提交

- **问题**：D 计划要求预审、源码与测试先提交，再启动市场研究；收到预审 PASS 消息后启动prepare时，JSON 尚未落盘。
- **死胡同**：把消息已经通过当成文件已经提交。即使代码和口头审核都早于研究，仍不满足事先约定的收据顺序。
- **有效路径**：保存原消息/文件时间，记录收据约晚12.4秒、没有倒填、没有改配置重跑，并重新核对源码SHA及52项D测试。报告明确这项流程未完全满足，而非把后补文件写成事前证据。
- **通用规则**：启动前检查要求的收据文件存在且其哈希已进提交；不要根据 agent 的进度消息推断文件状态。若顺序已偏离，保留原事实并披露，不能修改时间或删除产物伪装首跑。
- **牵连**：`experiments/active/exp-spike-v3-formation-gate-20260910-v1/PROJECT_PLAN.md` 与 `qa/preflight_review.json`。该偏差不改变策略失败结果，但审核通过与流程合规必须分开记录。
