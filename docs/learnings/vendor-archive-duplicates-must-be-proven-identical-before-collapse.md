# 供应商归档重复行只能在证明逐字段相同后折叠

- **问题**：OKX 多个 2023-10 月包在同一组 1m timestamp 上各出现两行；若一律报错，会丢掉整批可用历史，若直接 `drop_duplicates(timestamp)`，又可能吞掉价格或成交量冲突。
- **死胡同**：把「timestamp 重复」统一当作损坏，或为了让任务继续而无条件保留第一行。前者把可证明无损的供应商重复放大成数据缺口，后者把未知冲突伪装成确定数据。
- **有效路径**：先按 timestamp 分组，再对组内全部原始字段做逐行去重；仅当每组只剩一条唯一完整记录时折叠，并在月审计中记录原始行数与删除数。任一字段冲突继续 fail-closed，错误必须带币种和月份上下文。
- **通用规则**：数据摄取的 dedupe 条件必须比下游 identity 更严格；「同 key」不等于「同记录」。允许修复时同时保存可计数的修复证据，禁止静默清洗。
- **牵连**：`src/data/fetch_okx.py`、`tests/test_fetch_okx_archives.py`、官方 OKX 1m 月包到 UTC 15m 的聚合路径；该规则不允许跨 timestamp 合并，也不允许修复冲突 OHLCV。
