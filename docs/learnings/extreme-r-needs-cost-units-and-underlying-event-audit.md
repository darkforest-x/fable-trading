# 极端 R 必须先核对计量单位和重复行情

- **问题**：V7/V1 全池结果同时出现 V1 的数百 R 盈利与 V7 的负八十余 R 交易，直接看平均 R 容易把两者误读成同一种账户风险。
- **死胡同**：仅列最高盈利图或最差亏损图，会掩盖跨交易所其实是同一次 RAVE 行情，以及 USDC 的极小初始风险把正常百分比费用放大成巨大 R 的事实。删掉这些样本后重新报“更好结果”又会形成事后挑池。
- **有效路径**：先对全部已平仓事件按价格、方向、初始风险与固定费用重算净 R；再把原始全池保持不变，明确单列事后敏感性诊断与其选择原因。将同一底层币的跨交易所获利视为集中度，不能称为多次独立验证。
- **通用规则**：反常数字先查单位、公式和底层事件数。敏感性表解释原始结果的依赖，不产生新的“获胜配置”。
- **牵连**：`yoyo/evaluation/spike_v7_v1_audit.py`、原始 V1 归档账本、V7 全池共同执行账本；未改变任何信号、样本池、费用或风控规则。
