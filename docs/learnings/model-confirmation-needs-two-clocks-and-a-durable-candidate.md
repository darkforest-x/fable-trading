# 延迟模型确认必须保留原信号与确认的两个时钟

- **问题**：指标先出箭头，YOLO可能几根以后才确认；直接修改旧事件会让点位和新鲜度回到旧箭头，或绕过原有不重发机制。
- **死胡同**：把原箭头改成已确认再调用原 upsert_event 不成立：事件已存在，outbox只随首次插入创建；反过来强行重排队又可能把历史确认当成新信号。
- **有效路径**：原箭头保持不可变，另存候选状态与最后完成检查端点。模型通过时独立生成确认事件，并把候选终态、事件和两路通知队列作为单一事务提交。事件身份包含原箭头身份，确认收盘是新鲜度起点，实际推理时间单独记。
- **通用规则**：串联异步条件时先画清每个条件何时可知、身份属于哪个原始事件、哪次检查已持久化，再连接通知。失败重试同一未完成端点，未来反转不能取消较早已确认的事件；同根反转必须优先取消。
- **牵连**：`yoyo/monitor/model_gate.py`、`store.py`、`policy.py`、TG/Bark及前端30分钟门。原始OHLC只在内存，恢复历史不可用要诚实标记，不能无限重试或冒充无命中。线上复用因果指标列，禁止搬入离线完整未来随访条件。
