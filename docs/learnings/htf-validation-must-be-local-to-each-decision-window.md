# 高周期数据校验必须局限于每根决策 K 线当时需要的窗口

- **问题**：将 SPIKE V12.8 的 15m/H1 方向门接入监控时，需要处理 H1 缺口，并保证追加未来数据不会改变已经形成的信号。
- **死胡同**：先验证整段 H1 序列，只要任意位置有缺口就拒绝全部信号。这样未来的一个坏小时会抹掉此前完全有效的历史前缀；把 15m 数据误传给假定 5m 输入的聚合函数也会取错小时窗口。
- **有效路径**：直接使用原生 H1，在每根本图 K 线开盘时定位刚完成的小时，逐窗口要求连续 60 根有效收盘。缺口只阻断跨过它的窗口；用未来缺口、未来坏 candle 和前缀重算检查因果性。H1 门过滤新入场，但原始反向 side 继续交给已有参考仓位的退出逻辑。
- **通用规则**：先冻结输入频率、可知时刻与窗口，再校验该决策所需的数据；不要把整个未来数据集的完整性变成过去特征的前置条件。
- **牵连**：`yoyo/monitor/v128_signals.py`、`yoyo/monitor/v128_lines.py`、对应适配器测试。没有改变策略阈值或交易资格；这是时序与版本一致性修复。
