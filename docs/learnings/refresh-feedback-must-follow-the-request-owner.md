# 刷新反馈必须跟随请求所属页面

- **问题**：共享刷新按钮只给信号请求反馈，研究表首次读取显示空表；离页后研究失败可能污染当前页面。
- **死胡同**：一个全局 busy 布尔值无法处理切页后两个请求的完成顺序；已加载列表每次后台刷新都插入提示，会造成阅读位置跳动。
- **有效路径**：按页面统计未完成刷新请求；研究并发刷新共用同一 Promise；首次加载、失败、空结果分开显示，后台更新保留现有布局。异步错误出现时再次检查所属页面，包含独立任务轮询。
- **通用规则**：异步操作的反馈要绑定发起上下文，不能按完成时碰巧打开的页面归属。测试应覆盖旧请求晚于新请求完成。
- **牵连**：`yoyo/monitor/static/app.js`、`research.js`；`tests/monitor/frontend_shell.test.cjs`、`frontend_research_lifecycle.test.cjs`。未改变 API、账本或运行参数。
