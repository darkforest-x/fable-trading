# 参数扫到边界还在变好,就说明扫的不是那个参数

- **问题**:给 TP5×ATR/SL2×ATR 的止损加"最小距离下限",净收益随下限单调上升——
  0.4% 时 +0.0314%,一路到 4.0% 时 +0.1336%,**扫到扫描区间尽头都没有拐点**。
  第一版脚本的判读模板还写着"TP率没塌 = 没砍长尾",直接把它报成了改进。
- **死胡同**:把它当调参问题,继续往上扫找最优下限。区间加宽到 4% 仍单调,
  再往上只会继续单调——因为**根本没有内部最优点可找**。
- **诊断的那一列**:打印**超时率**。基线 8.3% → 下限 1.2% 时 12.9% →
  下限 4.0% 时 **69.6%**。障碍越推越远,触发得越来越少,"最优下限"其实是在
  逼近"根本没有障碍"。TP 率同步从 27.3% 塌到 4.2%,而模板判读把这句话说反了。
- **有效路径**:加**对照组**——把参数推到它逻辑上的极限,作为一行显式结果:
  `无障碍纯持 72 根` = +0.2645%(基线的 8.5 倍),`只止盈无止损` = +0.1711%,
  `只止损无止盈` = +0.0756%。对照组一出,结论立刻从"下限 4% 是最优参数"
  变成"**障碍本身在扣分,止损是主要破坏者(去掉值 +0.14%)**"。
- **通用规则**:任何单调到扫描边界的 sweep,**先加对照组再解释**,不要加宽区间。
  对照组 = 把该参数推到 0 或 ∞ 的退化情形。如果对照组和"最优参数"结果接近,
  那么这个参数从来不是在被优化,只是在被移除。
  推论:判读文案不许用固定模板断言"没砍长尾"这类事实——
  必须由数据算出来(TP 率相对基线的比值),否则模板会替你撒谎。

  `scripts/diag_no_barrier_tail_risk.py`(均值好不等于能用,补尾部与复利路径)。
