# 成功解析档案不等于历史时间格点完整

- **问题**：V34真实流量覆盖审计需要判断两年输入可用性，旧下载结果也有 complete 状态。
- **死胡同**：沿用该状态会把“至少一个月有合法行”误当整段可用；相邻异常间隔次数也不等于缺失根数，首尾缺失完全不在该计数内。
- **有效路径**：先冻结精确月份清单与官方checksum，再分别检查已见行合法性和理论日历集合差。未验证档案记unknown，已验证档案的缺根记missing；不补零、不去重。末根按open排除右端，但完整边界允许等于右端。
- **通用规则**：任何复用的complete先查实现语义，再选择与当前决策一致的分母。文件hash、行合法、时间覆盖与实时可得性是四个不同的结论。
- **牵连**：yoyo/data/binance_um_archives.py 的历史状态不改；V34在独立 runner 中核验。V33 parser 保持纯函数契约，原缓存只读，未改交易阈值。
