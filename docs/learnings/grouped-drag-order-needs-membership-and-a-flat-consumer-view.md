# 分组拖动要保存分区归属，并为原消费者保留完整顺序

- **问题**：策略选择器从单层排序改成 live 默认常用、其他折叠后，仅保存一个数组无法表达用户把旧策略拖到外层或把 live 收起的选择。
- **死胡同**：只把 live 排在数组前面，会在刷新时丢失手动分组；只向原消费者返回外层列表，又会漏掉二级账户的持仓。把旧的单列表 offsetTop 算法直接套到嵌套容器，也会算错跨区落点。
- **有效路径**：用独立 v2 存储保存 main/more 两组，旧 v1 只迁移组内顺序；缺失的新策略按默认规则加入，已保存的手动归属优先。拖动按分区和可见行的边界计算插入点，取消恢复两组快照，放下才保存；getOrder 仍返回两组合并的完整唯一序列。
- **通用规则**：展示层增加分组时同时检查持久化、旧数据迁移、读取顺序的消费者、隐藏项焦点和空分区落点。默认折叠不应把焦点放到隐藏的已选项上，可以聚焦显示当前项的折叠按钮。
- **牵连**：`reclaim-strategy-book.js/.css`、策略小册前端测试与 `reclaim-watchlist.js` 的顺序消费契约。触摸提交/取消、鼠标双向拖动、刷新保存、键盘跨组、外层全空和窄屏二级末尾已验证；仅改变浏览器展示偏好。
