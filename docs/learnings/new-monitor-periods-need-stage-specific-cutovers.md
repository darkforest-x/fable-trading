# 新周期必须有独立的两阶段通知启用边界

- **问题**：把 Spike 从 15m/1H/4H 扩至 5m，既要让新箭头和后续模型确认分别通知，也不能在预热时补发旧信号。
- **死胡同**：只改扫描字典或前端按钮并不完整。YOLO 和 TV 桥各有独立周期白名单；若新周期继承旧阶段的全局启用时间，首次拉取的历史箭头也可能获得发送资格。
- **有效路径**：统一检测和 TV 周期注册表，沿用现有按 protocol × timeframe 持久化的首次启用边界；分别验证 direct/model 两阶段，比较扩展前后的旧周期和渠道边界，测试重启不吞待发送的新事件。
- **通用规则**：扩周期先追踪数据、检测、展示、链接、原始通知和确认通知整条路径。预热历史用于初始化状态，不能仅因新程序看见它就成为新通知；新增请求量必须算进实际延迟。
- **牵连**：`yoyo/monitor/__init__.py`、`service.py`、`yolo_detector.py`、`tradingview.py`、`tests/monitor/test_5m_enablement.py`。5m 使用原生 OKX K 线，背景周期为 1H；新鲜度 30 分钟、扫描限流和模型阈值不变。
