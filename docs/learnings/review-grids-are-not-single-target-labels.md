# 参数审核网格不能冒充单目标标注图

- **问题**：为了比较 Core4–7，把四个候选框放进同一张图并批量发到 TG；Owner 看到的是“每张有四个框”，而不是模型最终会学到的单一目标。更严重的是，v2 把“框太窄”误解为向右追加 3 根确认 K，并把每张不同的密集锚点改成统一 `t-3`，导致红框整体右漂。
- **死胡同**：把几何参数探索页直接当交付图片；再用全局偏移和统一确认长度修外观。这样既混淆“待选参数”和“目标标签”，也丢掉了逐样本的形态位置，继续调整宽度只会在错误锚点上变宽或变窄。
- **有效路径**：先停止发送并在 TG 明确作废旧图；回到冻结 v1 清单中每张自己的五根六均线最密 span，横向只保留这 5 根、确认 K 为 0，纵向只用同一核心的完整影线与六均线。最终每张只画一个红框，并用后核心 OHLC/MA 强干预验证 50/50 个框四个坐标完全不变。
- **通用规则**：参数网格只能用于协议探索，不能作为“模型实际看到的图”交付；批量目标图必须做到一张一个已声明语义的框。Owner 指出位置漂移时，第一步核对是否保留逐样本锚点，禁止先套全局 delta 或追加统一确认窗。
- **牵连**：`yoyo/datasets/ma_launch_density_core_box_review.py`、`experiments/active/exp-15m-ma-launch-density-core-box-review50-v3/`、TG 批量交付；与 `per-image-reboxing-needs-indexed-boundaries-not-global-offsets.md` 同时适用。v3 仍是 P0 审核提案，不能转 YOLO 标签或启动训练。
