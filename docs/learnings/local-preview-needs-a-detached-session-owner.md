# 本地预览必须由独立会话托管

- **问题**：页面在开发与浏览器验收时可访问，但交付后 4173 与 8643 同时消失；前端和模型桥都由同一个临时命令会话持有，会话结束时整棵进程树被清理。
- **死胡同**：普通长运行命令只能保证当前工具调用期间存活；`nohup ... &` 在本环境也会被命令执行器回收，日志甚至来不及落下，因此不能把一次 HTTP 200 当成持久交付证据。
- **有效路径**：用系统自带的 detached `screen` 会话托管 `npm run dev:full`，再分别检查 `screen -ls`、4173/8643 监听端口、两个 HTTP 200，并从浏览器重新加载确认页面、模型和实时流都恢复。
- **通用规则**：交付 localhost 页面前，先识别服务进程的会话所有者；需要跨回合存活时必须使用独立会话，并在最后一条回复前做端口与浏览器双重验证。
- **牵连**：`prototypes/fable-signal-console/scripts/dev-full.mjs` 同时管理 Vite 4173 和模型桥 8643；当前托管会话名为 `fable_signal_console`。
