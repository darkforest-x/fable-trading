# Policy state must be recomputed inside dynamic replay

## Problem

A static candidate table can contain causal market features, yet position,
stop, cooldown and equity fields taken from the baseline ledger are not valid
features for a different gating policy. Rejecting one earlier entry changes the
state seen by later raw signals, including which signals become executable.

## Dead end

Score only the 166 V9 baseline trades, attach the state recorded on that
baseline path, and delete rejected rows. This misses 169 of 335 raw candidates
and silently assumes that changing an earlier action leaves every later state
unchanged.

## Effective path

Keep the 335-row causal market surface static, but recompute policy state online
inside every dynamic replay. Give each action event a candidate id, policy-path
hash, pre-state hash and action context. Require one finite timely score for
every raw candidate, even when cooldown or same-side semantics mean the model
does not control the action. Prove allow-all identity and fail closed on missing,
duplicate, early, late, non-finite or hash-mismatched scores.

## General rule

Any feature that can change after an earlier policy decision is an online state
variable, not a reusable dataset column. Static features may be cached only when
their value is independent of the policy path.

## Implications

- Entry gating must run through a full stateful simulator, not a filtered trade
  CSV.
- Opposite-close and opposite-reopen are separate actions; an entry model must
  not accidentally suppress the baseline close.
- Close-versus-hold requires paired counterfactual utilities and a separate
  experiment.
- The governing contract is generated by
  `scripts/design_pine_eth_15m_state_aware_lr_contract.py`.
