# Mobile display caches must preserve account identity and data age

- **Problem**: Spike mobile showed blank logos and reset account statistics to skeletons on every tab visit. Loopback account reads took about 0.2 s, while the public path took 4.7–6 s for tiny statistics responses; a 200 KB state response reached 15 s. The loading page also mislabeled live funds as paper funds.
- **Dead end**: A server cache alone cannot remove the mobile round trip. Clearing component state on remount defeats previous successful reads. Persisting a complete trading state and treating it as current would risk cross-account leakage and stale opening permissions. Assuming every `.png` URL contains PNG also discarded valid OKX WebP/JPEG artwork.
- **Effective path**: Package verified public artwork in the native bundle with an immediate text fallback. Persist only display statistics locally, keyed by an authorization-scope hash, environment, immutable account ID and period; retain values while refreshing, expire after 24 h, and clear on deauthorization. Deduplicate in-flight reads and prevent late responses from repopulating cleared storage. Reuse fresh parent account equity independently of delayed historical statistics. Compress large responses and bound contract-list DOM work. Live display reads use committed SQLite WAL snapshots without acquiring the writer reservation; execution still uses its existing exclusive transaction and freshness checks.
- **General rule**: Measure local compute, public transfer, and view-reset behavior separately. Every persisted financial display needs an explicit identity, timestamp, expiry and logout rule. A display cache must never become the authority for trade sizing or permission.
- **Scope and evidence**: `yoyo/discipline_app/mobile/src/readCache.ts`, `statisticsData.ts`, `Statistics.tsx`, `CoinLogo.tsx`, `ContractOptions.tsx`; backend `book.py`, `live_book.py`, `api.py`. Fake-account tests verify readers complete during an uncommitted writer, stale account data still rejects preview, compression keeps private HTTP responses `no-store`, persistence survives cache re-instantiation, and account/auth/mode separation holds. The slow/offline UI fixture shows immediate account equity before its deliberately delayed statistics, cached values offline, disabled opening, and no exchange writes.
