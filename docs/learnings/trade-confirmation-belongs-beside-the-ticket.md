# 交易确认应利用表单旁边的可用空间

- **问题**：紧凑交易页面加入止盈止损后，输入区变长，成交确认仍接在表单下方，桌面右侧却有可用空间。
- **死胡同**：第一轮仅增大文字、输入边框并给止盈止损分组，虽然层次改善，但表单高度进一步增加；只调整卡片外观并不能让确认动作更容易找到。
- **有效路径**：把全仓、杠杆和方向并成同一行，把成交预览移入右侧记录栏上方。桌面输入与价格/费用确认并列，手机依照 DOM 顺序自然变为输入、确认、记录；保留原确认按钮、报价失效和请求事件语义。
- **通用规则**：表单新增分组时，同时检查关键动作的可见位置。优先利用已有横向空间和明确的阅读顺序，不靠缩小文字或隐藏信息制造紧凑感。
- **牵连**：`yoyo/monitor/static/paper-desk.js`、`paper-desk.css`。1440 桌面已验证限价确认，390/320 手机无页面横向溢出，27 项前端回归通过；未更改交易计算与账本。
