# 历史截面扫描先锁确认收盘，再锁完整高周期桶

- **问题**：Owner 要求只检查2026-08-19北京时间18:00–22:00，原Grade-A却用核心后5根K线挑选事件。直接按核心时间筛选，会把以后才确认的形态算作当时已知。
- **死胡同**：只按CSV的open_time小于22:00截断，仍可能保留20:00开盘、午夜才收盘的4小时K线。只在读取全量价格后裁图，也不能证明计算未接触未来。复用原builder的额外绘图右边距，会无故漏掉最后可确认的一根。
- **有效路径**：用`core_end+5`的收盘时间定义扫描端点；先按时间戳屏蔽不完整/越界价格，再算特征。30分聚合1小时/4小时必须有完整、UTC对齐的组成K线。原左侧14根连续性约束保留；纯绘图用第6根右边距不作为信号条件。每张图止于其确认端点。
- **通用规则**：明确数据行的开盘/收盘语义、事件最早可知时间和全局截止时间，分别验收。增加未来价格毒化与缺失组成K线对照；缺数据是覆盖缺失，不能算无信号。
- **牵连**：`yoyo/data/ma_snapshot_inputs.py`、`yoyo/datasets/ma_launch_snapshot_scan.py`、`yoyo/datasets/ma_launch_owner_perfect_filter.py`；本次不改形态数值阈值、不评估后续收益、不训练模型。原15分参考的跨周期迁移仅为探索性回放。

- **本轮补充反例**：epoch-ms读取器会把`截止开盘时间+1ns`向下截成同一毫秒，仍排除最后已收盘bar。完整端点计数捕获30分只有8/9、1小时只有4/5的问题。调用边界必须使用源时间精度（+1ms），并以“最终恰好收盘的bar被包含、下一根毒化价格不解析”做集成测试，不能只测时间掩码。高周期预跑保留为失效记录，正式全量重跑修正。
