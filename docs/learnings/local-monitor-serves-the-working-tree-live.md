# 本机监控服务直接用工作区的前端文件，改动保存即上线

- **问题**：改全市场报警面板时，最初搭了一个本地静态预览页，用假的推送和假 K 线验收。
- **死胡同**：假数据只能证明布局，证明不了接口契约。比如回看 K 线的周一锚点周、历史记录里 18 条测试报警的占比、真实币名长度对行布局的影响，都只有真实数据才看得出来。还有一点：工作区里的改动其实早已在 owner 正在用的页面上生效，预览页给了“还没上线”的错觉。
- **有效路径**：`yoyo.monitor.launch_agent --port 8766` 直接从工作区的 `yoyo/monitor/static` 提供静态文件（`curl /static/spike-alarm.js` 能看到刚加的函数）。在内置浏览器打开 `http://127.0.0.1:8766/` 做只读的端到端验收：读历史、打开回看，不点“测试报警”（测试报警会弹到 owner 所有打开的页面）。
- **通用规则**：改 `yoyo/monitor/static` 前先确认 8766 是否在运行；在运行的话，任何保存的半成品都会立刻出现在 owner 页面上，所以要按“已上线”的标准改，改完马上用真实页面只读验收。会写数据或推送的操作（测试报警、确认、下单）不在验收里点。
- **牵连**：`yoyo/monitor/launch_agent.py`；`yoyo/monitor/asset_delivery.py`（资源版本号按 mtime 计算，浏览器会拿到新文件）；8766 还经 SSH 反向隧道转到 3060（8767）。
