# 日志图片应绑定仓位生命周期，并与文字保存解耦

- **问题**：持仓与历史仓位日志要保存截图，网络重试、误移除和未保存的分析文字都不能破坏记录。
- **死胡同**：把图片塞入高频持仓快照或文字版本，会扩大轮询负担并制造无关冲突；上传完成后重载整个日志，会覆盖正在输入的文字。
- **有效路径**：图片作为 SQLite 内独立 BLOB 记录绑定稳定 position_id，读取日志只返回元数据。内容哈希在同一仓位内去重；移除可恢复；独立上传结果只替换图片列表。服务端实际解码限制静态 PNG/JPEG/WebP、大小与像素数，按 position_id 校验读取与恢复，导出包含原始图片。
- **通用规则**：附件的持久化、重试和删除语义要独立于文本草稿；展示和删除记录时始终带所属对象的标识。
- **牵连**：`yoyo/research_workspace/paper_desk_images.py`、`paper_desk_journal.py`、`paper_desk_api.py`、`static/paper-desk.js`；导出 schema 8，6 MB/张、12 张活动图片，测试覆盖重启、串单、去重、恢复和上传失败保留草稿。
