# 检测结果浏览与新建扫描草稿必须分开保存

- **问题**：YOLO 工作台的表单、图表、任务表和全币种按钮纵向堆叠。用户点选位于页面底部的币种后，真正变化的图表在屏幕外；打开旧任务又会覆盖新检测的配置。
- **死胡同**：原页面的提交、切币、图表和导出都能逐项通过功能检查，但这不能证明连续使用顺畅。把每个功能继续塞进同一页，只会增加滚动距离与隐式状态依赖。
- **有效路径**：以“找到有形态的币 → 切币看框 → 放大或核对原图”为主路径。默认过滤有形态结果，图表旁切币，首次定位检测窗口；记录、巡检与模型说明放入独立页签。浏览状态写入地址，新检测与巡检各用独立草稿，提交时生成参数快照。用真实全市场任务和一次 ETH 5m 提交验证连续流程，另检查搜索无命中、刷新保留币种、窄屏与弹窗。
- **通用规则**：先验收用户连续完成一个目标时的视线移动、滚动与状态保持，再验收单个按钮。历史记录描述“当时执行了什么”，草稿描述“下一次准备做什么”，两者不能共享可变对象。
- **牵连**：`yoyo/monitor/static/yolo-detect.js`、`yoyo/monitor/static/yolo-detect.css`、`tests/monitor/frontend_yolo_detect.test.cjs`。只调整交互与显示，不改变模型、检测参数、因果窗口或交易准入。自动测试覆盖过滤、深链币种、参数快照与可比任务范围；浏览器证据在 `output/playwright/yolo-ux-20261016/`。
