# 图表周期和特征来源必须进入验收输入

- **问题**：Owner 要核对 PEPE 1H 的 V5 漏报，先按当时打开的 4H 解释；随后本地重放给出的 V4 时间又与原生 1H 图不一致。代码测试通过无法证明重放的是 Owner 那张图。
- **死胡同**：把当前窗口周期当成研究要求，或只凭同币种同周期的特征文件名认定算法一致，会让精确的状态机诊断建立在错误输入上。V5 首版还把“实体可以在原信号前后出现”扩成连续近零 12 根等新前置门，合成测试忠实验证了错误规格。
- **有效路径**：先固定交易所、币种、周期、时区、K 线开盘/收盘语义，原生读取已知确认根的 OHLC、六线、原确认值和密集计数。重放必须认证 SPIKE 本身使用的特征工件及 SHA，不能把上游同名特征当成下游新算法特征。修复以这个真实事件的来源链为断言，未来条件完成时只画当前根。
- **通用规则**：每次图表回归先证明“同一张图、同一算法输入”，再判断哪条条件挡住信号。已知正例仍缺失就不能拿编译成功作为交付验收；一项结构要求先做最小实现，不顺手捆绑新的时间阈值和箱体条件。
- **牵连**：`spike_burst_v5.pine`、`spike_burst_v5_structure.py`、`spike_v5_pepe_regression.py`。旧 4H 报告按历史保留，修复报告明确纠正为 1H；无收益或实盘有效性推断。
