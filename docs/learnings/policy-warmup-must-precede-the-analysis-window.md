# 延迟入场政策必须先建立自己的持仓历史，再裁统计窗

- **问题**：将 SPIKE 入场时段研究从两个月扩至多年时，原策略有窗前串行持仓，延迟政策却只消费窗内候选，起点可能继承原策略的持仓而非自身历史。
- **死胡同**：只把 `warmup_start` 往前移不够；它扩展了指标输入，却不会让仅读取窗内 decisions 的延迟 worker 重放更早的确认和成交。直接借用 baseline carry 只适用于“在起点切换政策”的实验定义。
- **有效路径**：区分回放起点与分析起点。回放从原始可用边界按空仓开始，所有政策各自串行演进；统计只在更晚的 `analysis_start` 后按实际成交时间截取。数据缺口仍保留、源边界仍需披露，不能声称恢复了未知的边界前仓位。
- **通用规则**：扩窗或比较延迟政策时，先画清楚指标预热、政策状态预热、统计窗三条时间边界；不能把价格指标已预热当成交易状态已预热。
- **牵连**：`yoyo/evaluation/spike_v128_long_replay.py`、`yoyo/evaluation/spike_v128_retest_entry.py`、`experiments/active/exp-spike-v128-entry-clock-long-20260923-v1/config.json`。历史两个月实验使用切换政策时的共同初始持仓定义，原产物不回写。
