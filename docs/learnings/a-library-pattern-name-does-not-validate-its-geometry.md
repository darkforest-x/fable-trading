# A library pattern name does not validate its geometry

- **Problem**: The pre-touch Monday1618 study needed Pyharmonics 1.5.3 XABCD candidates. Source inspection and synthetic price mirrors showed that bearish completion prices were asymmetric. Real forming candidates also sometimes returned XABC prices outside their named pattern's own ratio ranges.
- **Dead end**: Trusting `completion_min_price` / `completion_max_price` or accepting a `forming()` name would silently turn implementation artifacts into a trading feature. The helper uses `max(A,C)` for both directions, while the search matrix uses the appropriate trough for bearish patterns. A joined candidate can also carry ratios from a different A anchor. Repeating the scan or widening tolerance would not resolve either inconsistency.
- **Effective path**: Before viewing returns, freeze the library version and tolerance. Project the intersection of the same XD and BCD ratio bands using `max(A,C)` for bullish and `min(A,C)` for bearish patterns; verify reflection symmetry with actual library searches. Recompute XAB and ABC ratios from every returned candidate's actual prices. Preserve raw candidates separately and exclude invalid joins without tuning thresholds. Run prefix truncation and future mutation checks independently of geometry checks.
- **General rule**: A recognizer's label is a proposal. Validate its returned coordinates against its advertised definition and causal information boundary before using it as an experimental feature. Price reflection and actual-coordinate checks catch different failures; passing one does not imply the other.
- **Affected files**: `yoyo/evaluation/monday_harmonic.py`, `yoyo/evaluation/monday_harmonic_summary.py`, `tests/evaluation/test_monday_harmonic.py`; experiment `exp-monday-harmonic-confluence-20261031-v1`. Raw versus validated candidates and rejection counts remain in that experiment. These adapter corrections do not establish that harmonics improve trading returns.
