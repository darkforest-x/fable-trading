# Live ticks do not prove chart history is loaded

- **问题**：0.8.13 的手机图表历史请求失败，5 分钟图只收到一根实时柱并撑满横轴，1 分钟图空白。实时价格可用不代表历史读取成功。
- **死胡同**：只用最近一笔推送时间决定是否重试 REST，会在 WebSocket 正常时永久压住历史补齐；Mac 的公开 REST 请求成功也不能证明 iPhone WebView / 5G 路径成功。原版没有留下足够网络错误细节，因此不把故障断言为某一种 CORS 或运营商问题。
- **有效路径**：历史读取复用 App 的原生 HTTP 通道，优先访问现有认证服务上的只读 OKX 转发，失败才回到同一 OKX 公共源且不携带服务授权。历史恢复与推送新鲜度分别跟踪，独立退避重试；实时断线后每 5 秒尝试 REST，并显示“定时更新”。不足两根可靠历史时不渲染单柱，也不自动翻页；初次成图保留固定数量的可视柱位。
- **通用规则**：快照完整性、增量新鲜度、视口初始化是三件事，必须分别建状态与回归场景。测试要包括“快照失败但推送一直成功”，而不只是全断网。停止或切换后取消可取消的读取，并隔离原生请求的迟到结果。
- **牵连**：`candleSession.ts`、`candleTransport.ts`、`CandlePanel.tsx`、`candles.py`；300 根初次读取、2000 根内存上限、缓存隔离保持。新 API 不读取或写入账户账本，不改变下单/保护规则。仅模拟网络状态与桌面公开源验证不能替代真机移动网络运行确认。
