# Fixed return capital must not become a risk baseline

- **Problem**: The owner wanted a cumulative percentage and explicitly approved a pre-trade equity observation as fixed capital. The live ledger also contains current equity, available margin and a daily loss baseline, all of which have different purposes.
- **Dead end**: Deriving the denominator from current cash or daily opening equity silently rebases returns after transfers or midnight. Reusing the confirmed display capital for sizing or daily loss checks would change execution policy without authorization.
- **Effective path**: Store confirmed capital as separate account-bound metadata with provenance and an audit event. Configure it locally in a serialized, idempotent SQLite transaction; reject account mismatch and replacement. Calculate App-managed cumulative PnL divided by this fixed amount, retain null for unconfigured accounts, and state the denominator in the UI. Tests cover account isolation, restart persistence, external cash changes, daily baseline changes, period filters, no exchange writes and preservation of all risk fields.
- **General rule**: A return denominator is a metric definition, not a wallet balance or risk limit. Keep its approval, identity, lifetime and mutation path separate from execution state; never infer a whole-account money-weighted return from this ratio.
