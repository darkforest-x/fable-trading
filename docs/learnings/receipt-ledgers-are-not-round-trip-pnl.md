# 成交记录与完整交易结算必须使用不同口径

- **问题**：Pro 账户历史误读不存在的 `order_history` 字段后退回本地分笔列表，开平筛选失效；成交盈亏也容易被标成完整交易净收益。
- **死胡同**：仅用相近字段名和示例 JSON 接界面，会让空结果看似正常，最终落到无法筛选的本地记录。将 `pnl` 直接加费用也不能代表一笔完整交易，开仓费用和资金费可能属于其他回执。
- **有效路径**：逐层核对真实 `account.data.history.items`，按双向持仓的 `posSide + side` 映射开平。未知净持仓方向不猜。USDT 成交盈亏加本笔 USDT 费用单列为本次成交净额；其他费用币种不擅自换算。完整交易的收益归属继续读取原结算统计。
- **通用规则**：先确定账本粒度、费用符号和币种，再绑定 UI。用开仓、平仓、净持仓未知方向、非计价币费用做契约验证，不能只验字段有数字。
- **牵连**：`static/pro/account-records.js`、`account-data.js`、账户与交易页面；不改变交易所账本或原执行策略。
