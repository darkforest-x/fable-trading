# 训练进度必须来自逐轮输出，而不是整组结束回执

- **问题**：长时间 GPU 训练后需要自动衔接评估，监控必须区分仍在计算、停滞与真正完成。
- **死胡同**：初版待审 watcher 以 training_receipt.json 内容不变满15分钟为卡死条件，但训练入口只在每个 arm 结束时写回执，正常40轮训练也会被误判。初版未执行，没有中断实际训练。
- **有效路径**：从实际 results.csv 的 epoch 序列与 mtime 识别进度；整组完成则同时要求 receipt completed、A/B完成以及两份CSV恰含1至40轮。状态声明与逐步计算证据各司其职。
- **通用规则**：建立监控前先读取生产者的写入时机。进度应检查周期输出，完成应检查终态与必要产物，不能用同一个低频状态文件代替两者。复制及恢复必须核对权重、输入、代码和产物哈希。
- **牵连**：scripts/research/watch_ma_profit3r_owner1500_v4.py、scripts/windows/train_ma_profit3r.py；仅衔接已授权离线训练，不改变配方或生产状态。
