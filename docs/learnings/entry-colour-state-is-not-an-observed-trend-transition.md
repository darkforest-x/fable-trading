# 反向颜色状态不能冒充已经观察到趋势反转

- **问题**：K2 等待版本有大量入场后5min退出，原 simulator 检查的是反向状态；仅有退出账本不能断言发生过翻色。
- **死胡同**：拿小时K2颜色解释5min退出，或把后续盈利路径的MFE当入场质量，混淆了两个时间尺度和不同信息时点。直接延迟退出还可能只是延长反向持仓。
- **有效路径**：先冻结相同母请求与对照，读取恰在entry完成的原生5min颜色；把已有反色与相邻同向→反向边沿分成两个明确策略。原本同向的完整路径必须恒等复现，差异只在事先定义的状态分支解释。未知管理色重置边沿，未知执行价格仍删失；硬止损与共同期限不失效。
- **通用规则**：用户说“变化”时，先写出变化前状态来自哪根已完成bar，再写状态转移。不能用别的级别颜色初始化，也不能让缺失状态默认为False。机制修正不等于收益通过。
- **牵连**：`yoyo/data/hourly_impulse_colour_context.py`、`yoyo/layers/l3_backtest/hourly_impulse.py`、V5预注册。V4仅61.35%匹配覆盖的已知限制必须在看新收益前保留，不能事后补选有利对照。
