# A chart workbench redesign must preserve interaction state as well as DOM contracts

- **Problem**: Repeated palette and font adjustments left SPIKE Vision Lab visually crowded. Navigation, evidence, credentials and request inspection competed with the chart; the user requested a full frontend rebuild.
- **Dead end**: Retaining the same information hierarchy while changing only surface styles did not address the complaint. During integration, a text removal action inherited a square icon button and wrapped over the reference image. Replacing result HTML on unrelated renders would also discard disclosure state and unsaved review text.
- **Effective path**: Separate persistent navigation, the candidate queue, the chart, and progressive result details. Share semantic colors and one type scale, keep reference actions outside images, and compare result markup before replacing its DOM. Preserve IDs, delegated actions, raw-body text rendering, image URL validation and recognition guards. Inspect actual live charts and saved runs at desktop and mobile sizes instead of judging an empty screen.
- **General rule**: Before a visual rebuild, map the existing DOM/event contract and the primary user task. Validate populated, loading, error and narrow-screen states; an API test alone cannot detect clipped actions or lost drafts.
- **Scope**: `yoyo/vision_research/static/{index.html,styles.css,app.js,theme.js}`, locally bundled Lucide 0.468.0 icons, existing TradingView chart and SPIKE light/dark tokens. Backend request parameters, stored references, credentials, recognition windows and research eligibility remain governed by their existing contracts. Validation used 185 existing vision/boundary tests, JavaScript syntax checks, and real-browser desktop/390px checks without a paid inference request.
