# episode 最高置信度会被重复窗口次数系统性抬高

- **问题**：同一行情被相邻 endpoint 与 W18–25 反复命中后，episode 内最高 confidence 看起来很高，容易被误解为模型一开始就很确定，甚至被拿来做信号质量排名。
- **死胡同**：只统计每个 episode 的最大分，忽略这个最大值来自多少次候选抽样、出现在首次检测之后多久；候选越多，随机抽到高分的机会本来就越大。
- **有效路径**：同时保留“最早可见原框分数”和“episode 最终最高分”，量化最高分相对首次检测的延迟，并用固定候选数、置换分数秩的零假设检验最大分与重复次数的关系。本轮首次分数与候选数 `rho=0.281, p=0.0761`，最高分与候选数却为 `rho=0.859, p=0.00010`。
- **通用规则**：任何重叠滑窗检测的线上比较只用首次可见分数；最大分只能作为事后轨迹字段，不能作为校准、阈值选择或质量证据，除非先控制抽样次数和检测延迟。
- **牵连**：`scripts/analyze_15m_ma_launch_owner_yolo_eth30d_confidence.py`、候选阈值、W18–25、episode 合并、实盘因果时间；阈值敏感度必须同时报告保留数量与额外延迟。
