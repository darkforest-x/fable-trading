# Label Studio配置门应比较XML语义而非保存格式

- **问题**：future150发布前拒绝了正确的现有布局；服务端保存后的XML SHA与源码不同。
- **死胡同**：直接把原始配置字符串不等当成Owner修改。检查显示canonical XML完全一致，差异来自服务端规范化的空白。
- **有效路径**：准入、并发检查和读回使用canonical XML比较；训练图绑定、控件name/toName和选项仍逐项保护。收据同时保留源配置和服务端原始SHA。
- **通用规则**：对有规范化保存行为的结构化配置，先区分序列化差异与语义差异。允许等价格式不等于允许未知字段、类别或图像绑定变化。
- **牵连**：`yoyo/review/publish_future_context.py`，30项发布器测试包含空白规范化允许、主图绑定改变拒绝。
