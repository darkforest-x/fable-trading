# 放大实时图表时，移动唯一节点，保留同一份状态

- **问题**：spike 的图表每轮刷新可能重绘，用户希望放大查看后还能恢复原布局，主图、副图和光标都应对应当前选中的合约。
- **死胡同**：评估后未采用复制 SVG 或另建一套弹窗图表。副本容易只保留打开时的行情，形成两个同名节点、重复监听器和两套请求时序；新行情更新后，详情与弹窗可能指向不同的图。
- **有效路径**：将同一个 `chart-frame` 移入 body 层原生 `dialog`，关闭后移回固定的 `chart-slot`。图表容器、行情请求和光标监听器保持唯一；Esc、按钮关闭、选择失效与页面切换都调用幂等恢复。原生 dialog 负责背景不可操作和焦点范围；打开时跳过页面搜索快捷键，避免操作隐藏背景。close 事件还需确认 dialog 当前仍关闭，防止晚到的旧 close 事件关闭刚重新打开的窗口。
- **通用规则**：为持续更新的组件增加放大视图时，先明确唯一的数据状态与 DOM 归属，优先搬移现有节点；独立副本需要承担额外同步契约。视觉放大不应触发额外行情请求或改变蜡烛窗口。
- **牵连**：`yoyo/monitor/static/index.html`、`app.js`、`styles.css`。保留原生 120 根图表、零轴和 IMACD；周期筛选、监控与通知不属于此次布局变更。
