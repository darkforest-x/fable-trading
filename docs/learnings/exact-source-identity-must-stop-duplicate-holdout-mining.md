# 精确源码身份必须阻止重复 holdout 挖掘

- **问题**：同一份 Pine 源码可能通过新的附件路径再次出现，并再次被要求“改成 15m 后做超参
  优化”。如果只看文件名、对话时间或自然语言任务，会把已经完成且已经消耗 holdout 的实验误当成
  新实验，进而在相同数据上继续选参数。

- **死胡同**：直接按新附件路径重跑搜索，或把已查看过的 final-preholdout / holdout 换个名称继续
  当 OOS。路径变化不产生新源码，换一个参数族也不恢复样本独立性；这种重跑只会增加选择偏差。

- **有效路径**：先计算附件内容 SHA-256，再到 `experiments/registry.yaml`、冻结配置和产物清单中
  解析同一源码身份。若命中已消费实验，则只运行不打开行情数据的账本哈希校验、既有产物验证和
  单元测试；交付冻结候选及其失败边界。新的参数选择只能依赖预先登记、真正后到的前向样本。

- **通用规则**：研究请求的身份是 `源码内容哈希 + 品种/venue + 周期 + 执行契约 + 数据边界`，
  不是附件路径或任务标题。任一身份命中 `holdout_consumed: true` 或 `reuse_allowed: false` 后，后续
  请求默认走证据复核，不得自动开启同窗搜索；需要继续优化时，先冻结候选并建立新前向协议。

- **牵连**：`exp-pine-eth-15m-v1`、`v12f_holdout1_consumption.json`、
  `scripts/backtest_pine_eth_15m_v12f_holdout1.py --verify-existing`、holdout 铁律与多重检验纪律。
