# 全量回放验收必须同时验证文件集合、数据流集合和汇总分母

- **问题**：V9 回放器给每个产物写 SHA，但旧完成检查只验证回执中列出的文件。若回执少列一张表，所有已列 SHA 正确也不能证明两组完整。
- **死胡同**：仅凭 `complete=true`、目录数为 3531 或文件哈希一致宣布全量完成。它们不能发现遗漏的 arm、错误 stream key，也不能证明汇总数字来自逐笔表。
- **有效路径**：在独立统计入口要求固定六文件、V8/V9 两组、源 3531 key 集合逐个相等、源与产物 SHA 未变、逐流事件/平仓/删失/净 R/10R 与汇总交叉一致；全部通过才生成全量报告。正在运行的回放源码不变，补强聚合门即可检查真实产物，避免无理由重耗行情。
- **通用规则**：先声明完整产物 schema 与源集合，再验证哈希与数量。候选池、准入、实际成交、共同平仓对照各用自己的明确分母。
- **牵连**：`yoyo/evaluation/spike_v9_full_replay.py`、`yoyo/evaluation/spike_v9_full_report.py`、`tests/evaluation/test_spike_v9_full_report.py`；版本身份、holdout 暴露计数和并行任务共享工作区。
