# 异步校验必须等待数据，并在提交前重新确认草稿仍然有效

- **问题**：检测弹窗需要当前 OKX 币种池来检查输入。页面刚打开时列表尚未返回，格式合法的错误币名会绕过本地校验，创建失败任务；等待期间用户也可能关闭弹窗或换一份草稿。
- **死胡同**：仅在列表已经加载时校验，看起来能拒绝错误币名，单测也通过，但实际快速操作复现了一条 NOTREAL 失败记录。用“列表为空就交给后端”掩盖了尚未完成与确实不可用的区别。
- **有效路径**：复用同一个加载 Promise，提交按钮显示正在检查并避免重复触发。数据到达后校验当前输入，再检查弹窗是否仍打开、草稿对象是否仍是同一份；数据源失败明确显示重试原因，不创建任务。浏览器验证快速提交、时间对齐、未提交草稿刷新恢复；异步测试额外覆盖未知币名与等待期间关闭弹窗。
- **通用规则**：用户点击时的意图不自动延续到异步等待结束。所有异步前置检查之后、真正写入之前，都要核对该操作所属界面和草稿是否仍有效。测试要覆盖“依赖尚未就绪”的时刻，不能只检查加载完成后的静态页面。
