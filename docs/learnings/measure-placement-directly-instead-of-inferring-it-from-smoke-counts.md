# 我从 smoke 计数推出的"平移害了 tip 对齐",一测就崩;而且那两个计数本来就不该比

**日期**:2026-07-27
**类型**:反直觉结论 / 自证伪(短检测器 v1b 审查)

## 一句话

我看到 `translate=0.02`(imgsz 960 → 约 ±4 根 K 线)大于推理门 `TIP_EDGE_BARS=2`,
就推断"训练教它容忍 4 根、推理只给 2 根 → 框被门挡掉",还拿 tip-smoke 的
`tip 19/27 vs live 4/27` 当佐证。**直接测量后:324/324 的预测框右缘精确落在 tip 上
(差 0 根),门挡掉 0%。假设完全错。**

## 怎么测的(关键是选对样本)

`datasets/dense_owner_side_short_tip` 的 **val split(324 张,训练未见)**,
按构造 tip = 图右边缘、真值框结束于此。对每张跑 v1b,**不施加 tip-edge 门**,
量"预测框右缘差 tip 几根"。有门的产物(detect1000 包)不能用来测这个——
它已被门筛过,分布是被裁剪的,必然全在 2 根内。

结果:差 0 根 = 324 / 差 1 根 = 0 / 差 2+ 根 = 0。

## 两个教训

1. **参数量级 ≠ 实际行为。** `translate` 的确会平移 ±4 根,但模型仍然学会把框钉在边缘——
   增强的"可能范围"不等于"模型最终的定位精度"。**凡"某超参会不会害了 X",先直接量 X,
   别从超参数值推。** 这次量一次只花 10 分钟,推理链却已经写进了两条对话。
2. **两个不同条件下的计数不能直接相比。** `tip 19/27` 是在**构造出有密集的窗口**上开火,
   `live 4/27` 是在**任意当前时刻**开火。任意时刻只有约 15% 的币恰好处于均线密集——
   **那是基础率,不是故障**;70% vs 15% 的落差恰恰证明检测器在区分。我把正常现象当成了
   症状,再反向去找"病因",于是造出一个不存在的病因。**先问"这个数该和什么比",
   再问"为什么低"。**

## 留着的诚实边界

本测只覆盖 **in-distribution 正样本**(每张都真有密集在 tip)。它证明了"该开火时框贴边",
**没有**证明"模糊/困难窗口上的定位也这么准"。若日后要问后者,需要另建含难例的集合。

顺带:`hsv_s/hsv_v=0.05` 与铁律 5 字面("hsv 全关")冲突,但 `hsv_h=0`——
**真正会把红 K 变绿 K 的色相项是关死的**,s/v 只让饱和度/明度浮动 5%。四个检测器
(`v13_pad200`/`short_v1`/`short_tip_v1`/`v1b`)一路同值。属于**规则文字该改准**,
不值得为它重训。这条待 owner 裁。
