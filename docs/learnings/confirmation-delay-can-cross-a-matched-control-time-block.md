# 确认延迟可能让随机对照的时间块失配

- **问题**：周日插针等待数根4h确认后，实际入场已到下周一；旧候选记录的week来自插针周，随机对照也在插针周。BTC/ETH原3根4h基线就有5笔这种情况。
- **死胡同**：仅检查信号和对照的week字段相等会误报匹配成功，因为双方字段沿用了同一个插针周。增加确认根数还可能改变这种失配比例。
- **有效路径**：从实际entry_time重新计算America/New_York周，逐对核验币种、方向、入场周和因果波动桶，且要求3笔对照均已判定。旧成交账本完整保留，不能满足条件的交易只从配对统计排除；同表同时给出已配对信号和随机对照的平均R及样本量。
- **通用规则**：任何改变确认延迟的研究，都要从实际执行时间重建匹配块，不能相信继承的分组标签。研究收益与配对证据的分母必须分别列清。
- **牵连**：`yoyo/evaluation/monday_parameter_analysis.py`、`tests/evaluation/test_monday_parameter_analysis.py`；本次18配置的止盈止损、成本与早期选参规则不变，历史文件不改写。
