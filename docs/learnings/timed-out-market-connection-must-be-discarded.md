# 超时后不能继续复用同一市场数据连接

- **问题**：BaoStock 持久连接批量抓取中，`sz.000425` 请求墙钟超时，后续出现接收错误；`sz.001914` 的后复权响应又混入未复权与后复权两种 `adjustflag`，被校验拒收。
- **死胡同**：仅在请求超时时停止当前函数，然后让下一只股票继续使用同一socket。超时不等于远端取消，旧响应或未读分页仍可能留在连接中；下一请求即使有响应，也不一定属于当前请求。
- **有效路径**：每个价格或元数据请求失败后关闭当前worker自己的socket、清空本地client引用，下一个请求重新登录，不发送会影响其他匿名连接的logout。继续强制校验响应代码、复权标志、日期与OHLC比例。原失败响应/日志隔离保留，同代码用新会话重试，不能换一只股票掩盖失败。
- **通用规则**：对不能证明请求取消与响应关联的有状态协议，超时连接就是已污染连接，应丢弃而非复用。超时、分页终止和响应身份校验是三道不同的证据门。
- **牵连**：`yoyo/evaluation/ashare_data.py` 的 `_reset_worker_client()`、`_fetch_worker()`、`validate_daily()`；同源原始数据缓存和失败记录。信号规则、股票代码抽样及历史日期均未因技术重试改变。
