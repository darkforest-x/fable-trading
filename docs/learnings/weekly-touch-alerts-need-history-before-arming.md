# 周内首次触价报警必须先核对已发生的触价

- **问题**：监控周一外扩价位时，中途启动或断线恢复只能看到当前行情；直接把第一次收到的越界价格当作本周首次触及，会补发历史报警。实时 K 线的高低价还可能意外覆盖用于展示的周一锚点。
- **死胡同**：只记进程内的已报警集合，重启便失去去重；仅以接收时间判断新旧，无法区分启用前已经出现的分钟影线。组装响应时直接展开实时 K 线对象，也会让同名 high/low 替换周一高低点。
- **有效路径**：完整周一小时线决定固定锚点，之后到当前小时的完整行情先消费历史触价；按周、合约、方向在 SQLite 原子去重。实时分钟流保留盘中极值，订阅使用独立启用时间与代次；断线或单币缺口先恢复历史，再恢复新报警。同一分钟内须有启用后的连续观测才能确认新触价。API 显式投影报价字段，周一和当前 K 线的高低点分开。
- **通用规则**：当提醒承诺“期间首次”时，完整期间历史与持久去重是启用前提；通知的启用边界不等于行情 K 线的起点，接收时间也不等于首次发生时间。
- **牵连**：`yoyo/monitor/monday_fib.py`、`monday_fib_service.py`、`tests/monitor/test_monday_fib.py`。位置报警独立于入场确认，默认关闭，不改变交易执行器与旧通知订阅。
