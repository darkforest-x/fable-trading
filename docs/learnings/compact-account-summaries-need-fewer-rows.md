# 首页账户摘要先减少信息行数，再调整字号

- **问题**：实盘账户摘要占约 208px，主任务 K 线被推到首屏下方；单个卡片内部好看不等于首页空间分配合理。
- **死胡同**：把权益、次指标、状态和结算信息逐层纵向排列；仅减字号会损害可读性，却保留重复的纵向开销。生成稿宣称高度达标也不能代替浏览器测量。
- **有效路径**：先由 Stitch 改稿，桌面四个指标并排，手机四格排列，结算明细默认折叠。浏览器实测桌面账户区 118px、K 线顶部上移约 92px；明细开关状态独立于资金刷新，刷新只更新文本。
- **通用规则**：紧凑化先定义模块高度和下方主任务的可见空间，再减少默认信息行数；验收必须覆盖实际内容、展开态、刷新焦点和窄屏，而非只验占位设计图。
