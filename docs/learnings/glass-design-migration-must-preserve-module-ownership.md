# 全站玻璃样式迁移必须保留模块的行为归属

- **问题**：将多年代际的 Spike 页面统一为 1.618 的浅色玻璃规范，导航、懒加载样式和 Shadow DOM 各自拥有生命周期；仅调整主题变量无法覆盖这些边界。
- **死胡同**：首轮窄屏检查中，外部信号页虽然表格已有内部滚动，页面仍被撑宽到 748px。问题来自父级 grid 的自动最小尺寸；继续修改表格颜色或 overflow 无法消除父级的最小内容宽度。
- **有效路径**：先由 Stitch 产出统一设计，再以语义 token 和最后加载的明确组件族适配层接入；嵌入式 VLM 在自身 Shadow DOM 内应用同一材质。低频导航复用原节点的 click，密度控件移动原节点以保留监听器；宽表父级使用 minmax(0,1fr) 和 min-width:0。浏览器检查真实内容、窄屏溢出、搜索焦点、账户路由参数与减少动态效果。
- **通用规则**：跨页面改设计时，先确定样式级联和行为所有者；保留生命周期入口，把透明度、对比度和动效作为分层设计。响应式溢出须沿容器链检查最小尺寸，不能只检查最内层滚动区。
- **牵连**：`yoyo/monitor/static/{design-tokens.css,glass-system.css,workspace-command.js,vision-module.js}`；Stitch 项目 `8978791379095391159`、页面 `df514d3934a043a19f6c8c81bc56f878`。`node --test tests/monitor/frontend_*.test.cjs` 从原 535 项增至 540 项通过；新增行为测试覆盖导航分组、账户查询参数、关闭焦点和原控件身份。
