# 倍投的失败机制与 edge 符号无关，所以"等找到 edge 再上倍投"是错的顺序

- **问题**：Owner 想在 ETH 3m V8 上做合约倍投，直觉是"胜率再低，连亏之后总会赢一次"。
  需要判断这是参数问题还是结构问题。
- **死胡同**：先按常规思路去搜倍投参数（底注 × 层数 × 复位规则）。
  `exp-spike-eth-martingale-20260914-v1` 搜了 40 组，开发冠军期末 923U（<1000U），
  验证全亏。但这只证明"这 40 组不行"，无法回答"是不是还有没搜到的组合可行"。
  在参数空间里继续搜是无底洞。
- **有效路径**：把期望本身当成变量，分布形状用整体平移固定住，在
  **零期望 / 正期望 / 负期望**三档 × **保留亏损聚集 / 打散聚集**两种序列下
  重跑同一套破产模拟。倍投在 **6/6** 格子里破产率最高（零期望档 91.5%–100%）。
  关键判断：倍投的下注阶梯与亏损方向**同向**——连亏时下注指数增长，
  撞资金上限的时间只取决于**连亏长度**，而连亏长度由分布形状和序列相关性决定，
  **与均值符号无关**。所以不存在"edge 够大就能救倍投"的参数区间；
  第 3 轮实测要把破产率压到 5% 以下需要每笔净 R 加成 +0.8，而最优格子 CI 上界
  对应的加成只有 +0.352。
- **通用规则**：判断一个资金方案能不能用，**先问它的加码方向与亏损方向是否同向**，
  再去搜参数。同向的方案（倍投、亏后加仓、金字塔补仓）其破产时间由连亏长度决定，
  必须先测连亏分布；反向的方案（顺势加码）才有资格谈参数。
  参数搜索永远回答不了结构问题。
