# A confirmed command must not become uncertain because refresh failed

- **问题**：纪律 App 提交指令后会刷新持仓；如果两个请求共用失败处理，已被服务端受理的指令可能被后续查询失败误报为未确认，并触发错误的震动和重试提示。
- **死胡同**：把「提交 + 刷新」当作一个成功或失败的异步操作。查询失败不能反证之前的写入失败；同样，收到明确拒绝也不等于网络断线导致的未知结果。
- **有效路径**：以写入接口的回执确定成功反馈，刷新失败只更新连接状态。明确 HTTP 拒绝与网络或服务器异常分开处理；未知开仓结果保留同一请求编号重试。隔离模拟账本通过浏览器验证受理、平仓与亏损冷静状态。
- **通用规则**：先确定副作用是否得到确认，再单独处理读模型刷新。视觉、触感和重试策略必须跟随同一事实边界。
- **牵连**：`yoyo/discipline_app/mobile/src/App.tsx`、`api.ts`、`feedback.ts`；不涉及交易所实盘接口。
