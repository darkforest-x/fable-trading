# 前端丢弃旧响应不能阻止旧预览废弃新报价

- **问题**：快速修改止盈或止损会并发计算预览。较慢的旧请求如果最后写入队列，会把用户正在看的新报价标为 superseded，导致确认时突然失败。
- **死胡同**：前端版本号只能阻止旧结果上屏；AbortController 也不会终止已经进入同步服务线程的计算。
- **有效路径**：服务按检测引用记录当前请求代次，在写入预览队列的同一把锁内检查代次。后发请求无论成功还是失败，都不允许先发请求重新成为当前报价。前端同时取消过时读取，编辑立即清除确认资格。成交确认请求不参与这些取消。
- **通用规则**：只要异步结果有服务器端副作用，过时代次检查必须放在产生副作用的位置，不能只检查渲染。
- **牵连**：`manual_api.py`、`manual-live.js`、预览队列并发回归测试；没有放宽报价有效期或逐笔确认。
