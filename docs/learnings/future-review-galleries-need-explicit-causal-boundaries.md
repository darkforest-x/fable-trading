# 未来复盘图不能只“包含”未来，还必须显式标出因果边界

- **问题**：历史信号图的数据域实际已经延伸到冻结快照末端，但固定“latest 80 bars”的说明、局部检测框和“最新优先”的画廊顺序，让读者首先看到的是右端信号，无法确认每张图究竟有多少根未来 K 线。
- **死胡同**：只扩大上下文窗口或口头说明“右边就是未来”不够；事件越靠近快照右端，可见未来越少，而最新端点天然为零。若不标出首次可用时刻、共同终点和未来根数，图像包含未来仍可能被读成没有未来，也容易把代表检测点误当事件首次可交易点。
- **有效路径**：保留因果模型输入及其像素哈希不动，另建 review-only 全快照图；主面板画该币全部冻结确认 K 线，用实线标 `FIRST SIGNAL`、虚线标代表输入终点，并直接写出严格位于首次信号之后的未来根数/天数。画廊默认最早信号优先，当前 tip 事件明确显示未来为 0。
- **通用规则**：未来复盘交付的第一步不是“多画几根 K 线”，而是定义并可视化三件事：因果边界、统一观察终点、边界后的样本数；模型输入与富信息复盘图必须分目录并各自留哈希/manifest。
- **牵连**：`scripts/build_4h_yolo_global_future_gallery.py`、`charts_global_future/`、`all_global_future_charts.html`；延续 [人工审核未来对照必须与训练输入物理隔离](human-review-future-context-must-be-physically-separated-from-training-input.md)，不改变 YOLO 权重、阈值、输入、检测结果或 holdout 配置。
