# 原生回测截图的抄录必须通过数量与公式复核

- **问题**：TOTAL2 原生策略已编译并产生交易，但第一次截图抄录把成本 R、净 R 和样本数读错；JSON 格式合法掩盖不了数值矛盾。
- **死胡同**：要求同一个执行代理再次确认，得到的仍可能是同一阅读错误；在截图未保留、标签已关闭时，主代理也无法验证。不能把 `jq` 成功或源码哈希一致当作绩效正确。
- **有效路径**：保留原始错误收据，独立复核可见原生交易列表和统计表，并使用“有效量比根数不得超过已收盘根数”“预热不得早于最短所需窗口”“毛 R − 成本 R = 净 R”等不变量定位问题；只对实际读到的字段下结论。
- **通用规则**：UI 研究交接先保留仍可查看的页面与真实截图，再转交主代理。观测值、推算值与未读清值分栏，错误收据追加纠正而不覆盖。
