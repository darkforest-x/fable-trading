# 巡检发现必须按形态聚合，并保留精确看图入口

- **问题**：定时任务有结果，但用户必须逐任务、逐币寻找识别框；相同形态反复被扫描，还可能被当成多次新发现。
- **死胡同**：复用任务列表只能定位到任务，默认选币或恢复旧图表视角都可能展示另一处框。用最近扫描时间排序，也会让旧形态反复置顶；只对最近一天去重会丢掉更早的首次发现时间。
- **有效路径**：从不可变结果行增量投影形态元数据；同币、周期、方向和冻结输入契约内，以重叠核心合并。保留全历史首次观察时间用于排序、最新观察用于精确 job/symbol/detection 链接，时间筛选放在合并之后。显式巡检定位优先于保存的图表视角；普通浏览仍恢复原视角。失败更新保留上次列表并显示中断，不冒充空结果。
- **通用规则**：先区分事件、检测确认和实际观察三个时钟，再设计发现列表。列表的每一项必须能追到实际展示的框，而不是只追到包含它的任务。
- **牵连**：`yoyo/yolo_workbench/discoveries.py`、`api.py`、`yoyo/monitor/static/yolo-detect.js`；缓存基于现有 results 只追加契约，服务重启从原账本重建，不改原结果、推理参数或巡检计划。
