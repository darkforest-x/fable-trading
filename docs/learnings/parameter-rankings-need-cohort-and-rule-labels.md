# 参数排名必须同时说明规则、分组与收益口径

- **问题**：按胜率排序的参数CSV把配置、品种和时期混排，用户将前16行理解为16种策略；`v20`也会被误读为所有方案都要求成交量。报告另把汇总组枚举写成`GROUP1`，但数据实际是`GROUP1_GROSS`，导致筛选空白。
- **死胡同**：仅翻译列名或给最高胜率不足以解释结果。相同胜率的平均盈亏可能差很多，黄金毛收益也不能与加密净收益直接排名；原始配置字段存在不代表该规则使用了它。
- **有效路径**：保留原始配置和数据，另加中文规则及生效条件，逐条联结同配置同品种的全期、早期、后期结果。从冻结成交账本补平均盈亏、实际盈亏比和连损，并核对全部243条与原汇总一致；不重跑成交。汇总筛选使用实际数据键。
- **通用规则**：解释排名先辨明行粒度、重复覆盖、统计分母与毛净口径，再谈高低。把“选中的时期”与同一方案其他时期并排，避免把六笔交易的高胜率当成稳定最优。
- **牵连**：`monday_parameter_readout.py`、报告`ParameterReadout.jsx`与`LatestResearch.jsx`；沿用首次Stitch模板、原费用、原参数与冻结执行结果。
