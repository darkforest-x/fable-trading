# 可恢复研究队列必须逐阶段联结真实输入

- **问题**：批量找事件、结算收益、筛选容量需要连续运行数小时；进程中断、并行提交或只校验回执自身哈希，都可能让队列跳过工作或接受来源不一致的样本。
- **死胡同**：只用 mock runner 测“命令被调用”，无法发现真实 Git 调用签名、无关暂存文件被带入提交，以及测试中标签 ID 与筛选 ID 根本不同的问题。只记“批次扫描完成”也不代表该批的结算和筛选已经完成。
- **有效路径**：每阶段验证输入和输出 SHA，同时逐事件核对上下游身份与不可变字段。扫描批次与后续筛选轮分别保存状态；恢复时完成缺失的下游轮。提交使用明确 pathspec，并用临时真实 Git 仓验证无关暂存改动仍留在暂存区。容量依据联结后的独立 train 赢家重新计数。
- **通用规则**：长任务先定义可恢复阶段和数据契约；至少有一个测试跨过真实外部边界。回执不是证据本身，必须能回到对应输入和实际产物。
- **牵连**：`yoyo/datasets/ma_profit_queue.py`、`tests/evaluation/test_ma_profit_queue.py`；本轮只控制离线研究队列，不改变形态、收益或实盘规则。
