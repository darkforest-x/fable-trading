# 入场过滤实验必须固定原事件的消费顺序

- **问题**：SPIKE V11.2 原规则每框只取第一次突破；给突破加六均线支撑门时，很容易顺手改变哪个事件被允许入场。
- **死胡同**：先把不满足支撑的突破删掉，再让 `box_joints` 找首个突破，会让原本被拒绝的框等待第二个突破。看似只加一个过滤条件，实际同时引入了重试；只裁掉旧成交账本也会遗漏因腾出仓位新增的成交。
- **有效路径**：先完整生成原一次性事件，再加当前 bar 的支撑条件；每个实验臂分别串行重放。共同事件保持原 trade_key，使随机对照保持相同，但联结时必须使用 arm + trade_key。
- **通用规则**：修改事件资格前，先固定它消耗配额/状态的时点；明确失败是否允许重试。用“首个失败、后个成功”的最小例子和“早单过滤、后单释放”的例子验证，不从已成交子集冒充新策略。
- **牵连**：`yoyo/evaluation/spike_v112_support_study.py`、`tests/evaluation/test_spike_v112_support.py`；本轮只改 close > ropeHigh，不改重试、退出、费用或生产默认。
