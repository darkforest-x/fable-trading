# 全仓数量必须先预算手续费，再向下取整

- **问题**：界面改成全部可用资金开仓后，直接用余额乘杠杆再除价格，会把开仓手续费漏在预算外，导致真正提交时资金不足。
- **死胡同**：仅隐藏数量输入框、在浏览器用浮点数计算数量，既不能锁定当前挂单占用，也不能保证与后端 Decimal 账本一致；没有把这种方案当作可交付实现。
- **有效路径**：后端用一致读快照计算可用资金，再以 `可用资金 / (价格 × (1 / 杠杆 + 费率))` 求数量并向下取整。限价单用委托价预算。预览固定数量，确认事务重新校验资金；若期间发生变化则拒绝，不悄悄改用户已确认的数量。
- **通用规则**：全额操作先写出包括费用与已有占用的守恒式，再决定精度和舍入方向。预览不是资金锁；挂单提交才冻结。
- **牵连**：`yoyo/research_workspace/paper_desk.py`、`paper_desk_api.py`、`tests/research_workspace/test_paper_desk_limits.py`。每边 0.1% 成本保持不变；“全仓”在本产品明确指全部可用资金，不声称实现交易所强平或跨仓风险引擎。
