# 删除研究功能必须按归属和引用关系清理

- **问题**：一个研究入口背后还有源码、行情缓存、实验登记、产物记录、知识库副本和系统启动项；只删除菜单会留下可重新生成数据的后台及失效引用。
- **死胡同**：按关键词把所有命中文件删除，会误伤被不同市场共用的模型、渲染器和回放引擎；只看 Git 差异又会漏掉被忽略的大量数据文件。
- **有效路径**：先核对实验与产物的引用集合，区分专属调用方与共享依赖；检查后台写者后按明确路径清除数据，同步移除登记和入口。登记删除前后逐条比较剩余记录，目录统计包含未跟踪文件且不跟随越界软链接。
- **通用规则**：删除范围由资源归属决定，不由关键词命中或 Git 是否跟踪决定。验收同时检查残留文件、注册表、后台配置及实际页面。
- **牵连**：实验与产物注册表、研究工作台、独立启动项；共享工作目录里的其他未提交改动必须保留，提交只包含本次清理。
