# 容量门调整必须与收益标签的血缘分开

- **问题**：Owner 把启动训练的独立事件门槛从 3000 改为 1500，而已完成的扫描、收益标签和增量缓存都绑定原始计划 SHA。
- **死胡同**：直接修改原 plan 的数量会让不涉及容量的缓存失效；覆盖旧 contract 则让历史未过门的结果失去当时口径，甚至被新门槛错误重解释。
- **有效路径**：保留原 plan、旧 contract 和旧轮回执；新建包含 Owner 原话的 amendment，用 SHA 绑定原计划和旧契约，再由新 selection/training contract 只覆盖容量门。工作队列在停止边界保存旧状态与迁移回执，之后的选择显式使用新契约。发现规则和收益实现不动，旧标签继续按原始身份与实现哈希核验后复用。
- **通用规则**：先判断变更影响哪一阶段的语义，再版本化该阶段的控制文件；不能用一个全局可变参数重解释所有历史产物。
- **牵连**：本轮 `exp-ma-profit3r-20260922-v1` 的 selection、queue、dataset、Windows trainer；数量始终按独立 train 事件计，A/B 图片变体不增加容量。
