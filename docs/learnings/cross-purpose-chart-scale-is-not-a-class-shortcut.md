# 跨用途图表尺度不同不等于类别捷径

- **问题**：同一段行情在 48 根人工审核图和 W14–22 模型输入图里都铺满 1280 像素，单根 K 线宽度与纵轴重算结果明显不同；仅凭观感容易把它判断成训练正负样本的缩放错误。
- **死胡同**：继续挑几张截图肉眼对比只能证明“两个用途看起来不同”，不能证明正类与负类是否用了不同渲染管线，也抓不到窗口长度分布造成的类别 shortcut。
- **有效路径**：先核对正、easy、hard 的实际 `render_chart` 调用点，再按 split × class 逐档比较 W14–22 和 confirmation3–5 分布。跨用途差异确实存在，但训练内三类同渲染器，easy 每档等于 positive、hard 每档等于 positive 2×，因此不是类别画风差异。
- **通用规则**：遇到“训练图看起来和审核图不一样”，第一步同时审计调用路径、像素尺寸、窗口支持集和各类分布；只有类条件分布不同才有 shortcut 证据，不能把跨用途视觉差异直接定性成训练 bug。
- **牵连**：`yoyo/datasets/ma_launch_t3_training.py`、`datasets/ma_launch_t3_10000_v1/manifest.jsonl`、W14–22、confirmation3–5、1280×742、48-bar review-only 画廊。
