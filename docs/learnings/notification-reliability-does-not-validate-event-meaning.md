# 消息送达成功不能证明事件定义正确

- **问题**：用户要IMACD主线刚离开零轴的启动，监控却同时推送密集入场、近零范围释放与趋势结束。70条真实回执里有32条趋势结束、13条近零释放，传输与去重通过也无法补救语义错误。
- **死胡同**：把Pine里所有有标记的事件都当成值得通知的信号，再以扫描覆盖、TG回执和UI测试宣称完成。近零范围不是精确零轴，回到零轴与离开零轴方向相反；传输测试不检查用户想知道的事实。
- **有效路径**：把“前根md==0，本根md>0或<0”定义为单独zero_breakout契约，微小非零立即合格；其他特征作背景。引擎、队列、发送端、API、统计和主图箭头统一口径，并以反例明确拒绝延续、回零、ATR释放和信号线交叉。
- **通用规则**：先用一条正例和几条最易混淆的反例固定通知事件，再测送达。升级用与行情相同的校准时钟记录首次生效点，保留旧回执但不把重算历史以新事件身份再推送。
- **牵连**：`yoyo/monitor/signals.py`、`policy.py`、`service.py`、`store.py`、`telegram.py`、`server.py`、`static/`；不改变订单、模型或原Pine。对照旧交付见`analysis/p0_imacd_mac_monitor_20260908.md`。
