# 异步评分通知必须绑定原事件并保留等待态

- **问题**：2026-10-30，Owner 要周一 1.618 Telegram 只推原始评分严格大于 0.4；触价入通知队列时，另一线程尚未把评分写入数据库。
- **死胡同**：立即取最新币种评分会串周或串方向；把没有评分行当低分会漏掉稍后就绪的高分；先标记发送中再等评分，会让重启把尚未发出的消息当成投递结果未知。仅凭 `taken` 也不能代替独立的通知阈值。
- **有效路径**：按纽约周、币种、上下沿、触价及观察时间戳读取原始评分。无记录保留 pending，明确错误终态则跳过；在数据库锁外读分，严格比较未舍入值。通过门槛后才原子认领同一事件，并再次校验订阅代次及原 90 秒新鲜度。等待项按下次可处理时间排序，让后续已就绪事件继续处理。
- **通用规则**：通知过滤依赖异步信息时，先区分“未就绪”“明确不合格”“已开始投递”；用事件身份联结，不能用最近一条或显示舍入值代替。
- **牵连**：`monday_fib.py` 的 pending/claim/deliver_once、`monday_reclaim_paper.py` 的只读 notification_score、`server.py` 的启动前接线。模型、交易入场、Bark、已发送记录及不确定 HTTP 结果不自动重发的规则保留。
