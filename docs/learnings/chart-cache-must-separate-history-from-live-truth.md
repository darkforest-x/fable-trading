# Chart caching must separate historical preview from live truth

- **Problem**: Backend SQLite and memory caches did not prevent a slow chart entry. Browser timing showed the paper snapshot starting only after boot, followed by serial Monday levels, a duplicate levels read, and a late chart library load. Per-chart memory disappeared on reload and was isolated between the paper and Monday pages.
- **Dead end**: Increasing backend retention or treating all responses as long-lived browser cache would not remove the serial dependency chain. Persisting whole chart context would also retain paper fills and misrepresent old data as live. No backend cache/rate limits were changed.
- **Effective path**: Fetch only the selected public candle/anchor pair alongside startup code; consume warmed responses once. Share public memory across independently owned chart controllers. Persist a strict OHLC/anchor whitelist in asynchronous IndexedDB, keyed by symbol, NY week and native period. Bound history to 12 views of 720 closed bars and anchors to 32, reject records older than 24 hours, and revalidate online. Mark restored history as stale until a fresh response replaces it; empty loading responses must not erase an already visible historical preview. Guard every async restore by current chart identity and fresh-data precedence. Skip unchanged live snapshots without suppressing volume or stale-status changes.
- **General rule**: Measure the browser dependency waterfall before adding cache capacity. Treat cached history as a display aid, independently from live tips, account truth and execution authorization. Verify persistence by blocking the actual candle/anchor endpoints and reloading, then verify online recovery; unit tests alone do not establish browser persistence.
- **Affected code/constraints**: `public-chart-cache.js`, `startup-hints.js`, `monday-fib-chart.js`, `reclaim-chart.js`, `monday-reclaim-paper.js`, `monday-candle-feed.js`. Backend CandleHub remains the single public-history writer with its existing request budget. Paper balances, fills, positions and order checks never enter IndexedDB. Browser tests leave no blocked URLs or temporary tabs behind. IndexedDB contract: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API).
