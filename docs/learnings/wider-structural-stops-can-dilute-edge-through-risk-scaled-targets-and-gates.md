# 更宽的结构止损会通过风险缩放目标和执行门稀释优势

- **问题**：K1→K2 的失败单里，很多止损后又走到 3R；直觉上给 K2 极值外再加 ATR 缓冲，似乎应该减少“扫损”。但 15m、5m 从 0 增至 0.10–0.50 ATR 后，开发期稳健净收益全部下降。
- **死胡同**：只看“止损后是否反向走回目标”会把更宽止损当作纯粹的容错。实际 3R 目标按风险距离同步外推；同时 `fee_to_risk` 门会放入原先被拒绝的窄风险信号，并改变 cooldown 后谁先占用交易名额。因此事件数增加不等于原交易获救，也不是同一批交易的公平比较。
- **有效路径**：先按真实执行链比较全体结果，再把原始 0 ATR 交易锁成固定 cohort，只重算止损与 3R 目标。两种口径都恶化：15m 全体稳健分从 -16.35bp 降至最低 -23.07bp，5m 从 -17.68bp 降至最低 -20.48bp；固定 cohort 也随缓冲扩大总体走弱。被救回的止损少于因更远目标/路径变化而转成止损的原非止损交易。
- **通用规则**：测试结构止损宽度时，必须同时报告三层：真实执行 cohort、固定信号 cohort、门禁/冷却导致的 cohort 置换；若目标用 R 缩放，不能把“宽止损”解释成只改变止损。
- **牵连**：`scripts/research_btcusdtp_k1k2_stop_buffer.py`、`scripts/diagnose_btcusdtp_k1k2_stop_buffer.py`、`k2_stop_buffer_atr`、`target_r=3`、`fee_to_risk_max=1.25`、15m/5m cooldown、20bp 往返成本；本结论只来自 2023–2024 development，未打开 audit 或 holdout。
