# 独立额度必须同步拆分每一道资金预留池

- **问题**：BTC 用满保证金额度后 ETH 被挡住。原规则同时存在 BTC/ETH 共用保证金池和跨币种共用的名义仓位池，Owner 要求两者各自独立。
- **死胡同**：只修改前端提示或保证金分类不能解决问题，第二道名义仓位预留仍会把另一币种截成零；直接改变缺字段的旧账本默认值又会静默放宽历史规则。
- **有效路径**：把额度范围保存为显式 policy 字段，前端估算与服务端验收使用相同池身份。新规则分为 BTC、ETH、山寨币共享三池，旧字段缺失仍解析为旧共享语义。Owner 本地迁移只改当前入场规则并增加 revision，保留持仓保护、挂单意图、计数、冷静期及历史；旧预览因此失效。验证持仓/挂单占满 BTC 后 ETH 计划仍等于空池计划，同币种部分成交与余单合计只占一次，山寨池仍共享。
- **通用规则**：遇到“独立额度”需求，先列出展示、预览、接受、成交核验用到的所有资金池，再分别检查池身份、余量与全账户现金约束。额度上限相同不代表额度范围相同。
- **牵连**：`yoyo/discipline_app/policy.py`、`book.py`、`mobile/src/ticketEstimate.ts`、`entryAvailability.ts`；`tests/discipline_app/test_independent_allowances.py` 和 `margin_allocation.test.ts`。未更改单笔风险、日亏、次数、可用资金及交易所保护规则，验证仅用合成账本。
