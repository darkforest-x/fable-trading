# 操作提示的生命周期不能依赖轮询重绘

- **问题**：模拟开单把操作反馈从页面横幅改成浮窗，页面每 5 秒轮询，且新建账户和止盈止损使用原生模态对话框。
- **死胡同**：排除的方案（未实施）是每次 render 重新启动消失计时，或只给浮窗更高的 z-index。前者会让成功提示随轮询续期；后者无法越过原生 dialog 的顶层及交互隔离。关闭提示时整体重绘也会干扰正在填写的表单。
- **有效路径**：将提示存为有独立 ID 的事件，成功提示只在产生时设置计时器，关闭时仅更新提示容器。容器置于当前对话框内并通过手动 popover 进入顶层，页面无对话框时则置于工作区。后台同一错误在恢复前去重；操作已记账与随后刷新失败分开表达，关闭提示不清除待核对请求。
- **通用规则**：改动操作反馈时，先区分事件、持续状态和重试凭据，再验证重绘、模态层、关闭及超时是否影响这些不同生命周期。
- **牵连**：`yoyo/monitor/static/paper-desk.js`、`paper-desk.css`、`tests/monitor/frontend_paper_desk.test.cjs`。在独立浏览器样例中验证浮窗显示、自动消失及模态内关闭，没有向运行中的模拟账户提交测试交易。
