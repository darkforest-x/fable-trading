# Fee breakeven changes the exit path, not just the cost column

- **问题**：An exact-entry stop loses its entry and exit commissions. Moving it to a fee-neutral price can recover that cost, but can also stop a trade before its original target.
- **死胡同**：Adding commissions back to old stopped trades would assume their old exits still occur. Using a taker/taker formula for a maker entry also overstates the required stop distance. A reclaim close can lie inside the entry price without leaving enough room to place the fee-neutral stop.
- **有效路径**：Use the actual native entry commission C, filled quantity Q, entry E, side s and exit fee t: B=(E+s*C/Q)/(1-s*t). Round long upward and short downward to the price tick and check native Money rounding. Owner chose to retain exact-entry protection until a completed execution-period close leaves at least one tick behind B. Re-run only affected trades with native orders, preserving existing baseline fills and controls.
- **通用规则**：A changed stop requires a new execution path and paired trade comparison, not fee repricing. Record fee protection separately from entry-price protection; outward rounding can turn an economically flat exit into a tiny positive return, so show target-hit rate alongside strict positive-net win rate. Gaps can still execute below fee breakeven.
- **牵连**：`yoyo/layers/l3_backtest/nautilus_reclaim_fee.py`, `yoyo/evaluation/monday_reclaim_fee.py`; owner answer 2026-10-24. New adapter binds the existing run_native code to a private strategy namespace so source identity of running baseline workers stays unchanged. Active replay windows retain all bars through the original exit: because only the stop tightens and TP is unchanged, new exits cannot be later; native fixtures and per-trade checks enforce this bound. This optimization does not apply to changed entries, wider stops or new price-history features.
