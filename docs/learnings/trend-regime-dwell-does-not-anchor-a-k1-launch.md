# 趋势 dwell 不能保证 K1 是启动点

- **问题**：K1→K2 策略用双均线强趋势连续若干根来减少盘整信号，但实际信号距 regime 起点中位数仍可达到几十根，识别成了成熟趋势里的局部穿越。
- **死胡同**：继续缩短 `strong_dwell_bars`，或在信号后追加 `regime_age<=N`。前者只改变何时宣布强趋势，后者在不同时间段挑出不同噪声；两者都没有规定哪一根 K1 有资格启动 episode。
- **有效路径**：把状态记忆锚到 K1 本身：中性/收缩后首根合格贯穿负责 arm，2–8 根内首个合格 K2 消费该 episode；只有重新中性或反向启动才 rearm。
- **通用规则**：需要“抓启动”时，先检查事件时钟由谁启动。趋势状态、冷却时间和距离上限只能约束上下文，不能替代显式的首事件身份。
- **牵连**：`scripts/research_asset_specific_k1k2_15m.py`、`strong_dwell_bars`、`regime_start_i`、K1 去重与 Pine episode 状态机；下一版必须用新前向数据验证。
