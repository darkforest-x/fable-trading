# 分钟接口的请求条数不是可用历史承诺

- **问题**：A 股 1h/会话 4h 扫描向 Eastmoney 60m 接口请求 `lmt=1024`，参考指数实际只返回 127 根（2026-07-21 至 2026-09-02 14:00）。这既达不到完整 W19 图所需的 `MA120 + 18 = 138` 根 1h bar，也不可能形成预注册要求的 160 个完整 4h 交易日。
- **死胡同**：把请求参数、AKShare 的 period 支持或 HTTP 成功当成历史覆盖保证。上游可以接受 `lmt` 却仍只保留近期分钟数据；若先扇出全市场，几千次请求之后才会发现模型根本没有 warmup，浪费配额并容易把“数据不足”误报成“零信号”。尝试用旧 `end` 参数向同一接口倒页也被上游断开连接，不能据此宣称可分页。
- **有效路径**：在加载模型和请求任何个股前，先用同源宽基指数取一页，检查实际首尾时间、精确交易时段槽位和两个下游最低历史需求；不足就写消费账本并 fail-closed。需要改用新浪/其他供应商、日线替代会话 4h，或改变 warmup 时，视为新的数据配置，先重新预注册和取得 holdout 授权。
- **通用规则**：分钟全市场任务的第一条网络请求必须是参考品种 preflight；用“实际返回根数与精确时序”验收，而不是用 `limit` 参数、文档支持的 period 或状态码验收。最低根数应从最长特征窗口与完整模型输入反推，例如 `max_ma_period + max_window_len - 1`。
- **牵连**：`scripts/scan_ashare_yolo_1h4h_long.py`、`yoyo/data/ashare_sessions.py`、Eastmoney `stock/kline/get` 的 60m 近期历史上限、Grade-A `MA120 + W18/W19` 输入合同、holdout #9/#10 消费账本。AKShare 文档也明确把东财分钟接口描述为只能获取近期分时数据。
