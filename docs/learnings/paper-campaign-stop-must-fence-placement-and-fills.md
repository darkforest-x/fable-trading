# 持续模拟挂单的停止必须同时约束下单与成交

- **问题**：全币种周一 1.618 持续开关会跨浏览器、后台线程和周区间存在。仅停止扫描不能阻止在途预览继续挂单，也不能阻止撮合线程成交旧周委托。
- **死胡同**：把普通单笔下单循环扩成批量，会重复消耗同一份可用余额；只在扫描开始读取开关，停止与网络响应交错时仍可能新增订单。放宽普通下单的数量限制又会改变手动交易行为。
- **有效路径**：预览按同一账户逐笔虚拟预留保证金与入场费；真实下单复用纸面账本并在 SQLite 写事务中重新检查余额、配置代次、当前纽约周和过期时间。撮合事务先取消失效代次与过期单。账户×周×币种×方向的持久唯一键防止重启重复挂单，停止只撤销此功能拥有的未成交订单。批量扩容只允许经内部身份校验的路径。
- **通用规则**：持续开关的权限边界应落在最终写入与成交处，不能只放在页面或调度入口；预览是可审阅估计，不能代替提交时的余额与状态复核。
- **牵连**：`monday_bulk.py`、`paper_desk_limits.py`、`paper_desk.py`；同向已有持仓跳过，Maker/Taker 分开记账，纽约周界按时区计算。配置重试复用请求 ID，版本冲突要求刷新；没有真实交易或模型准入变化。
