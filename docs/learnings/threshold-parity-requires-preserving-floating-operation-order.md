# 阈值边界复现必须保持浮点运算顺序

- **问题**：V13.1 规则拆解完整样本检查中，ENSOUSDT 30m 原始信号少一根，EULUSDT 60m 的一个空头信号被推迟。原始研究引擎未改动。
- **死胡同**：将 `abs(close-open)/(high-low)>=0.55` 向量化时改写为乘法比较；实数代数等价不保证浮点阈值判断等价，少数边界还会改变持续等待状态。四币 smoke 与随机行情测试没有覆盖这些精确价格。
- **有效路径**：逐根比较独立原始引擎，定位实体占比边界。ENSO OHLC 为 0.861/0.876/0.856/0.872，EUL 为 1.522/1.536/1.496/1.5；保留原版除法顺序，加入真实价格的行为回归测试。收益分析前重新计算全体规则和特征；旧完整收据只可复用输入相同且退出逻辑未改的价格路径。
- **通用规则**：优化阈值计算时先保证逐事件语义一致；完整样本的少量不一致不能被“误差很小”豁免，状态机可能放大它。复用缓存必须按依赖拆分，检测器变了不能直接复制旧政策成员与持仓队列。
- **牵连**：`yoyo/evaluation/spike_v131_rule_facts.py`、`spike_v131_rule_study.py`、`tests/evaluation/test_spike_v131_rule_facts.py`；失败运行及诊断保留在 `exp-spike-v131-rule-state-20261019-v1`。
