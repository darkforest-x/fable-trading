# 共用模型管理不能代替输入输出契约

- **问题**：YOLO、VLM、LightGBM 和规则研究逐渐各自拥有菜单、数据与流程；需要共用平台，又不能让模型组合看似接通却实际被忽略。
- **死胡同**：仅把能力放进同一个模型菜单，或将 YOLO → VLM → LightGBM 固定串联，都不能证明数据和输出契约兼容。旧 LightGBM 权重存在、ACTIVE 指针存在，也不代表有效执行 bundle 或经济验证通过。
- **有效路径**：在原有层外建立数据、特征、模型、策略、评估、前向运行的目录与版本化组合。保存研究计划和允许运行分开；实际适配器必须消费所有绑定，否则明确阻塞。运行固化计划版本，模型审计单独记录身份与未知项。
- **通用规则**：整合系统先核对每项能力消费什么、产出什么、由谁执行与验证，再建立共同注册表和版本引用；共享目录不授予兼容性或准入资格。
- **牵连**：`yoyo/contracts/research.py`、`yoyo/research_workspace/platform.py`、`model_catalog.py`、回测与 paper API；四层 import 边界、P0/P1 与原冻结成本继续有效。
