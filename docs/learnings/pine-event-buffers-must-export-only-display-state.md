# 跨周期画历史事件，要逐源 K 线累积、只导出必要的显示状态

- **问题**：固定 1H 勾叉要在 5m、4H、日周月图显示，且只在源小时收盘后出现。大周期直接请求信号布尔值只能拿到一个小时；逐小时返回整份历史事件列表又触发了 TradingView RE10139 内存上限。
- **死胡同**：第一版虽然把列表限制为 100 条，仍对 12000 根源 K 线重复跨上下文复制列表。原生编译通过，但加入图表时报 `Memory limits exceeded`。事件条数有上限不等于总请求内存有上限。
- **有效路径**：在 1H 上逐根运行原公式并累积有界事件，保留时间、收盘可用时间、价格和方向；只向主上下文返回最新源 K 线及最后历史源 K 线的状态，其余返回 na。小周期对整份状态偏移后使用 lookahead_on；大周期选择不晚于观察时间的状态。观察时间取当前时钟与图表收盘时间的较小值，避免初次加载把未来的计划收盘误作已经发生。绘图只管理自己的句柄，并提前从 500 条总预算中预留容量。
- **通用规则**：先区分“每根源 K 线都要计算”和“每根图表 K 线都要接收完整列表”。绘图只需要末端状态，内存设计按跨上下文复制次数计算；编译通过不能代替原生运行。跨周期验收比较事件时间、价格、方向和数量，而不只看图上有线。
- **牵连**：`yoyo/evaluation/pine/monday_range_v2_1.pine`；`tests/evaluation/monday_range_v2_1_native_checks.pine`；[TradingView 内存限制说明](https://www.tradingview.com/pine-script-docs/errors/RE10139/)；历史覆盖仍受源数据与保留数量限制。
