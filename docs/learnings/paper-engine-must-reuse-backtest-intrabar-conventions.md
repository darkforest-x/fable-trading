# A paper engine must reuse the backtest's intrabar conventions, or its record cannot confirm the backtest

- **Problem**: The owner asked for the Monday 1.618 limit-reclaim v2 rule to run as simulated live trading. Live quotes arrive as minute candles (high, low, last price), not ticks. Inside a minute in which both the fill or stop and the target are touched, the order of events is unknown.
- **Dead ends**: The obvious live logic is "a high above the target means the target filled". That is the optimistic O-L-H-C ordering. Under that ordering, short same-bar targets inflated the Codex backtest. Only 247 of 1,792 survived the other ordering, and their mean went from +398bp to −51bp. A paper engine that counts those fills would reproduce the bias the research removed. Its forward record would then look like a confirmation without being one. A second dead end was doing REST reads and SQLite writes inside the stream callback. The Monday stream feeds 507 contracts, and blocking it delays every other consumer.
- **What worked**: The engine applies the same conservative rules as the worst-path backtest. In the fill minute, a target counts only when the close is beyond it. In any later minute, a stop beats a target. A failed reclaim exits at the confirmation close as a taker. Fees and slippage are booked the same way as in the backtest (maker 2bp, taker 5bp, slippage reported separately as `net_slip_bp`). The frozen score file is asserted equal to the experiment's file by a test. Stream listeners only enqueue, and a worker thread does the I/O. The first live trade, a 40 percent three-minute LIGHT crash, was checked against OKX 1m candles before being believed. It filled and hit target in the same minute, and the close of 0.212 was beyond the 0.2027 target, so it passed the conservative rule.
- **General rule**: Before writing a paper or live engine for a backtested rule, list every place where the backtest had to assume an intrabar order. Implement the conservative side of each assumption in the engine, and pin the model or parameters with a parity test. An outlier first trade gets checked against exchange candles before it is reported.
