# 模拟挂单也必须把冻结、撤单与成交放进同一事务

- **问题**：页面关闭后挂单仍需触发；重复轮询、撤单与市价操作可能争用同一份资金或持仓。
- **死胡同**：只在页面定时器中保存目标价格，刷新或关闭页面便丢失；只在成交时检查余额也会允许多张挂单重复使用同一笔钱。没有用这些方案代替后台订单状态。
- **有效路径**：SQLite 持久化订单，开仓预留保证金与预计手续费，平仓锁定数量。创建、撤销、撮合共享 BEGIN IMMEDIATE 写事务和请求回执；后台线程只用提交后新鲜 bid/ask 触价，保守按委托价全额成交，唯一 fill_id 防重。缺行情等待，资金在触价前恶化则拒绝并释放占用；停机不补历史触价。
- **通用规则**：持久化意图与可执行状态分开。价格触达只提供触发证据，资金和数量仍须在写事务内裁决。并发撮合与撤单必须至多产生一个最终结果。
- **牵连**：`paper_desk_limits.py`、`paper_desk.py`、`yoyo/monitor/server.py`。独立本地模拟线程不进入 forward 脉冲，也不调用交易所下单接口；固定报价、过期报价、并发竞态和重启测试提供验收证据。
