# 信号 R 统计必须先去重、分清参考路径，再分页

- **问题**：前端需要按日、周、周期和方向统计 R，但原接口只返回最近 500 条；YOLO 确认又是原信号的第二条事件。
- **死胡同**：在当前卡片数组直接求和会漏掉后面的记录；把 YOLO 当新交易会重复记账；把峰值 R 或缺失退出 R 当成已实现收益会虚增结果。
- **有效路径**：服务端先按协议与来源取完整集合，用原始信号 ID 联结最新 performance，再按原信号北京时间收盘日归属日/周，最后筛选、排序和分页。已结束使用 exit_r，运行中使用 current_r，分开求和；缺失及非有限值不当作零。
- **通用规则**：先定义统计单位、时钟与收益来源，再决定 UI 的总计和分页。信号参考 R 未扣成本，不是账户实际收益；研究回放缺 performance 时保留未知。
- **牵连**：yoyo/monitor/signal_analytics.py、store.py、server.py、static/app.js；原始多头与独立空头协议；实时/预热/回放来源隔离；YOLO 不能重复计入。
