# Entry-stop shortcuts must resolve inside the ledger transaction

- **问题**：持仓卡片需要一键将止损移到开仓均价；页面里的均价、止盈和当前行情可能在点击之前已变化。
- **死胡同**：不能仅把前端显示的 entry_price 回传为普通止损，否则并发加仓后会使用旧均价，也可能覆盖另一次调整后的止盈，或把已有更有利的止损后移。开仓价也不是含手续费的净保本价。
- **有效路径**：客户端只提交 stop_to_entry 意图、新鲜报价 ID 和幂等请求号。服务端在账本写事务内读取当前剩余仓位、均价及原止盈，核对多空对应可平仓价；已在开仓价或更有利位置时保持不动。复用保护修改回执、导出审计及后续触发逻辑。前端只给出即时可用提示，服务端仍负责最终校验。
- **通用规则**：涉及当前资源状态的快捷操作应发送意图，由同一事务计算目标值并保留无关字段；快捷入口不能降低原有幂等、新鲜度和并发保障。
- **牵连**：`paper_desk.py`、`paper_desk_api.py`、`paper-desk.js` 及对应 stops/frontend 测试。隔离临时账本验证多空止损 100、止盈 130/70 保留；测试不修改用户账本。证据在 `output/paper-entry-stop-20261017/`。移动端 44px 规则需要足够选择器优先级，避免被模块 ID 样式覆盖。
