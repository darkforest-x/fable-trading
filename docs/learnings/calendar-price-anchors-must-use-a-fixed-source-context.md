# 固定日历的价格锚点必须与显示周期解耦

- **问题**：V2.42 的 ETH 2026-10-12 周一区间在 12h 图显示下 1.618=2322.35，15m 图为 2301.86。Owner 确认统一按纽约完整周一，而不是按图表 K 线开盘日取整根 OHLC。
- **死胡同**：仅保持纽约时区不够：12h 整根累计仍会漏掉周一前段并纳入周二。扩大原有共享 15m 上下文至 100000 根后，原生 Pine 内存超限；把新模块的对象返回改成标量仍超限，不能仅把错误归因于新对象。
- **有效路径**：V2.43 在独立固定 30m 上下文累计选定时区周一 00:00 至周二 00:00 的完整源 K；该周期与纽约、UTC、上海的日界线对齐。请求只返回标量字段，原有 15m profile／交易引擎维持原范围。低图表周期取偏移后的已确认快照；高图表周期在源上下文累计每根后采样，并剔除尚未收盘快照。日线也用所选时区。首段缺失的周一区间不发布，跨周清空；插针判断要求信号整根开盘不早于周一完成，不能让跨越周二零点的高周期 K 借用后知高低点。
- **通用规则**：把“窗口按哪个日历切”“底层哪种粒度能准确切边界”“在哪个图表显示”分别定义。固定日历价格不可用当前图表 OHLC 替代。增加请求历史时检查同上下文的其他模块及实际原生内存，而不只检查新函数。无源数据时保留缺失，不回退到错误的图表周期价格。
