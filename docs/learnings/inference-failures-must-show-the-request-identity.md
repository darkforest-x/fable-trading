# Inference failures must show the identity of the actual request

- **问题**：The ACU screenshot showed a Zhipu read timeout after Qwen had previously been selected. A generic incomplete-result card hid provider identity inside details and rendered empty evidence, risks and direction as though a judgment existed.
- **死胡同**：Assuming the screenshot was stale, that the provider had silently fallen back, or that a read timeout proved poor visual reasoning would all exceed the evidence. Increasing a wait budget alone also cannot identify whether provider processing or transport caused the silence.
- **有效路径**：Compare live status, private configuration metadata without printing credentials, and the immutable run/exchange. On 2026-09-24, the active profile had been saved as Zhipu at 12:37 local time. ACU run `b44a47e913e74545b70aeca043605363` used `glm-5.3-flash`, six images, non-streaming output and max reasoning; its read phase timed out after approximately 300 seconds with no complete HTTP response captured. Qwen's separate profile still had no key. This establishes request identity and failure phase, not who changed the configuration or the remote cause.
- **通用规则**：Current selection and historical request identity are different facts. Show the frozen provider, model, time and elapsed duration on the result card; missing historical identity stays unknown. A failed request has no accepted shape verdict. An enabled worker waiting for a key must visibly say it is waiting. Do not switch suppliers, relabel past records or replay unknown requests while diagnosing a screenshot.
