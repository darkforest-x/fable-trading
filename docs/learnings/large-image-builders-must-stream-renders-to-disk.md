# 大批量图片构建必须逐张落盘

- **问题**：统一审核包要生成 2,649 张 1280×742 RGB 图；若先把所有 `numpy` 像素数组收集完再写盘，峰值仅原始像素就约 7.5GB。
- **死胡同**：第一版 builder 把每张 `image` 留在 `rendered` 字典，完成全部币种后才进入写盘循环；实时检查发现运行数分钟仍是 0 个产物，及时中止了空构建。
- **有效路径**：每张图渲染后立刻 PNG 编码、写盘并记录 SHA，内存只保留窗口端点、路径和哈希等小元数据；同币种 DataFrame 用完即释放。
- **通用规则**：批量媒体 builder 在正式运行前先估算 `数量 × 高 × 宽 × 通道`；超过数百 MB 就默认使用“生成一项、校验一项、落盘一项”的流水式结构，并用产物计数观察进度。
- **牵连**：`yoyo/datasets/fixed_w10_canonical_review.py`、`_write_png`、2,649 张、1280×742 RGB、约 287MB 压缩 PNG。
