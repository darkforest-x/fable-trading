# Bark 的归档 TTL 不是发送新鲜度

- **问题**：Owner 发现通知几分钟后不见了，并明确 Bark App 内历史也消失。1.618 推送含 `isArchive=1, ttl=600`。
- **死胡同**：只检查是否启用归档或是否收到推送，会漏掉已经保存后又自动删除的机制；把 `ttl` 当作过时交易提醒的投递期限，反而删掉了复盘记录。
- **有效路径**：按通知消失的具体位置区分横幅与归档，核对 Bark 官方 API 的字段语义：`ttl` 是归档有效秒数，600 即10分钟。删除发送端 TTL，保留显式归档；交易信号新鲜度仍由发送前90秒资格判断负责，去重和回执不变。用假发送器断言请求归档且无 TTL，并回归过期信号不发送。
- **通用规则**：分别定义“可发送的时间窗”“设备展示行为”“历史保留时间”；不能因字段都叫过期时间就复用一个参数。
- **牵连**：`yoyo/monitor/monday_fib_bark.py`、`tests/monitor/test_monday_fib_bark.py`；[Bark 官方 API](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md#push)。删除旧消息的客户端行为不由服务器回执证明；旧记录不自动恢复，也不自动重发。
