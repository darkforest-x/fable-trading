# 更细的图表周期必须读取真实细粒度行情，成交时间仍以原账本为准

- **问题**：回测回看和实时壁纸新增 1m、2m、3m，但原研究行情可能只有 5m，OKX 也没有原生 2m 周期。
- **死胡同**：仅扩充下拉选项会将不支持的周期传给上游；拆分已有 5m OHLC 无法还原分钟路径。把新图上的分钟位置当成原研究的成交精度，同样没有证据。源码和接口检查即排除这两条路径，未生成伪造行情。
- **有效路径**：实时 2m 只在展示适配层聚合完整的 UTC 1m 对，形成中数据单独返回；缺分钟不补齐。历史回看先复用登记的 Binance 1m 缓存，仅为缺失的交易窗口读取同合约官方日档并写入独立展示缓存。用完整聚合后的 5m 高低收和成交量核对原数据，周区间及开平仓记录保留原账本语义。开盘价未作为核对项：部分原档的零成交分钟开盘口径不同，不据此改写原档。
- **通用规则**：新增图表周期先核对上游原生周期与源数据最小粒度；只允许向上聚合，细化必须找真实数据。展示粒度不会自动提高回测成交精度。
- **牵连**：`yoyo/monitor/chart_periods.py`、`monday_candles.py`、`monday_chart_history.py`、`strategy_backtest.py`、`yoyo/data/binance_minute_window.py`；历史研究输入只读，不改变扫描器、成交引擎或成本。验证覆盖缺失分钟、未收盘桶、历史翻页、来源核对以及桌面和手机周期切换。
