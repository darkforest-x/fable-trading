# 已确认候选不能要求未来行存在

- **问题**：旧 owner K1/K2 检测循环止于 `len(featured)-1`，使最后一根已收盘 K2 因为没有下一行而消失；旧对照又使用整月分位数与未来候选排除区。
- **死胡同**：直接复用旧 `load_featured` 或补一根假的 OHLC，既会扩大读取范围，也把“有无可执行价格”混入形态定义。缩短读取窗口并不能消除这类依赖。
- **有效路径**：按 Pine 源码独立提取纯形态候选，包括最后一根完整 K2；候选、下一开盘执行、最终收益分开。对照使用各自决策之前的 ATR 排名；未来价格只能进入结果标签，不能决定过去是否是候选。
- **通用规则**：先问输出代表候选还是成交，再做前缀不变性测试。不得用下一行的存在性补救候选器接口。
- **牵连**：`scripts/backtest_btcusdtp_1h_owner_causal_v2_preholdout.py`、`yoyo/data/k1k2_owner_source.py`、V36 同源研究；旧报告与历史输出不改写。
