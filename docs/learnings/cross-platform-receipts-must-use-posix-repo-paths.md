# 跨平台回执必须使用 POSIX 仓库相对路径

- **问题**：Windows 3060 正常完成推理并把所有文件与 SHA 拉回 Mac，但独立 verifier 把回执中的 `analysis\output\...` 当成一个含反斜杠的单独文件名，因而错误地报告产物缺失。
- **死胡同**：直接用 `str(path.relative_to(ROOT))` 写回执，默认本机路径分隔符也是跨机协议；或者事后改写已生成的 JSON 路径。前者只在同操作系统验证时碰巧成立，后者会破坏已经核过的远端/本地回执 SHA。
- **有效路径**：写端统一用 `Path.as_posix()` 序列化仓库相对路径；读端先兼容规范化历史 Windows 反斜杠，再拒绝绝对路径、盘符和 `..`，解析后确认仍位于仓库内。原始远端回执字节保持不变，因此传输身份审计仍成立。
- **通用规则**：JSON/CSV 回执中的路径是协议字段，不是显示文本；所有跨机 writer 一律输出 POSIX 仓库相对路径，verifier 必须同时做兼容解析和目录逃逸检查。
- **牵连**：远端训练/推理 worker、artifact registry、SHA 回执、Mac 验收、Windows 路径分隔符与路径遍历防护。
