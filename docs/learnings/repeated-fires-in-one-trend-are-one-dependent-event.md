# 同一趋势里的重复开火是一个依赖事件，不是多份样本

- **问题**：v10 十日事后极端涨跌池出现 221 条信号，但只覆盖 107 个币日；同币同日 2 次或 3+ 次开火组的表面胜率高于只开 1 次组，容易被误读为“重复框越多，模型越准、样本越充足”。
- **死胡同**：按每个检测框独立统计收益或直接拿去训练，会把一段持续下跌同时复制成多个正例；趋势越强，检测器越容易重复开火，收益标签也越好，于是样本量、置信度和经济表现一起被共同原因虚增。
- **有效路径**：先按同币、相邻时间和同一趋势段聚成 event cluster，再区分 `first_start`、`continuation` 与 `failed`。汇报同时给出信号粒度和每币日首次信号粒度，判断层训练与时间切分以 cluster 为最小不可拆单位。
- **通用规则**：遇到滑窗检测产生的密集命中，第一步先量“框数 / 独立事件数”，并在任何胜率、收益、交叉验证前完成事件聚类；重复命中只可作为状态持续或再入场特征，不能自动增加独立证据数。
- **牵连**：`scripts/analyze_v10_daily_movers_patterns.py`、`analysis/output/v10_daily_movers_10d_patterns/`、后续 ETH 3m/5m/10m 双视图标签 schema、按时间切分与匹配随机对照；并与 [事后涨跌榜审图必须把选池前视与因果检测分开](posthoc-mover-gallery-must-separate-ranking-lookahead-from-causal-detection.md) 配套使用。
