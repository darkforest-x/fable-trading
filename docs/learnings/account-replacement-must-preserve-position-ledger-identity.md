# 更换账户必须分离账户身份与原持仓账本

- **问题**：Owner 授权更换 OKX 凭据；只读验证发现新 UID 与原账本不同，旧账户仍有两笔系统持仓，新账户另有外部持仓和挂单。
- **死胡同**：没有采用直接覆盖凭据后复用原账本的办法；这会使执行器无法验证仓位归属。清空旧账本也不能解决问题，因为原仓位仍需要原账户凭据及交易回执继续管理。
- **有效路径**：先用只读客户端验证新身份、账户模式与权限，再核验旧仓保护。原单写进程退出且锁释放后，整体保留旧私有运行目录及账本，启动指定该目录的 `--manage-only` 管理器；默认运行目录改用新凭据和空账本，网页根据凭据文件身份刷新。新账户存在未登记持仓时，不绕过归属门启用交易，先明确现有仓位管理范围。
- **通用规则**：API key 轮换与账户更换是两类操作。先比较 UID；同账户保留全部账本和截止时间，不同账户分别保留凭据、订单、持仓、确认队列及执行锁。新账户下单资格必须另行验证，连接成功不等于可以开仓。
- **牵连**：`yoyo/okx_execution/{config,store,engine,manual_queue,dashboard,__main__}.py`；私有 `OKXExecution` 与 `OKXExecution-previous-20261017`；旧账户仅管理原仓，新账户空确认队列。凭据不进入仓库或诊断输出，不通过测试单验证连通性。
