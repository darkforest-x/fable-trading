# 只测召回不测开火率,等于奖励"见什么都喊"的检测器

- **问题**:v9 金标召回 84.0%、IoU 0.596、宽度比 1.00、右缘偏移 0,据此宣布"检测层做好了"。
  owner 看了 30 张图当场说"一大半不是我的形态,3 天 1100 个信号明显不对"。
- **死胡同**:v6→v7→v8→v9 每一版都在优化召回和框的几何精度(IoU / 宽度 / 右缘),
  **没有一版在控制"该不该开火"**。v8 召回掉到 14.1% 被判为"学窄了"否掉——
  它可能才是接近 owner 标注密度的那个,只是判据本身选错了。
- **一量就现原形**:

  ```
  owner 标注密度      0.18 ~ 0.36 条/币·月
  v9 生产开火密度     48.8 条/币·月       ← 137 ~ 274 倍
  ```

  **一个到处开火的检测器,召回必然高。** 84% 从来不是"和 owner 一致"的证据。
- **第二层错误**:那个 84% 是在 `SCAN_CONF = 0.05` 下测的,而生产是 `DEFAULT_CONF = 0.30`。
  在真正用的门槛上召回只有 **19.5%**。而且结果 JSON **没有记录 conf**——
  报了一个数字却没记它的工作点。
- **门槛救不了**:conf 扫描显示要压到 owner 的密度需 ≥0.50,那时召回 **0%**;
  中间没有可用工作点。区分度 AUC 0.7575(真实但远不足以砍掉 4582 倍)。
- **根因在训练集**:负样本采样器写着

  ```python
  ok, _ = passes(fast, full, close, tip, ...)
  if ok: continue        # 长得像形态的,直接排除
  ```

  所以简单负样本全是"一眼就不像"的,模型从未见过"像但不是"。
  真正的困难负样本只有审阅包里 319 个 owner 否决,对约 1600 个废样本。
- **通用规则**:任何检测器的验收**必须同时报召回和开火密度**,
  且**两者必须在同一个 conf 下测,那个 conf 必须是生产值,并写进结果文件**。
  只报召回的验收等价于奖励过度开火。
  推论:负样本采样若排除"看起来像"的位置,模型就永远学不会边界——
  困难负样本必须来自模型自己的误开火,不能来自随机采样。
