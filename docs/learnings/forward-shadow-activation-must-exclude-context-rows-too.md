# 前向影子启用线也必须排除上下文行

- **问题**：新建 V7/V8 影子账本时，即使历史信号不入库，初始化所需的诊断上下文或市场快照仍可能把启用前 K 线写进影子库，污染“全是新盲样本”的声明。
- **死胡同**：只在事件插入处检查 `signal_close < activation`，并允许等于启用时刻的收盘或启用前上下文进入。这样事件表暂时为零也不能证明影子库的时间边界干净。
- **有效路径**：首次启动持久化不可变 `activated_ms`；信号、路径 K 线和市场快照全部要求 `bar_close_ms > activated_ms`。若已有账本的证据类型使用了较弱边界，就换新协议和新数据库，不能悄悄改写旧合同。测试覆盖启用前、恰好等于启用时刻和启用后，同时核对影子库只有专用表且没有通知、订单或模型候选表。
- **通用规则**：任何前向影子系统都要把 cutover 应用于事件、特征上下文、路径更新和市场快照；验收不能只数信号行。
- **牵连**：`yoyo/monitor/v78_shadow.py`、`tests/monitor/test_v78_shadow.py`、独立 `v78-shadow-v2.sqlite3`；影子只记录，不推送、不下单。
