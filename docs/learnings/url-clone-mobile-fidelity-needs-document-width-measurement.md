# URL 复刻的移动端一致性要测文档宽度，不能只看视口宽度

- **问题**：源站在 390px 手机视口中看起来像移动布局，但完整页面实际保持 720px 内容画布；第一次实现只继承常规断点后得到 706px，导致横向裁切和面板比例出现 14px 漂移。
- **死胡同**：只用同尺寸截图肉眼判断，或把“手机视口”直接等同于“内容必须收缩到视口”，都会把源站的真实溢出行为误判为待修复的响应式问题。截图顶部相近，也掩盖了完整页面画布宽度不一致。
- **有效路径**：同时测量 `window.innerWidth`、`document.documentElement.scrollWidth`、工作区边界和整页截图像素，再以源站的文档宽度作为复刻契约；确认源站为 720px 后，在同一断点为本地工作区设置相同最小宽度，并重做整页并排比较。
- **通用规则**：复刻 URL 的移动端时，第一步同时记录视口尺寸、文档滚动尺寸和主容器尺寸；忠实复刻应保留源站已观察到的溢出或裁切，不要未经授权替它“优化响应式”。
- **牵连**：`prototypes/fable-signal-console/src/styles.css`、`prototypes/fable-signal-console/design-qa.md`、390 × 844 浏览器视口、720 × 2673 整页画布，以及桌面/移动并排截图证据。
