# 改退出规则之前先冻结旧账本，才能解释数字为什么变了

- **问题**：突破＋SPIKE账本会按最新K线重算每条模拟持仓。新增RSI退出后，如果直接覆盖同一份performance，旧浮盈、退出原因和串行占仓状态就无法再核对。
- **死胡同**：仅给新结果换一个basis名称仍会丢掉旧数值；把切换前快照叫“旧规则对照”也不成立，因为快照不再随行情更新，和新规则不在同一估值时钟。
- **有效路径**：首次切换前将全部联合持仓的旧performance及切换时间原子归档，后续刷新只更新当前投影。API和界面明确选择“当前回算”或“切换前快照”；旧快照按固定时钟筛选、标出时间，并且不伪装成当前持仓。事件ID和首次发现时间保持不变。
- **通用规则**：凡是会追溯改变历史数字的展示策略，先保存旧事实，再切换投影版本。要比较策略收益，另做同一行情截止、同一成交规则的双版本回放，不能用固定旧快照与滚动新值比较。
- **牵连**：`yoyo/monitor/spike_lines_worker.py`、`spike_lines_api.py`、`static/app.js`；只涉及模拟账本，不是交易账户操作。

原生浏览器验收还揭示了一个显示边界：清空JS状态但等防抖请求结束才重新绘制，会短暂把旧数值留在新版本选项旁。切换时必须立即绘制空值和加载提示，同时保留可选版本，再以响应版本和查询序号验收返回数据。
