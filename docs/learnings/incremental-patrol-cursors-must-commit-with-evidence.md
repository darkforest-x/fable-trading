# Incremental patrol coverage advances only with committed evidence

- **Problem**: Raising full-universe patrol frequency repeats old endpoints, while four-hour scheduling of a three-endpoint hourly scan misses one close. A crash between result and cursor writes can silently lose coverage.
- **Dead end**: Advancing a plan-wide timestamp after enqueueing claims that every coin succeeded. Restarting the whole market wastes completed inference. Replacing chart MA values with a shared canonical series changes the original warmup and can break exact input-image reconstruction.
- **Effective path**: Persist per-coin coverage, result and unit completion in one SQLite transaction. Resume pending units, retry failed coins without advancing them, and bound catchup per visit while retaining remaining endpoints. Short-period jobs alternate coins before long-period jobs. Store immutable OHLC blocks by content and preserve separate lossless per-observation MA values. This changes execution/storage, not label semantics, warmup, thresholds or qualification.
- **General rule**: A cursor is a statement of verified coverage, not a scheduling clock. Test crashes after the final result commit, failures between successful coins, delayed four-hour scans and exact chart reconstruction before changing cadence.
- **Affected**: `yoyo/yolo_workbench/patrol.py`, `storage.py`, `worker.py`, `market.py`, `store.py`. Local behavior tests cover these paths; full-market resource acceptance is deliberately separate and must pass before activating the owner-approved four schedules. Historical insufficiency remains explicit and cannot be relabeled as successful coverage.
