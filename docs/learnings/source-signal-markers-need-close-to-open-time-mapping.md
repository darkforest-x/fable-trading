# Source signal markers use close-to-open clock mapping and stay out of model pixels

- **问题**：SPIKE candidates had a signal time in the sidebar but no marker on the live chart; adding arrows must not shift the signal one candle forward or disclose the source detector's answer in a clean vision review.
- **死胡同**：Using the signal's close timestamp as a chart point would mark the next candle, because Lightweight Charts indexes candles by open time. Capturing the newly annotated chart unchanged would also alter model input semantics. Both shortcuts were rejected before shipping.
- **有效路径**：Match the exact open timestamp `signal_close - timeframe_duration`, require a present closed source candle, and render only a display arrow. Temporarily clear markers inside a synchronous screenshot transaction and restore them in `finally`. The library's v4.2.0 screenshot implementation flushes pending paints before copying pixels.
- **通用规则**：Distinguish event confirmation time, candle index time, display annotations, and inference pixels. Never snap a missing source event to the nearest candle or treat a source marker as a model verdict.
- **牵连**：`yoyo/vision_research/static/chart.js`, `tests/vision_research/chart_capture.test.cjs`; [TradingView 4.2 marker API](https://tradingview.github.io/lightweight-charts/docs/4.2/api/interfaces/ISeriesApi#setmarkers), [screenshot implementation](https://github.com/tradingview/lightweight-charts/blob/v4.2.0/src/gui/chart-widget.ts#L240). Automatic server renders remain clean; no Pine strategy, scanner, production gate, or signal calculation changed.
