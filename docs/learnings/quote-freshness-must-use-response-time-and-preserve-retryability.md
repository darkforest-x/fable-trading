# 报价新鲜度必须在响应后判断，读失败不能永久消费信号

- **问题**：2026-10-17 北京时间 01:30 的 XLM-USDT-SWAP 15m 空头信号于 01:36:37.716 被发现，但实盘没有开仓。只读执行账本中唯一记录为 `skipped / exchange quote is stale`，事件 ID 为 `4f9434a9d324c5a19c43ae51`。检查时执行器 PID 76972 心跳持续，账户权益与可用均为 125 USDT，持仓、普通挂单、保护单均为零；唯一 journal 行没有入场 intent。该事件晚于首次执行 cutoff（10-16 21:43:56.572），不属于启动前历史信号。
- **死胡同**：只看服务心跳、账户连接和全局 `worker_error=None` 会漏掉逐信号跳过；页面投影还从缺失的顶层字段读取币种/周期，且未展示 reason。不能把 `exchange quote is stale` 直接解释为行情真的旧了，也不能仅因现在超过 30 分钟就推断最初因信号超时而失败。当前账本未保存拒绝时钟与报价时间戳，因此无法断言原始请求究竟是超过 5 秒还是负时间差。
- **有效路径**：先按事件 ID 联结信号表与执行 journal，再定位 `Engine.prepare()`：它在 checkpoint、合约读取和 ticker 请求之前保存 `now`，随后要求 `0 <= now - ticker.ts <= 5000`。请求途中生成的正常报价会晚于这个旧 `now`，被误判。真实公开 ticker 的三次只读样本中，请求耗时分别为 2514/2332/2405 ms，收到时年龄为 573/607/336 ms；与请求前时间相减却为 -1941/-1725/-2069 ms，三次均触发旧校验。纯内存离线夹具亦复现：clock 从 1000000 经合约读取 +200 ms、ticker 读取 +200 ms，ticker.ts=1000350（收到时仅旧 50 ms），仍被判 stale。第二次 tick 不再调用报价，因为首次异常已写为 skipped，且 seen 集合包含所有历史状态。夹具没有真实网络、交易请求或账本写入。
- **通用规则**：将请求前、响应后与交易所数据生成时间分别记录；使用响应后的时钟判断报价年龄，发单前再次保持原有新鲜度要求。必须区分“没有写请求的暂时性读失败”与“写请求可能已成交但回执未知”：前者应在原信号有效期内有界重试，后者只能对账、禁止盲重发。持久化跳过原因、尝试时间和事件身份，避免页面只显示进程正常。发现根因不等于已修复或已部署，更不能清账后补开旧信号。
- **牵连**：`yoyo/okx_execution/engine.py` 的 prepare、enter 与 tick，`dashboard.py` 的 trade_row。官方 [OKX ticker 文档](https://app.okx.com/docs-v5/en/#order-book-trading-market-data-get-ticker) 将 ts 定义为报价数据生成时间。本次仅诊断并保存经验，未改应用代码、5 秒报价门、30 分钟信号门、执行配置、账本或进程；下一步修复须同时保留入场前校验与未知订单不重发约束。
