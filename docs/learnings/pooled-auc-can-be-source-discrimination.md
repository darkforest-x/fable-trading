# 合池 AUC 可能只是在分「样本来自哪一批」

- **问题**：给 659 条 owner 分级样本加上 YOLO embedding 后，「值不值得看」的 CV AUC
  从几何特征的 0.6102 跳到 0.8067（+0.1965），κ 从 0.13 到 0.43。数字漂亮得像突破。

- **死胡同**：先按常规检查了泄漏的几个明显入口——PCA 是否在折内拟合（是）、
  切分是否按币种分组（是）、标签是否掺了收益（没有）。三项全过，很容易就此收工。
  **这些检查全都只看「同一批样本内部有没有串」，看不到「几批样本混在一起」这件事本身。**

- **有效路径**：样本来自三处：数据集 train 侧、val 侧、以及最近 5 天的实盘扫描。
  按来源分层重测，AUC 从 0.8006 塌到 **任一子集只剩 0.57–0.65**。
  再看正类率：train 85% · val 84% · **scan 29%**，相差 55 个百分点。
  模型只要能认出「这张图来自历史数据集还是来自 5 天扫描」就拿到了大半标签——
  而两批的渲染批次、时间段、币种分布都不同，embedding 区分它毫无难度。
  同一次分层里，另一个任务（质量分级 A vs B+C）四个子集给出 0.69/0.71/0.73/0.74，
  **没塌**——所以分层不是把所有信号都杀掉，它精确地杀掉了假的那个。

- **通用规则**：**样本合池时，先看各来源的正类率差**。差得越大，越要怀疑模型在分来源
  而不是分标签。分组 CV 只防「同一实体跨折」，防不了「不同来源的标签基率不同」——
  两者是不同的病。凡是把多批数据合池的评估，都必须**按来源分层各报一次**；
  子集全线塌陷就是来源混杂，各子集一致才是真信号。CLAUDE.md「结果好得反常→第一假设
  是泄漏」在这里的具体形式，就是查来源基率。
