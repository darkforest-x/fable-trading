# 卡片浏览分页大小必须受响应预算约束

- **问题**：信号页只渲染 24 张卡，却并发请求三类各 2,000 条完整事件 payload；trace 显示大页请求可滞留 19–28 秒，而 `limit=1` 探针为 574ms。
- **死胡同**：服务器允许 2,000 条不表示前端首屏应请求上限。游标存在但首屏过大时，浏览路径仍被响应序列化和事件循环争用阻断。
- **有效路径**：前端将初始和后续 cursor 页固定为 500 条，保留独立的“加载更早记录”入口；服务端 2,000 条上限仍保留为安全 cap 和其它调用方兼容性。
- **通用规则**：API 最大 page size 是上限，不是 UI 默认。首屏批次要按完整 payload、并发请求数和实际渲染预算确定。
- **牵连**：`yoyo/monitor/static/app.js`、`tests/monitor/frontend_cards.test.cjs`；未改扫描、账本、信号、候选或通知。
