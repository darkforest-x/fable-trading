# 历史股票池与当前退市资料必须分别审计

- **问题**：A 股报告读取器从历史股票池 JSON 查找退市资料，但当前数据构建器已把上市/退市资料写进独立 `listing_metadata.json`。默认空列表会把错误路径包装成“没有退市记录”。
- **死胡同**：沿用旧文件结构并对缺失字段取空列表，虽然不会报错，却失去了区分“确实无退市记录”和“没有读取到证据”的能力；程序成功退出不是数据完整的证明。
- **有效路径**：按构建器当前契约读取独立资料文件，单独列出缺失代码、查询错误和退市记录，且排除股票池外的指数资料。报告缺少整个侧车文件时明确失败，不制造无退市结论。
- **通用规则**：数据生产者移动字段后，审计消费者必须验证来源文件和覆盖率。用于选股的历史集合与用于解释的当前状态应物理分离；后者不能悄悄变成存活过滤器。
- **牵连**：`yoyo/evaluation/ashare_data.py`、`yoyo/evaluation/ashare_report.py`、`tests/test_ashare_report.py`；历史证券池固定在 2020-01-02，当前资料只作审计，不参与特征和选参。
