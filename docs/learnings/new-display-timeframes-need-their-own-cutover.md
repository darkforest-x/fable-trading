# 新增展示周期需要自己的启用时间

- **问题**：在已有 V1 30m/1H/4H 监控上增加仅展示的 15m。直接复用 V1 原始启用时间，会把新增周期首次回算的旧箭头混入实时列表。
- **死胡同**：把展示周期加入 Bark 周期可以顺带获得通知边界，但违反 15m 不通知的要求；只加前端筛选则没有实际扫描数据。
- **有效路径**：保留 V1 参数和 Bark/YOLO 通知周期，扩展行情扫描与前端周期映射。扫描器先用校准后的交易所时间幂等保存 15m 展示启用时间，再抓取和回算。实时/预热查询和总数使用同一个展示边界，空边界不把旧数据当新信号。模拟扫描验证旧信号归预热、新信号可展示、没有 Bark 队列或 YOLO 通知候选。
- **通用规则**：采集范围、展示范围、通知范围分别管理。新增展示周期不能继承旧周期的历史资格，也不能自动获得通知权限。
- **牵连**：`yoyo/monitor/__init__.py`、`v1_worker.py`、`store.py`、`service.py`、`static/`；`display_policy:spike-v1:15m`；冻结 V1 判定和原有通知门不变。
