# 请求失败日志不能代替当前数据完整性审计

- **问题**：A 股主板取数的早期 `listing_metadata.json` 记有 sh.601188 登录失败，但之后保存的原始 basic 文件已完整且通过哈希核验。报告若直接复制早期错误，会把已恢复的数据误报为缺失；同时冻结 200 只、源完整 199 只、研究可用 197 只是不同口径。
- **死胡同**：把累积请求日志当作“当前状态表”，并用“目录里有文件”同时代表取得数据、数据可靠和可参与研究。前者无法表达恢复，后者会把混合复权标记或无法解释权益变动的证券混入研究分母。
- **有效路径**：保留原请求与错误日志，另生成绑定股票池、排除表及原始来源哈希的最终审计。报告优先使用最终审计的逐证券资料，并重新核对 basic 来源哈希；历史错误单列。原始冻结池不补换，研究统计排除质量失败证券，等权基准保留失败证券原有现金槽位。
- **通用规则**：先区分“请求尝试”“当前来源证据”“研究准入”三个状态，再统计各自分母；不能通过删除旧错误伪造干净历史，也不能让旧错误覆盖已经核实的恢复。全段质量筛选即使不使用策略收益，也要披露其可用性判断并非当时完全可得。
- **牵连**：`yoyo/evaluation/ashare_report.py`、`tests/test_ashare_report.py`；本轮 `data_mainboard/exclusions.json`、`mainboard_data_audit.json` 与 `listing_metadata.json`；冻结股票池、研究可用池和基准现金分配不得互相替代。
