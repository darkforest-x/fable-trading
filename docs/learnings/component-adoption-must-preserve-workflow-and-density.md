# 引入组件库要同时控制信息密度和现有交互边界

- **问题**：均线密集工作台的币种周期折成两行，重复提示和大卡片挤占 K 线；用户要求紧凑且采用成熟 UI 组件。
- **死胡同**：只套组件库的默认外观不能解决信息顺序与占位问题。手机验收还发现打开选择器时自动聚焦搜索，会弹出候选覆盖原列表；仅缩小行高仍然难用。未尝试全站换框架，避免把这次界面任务扩大为路由和交易状态重写。
- **有效路径**：Bootstrap 5.3.8 仅导入按钮、表单、导航与 dropdown，CSS 限定在 opt-in 容器；保留 native dialog 和原有事件/API。用现有主题 token 合并状态条、缩短操作文案并让周期单行。桌面行高约63px；手机保留38–40px点击区域、16px输入字体，打开选择器先聚焦关闭按钮，选择周期后回到图表标题。
- **通用规则**：先沿真实任务路径量出空间被哪里占用，再决定组件与布局；同时验证深浅色、窄屏、键盘、焦点及滚动，不把引入依赖当成 UX 完成证据。金融界面压缩说明不能取消价格核对与逐笔确认。
- **牵连**：`yoyo/monitor/ui/`、`static/module-loader.js`、`static/yolo-detect.js`、`static/yolo-compact.css`；70项相关前端检查通过，真实390px/桌面/深色/订单预览截图在`output/compact-ui-20261017/`。只读预览，没有真实下单；两个账户与仓位规则未变。
