# 研究登记、落盘回执和运行快照必须保留各自身份

- **问题**：整合 YOLO 工作流时，形态 v6 实验登记仍写研究中，训练回执却已完成；历史模型指针和当前通知检测器也来自不同记录。
- **死胡同**：只显示登记状态会误报训练仍在运行；用回执覆盖登记又会丢失历史判断。把服务 `loaded=true` 当成生产准入，会混淆通知检测和交易执行。
- **有效路径**：并列显示登记状态、带来源的回执状态与带时间的服务快照。阶段归类仅帮助检索，训练最后一行仅代表落盘记录。模型登记同时匹配路径和版本哈希；权重是否存在、资格声明和实际准入分别呈现。
- **通用规则**：整合流程前先列清每个状态由谁写入、何时采集、能证明什么。跨来源冲突应可见；缺失、未登记、未复核不能转换成零值或通过。
- **牵连**：`yoyo/research_workspace/yolo.py`、`api.py`、`worker.py` 和统一前端。页面读取与证据快照复用同一有限目录读取器，只在已登记实验内读取允许的 JSON/CSV，避免页面可见的证据在保存时遗漏；不触发训练或模型切换。
