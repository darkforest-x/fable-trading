# 减少重复提醒必须把新入场召回与旧交易覆盖分开

- **问题**：SPIKE V3 的父预警很密，增加趋势参考占用或完整近零蓄势，看起来都能大幅减少图上标记；但减少标记不等于保留了用户想抓的启动。
- **死胡同**：把已有风险参考覆盖加回及时新信号命中数，会让严格漏报被隐藏。2026-09-10 固定研究中，A 总标签减少 61.11%，V3 原及时正例的新预警保留仅 45.32%；B 标签减少 95.09%，保留仅 1.44%。A 有 996 个正例时点存在参考覆盖，但参考以信号收盘价启动，真实模拟成交使用次根开盘，两者并非同一对象。既有参考还在，既不能证明实际交易存活，也不能证明使用者持仓。
- **有效路径**：评分前分别冻结提醒负担、新预警召回、原命中保留率以及参考覆盖，后者绝不修补前三者。独立逐根复核所有检测状态和实际成交路径后，再单独解释被过滤事件：旧参考是否存活、该参考对应的实际模拟交易是否存活、是否退出同根或数据不可判定。描述性持仓覆盖不能让已经失败的预登记门变成通过。
- **通用规则**：去重首先问“哪个对象重复了”：同一根的父子升级、同一趋势的观察更新，还是一笔已经结束后的新启动。提醒事件、参考框、确认价和实际成交必须有独立 ID 与生命周期。后验上涨只定义评价标签，不能决定当时是否静默。
- **牵连**：`exp-spike-v3-focus-20260910-v1`；`yoyo/evaluation/spike_burst_v3_reference_gate.py`；`spike_burst_v3_structural.py`；`spike_burst_v3_focus_study.py`。成本与风险参数未更改；固定 61 日历史样本已经被研究，不能称盲测或未来无漏报保证。
