# 浮动开单面板必须保留唯一提交所有者

- **问题**：1.618 需要快捷开单，同时复用模拟页的市价、限价、保护与结果核验；两处入口可能在报价请求尚未完成时切换页面。
- **死胡同**：复制表单与提交函数会分裂草稿、请求 ID 和不确定结果的重试状态；把背景最新触价直接绑定订单币种，会在用户编辑时偷偷改变下单目标。代码检查即排除这两种接法。
- **有效路径**：将原模拟模块的 DOM 节点暂时挂载到浮动容器，共用同一状态、校验、报价和提交函数，关闭后放回原父节点。浮动控制器只捕获初始币种并管理生命周期，异步加载用版本号拒绝过期挂载；测试覆盖路由切换、关闭期间加载完成和原提交接口。
- **通用规则**：快捷入口只负责入口和展示；订单的报价、账户、幂等请求与重试必须归同一所有者管理。界面复用不代表另一种账户执行规则已经得到授权或支持。
- **牵连**：`monday-quick.js`、`monday-fib.js`、`paper-desk.js` 及对应前端测试；Stitch 页面 `978ce337aef8424b9b21d7f2dc5cd0df`。均线手动实盘的现有 3% 风险、市价和 3R/5R 规则与模拟自选参数不同，实盘规则澄清前不改执行器、不发真实订单。
