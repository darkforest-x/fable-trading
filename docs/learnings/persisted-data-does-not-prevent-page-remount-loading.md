# 持久缓存不能代替页面实例与订阅生命周期管理

- **问题**：1.618 页面已有 K 线磁盘缓存，但每次切回仍出现整屏“正在读取触价记录”；在触价接口延迟 2 秒时，旧版切回约需 2.3 秒。
- **死胡同**：仅缓存 K 线无法解决上层触价列表从 null 起步的问题；仅保留组件而继续后台订阅，又会让隐藏图表不断绘制。卸载时同步序列化并遍历 localStorage 也会占用切页帧。
- **有效路径**：保持图表实例，公开触价快照、合约与周期按纽约自然周恢复；在隐藏、后台和抽屉遮挡时暂停订阅，返回后后台更新。K 线内存立即可读，磁盘写入合并到空闲阶段。缓存明确作为显示数据，服务端风险与下单校验不读取它。
- **通用规则**：先测量首次加载、再次进入和冷启动三个路径，分别定位上层数据门、组件销毁和同步存储；同时核对隐藏页活跃连接为零，不能只测首屏速度。
- **牵连**：`FibHome.tsx`、`fibCache.ts`、`CandlePanel.tsx`、`candleData.ts`；纽约换周与夏令时测试；原始合成验证在 `output/playwright/app-performance/`，不能据桌面浏览器结果宣称真机帧率。
