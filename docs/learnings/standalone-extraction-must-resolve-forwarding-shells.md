# 独立抽离前必须解析转发壳的真实实现

- **问题**：从主仓库抽一个可独立安装的 YOLO 项目时，当前检测层的 `data.py` 和
  `render.py` 只剩跨仓库转发 import；直接复制当前文件会让新项目在离开父仓库后立即失效。
- **死胡同**：把“检测目录里的文件”机械等同于“检测层完整实现”。重构后的目录仍保留旧入口名，
  但入口文件的短小不是模块简单，而是实现已经迁走；复制目录只能复制到隐藏耦合。
- **有效路径**：先用 import 盘点识别转发壳，再沿文件 git 历史找到迁移前最后一个自包含实现；
  抽取后把所有 import 改成新包内部路径，并用 AST 测试禁止父包和业务层依赖重新进入。
- **通用规则**：做独立子项目的第一步不是复制文件，而是画出运行时 import 闭包；遇到转发壳，
  必须解析到实际实现并在目标项目内形成闭包，然后用自动边界测试证明“可独立”。
- **牵连**：`src/detection/data.py`、`src/detection/render.py`、提交 `80022fe` 的父版本、
  `yolo-xx/src/yolo_xx/`、`yolo-xx/tests/test_scope.py`；外部约束是新项目不得依赖判断、
  执行、交易、ACTIVE 或部署逻辑。
