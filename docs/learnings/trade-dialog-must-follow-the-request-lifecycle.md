# Trade confirmation dialogs must follow the request lifecycle

- **Problem**: Moving a quote preview into a modal changes focus, background interaction, and error visibility even when the order payload remains identical.
- **Dead end**: A first broad template replacement accidentally inserted the modal into ledger subpanels as well as the page root. Existing string-only tests passed because they never counted or opened dialogs. Browser checking also found that Tab from the last enabled action after expiry could leave the dialog for browser chrome.
- **Effective path**: Render exactly one native dialog at the workspace root, cycle enabled action buttons, and restore focus to the current ticket after cancellation. Keep submission non-dismissible; after an uncertain response, close the modal and focus the durable original-request retry. Release scroll locking on cancellation, input invalidation, and route departure, and discard quotes arriving after departure. Verify each ledger tab, expiry, submission races, and real small-screen behavior.
- **General rule**: Before moving a transactional confirmation, map the quote, pending request, focus, and dismissal states together. A visual overlay alone does not establish a correct modal workflow. Fee disclosure should use the returned preview fee and snapshot rate without changing the accounting policy.
