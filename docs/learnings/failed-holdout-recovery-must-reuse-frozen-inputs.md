# Holdout 运行失败后恢复必须复用原冻结输入

- **问题**：最新行情扫描在模型已经读取 holdout 后因实现错误中止；若直接重跑网络抓取，15m 闭合点、币种全集或行情字节都可能前移，表面上是“修复重跑”，实际上已经换了评估配置。
- **死胡同**：删除 `.building` 后重新请求最新行情，或者因为没有最终结果就宣称 holdout 未消费。前者把修复与新数据混在一起，后者抹掉了真实的数据访问。
- **有效路径**：保留失败目录和错误回执，固定其 universe、每周期闭合端点及 candle SHA；用已提交的恢复声明只允许实现层修补，并从这些 CSV 离线重建新结果，恢复阶段禁止再次访问行情 API。
- **通用规则**：任何 holdout 任务一旦开始读取就立即记为已消费；实现故障后的首选恢复路径是“冻结失败现场 → 声明唯一修补 → 离线复用原输入”，而不是重新获取“最新”数据。
- **牵连**：holdout 消耗编号、`holdout_consumption_started.json`、`failure_receipt.json`、预注册 source commit、失败目录保留策略，以及恢复运行中的 `additional_market_read=false` 证据。
