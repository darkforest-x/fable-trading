# 配对图必须先统一两条线的请求集合，再计算均值

- **问题**：V7匹配表保留全部286请求，但仅283个有完整三控制。案例收益列全部有值，对照／超额列的3个未匹配值为空。
- **死胡同**：直接对三列分别mean会把策略286笔与对照283笔混比；把“283配对”误写成CSV只有283行又会令复算断言失败。均值函数各自跳过NaN不等于匹配分析。
- **有效路径**：先验证完整请求身份、UTC时刻、原始案例收益一致，再按三控制且双方结果均有限确定同一个配对子集。两条月图仅聚合此集合；全286请求只提供覆盖率分母。合成例加入未配对+90%收益，确保它不能抬高任一配对均值。
- **通用规则**：对照分析先锁定共同观察单位，再做逐月或总体聚合。完整台账行数、已分配数、完整配对数、真实成交数必须各有名字，不能互换。
- **牵连**：`yoyo/evaluation/hourly_impulse_source_report.py`、`tests/test_hourly_impulse_source_report.py`、V7 `VERIFICATION.md`。修的是呈现与复算示例，冻结回测的配对结果未变。
