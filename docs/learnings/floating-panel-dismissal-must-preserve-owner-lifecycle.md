# 浮层外部关闭必须走所有者的清理逻辑

- **问题**：1.618 统计分析、交易簿与账户详情打开后，点击图表空白处不会收起；各浮层关闭与 Escape 规则分散，父页面还可能先处理子弹窗的 Escape。
- **死胡同**：仅补隐藏样式会留下请求、轮询和图表实例；全局遮罩会挡住原本要点击或拖动的图表；无条件处理 Escape 会连父面板一起关闭。没有采用这些处理。浏览器补查还发现旧全局菜单的捕获阶段 Escape 会抢先关闭父菜单，仅给局部处理器加保护不够，必须同时核对全局监听器。
- **有效路径**：只给只读浮层接入 `bindOutside`，在 document 捕获阶段观察主指针按下，但不拦截原事件。排除面板及触发器，优先让原生 dialog/popover 处理事件，隐藏页面与图表专注态不触发关闭。通过原 `setOpen` / `setRecords` 清理资源；指针关闭不抢焦点，Escape 返回触发器。搜索先关闭自身，并消费这次 Escape。
- **通用规则**：先确认浮层所有者的关闭入口，再统一外部交互；不要用全局透明度、遮罩或直接删除 class 替代生命周期管理。必须验证触发器重复点击、内部筛选、内部拖动到外部和嵌套层级。
- **牵连**：`yolo-preview-sheet.js`、`monday-reclaim-paper.js`、`reclaim-analytics.js`、`reclaim-watchlist.js`、`strategy-backtest.js`、`stitch-workspace.js`。61 项相关 Node 测试通过，Chrome/WebKit 另做实际交互验证；原生子弹窗使用隔离的浏览器临时夹具。设计来源为 Stitch 项目 `8978791379095391159` / 画板 `e392e183ed3c45bab90093b1bad0e9db`，保留原有样式与透明度。
