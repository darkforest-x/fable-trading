# 精确分位数边界要使用保真浮点读取

- **问题**：V13.1 三币 smoke 的独立 CSV 审计发现一个 BTC15m 样本的分组不同：原文件为 1.8396688922272746，pandas 默认读为 1.8396688922272744，标准库保留原数值。边界恰由这个样本拟合，导致独立实现对成员资格意见不同。
- **死胡同**：收益数值容差不能用于离散分组资格；加入 epsilon 会悄悄改变预先声明的 `<=lower` 分组，并使可复现依赖任意容差。
- **有效路径**：只在新汇总器读取已保存路径与特征时启用 `float_precision='round_trip'`；拟合阈值、应用阈值和标准库审计都解释同一精确序列。保留失败 smoke 汇总，按新版本重新生成并验证。
- **通用规则**：数值序列化的可复现包括解析语义。使用样本分位点作严格决策边界时，优先验证真实精度边界案例，不用容差掩盖成员集合差异。
- **牵连**：`yoyo/evaluation/spike_v131_rule_summary.py`、独立标准库核验、`tests/evaluation/test_spike_v131_rule_summary.py`。不修改原始市场数据读取或既有历史研究引擎。
