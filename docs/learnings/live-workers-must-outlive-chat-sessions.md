# 实盘执行器必须由独立服务托管，不能依赖聊天终端

- **问题**：2026-10-18 信号中心仍可查询账户，但自动执行的最后心跳停在 00:15:57。前一晚更新后实际运行的是 Codex 临时 PTY 子进程，原 LaunchAgent 已停止。
- **死胡同**：只看账户余额刷新、进程曾经存在、旧 plist 或旧交接记录，都不能证明当前执行受到后台托管。旧 LaunchAgent 的正常退出记录也不能解释后来 PTY 进程的退出。
- **有效路径**：联结原始启动命令、PID/PPID、执行心跳、LaunchAgent 状态及对应聊天会话日志。20:00 启动命令使用 `tty=true`；00:15:55 会话取消订阅，00:16:55 记录 teardown / Shutdown。证据指向临时会话生命周期这一部署缺陷，但没有取得该子进程的精确退出信号。恢复应使用独立 LaunchAgent，并核对新 PID、进程父级、锁和持续更新的执行心跳。
- **通用规则**：实盘启动后的验收必须确认进程由谁托管、是否接受新单、账本与交易所是否一致；不能把启动成功当作持续运行。恢复前先查实际仓位与委托，外部平仓须用完整成交回执对账，保留历史和原信号切点，禁止清空账本或重放旧单。会话解除与退出相关不等于已经获得操作系统退出码。
- **牵连**：`yoyo/okx_execution/__main__.py`、`engine.py`、`dashboard.py`；本机私有 `OKXExecution/worker-session.plist` 和 `recovery-20261018/`。Owner 本次明确授权核验后恢复，并确认八笔为其手动平仓。交易配置、风险参数、凭据及账户隔离保持原约定。
