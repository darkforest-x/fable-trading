# 隐藏页面需要明确的请求和资源归属

- **问题**：切页只隐藏 DOM，搜索 Worker、PDF Blob 和重型页面仍常驻；慢请求能占住刷新锁。
- **死胡同**：只丢弃过期回调没有结束请求，Worker 的主线程引用置空也不等于 terminate。每次收到 inactive 都重置闲置计时，会在频繁导航时无限延后回收。模块并发执行又可能打破脚本依赖。
- **有效路径**：页面拥有 GET 请求的合并、15 秒超时、取消和退避；离页主动取消读取，写操作不随导航取消且不自动重试。闲置 60 秒释放重型 DOM、搜索索引/Worker、PDF URL，同时保留阅读选择和笔记；PDF 缓存只保留一本，异步返回受资源代次限制。脚本用 preload 同时下载，CSS 就绪后依次执行，失败能重试。
- **通用规则**：资源要有创建者、容量上限、撤销条件和重建路径；测试离页、重进、挂起、过期返回和真实释放，不把 DOM 隐藏当回收，也不把常驻直接称为内存泄漏。
- **牵连**：`workspace-runtime.js`、`module-loader.js`、市场/YOLO 请求、`transcript-search.js` 和阅读页面。使用本轮单个临时 IAB 标签，结束关闭，不启动额外 Chrome；后台调度与执行器不属于页面生命周期。
