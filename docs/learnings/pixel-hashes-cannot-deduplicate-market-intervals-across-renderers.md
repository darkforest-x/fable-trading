# 跨渲染器去重不能只看图片哈希

- **问题**：第三臂把Owner确认误报替换进旧hard-negative池时，图片SHA显示584个新输入与2,286个旧hard全部不同；但按币种、窗口开始时间、结束时间和W复核，发现1个新旧样本其实来自完全相同的原始市场区间。
- **死胡同**：只用`image_sha256 + label_sha256`去重会把渲染器版本、压缩参数或坐标轴细节造成的像素差异误认为新行情，导致同一段K线以两张不同PNG重复训练。
- **有效路径**：同时维护两层去重键：像素层继续检查image+label SHA；语义层对行情图使用`symbol + normalized_start_time + normalized_end_time + window_len`。任一层冲突都排除旧行，并在同W桶内确定性补齐，保证总量和窗口分布不漂移。
- **通用规则**：图片哈希只能证明“文件不同”，不能证明“样本语义不同”。只要渲染链可能演进，时序图像数据集就必须保留可规范化的原始区间身份，并在组装阶段做内容去重和语义去重两道门。
- **牵连**：`scripts/build_owner_short_gold_center_hardneg_r2.py`、第三臂hard-negative替换、固定W12–19桶、有效样本量与单变量纪律。
