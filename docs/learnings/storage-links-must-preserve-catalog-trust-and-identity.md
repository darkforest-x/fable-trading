# 软链接保住文件路径，不会自动保住目录工具的访问契约

- **问题**：2026-09-24 迁移历史行情到移动硬盘后，旧路径经软链接能被 pandas 正常读取，但项目 `DatasetCatalog.file()` 对真实路径实施仓内限制；仅检查普通文件读取不足以验收迁移。
- **死胡同**：把软链接可读当成应用兼容会漏掉两道门：外部目录不会被索引，已有索引的纳秒修改时间也与 NTFS 驱动稳定呈现的整秒不一致。直接放开所有外部路径或放松全部文件时间检查会损害原有外部缓存和路径越界保护。
- **中间验证**：曾将已完成逐文件 SHA-256 验证的迁移登记在本机目录配置中，绑定明确源路径、目标目录、分区 UUID 和本机哈希清单。保留数据集 ID 与逻辑文件路径，只按已验证副本更新时间元数据；原索引单独备份。已登记外接文件每次读取先核对硬盘身份和内容哈希，其他外部目录仍被排除。
- **通用规则**：存储迁移同时验收物理内容、旧路径、消费者访问边界和索引身份。可移除介质必须明确离线行为；同名硬盘不能代替原分区。低精度文件时间不能承担完整性证明，同大小、同时间的篡改也必须被哈希检查拒绝。
- **运行身份**：命令行消费者读取通过后，实际8766 LaunchAgent读取相同文件仍触发 `PermissionError: Operation not permitted`。运行用户相同不代表 macOS 对不同启动上下文给予相同的磁盘访问权；以后在释放源副本前，须用真实后台入口验证目标盘权限。权限未解决时应保留旧索引并给出明确错误，不能静默当成空数据集；本轮中间方案曾补此回归用例；Owner 随后要求直接选择方案，最终采用下述本机常用数据布局。
- **牵连**：`yoyo/data/external_storage.py`、`yoyo/data/dataset_catalog.py`、`tests/test_external_dataset_storage.py`；本机登记为 `data/crypto/_catalog/external_locations.json`。独立用例覆盖登记数据重索引与读取、离线/错盘保留旧索引、同大小同时间内容变动、链接越界、未登记文件和文件消失；原有外部缓存排除测试继续通过。

- **最终有效路径**：2026-09-24，选择将网页使用的行情 CSV 与元数据迁回本机，逐个哈希对照原始清单并恢复原纳秒时间；仅原始 ZIP 下载包依赖移动盘。真实后台下载返回200且响应哈希一致，研究读取样本通过。撤回本轮临时外部访问实现和登记，保留原有目录边界；中间代码及测试副本移至操作收据目录的 `external-access-attempt/`。不为存储搬迁额外扩大 Python 权限，外接盘保留已校验完整副本作备份。
- **选择原则**：按真实消费者划分常用数据与冷归档，比仅按目录体积迁移更稳妥。先用运行中的服务验证候选介质访问，再释放源文件；如果后台权限不兼容且本机容量允许，保留运行必需文件本地可减少驱动、权限和拔盘的运行依赖。ZIP 从网页索引移除但原路径留链接，不能把离线归档冒充随时可下载文件。
