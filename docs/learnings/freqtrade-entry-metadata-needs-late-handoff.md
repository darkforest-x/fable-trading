# Freqtrade 入场元数据必须在框架重置后交接

- **问题**：原生因果状态机已经产生 100 个入场，但同一逻辑移植到 Freqtrade 后回测为 0 笔；表面像是策略条件没有触发。
- **死胡同**：直接在指标计算阶段写 `enter_tag`。Freqtrade 的入场建议流程会先初始化框架拥有的信号列，因此较早写入的标签被清空；继续放宽形态阈值只会误诊为“信号太少”。
- **有效路径**：先把完整因果状态机的 setup、方向、止损和确认延迟写入策略自有列 `fable_entry_tag`，再在 `populate_entry_trend()` 中把最终选中的行交接给 `enter_tag` 与 `enter_long` / `enter_short`。用时间、方向、入场价、止损价和确认延迟逐笔核对，100/100 完全一致后才接受框架结果。
- **通用规则**：移植到事件驱动回测框架时，先查清哪些列由框架拥有以及何时重置；策略内部状态使用私有列，最后一个受支持的信号回调才做交接，并把逐笔 parity 当成验收门而不是只对总收益。
- **牵连**：`FableTwoStageK2.py`、Freqtrade `advise_entry` / `populate_entry_trend` 生命周期、入场标签、动态止损元数据、原生与框架逐笔 parity。
