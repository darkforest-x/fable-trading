# 本机工作台映射公网，先鉴权再转换同源

- **问题**：原工作台只监听 loopback，以 TrustedHost 和 Origin 保护本机操作；直接穿透既不能兼容公网域名，也没有访客鉴权。页面之外，API、图表和下载同样包含私人数据。
- **死胡同**：开放 Host 通配或无条件重写 Origin，只解决访问报错，还会让跨站写请求伪装为本机操作。把远程卡片继续接到桌面打开接口，也会在错误设备上触发动作。
- **有效路径**：保持原服务监听与同源逻辑，前置独立 Caddy 密码网关。所有资源先认证，写请求先验证公网 HTTPS Origin，再剥离认证/代理头并转换到固定 loopback 上游。用真实 Caddy 和隔离上游验证鉴权、跨站拒绝、凭据不转发及重定向；远程卡片改在访问者设备打开网页。公共 HTTPS 路径另实测 401/200/403/422，避免只证明本机代理能通。
- **通用规则**：Origin 是请求来源约束，不是登录。任何隧道适配必须先明确访问者权限，再改写用于内部路由的身份头。共享密码的本人管理入口不能称为访客只读入口；免费临时地址能连通也不等于获得长期可用性保证。
- **牵连**：`yoyo/monitor/public_tunnel.py`、`tests/monitor/test_public_tunnel.py`、前端远程看图分流。Cloudflare Quick Tunnel 无 SLA、重建会换地址；Mac 离线仍会不可用。没有改变策略、通知规则、AI 凭据或交易执行资格。
