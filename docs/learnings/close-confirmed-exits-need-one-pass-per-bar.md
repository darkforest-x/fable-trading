# 收盘确认退出必须把开盘执行与收盘判断分成两个阶段

- **问题**：把“整根实体越过高周期线”接入原有单仓引擎时，存续仓的开盘退出、新仓成交与当根收盘更新有不同信息时点。一个处理整根K线的step若在新仓处理前后各调用一次，就可能先看到收盘，随后又用同根开盘退出。
- **死胡同**：函数在串行和固定入场路径中共享，不代表时间语义自动正确。本轮初稿静态审查发现同一存续仓重复调用完整step；它既可能同bar兑现MA确认，也可能用新追踪位追溯止损。问题在运行真实价格实验前发现，未用错误收益作裁决。
- **有效路径**：明确开盘阶段只消费上一根已存在的保护/退出意图，随后处理本次开仓，再执行一次盘中触价与收盘确认；固定入场也使用同一阶段顺序。增加收盘跌破后必须等到下根open的串行反例，并以原版全部账本作parity门。
- **通用规则**：审因果回放先画每根bar的信息时序，不只看用了哪些历史列。确认止损的初始R只能作参考分母，确认后按实际下一开盘成交，亏损允许超过1参考R；不能用线价填平等待损失。
- **牵连**：新离线模块`yoyo/evaluation/spike_ma_confirm.py`与`spike_ma_confirm_study.py`；不改变旧TV/Pine脚本。实验`exp-spike-ma-confirm-20260922-v1`将同时报告净bp与参考R亏损尾部。
