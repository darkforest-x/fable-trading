# 重叠滑窗检测必须同时保留候选账本与事件账本

- **问题**：同一段 15m 行情会在相邻 endpoint 和 W18–25 多个输入中反复命中；把每个框都画成一张图，会把一个连续形态夸大成几十个独立信号，也让 Owner 看到大量重复框。
- **死胡同**：只按固定 5 根 K 去重仍会留下相邻但持续重叠的事件；反过来若直接丢弃重复候选，又无法追溯模型到底在多少个实际输入上出过哪些原始框。
- **有效路径**：原始预测框、窗口身份和四维坐标全部写入不可省略的候选账本；交付层再把决策区间连续重叠的候选合为 episode，每个 episode 只展示最早可见的一个原始框，并在 manifest 中记录被合并的候选数。图像交付与统计结论引用 episode，模型复现与审计引用原始账本。
- **通用规则**：遇到重叠时间窗检测，先明确“模型输出单位”和“用户决策单位”；前者必须逐框保真，后者必须按时间连续性合并，禁止用原始框数冒充独立信号数。
- **牵连**：`scripts/scan_15m_ma_launch_owner_yolo_eth30d.py`、`experiments/active/exp-15m-ma-launch-owner-yolo-eth30d-20260828-v1/results/manifest.csv`、W18–25、5-bar 去重与 episode 合并口径；合并只影响展示和计数，不得移动、缩放或重造 YOLO 框。
