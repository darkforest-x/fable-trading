# 固定风险的小金额也可能需要超过交易所上限的张数

- **问题**：Owner在BEAT做多、最近闭合5m低点止损的预览看到“超过单笔市价单上限”，怀疑单位bug。原提示不提供预算、张数、距离或上限，无法判断是代码错误还是实际约束。
- **死胡同**：只看账户不大就判断不可能超限，混淆了止损风险和名义仓位；直接降低张数、拆单或加宽止损会改变Owner选择的1R和执行规则。报错时刻未保存失败报价，不能把后续市场价格冒充当时价格。
- **有效路径**：真实只读核对BEAT：ctVal=10 BEAT、maxMktSz=7000张、lotSz=0.1，单位符合官方衍生品定义。以实查权益157.4722U及明确假设买价0.07697、止损0.07691重放，1R=4.724166U，需要7873.6张，确实超限；真实复查时买价已低于止损，不能宣称完整复现原报价。新增结构化拒绝证据，让UI显示风险预算、止损距离、计算张数、上限和两价，保留原拒绝条件与原异常字符串供执行器使用。
- **通用规则**：先按“风险预算÷每张价格风险”复核张数与合约单位，再判断是否bug；失败提示也必须给可核查的算术。没有原时刻报价只报告支持的条件，不编造逐笔归因。
- **牵连**：`risk.MarketOrderLimitError`、`manual_api.py`、`manual-live.js`与对应边界/API/前端测试；没有新增交易写请求，没有自动修改3%风险、止损、杠杆或订单拆分。原始读取`output/manual-ui-20261017/beat-order-limit-diagnostic.json`；字段定义：https://www.okx.com/docs-v5/#trading-account-rest-api-get-instruments 。
