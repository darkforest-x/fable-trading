# 回放历史需要服务器 cursor 才能越过最近记录上限

- **问题**：信号页每次只请求最近 2,000 条。三周期回放账本有 6,185 条，即使数据库已导入，早期信号也无法被客户端搜索或浏览。
- **死胡同**：提高单个 HTTP limit 会把所有历史塞进浏览器，并继续受固定上限和实时刷新覆盖影响。
- **有效路径**：以 `(bar_close_ms, event_id)` 的稳定降序 cursor 在服务器分页；前端仅在用户点“加载更早记录”时追加 raw 回放页，并在定时刷新时保留已加载的旧页。
- **通用规则**：浏览器侧的显示数量不是数据库覆盖。历史列表超过一页时，必须提供服务器端筛选和稳定翻页，不能把“最近 N 条”写成可搜索的全量历史。
- **牵连**：`yoyo/monitor/store.py`、`server.py`、`static/app.js`；cursor 只读，不触发候选或通知。
