# 两个交易入口的账户边界必须落实到运行目录与消费源

- **问题**：Owner为均线密集提供新账户，随后指出信号中心自动实盘被一起换走。之前把“替换当前账户”解释成全站默认账户替换，超出了实际入口范围。
- **死胡同**：只在UI改名称或把旧账户降为只管理，都不能保留两套入口的原用途；单账本混入外部持仓又会触发归属失败。
- **有效路径**：恢复原信号账户的凭据、账本、cutoff和自动消费源；另建均线密集私有runtime、队列、锁、日志和worker，API分别绑定。新账户只消费逐笔确认，UID绑定政策保留Owner现仓。同币种有外部仓位或挂单时拒绝开新单，防止合并数量与共享杠杆牵连外部仓位。
- **通用规则**：凭据变更先定位产品入口、执行源和持仓归属，不能从“当前账户”推导全局替换。隔离验收须比较真实UID是否不同、API数据来源、worker源和原cutoff，而非只看标签；专用runtime丢失政策时必须拒绝启动，不能回退成自动策略。
- **牵连**：`config.py`、`__main__.py`、`manual_engine.py`、`manual_inventory.py`、`manual_api.py`、两个账户UI；本机两个私有runtime。离线17项隔离场景覆盖外部持仓/普通单/算法单、分页和确认后变更；真实账户只读验证，无测试实盘订单。修正的是入口范围理解，不改Owner逐笔授权要求。
