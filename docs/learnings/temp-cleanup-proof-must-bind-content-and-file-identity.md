# 临时文件清理证据必须同时绑定完整内容和文件身份

- **问题**：2026-09-11，经 owner 授权清理工作目录外闲置数据。系统临时目录存在大量约 19–22 MB 的 `tmp.*`，单个样本是 NUL 分隔的相对文件路径清单，但该样本不能证明整批文件都可删。
- **死胡同**：仅凭临时文件名、大小相似或单个样本推断整批用途不足以支持删除。初次核验还有旧扫描器未退出、覆盖新版 manifest 的问题；看过的中间结果不能替代最终保留下来的证据。逐路径查询文件系统也会放大扫描成本。
- **有效路径**：停止旧扫描器，以独立的单写者 manifest 重新核验。限定本人拥有、至少 24 小时未改动的普通文件；逐文件完整读取并计算 SHA-256，检查 UTF-8、末尾 NUL、相对路径及空段/点段/控制字符约束。全部顶层组件与仓库目录元数据及明确的扫描状态文件名核对，不打开清单指向的数据文件。只有摘要完全相同时才复用语法检查结果，每个文件仍完整读取并核对读取前后 dev/inode/size/mtime/ctime。最终 597 份旧非空文件中，596 份通过；删除前再次核对文件身份及当前打开引用，删除 596 份，删除前分配块数合计 11,536,060,416 字节。
- **通用规则**：清理 manifest 只能有一个写者，原子写入并明确完成状态。删除必须绑定完整校验结果和当前文件身份；变化中、正在使用、过新或未通过的项目保留。实际释放空间另用整盘可用空间测量，目录分配块数不能直接等同于整盘净变化。
- **牵连**：未查明这些临时清单的生成进程，也未设置自动清理任务。原始研究数据未通过清单被读取或删除。本轮证据保存于 `/Users/zhangzc/.local/state/disk-cleanup/20260911/outside-cleanup.json` 和同目录 `certified-temp-cleanup.json`。
