# 条件化检测扫描必须先证明端点包络完整

- **问题**：只为 Pine 候选运行 W18/W19 YOLO 可以显著减少推理量，但模型框允许 4--5 根核心、
  2--9 根确认，融合又采用闭区间相交；若候选端点取得过窄，优化会静默漏掉本应匹配的检测。

- **死胡同**：只扫描 Pine 交叉所在端点、固定 `post2` 端点，或把“无需精确同 bar”实现成一个
  经验性的前后若干根容差。这些做法既覆盖不了全部合法核心位置，也无法证明结果与完整扫描的匹配
  子集等价。

- **有效路径**：先从几何契约反推端点全集。设 Pine bar 索引为 `p`，模型核心长度
  `L in {4, 5}`、确认长度 `q in [2, 9]`；两个闭区间相交时，核心起点满足
  `p - L <= c <= p + 1`，检测窗端点 `e = c + L - 1 + q`，因此所有可能端点恰好落在
  `p + 1 .. p + 14`。两个窗口长度仍都要扫描，推理后再以真实区间、方向和较晚
  `available_at` 做最终裁决。

- **通用规则**：条件化扫描只能优化候选生成，不能改变验收谓词。先用冻结的核心长度、确认长度和
  匹配边界推导一个可证明的超集，再通过测试枚举极值，并在输出前重验区间与可用时间契约。
