# 部分外接数据必须按实际文件解析存储位置

- **问题**：迁移旧图像时，同一个数据集的配置与标注需要留在本机，图片子目录放到移动盘；网页原有数据集 ID 和文件路径仍须可读。
- **死胡同**：只登记整个数据集根目录，或一律跳过软链接目录，都无法表达这种混合布局。前者会把外盘图片当越界文件拒绝，后者会在重新索引时悄悄丢掉图片；只修改当前索引的存储标签也不能修复下一次索引。
- **有效路径**：登记具体迁移子目录，索引前检查所有已登记外盘位置；遍历时仅进入目标精确匹配登记的软链接目录，并逐文件核对清单准入。保留本机根目录与原逻辑路径，网页显示“部分外接硬盘”。离线时在替换索引前失败，本机文件仍可读。
- **通用规则**：同一逻辑数据集跨多个存储位置时，身份属于逻辑根，访问授权与可用性属于实际文件。必须同时验证首次切换、重新索引和外盘离线三条路径，不能仅验证页面标签。
- **牵连**：`yoyo/data/external_storage.py`、`yoyo/data/dataset_catalog.py`、`yoyo/monitor/static/datasets.js`、`tests/test_partial_external_dataset_storage.py`。Owner 明确取消此次内容哈希；验收使用路径、数量、大小、时间和实际后台/HTTP 读取，测试禁止内容哈希。
