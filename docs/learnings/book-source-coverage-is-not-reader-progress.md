# 原文取得、逐章研读与个人已读是三种不同状态

- **问题**：Notion 第 56 条要求通读交易书原文、逐本做小册并接入前端。书目评分、全文文件、编者整理和 Owner 的阅读进度，不能用一个“已读”状态表达。
- **死胡同**：最初只完成前三章时，原文文件已经完整下载；文件存在不能证明其余章节已研读。完成第 24 章后，最终核对又发现 manifest 的逐章 reviewed 已全部更新，但顶层 reviewed_chapters 和 coverage_note 仍停在前三章：只检查页面或一个计数会漏掉矛盾。任务页的 PDF、网盘、Figma 占位块也经实页确认为空，不能当作已有原文。
- **有效路径**：每章保留原文锚点、覆盖状态、具体案例、解读边界与练习，完成多少就展示多少。原文归档另存 SHA-256；最终同时核对逐章内容、顶层覆盖和 Notion 小册。个人笔记、已读和复习日期独立保存在浏览器，可导出迁移；新小册发布不替 Owner 标为已读。未取得全文的候选只显示书目与来源。
- **通用规则**：建立阅读产品时先拆开“原文可得性 → 编者覆盖 → 个人学习 → 观点验证”，禁止前一状态自动推动后一状态。覆盖扩展后的交付核验要包含所有派生计数和说明，不能只数正文标题；作者故事和读者评分均不是策略验证证据。
- **牵连**：`yoyo/monitor/static/trading-books.json`、`trading-books.js`、`tests/monitor/frontend_trading_books.test.cjs`、本地忽略的 `data/reading/task56/manifest.json`；Notion 第 56 条及 Spike 交易资料库。完整研读仅覆盖《股票作手回忆录》1923 英文正文 24 章，其余五本仍待完整原文。
