# 后级代码门不能修复前级模型的首次提案延迟

- **问题**：希望把流水线改成“模型先检测密集、代码再确认突破”，以获得比 completed-history 语义门更早的信号。
- **死胡同**：只替换第二层规则，并期待它把已有模型框对应的时间提前。后级规则只能接受或拒绝已经出现的提案；在模型输出为零的时间段，它没有候选可处理。
- **有效路径**：先逐端点保留完整 raw-box 账本，以首个原始模型提案的完整可用时间作为整条串行流水线不可突破的下界；再比较代码门时间。若目标入场早于该下界，瓶颈确定在模型目标/输入，而不在后级代码。
- **通用规则**：优化串行检测器的延迟前，第一步先测每层的 earliest-available time；任何下游层都不得把输出回填到上游框内的核心时间。
- **牵连**：`scripts/diagnose_1h_filusdt_model_first_breakout.py`、raw YOLO 提案账本、完整检测窗右端纪律、tip/tip-1/tip-2 因果目标。
