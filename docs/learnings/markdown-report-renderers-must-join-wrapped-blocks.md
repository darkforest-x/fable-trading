# Markdown报告渲染器必须合并源码换行

## 现象

项目报告为了便于代码审阅，会把长段落和长列表项在Markdown源码中换行。旧版
`scripts/md_to_html.py`却把每一条物理行都当成独立段落，只识别无序列表，也不吸收列表项的
缩进续行。结果是HTML里一句话被切成多个段落，编号步骤失去列表结构。

## 根因

Markdown的物理换行不等于块级语义边界。空行、标题、列表标记、表格、代码围栏等才是当前项目
报告所需的块边界。逐行直接生成`<p>`会把源码排版误当成展示语义。

## 修复原则

1. 普通段落持续吸收后续非空、非块起始行，再用空格合并。
2. 有序与无序列表分别维护`ol`/`ul`状态；缩进续行并入当前`li`。
3. 标题、表格、引用、代码围栏、水平线和新列表项都必须终止当前块。
4. 用回归测试同时覆盖续行、列表关闭以及后续标题和表格，防止修复一个块后吞掉下一个块。

## 可复用结论

自制轻量Markdown渲染器不需要实现完整规范，但必须按“块”解析，而不能按“行”解析。只要允许
源码自动换行，段落续行和列表续行就是最低正确性要求。
