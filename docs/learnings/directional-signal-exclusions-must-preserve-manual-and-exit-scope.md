# 分周期方向的信号禁入必须与手动账户及退出管理分开

- **问题**：Owner要求将V13.1四组各20个历史亏损币用于信号中心。扫描器、通知、自动账户和独立手动账户复用部分代码，单改显示或共享币种函数都会产生不同作用范围。
- **死胡同**：只把新名单并入全币种集合，会误封同币其他周期和另一方向；在共享Engine.enter直接按周期方向检查，又会把SPIKE名单套到继承该方法的ManualEngine。实现中检查继承调用链发现这一点，部署前改成可覆盖的entry_exclusion，未把错误范围带入运行服务。
- **有效路径**：保留已有全周期范围；在单一契约中增加明确的周期/方向参数。扫描入口、持久通知发送前、自动信号源、准备/提交前和等待重试均复用它。ManualEngine对owner_manual_yolo事件继续使用原币种范围。行情维护和既有仓位管理不受新入场名单阻断，历史事件只失去新鲜标记而不被删除。逐项核对80条源名单及明确跨交易所名称映射。
- **通用规则**：上线任何筛选器前先列出所有消费者和共享父类，分别验证“新入场被阻断”“其他方向/周期仍可用”“已有仓位仍能退出”“独立账户不被波及”。持久队列必须在消费端重查，不能以生产端过滤代替。范围决策的人工授权不改变历史研究的证据等级。
- **牵连**：`yoyo/contracts/signal_universe.py`、`yoyo/monitor/v130_worker.py`、`notification_policy.py`、`yoyo/okx_execution/{source,engine,manual_engine}.py`；377项相关后端、40项前端通过。更广门禁另有8项既有文档/归档路径/历史登记失败，保留在`output/signal-bottom20-20261017/pytest.txt`，没有为本次上线绕过或修改它们。
