# 图表参考方向不能直接决定尚待成交的旧仓保护

- **问题**：V1+ 同根结束旧参考并创建反向参考时，下一根图表状态已属于新方向，真实模拟旧仓却还在等待开盘退出。直接读取图表的 active protection，会把新方向止损用在旧仓上；无真实旧仓时，未消费的反向指令还会误平后来建立的新仓。
- **死胡同**：沿用一个方向/保护变量同时代表图表参考和模拟仓位，或先用整根 high/low 检查止损再执行早已排定的开盘退出。二者都混淆状态归属和信息可用时间。
- **有效路径**：执行仓独立保存属于自己的已生效保护。按开盘跳空保护、消费上一收盘排定的退出、新入场、盘中保护、收盘更新的顺序推进。没有旧仓也要消费本次开盘退出指令。入场当根同样可能触及初始止损。
- **通用规则**：参考时钟与成交时钟不同的回测，先画清仓位和待执行指令的生命周期，再测试同根反转、开盘跳空、无实际仓的历史参考和入场当根止损；顺序错误不能靠收益汇总发现。
- **牵连**：`yoyo/evaluation/spike_v1_plus_replay.py`；V1+ 默认研究的合成回归；不得把这些 Python 检查冒充 TradingView 原生运行 parity。
