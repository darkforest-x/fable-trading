# “最新信号”图必须画最新端点，不能画事件段内最高分窗口

- **问题**：同一形态在连续滑窗中反复出框时，常规事件去重会保留整段最高 confidence；但用户问“最新信号”时，这张最高分图可能早了数个 bar，标题里的分数也不是当前端点分数。
- **死胡同**：直接复用离线画廊的“最高 confidence 代表事件”规则。它适合压缩重复提案，却会把历史峰值冒充当前状态；尤其在较慢周期上，几个 bar 就是数十小时。
- **有效路径**：事件身份仍用冻结的同币时间间隔去重；随后在事件关联的全部原始候选中，先取最后一个真实检测端点，再在该端点内取最高 confidence 作为交付框。事件段内峰值单列为 `event_peak_confidence`，不能覆盖最新分数；同时显式记录当前端点是否仍命中。
- **通用规则**：凡用户问“现在 / 最新 / 仍在不在”，第一步先把事件级聚合拆成 `event peak` 与 `latest endpoint` 两个字段；图和主结论必须使用后者，峰值只能作旁注。
- **牵连**：`scripts/scan_4h_ma_launch_yolo_latest.py`；`same_symbol_event_gap_bars=5`；`confidence=0.25`；W18/W19 连续滑窗；慢周期下 bar 数到墙钟时间的放大。
