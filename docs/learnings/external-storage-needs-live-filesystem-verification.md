# 外接存储迁移要以真实文件系统证据为准

- **问题**：2026-09-24，本机空间不足，Owner 授权将合适的数据迁往 Elements SE。外接盘虽有约 1.3 TiB 空闲，最初却是 macOS 原生 NTFS 只读挂载。
- **死胡同**：容量足够不代表可以承接迁移；Paragon 安装程序完成也不代表驱动生效。首次安装后，`diskutil info` 仍显示 `Volume Read-Only: Yes`，系统设置明确阻止内核扩展。未向只读盘迁移，也未格式化已有数据的外接盘。
- **有效路径**：从西数官方取得 17.2.410，核验开发者签名与苹果公证；Owner 亲自处理启动安全策略和扩展授权并重启后，重新检查同一分区 UUID、`UFSD_NTFS` 挂载、可写标志，再执行写入、fsync、读回及清除自建探针。此时才开始复制候选历史数据。
- **通用规则**：先验证实际挂载身份与能力，再决定操作。空间释放须以迁移前后实测区分归因：本次重启后空闲约 58 GiB，不能把这部分计作迁移成果。跨文件系统复制还须独立核对路径集合、内容 SHA-256 与原有元数据，不能只相信复制工具退出码；校验通过前保留本机原件。
- **持久性边界**：本次驱动在 `utime` 后的即时 `stat` 能短暂返回纳秒值，但稍后读回变为整秒，导致第一轮严格时间精度校验失败，原件保持不变。之后保留源端纳秒元数据清单，以挂载层实际稳定呈现的整秒核对修改时间；文件内容、路径、权限及原有扩展属性仍按原强度验证。不能把缓存中的即时读回等同于持久元数据能力。
- **牵连**：分区 UUID `9C313B72-8A2D-4E45-8CEF-51A3E1117FB3`，挂载点 `/Volumes/Elements SE`；操作脚本与原始收据在 `data/_storage_migrations/20260924-binance-history/`。macOS 可给新副本增加 `com.apple.provenance`，原有属性必须保留，不为追求属性集合相等而删除新增的安全元数据。启动安全策略是 Owner 的决定，不能把安装软件的授权自动扩展为降低安全策略的授权。
