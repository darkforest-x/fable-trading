# 自动信号审查必须锚定原始事件身份

- **问题**：V1 原始启动信号、同一事件的 YOLO 追加确认、历史回放和前端重复读取会经过不同链路；若自动 AI 审查监听任意一条链路，同一个启动可能被多次审查和多次提示。
- **死胡同**：把审查挂在 Bark 发送器、`/api/signals` 的每次读取或 YOLO 确认回调上。这些位置分别会受重试、页面刷新和二阶段确认影响，不能提供“一根原始箭头只审查一次”的事件语义；启用时直接遍历现有列表还会把历史信号误当新信号。
- **有效路径**：以已收盘 `source=live`、`confirmation=raw` 的 canonical raw event id 作为唯一审查键；启用时冻结现有事件为基线，只处理激活时刻之后的新事件。审查状态与输入快照使用独立持久化文件，结论保持只读旁路，不回写原信号、通知策略或执行状态。
- **通用规则**：给任何信号系统增加二阶段自动判断时，先固定原事件身份、激活时钟和独立去重账本，再增加分析逻辑。模型追加结论属于同一事件的新证据，不应重新生成原始审查事件。
- **牵连**：`yoyo/monitor/v1_worker.py`、`yoyo/monitor/store.py`、Codex heartbeat `spike-v1`、`analysis/output/spike_ai_review/heartbeat_state.json` 与 `reviews.jsonl`；审查结论仍需前向影子样本验证，不能直接视为自动开仓许可。
