# 服务状态诊断必须只输出需要的字段

- **问题**：Mac 监控的 `status` 命令直接转发 `launchctl print`，其中会包含系统继承的环境变量；只想确认服务运行，也会暴露与本服务无关的配置内容。
- **死胡同**：认为读取状态是只读操作，所以原样输出安全。只读只说明没有修改系统，无法约束返回内容；按某几个密钥名字打码也会漏掉未知名称。
- **有效路径**：原始 stdout/stderr 仅在进程内捕获。显示字段用白名单：服务名、状态、PID、运行次数、固定配置和日志路径。状态限制为已知枚举，计数只接受整数，嵌套环境字段不参与顶层状态解析；失败与超时同样不回显原文。
- **通用规则**：任何系统级诊断输出进入报告或对话前，先定义用户真正需要的字段，再提取和验证类型；不要把原始诊断文本当作可直接分享的摘要。
- **牵连**：`yoyo/monitor/manage.py`、`tests/monitor/test_manage.py`。这是独立管理 CLI 的修正，不需要打断正在运行的行情扫描，也没有改动系统环境变量或任何凭据。
