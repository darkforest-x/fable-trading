# 来源重叠校验应区分价格冲突与成交量序列化尾差

- **问题**：首4小时区间研究复用ETH两份OKX缓存时，严格OHLCV逐值比较拒绝合并。37,800根重叠bar的OHLC全部一致，2,979根volume有尾差，最大绝对差9.313225746154785e-10。
- **死胡同**：把所有浮点不相等都当成市场数据冲突会无故阻塞复用；把全体OHLCV改为宽松近似又会放过会改变成交结果的价格差异。
- **有效路径**：逐列定位差异，价格保留精确相等门；仅volume容许相对1e-12的序列化误差，记录差异数量与最大值，保留两份源哈希与原始文件。本策略不使用volume产生信号。
- **通用规则**：先按数据字段的经济作用定位冲突，再给有证据的数值序列化误差设置最窄容忍；不得静默覆盖价格冲突。
- **牵连**：`yoyo/data/four_hour_range_source.py`；`experiments/active/exp-four-hour-range-20260920-v1/source_config.json`。首次严格校验失败保存在source_acquisition_attempt1.log，未产生经济评分。
