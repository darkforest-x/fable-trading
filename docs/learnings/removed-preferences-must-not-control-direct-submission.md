# 移除确认开关时必须同时解除旧偏好对提交路径的控制

- **问题**：模拟开单改为点击后直接提交，原浏览器可能保存开启确认的偏好；确认弹窗与账户、保护价编辑还共用焦点管理。
- **死胡同**：只隐藏开关或把默认值改为关闭，仍会受旧 localStorage 值影响；删除整套弹窗辅助逻辑又会破坏保留的编辑弹窗。本轮在实现前排除这两条路径，没有在正式账本试单。
- **有效路径**：移除旧偏好读取、确认状态、订单确认弹窗及其事件；沿用获取报价 → 校验有效期 → 固定数量与参数 → 保存幂等请求 → 提交的原直接路径。账户与保护价弹窗继续保留焦点、Esc 和背景关闭规则。
- **通用规则**：废弃一个界面偏好时，先追踪它的持久化读取和控制分支；验收新旧偏好值、不可读存储、请求期间重复点击、离页、过期报价与结果不明重试。金额取整只作用于显示，不能回写请求或账本。
