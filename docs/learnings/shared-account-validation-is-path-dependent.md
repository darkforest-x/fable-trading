# 共享账户验证有路径依赖：开发期与验证期的独立账户不能拼成全期收益

- **问题**：同一个 V7 配置在独立开发期从 1,000U 到 2,707.59U，独立验证期从
  1,000U 到 2,453.82U，但从开发期开盘一路连续重放的全期账户却只剩 717.02U。
  如果把两个独立区间的收益率相乘，会得到一个不存在的“稳定增长链路”。
- **死胡同**：把单笔 R 序列当成与账户无关的可加样本，或把开发期终值直接当作验证期本金。
  共享账户还有余额门、10% 总初始风险上限、3 倍名义仓位上限、同币单仓与同时刻排序；
  前一笔是否被接纳会改变余额和占用，继而改变后续实际成交集合。独立验证从 1,000U 重启，
  因此它与全期后半段通常不是同一组交易。
- **有效路径**：同时保存三种互不替代的收据：开发期独立账户只用于选参数，验证期独立账户
  只回答冻结配置能否从相同本金复现，全期连续账户只描述真实历史路径。每份收据必须带实际
  accepted/rejected 账本、账户曲线和组合约束；只能在完全相同的起始状态和准入集合上比较。
- **通用规则**：余额或持仓会影响入场资格时，收益不是可交换的单笔列表。禁止相加、相乘或
  首尾拼接独立区间的终值；也不能用验证期独立盈利去解释全期为何亏损。若要模拟“每年重置”，
  必须把重置写进事前账户合同，作为另一种策略重新评估。
- **牵连**：`yoyo/evaluation/spike_account_growth.py`、
  `yoyo/evaluation/spike_account_growth_study.py`、
  `yoyo/evaluation/spike_account_growth_post.py` 与
  `analysis/p1_spike_account_growth_20260913.md`。同刻候选的 32 个无结果信息 seed 还表明，
  组合容量不足时，排序本身也能把同一冻结配置从盈利路径改成接近停摆的路径。
