# 空数据状态不能强制重开用户已取消的表单

- **问题**：模拟账户表单打开后没有取消入口，点击外侧或按 Esc 都不关闭；没有账户时，`!account || createOpen` 还会让任何关闭状态失效。
- **死胡同**：此前只把表单移到页面上方并聚焦，解决了“按钮没反应”的可见性问题，却没有验收退出流程。仅增加取消按钮也不够：空账户条件和后台重绘仍能把表单带回来。
- **有效路径**：账户空状态只提示入口，弹窗显隐由独立状态决定；复用原生 dialog 的键盘焦点约束，取消、关闭、外侧点击和 Esc 共用清理与焦点恢复。编辑期间暂停账户面板轮询重绘，同时拒绝打开前已发出的后台响应覆盖弹窗。提交中不把关闭解释为取消请求；结果不确定时允许关闭，但保留原幂等请求回执。
- **通用规则**：表单验收同时覆盖进入、输入、退出、重新进入；用空数据和已有数据两组测试，并加入后台刷新与延迟响应。用户取消的是草稿，不能顺手清掉已经发出的请求回执。
- **牵连**：`yoyo/monitor/static/paper-desk.js`、`paper-desk.css` 和 `tests/monitor/frontend_paper_desk.test.cjs`。本次 92 项相关前端测试通过；真实浏览器验证四种关闭方式及重开空草稿。未修改交易规则或后端账本。
