# 合并账本的字段归属必须由两侧原始 schema 决定

- **问题**：V11 独立账本验证器的合成测试通过，首次验证实际账本却误报候选 `launch_*` 字段丢失；实际研究结果没有丢列。
- **死胡同**：合成 fixture 给所有字段加 `_before/_after`，但 pandas merge 只为两侧共有非主键字段加后缀。按后缀猜来源会漏掉候选独有字段；跳过这些字段则恰好跳过本次新增机制最关键的审计。
- **有效路径**：由保存的旧、新 schema 求交集，共有字段还原带后缀列，独有字段还原原名。拒绝映射碰撞、缺列、覆盖及纳秒级时钟变化，再逐原字段比较。不改结果、不重跑行情；修复后 120 个合成测试和真实保存账本验证通过。
- **通用规则**：验证合并输出时先从输入 schema 推导字段来源；测试必须覆盖不对称列，不能让 fixture 与错误实现共享同一假设。
- **牵连**：`scripts/verify_hourly_impulse_launch_v11.py`、`tests/test_verify_hourly_impulse_launch_v11.py`；真实结果 49 个输出哈希保持不变。
