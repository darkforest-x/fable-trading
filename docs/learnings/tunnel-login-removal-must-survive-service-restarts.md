# Removing a tunnel login must update its durable configuration

- **问题**：The owner explicitly removed the username/password prompt from the existing Cloudflare Quick Tunnel on 2026-09-24. Caddy provided Basic Auth in front of the unified workspace.
- **死胡同**：Editing only the running Caddyfile would leave a generator that reinstates authentication on the next service start. Conversely, deleting authentication while readiness still expects HTTP 401 would falsely report an unhealthy gateway. Restarting cloudflared unnecessarily would also replace the temporary public address.
- **有效路径**：Remove Basic Auth and credential generation from the configuration source, make readiness require an anonymous HTTP 200, and update status/access instructions. Validate a candidate configuration before replacing the active file; restart only Caddy when the configuration changes. Keep cloudflared and its URL intact, and make repeated starts idempotent. Exercise anonymous reads/writes against a real Caddy test gateway and verify the deployed public URL without credentials.
- **通用规则**：An explicit authentication change must be reflected in generation, startup checks, runtime application, status and user instructions together. Authentication and request-origin checks are distinct: removing the login does not require removing HTTPS, host validation, same-origin mutation checks, credential stripping or local-only desktop restrictions. The owner explicitly chose link-accessible full workspace access; do not silently reinstate a login later.
- **牵连**：`yoyo/monitor/public_tunnel.py`, `tests/monitor/test_public_tunnel.py`, `yoyo/monitor/README.md`, and the private runtime directory `~/Library/Application Support/Fable/PublicTunnel/`. No scanner, signal, notification, VLM provider or trading configuration changes are needed.
