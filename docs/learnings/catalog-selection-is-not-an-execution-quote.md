# 合约目录与成交报价需要独立的新鲜度约束

- **问题**：手动模拟开单从自由输入改为可搜索下拉，需要展示当前可用的 USDT 永续合约，同时保留原有成交报价约束。
- **死胡同**：没有采用手工维护固定币种列表，因它会漏掉新增或已下线合约；也不能把“在下拉里选到了”当成有新鲜可成交报价，目录不是价格快照。
- **有效路径**：从 OKX 公开 instruments 接口筛选 live、SWAP、USDT 结算、linear 合约，目录缓存 5 分钟；用户选择后仍单独获取并确认原有 15 秒内 bid/ask 报价。搜索仅筛选目录，选中另一合约时清除旧预览；列表读取失败明确展示重试入口。
- **通用规则**：身份选择与执行条件分开验证。先确认选中的是完整合约标识，再按执行时钟获取报价；不能让搜索关键词成为订单标识，也不能复用上一对象的确认预览。
- **牵连**：`yoyo/research_workspace/paper_desk_api.py`、`yoyo/monitor/static/paper-desk.js/css` 与对应测试。交易数量、杠杆、费用及原报价新鲜度门保持原口径。
