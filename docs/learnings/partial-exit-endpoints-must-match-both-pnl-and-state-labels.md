# 分批退出端点必须同时核对收益与状态标签

- **问题**：runner 状态机的 0% / 100% 端点与既有 3R / 8R 引擎逐笔收益完全一致，但 0% 端点仍有少量 `sl_ambiguous` / `protected_stop_ambiguous` 被简化为普通止损。
- **死胡同**：只用平均收益或逐笔 PnL 误差验证新退出引擎。收益一致不能证明碰撞顺序、失败原因和状态统计一致；后续诊断会把语义漂移误判成策略差异。
- **有效路径**：端点测试同时断言逐笔 setup 顺序、gross/net、标准 outcome 和碰撞标签。runner 只有在对应目标具有非零退出份额时，目标与止损同根才应记为 ambiguous；100% runner 在 3R 的零份额“触碰”不能制造 8R 引擎不存在的歧义。
- **通用规则**：复杂退出引擎的退化端点必须与简单基准在数值和状态语义上双重同构；任何端点差异先按实现 bug 处理，再谈策略效果。
- **牵连**：`resolve_runner_exit`、stop-first 碰撞、0% / 100% runner、`metric_row` 的 TP/SL 分类；修复不改变交易收益，只修正可审计标签。
