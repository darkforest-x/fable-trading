# 困难负样本必须挖在时间切分的训练侧,否则一张都进不了课本

- **问题**:v10 重训的核心是给模型看 276 个"像但不是"的例子(v9 自己的误开火,
  owner 逐张否掉的)。数据集建完一查:

  ```
  negv9(v9 误开火 276)   train 0 · val 276
  ```

  **整轮重训的关键样本,一张都没进训练集。** 模型学不到它们,只是被考了一遍。
  训练当时已经跑到第 3 轮,不查就白跑 2.5 小时。
- **死胡同**:挖负样本时我扫的是"holdout 之前最后 800 根"——直觉上"最近的数据最相关"。
  但数据集按 `VAL_CUT = 2026-02-01` 切分,而那 800 根落在 2026-04-25~05-03,
  **整段在 VAL_CUT 之后**,于是全部被分到 val。
  两个决定各自都合理(挖最近的 / 按时间切),**合起来是致命的**,而且不报错。
- **有效路径**:挖之前先看切分点。改成只挖 `VAL_CUT` 之前,并且**每个币用各自的随机起点**
  ——第一版改完只挖 VAL_CUT 前最后 900 根,336 条全挤在 10 天里,
  模型会去学"这 10 天",不是通用的边界。加随机起点后覆盖 2025-06~2026-01、
  8 个月、30 个币,train 侧困难负样本从 190 涨到 **526**。
- **顺带的教训**:新包和旧包我用了同一个输出目录,**覆盖掉了 owner 标注的 277 条**。
  靠之前提交进 git 才捞回来。产出物只要是人工标注过的,就不能被脚本默认路径覆盖。
- **通用规则**:**任何"补充样本"的采集,第一步是确认它会落到切分的哪一侧。**
  时间切分下,"挖最近的数据"和"补充训练样本"是直接冲突的两件事。
  推论:采集脚本要显式接受切分点参数(本例的 `--before`),不能靠默认扫描范围
  碰运气;且样本必须在整个训练期上打散,不能挤在切分点附近。
  再推论:**训练开始不等于配置正确**——这个 bug 在第 3 轮才被发现,
  而它在第 0 轮就已经存在。开训后仍要核对每一类样本落在哪个 split。
