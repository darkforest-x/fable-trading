# 长历史交易日历也需要分段请求与独立收据

- **问题**：A 股周线预热需要十余年历史，一次请求 2008–2026 交易日历触发 BaoStock 60 秒墙钟超时，尚未开始行情采集。
- **死胡同**：把日历当作小元数据，以一个请求覆盖全部年份；SDK 仍需分页传输，多页耗时会越过已经设定的安全预算。
- **有效路径**：按年请求相同官方日历接口，每年独立缓存与请求哈希收据，成功后只按时间拼接，不延长超时、不换源、不补造交易日。
- **通用规则**：长历史采集先估算返回行数和分页次数，连日历与证券列表也要以可重试的有界区间采集。
- **牵连**：`yoyo/evaluation/spike_ashare_data.py`、`yoyo/evaluation/ashare_data.py` 的 `cached_query` 与 60 秒墙钟保护。本次失败发生在元数据采集，没有生成策略收益。
