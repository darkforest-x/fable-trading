# 时间切点做整数搜索前必须显式统一时间单位

- **问题**：BTC 研究的行情保留纳秒精度，而 pandas 3 从字符串建立的切点默认为微秒；直接用两边的 `asi8` 做 `searchsorted`，把全部有效信号归入结束日期以后，得到空候选。
- **死胡同**：两边都显示 UTC，时间字符串也正常，因此误以为可以直接比较底层整数。仅验行情连续和信号公式不能发现分区集合为空。
- **有效路径**：对行情索引与切点都先执行 `as_unit("ns")`，增加微秒／纳秒两种索引产生相同候选的行为测试，并让空候选预检直接报错。首轮空准备产物保留，未进入收益回测。
- **通用规则**：整数时间比较同时需要时区契约与精度契约；分区完成后验实际样本集合与计数，不能只验输入时间文本。
- **牵连**：`yoyo/evaluation/btc_range_wick_fanshen.py` 的 `candidates()`；前例见 [pandas 时间精度可移植性](pandas-datetime64-unit-portability.md)。本次未改框架或环境依赖。
