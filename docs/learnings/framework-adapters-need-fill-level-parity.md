# 接入回测框架必须保留逐笔撮合语义

- **问题**：PEPE 研究反复创建专用回放脚本，已安装的开源框架没有成为可复用入口；直接替换框架又可能改变同币多单、收盘成交和止损生效顺序。
- **死胡同**：把“已安装”当成“策略已接入”，或者仅将旧引擎算好的退出结果导入框架，都没有验证原生成交。照搬较新的在线示例也会遇到本机 1.231.0 的费用模型 API 差异；Pandas 3 的时间索引可能保留微秒，而框架要求纳秒。
- **有效路径**：复用冻结输入和已审计逐笔账本，使用 Nautilus 原生 HEDGING 持仓、市场单和 STOP_MARKET；策略只负责已收盘信息驱动的管理决策。边界测试先验证成交顺序，纳秒时间轴显式归一；再逐笔比较成交、保护价、激活时刻和费用。原账本只供运行后验收，不进入策略。
- **通用规则**：先列出持仓、信号时间、成交时间、费用、同 K 线竞争规则，再选框架。固定参数配置、数据缓存、结果缓存和简短摘要，比每轮换一个回放脚本更能减少重复工作。默认 O-H-L-C 不等价于止损优先的双障碍规则，未适配时不得宣称固定止盈已同口径接入。
- **牵连**：`yoyo/layers/l3_backtest/nautilus_independent.py`、`yoyo/evaluation/range_framework.py`、`scripts/backtest-range`；隔离 Nautilus 环境，主训练依赖不变。成本维持原始开仓名义本金的 20bp；独立收益不是资金账户曲线。
