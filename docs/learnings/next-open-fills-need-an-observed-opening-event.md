# 让框架在下一根真实开盘价撮合

BTC 5m 云带研究要比较同一批信号上的不同入场资格。信号要等当前 K 收盘，开平仓都要求使用下一根 K 的开盘价。直接在已收盘 bar 的回调里提交市价单，小样本成交在该 bar 收盘。仅把订单或结果的时间标签推迟不能解决这个问题。

适配器给 NautilusTrader 两个按顺序送达的事件。开盘时只送真实 open 构成的零区间 bar；随后才送这根完整 OHLC。开盘事件先处理已有的保护止损，再允许策略按开盘价下单。当 open 越过止损时，框架能以开盘价成交。同一根 K 盘中触发时，记录所属 5m 区间及框架事件时间，避免把 OHLC 事件末端误读成精确的盘中成交时间。

验收用前收与后开不同的输入，并覆盖开盘跳过止损、盘中穿过止损及开盘正常退出三个情况。每笔手续费核对实际成交价与数量。同一批 native fills 可以投影到不同入场过滤规则，前提是所有仓位在下一个候选前都能结束、各组使用相同退出且资金约束不会改变入场。

实现见 `experiments/active/exp-btc-cloud-reentry-20261106-v1/native_fills.py`。隔离运行时为 NautilusTrader 1.231.0。
