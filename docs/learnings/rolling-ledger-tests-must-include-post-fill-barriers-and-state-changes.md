# 滚仓账本测试必须覆盖成交后风险和数量状态变化

- **问题**：把 WIF 单笔逻辑泛化成跨币种模块时，初稿的简单合成测试能通过，但加仓后的净利润仍可能使用初仓状态，本应在次开成交的加仓也可能被同根稍后低点取消。
- **死胡同**：只断言“产生了加仓事件”“两个版本前两笔相同”或保护值字段为正，没有独立重算所有成交腿；如果两个版本共享同一个错误，比较一致仍会通过。函数默认参数还会在定义时捕获旧数量、旧费用，而不是随闭包状态更新。
- **有效路径**：在任何真实行情回放之前，构造至少三次加仓的独立账本，直接汇总全部数量×价格、逐次手续费与资金费；再构造入场同根止损、次开加仓后同根止损、回踩中更高上影、确认根更低低点、合法数量区间下界等反例。严格遵守 funding→开盘风险→开盘成交→盘中保护→收盘确认的顺序。
- **通用规则**：事件日志、资金守恒和因果时钟是三个独立验收面。跨币种数量要按合法整数步长做区间搜索；最小名义造成的无效低端不能破坏二分单调性。初仓风险始终用原数量和原止损，不能用最终大仓位和抬高后的止损重新定义。
- **牵连**：`yoyo/evaluation/profitable_roll_v03.py`、`tests/evaluation/test_profitable_roll_v03_invariants.py`、`yoyo/evaluation/profitable_roll_v03_audit.py`。本轮这些初稿问题均在真实数据运行前处理，旧报告和旧策略未覆盖。
