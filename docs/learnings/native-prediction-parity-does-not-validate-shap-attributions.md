# Native prediction parity does not validate an attribution sum

- **Problem**: SHAP 0.52 interventional TreeExplainer failed additivity for one ETH 2025Q4 row: native score 0.287505R versus attributed sum 0.333245R. Feature schema/order, cached native predictions, and SHAP internal tree predictions all matched exactly.
- **Dead end**: Prediction parity did not validate this separate attribution implementation. Removing the one incomplete background row still failed. Turning off additivity checks would accept an explanation that did not reconstruct the score; failed values were inspected only for diagnosis and rejected from conclusions.
- **Effective path**: Retain the frozen native model and the exact paired, training-only backgrounds. Keep native/path-dependent TreeSHAP as the primary explanation. For sensitivity, use PermutationExplainer with the actual native prediction callable at 3 and 10 budgets. All 48 batches reconstructed scores within 5.8e-15R; native/path-dependent contributions matched exactly. Cohort-term means changed by at most 0.0063R between budgets, but individual terms changed by up to 0.102R. This supports only the stated cohort-level sensitivity, not universal convergence.
- **General rule**: Treat prediction parity, additive reconstruction, and attribution stability as separate checks. Preserve failures and scope a verified fallback to explanations; do not retrain or replay trades to repair an explanation tool. A named interventional masker is not evidence of market causation, especially for correlated inputs.
