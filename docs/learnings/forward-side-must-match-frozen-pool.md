- **Problem**: Mainline L2 became short (v10 short_star pool) but `forward_scan` hard-coded `side="long"` and used long TP/SL geometry. Executor is long-only and **buys** when side is long, so the "reject short" guard never fired. Historical `forward_log` cannot count toward short 100-trade confirmation.
- **Effective path**: Carry `FrozenConfig.side`; default v10/v12 configs set `side="short"`. Live scan uses `extract_feature_rows_for_side`, `resolve_forward_exit_short` (PnL `1-exit/entry` aligned with wide-pool net barriers), and writes the true side. Executor still refuses short opens until owner enables short execution — safer than silent long buys.
- **General rule**: When strategy side changes, update **label, features, barrier resolve, ledger side, and execution** in one protocol version; never leave a hard-coded opposite side in the live path. Paper metrics and live books on mixed protocols must not be merged.
- **Follow-up (same day)**: `run_forward_tracking` must not pass a forced long `exit_resolver` (that re-broke short). Runtime load uses `load_runtime_artifact()` → `models/ACTIVE`. Canonical short PnL is `1 - exit/entry`. Idempotency key excludes score. Net targets skip second cost subtraction in `evaluate`.
