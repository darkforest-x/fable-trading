# 未确认的方向镜像既不是正例也不是负例

- **问题**：Owner当前只用ETH下跌案例冻结了空头“完美平台”语义，但动态校准样本中大量出现
  外观相近的多头启动。若直接做二分类，必须决定这些镜像属于同类、另一类还是排除。
- **死胡同**：把多头镜像悄悄混入同一正类会混合红绿K线与方向语义；把它们当空头负例又会让
  模型把同一种平台结构学成互相冲突的监督。两种做法都会把尚未作出的产品决策伪装成标签事实。
- **有效路径**：增加`mirror_unconfirmed`隔离桶。它不参与正负训练、不计入难负例，只保留来源和
  图像，等待Owner明确选择“空头单类 / 多空两类 / 方向归一化同类”后再迁移。
- **通用规则**：当唯一金参考只覆盖一个方向时，第一步先冻结direction scope；所有反向镜像进入
  隔离态，而不是由数据构建器替Owner作类别本体决策。
- **牵连**：`scripts/review_owner_eth_shortdelay_calibration.py`；
  `analysis/output/owner_eth_shortdelay_codex_firstpass_v1/`；Owner ETH空头参考；后续YOLO类别定义、
  镜像处理和难负例抽样。
