# 反手开仓先等旧仓实际归零

- **问题**：Pine策略在同一次执行中发立即平仓和反向entry，代码顺序不保证下单时的旧仓状态已经归零。
- **死胡同**：认为上一行调用close就等于下一行position_size已是0；strategy.entry原生自动反手可能把旧仓量加入新单数量。
- **有效路径**：确认反向信号时先保留queuedEntry并立即平仓；只有实际position_size为0时才发出队列中的新方向。成交回调只完成这项已确认决策，不读取历史最终OHLC制造新信号。
- **通用规则**：交易API调用与成交状态变更是两件事；依赖前一笔成交的动作要靠成交状态推进，不靠代码排列顺序。
- **牵连**：`yoyo/evaluation/pine/eth_bb_stoch_strategy_v2.pine`。此处消除自动加量的源码路径；原生无订单自检未覆盖实际券商模拟成交序列，报告保留该限制。
