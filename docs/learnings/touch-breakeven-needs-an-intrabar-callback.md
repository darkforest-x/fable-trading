# Touch breakeven needs an intrabar callback

- **Problem**: A fixed target with a 1R touch-triggered move to entry must protect a return within the same candle. The existing adapter only amended protection after a completed management close.
- **Dead end**: Checking the full candle high in its close callback and applying the stop retrospectively would invent an earlier decision. Leaving the callback unchanged would silently test a different, close-triggered rule.
- **Effective path**: Keep native Nautilus orders and matching. For an explicitly selected fixed-target path, expose the opening point and three continuous monotone OHLC segments to the engine. Amend at a visible endpoint before the next reversal leg, while entry and completed-bar features still run only at the original close. Opening gaps retain adverse-open fills; continuous legs retain trigger-price fills. Execute both OHLC and OLHC, retain their difference, and validate against a signed-path oracle. Segment timestamps encode sequence only, never observed tick times.
- **General rule**: Specify the trigger clock before comparing exit policies. A stop amendment needs to exist before the move it is supposed to protect; coarse candle data requires an explicit path sensitivity. Moving to entry still loses transaction fees.
- **Scope**: Optional `ExitPolicy.breakeven_on_touch` and `intrabar_path` in `yoyo/layers/l3_backtest/nautilus_independent.py`; default paths unchanged. Native regression tests cover same-bar reversals, adverse-first stops, redundant1R TP/BE, gaps, entry-bar exclusion and simultaneous positions. Owner-authorized study `exp-range-v237-fixed-exits-20261022-v1` retains frozen entries and20bp costs. No Pine or live default change.
