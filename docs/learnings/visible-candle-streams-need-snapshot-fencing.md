# 实时图表需要按可见周期管理连接，并防止历史快照覆盖新行情

- **问题**：移动端 K 线要缓存秒开、实时更新和断线补齐；切币、切周期及全屏又会触发组件生命周期。网络与绘图混在页面状态里，容易多开连接、串币或把实时价格回滚。
- **死胡同**：把 REST 返回值直接当最新全量数据，会覆盖请求期间先到的 WebSocket 更新；仅比较当前最后一根与快照首根，也会被先到的实时尾柱掩盖历史断档。针对这两种时序的合成回归可重现问题。
- **有效路径**：每个可见币种/周期独占一个可停止的数据会话。快照期间收集流更新，合并时由流更新优先，已闭合柱不回退；断档根据快照之前的历史段判断。停止时取消请求、关闭连接并使迟到回调失效。UI 按币种/周期标识接收数据，全屏只换画布而复用连接。
- **通用规则**：先画出缓存、快照和实时消息的到达顺序，再验证切换、后台、断线和迟到返回。缓存必须标明时效；实时图表只供显示，不能成为下单定价或风控输入。
- **牵连**：`yoyo/discipline_app/mobile/src/candleData.ts`、`candleSession.ts`、`CandleModule.tsx`、`CandlePanel.tsx`；`tests/discipline_app/candles.test.ts`。首屏 300 根，内存最多 2000 根，每个缓存最多 600 根、总计 12 组、保留 7 天；仅当前可见图表订阅 OKX 公共 K 线。
