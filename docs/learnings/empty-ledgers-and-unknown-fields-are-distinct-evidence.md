# 空账本与未知字段不能被同一种相等检查处理

- **问题**：复用历史研究 controls 时，有的币完全没有交易，CSV 只保留薄表头；另一些币有随机候选但无法建立交易，退出时间为未知。两者都必须保留到完整覆盖检查中。
- **死胡同**：对薄空 CSV 强取全部 control 列会报 KeyError；把两个未知日期转成 NaT 后直接 `.eq` 也会判不等。通过不检查 controls 或删掉这些币“让回测通过”，会把无样本或失败证据消失掉。
- **有效路径**：两边同时空的账本显式记录双方行数为零；仅一边空则失败。非空逐字段对账时，时间同时缺失才相等，单边缺失仍失败。本轮以父实验 AGIXUSDT 的薄空表头和有候选但无退出的合成控制记录分别验收。
- **通用规则**：缺列的空表是已知零观测，不是数据文件丢失；记录中的未知值是未观测事实，不是可填零结果。验证器先判集合/行数完整性，再按类型处理值的相等性。
- **牵连**：`yoyo/evaluation/spike_joint_btc_gate.py:_control_parity`；`yoyo/evaluation/spike_joint_btc_report.py:validate_parent_symbol`；新增两处回归测试。没有修改旧产物或原回放引擎。
