# 迁移切换的 HTTP 失败必须保留响应正文

- **问题**：一组图像复制与元数据检查通过，切换后的网页抽查返回 HTTP 409。原件自动恢复，但旧操作脚本只留下状态码，没有记录响应正文。
- **死胡同**：仅凭 409 或请求耗时猜测时间戳异常、外盘权限或磁盘繁忙，都不足以确认原因。副本元数据正常且重试成功，只证明恢复后的访问可用，不能追认第一次故障的原因。
- **有效路径**：失败时先恢复原路径与目录登记，保留原件；重试前归档该次背景探测、登记快照与切换记录，同时记录 HTTP 状态、URL、响应正文和时间。只有明确表示外盘身份查询暂时失败的响应才自动有限重试，其他冲突继续停止并保留数据。
- **通用规则**：带有回退动作的数据迁移，失败证据属于验收记录的一部分。不要为了重试覆盖它，也不要用重试成功代替根因证据。
- **牵连**：`data/_storage_migrations/20261016-task52-remaining/safe_cutover.py` 与各批切换收据。Owner 本次明确不做内容哈希，恢复与重试仍只使用元数据和真实后台/网页读取。
