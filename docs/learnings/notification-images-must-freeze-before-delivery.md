# 信号图片必须在首次发送前冻结

- **问题**：TG 信号需要配行情图，但扫描继续更新、发送可能限流；同一个信号的图片不能包含后来行情，也不能因图片发送结果不明而重复推送。
- **死胡同**：未采用的方案是在发送器里取最新图、失败后再发文字。前者让重试改变信号证据，后者在超时但已送达时生成重复消息；这里没有把该方案当作真实线上事故。
- **有效路径**：扫描器先截断到信号 K 线，渲染器再校验目标时间、收盘价和指标值。PNG、哈希、首次事件及两个渠道队列在同一事务提交。渲染在 HTTP 前失败可以选文字；上传已开始后的不确定结果保持 unknown。429 重试同一份已冻结图片。
- **通用规则**：先明确图片代表哪个时刻，再固定内容和消息身份。降级是否安全取决于是否已开始外部发送，而不是错误看起来是否可恢复。
- **牵连**：`yoyo/monitor/snapshot.py`、`service.py`、`store.py`、`telegram.py`；未来扰动、目标匹配、事务回滚、并发去重、429 与未知回执测试。PNG 是派生展示产物，原始 OHLC 数组仍只在内存。
