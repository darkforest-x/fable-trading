# 用户指定现有链接时，先精确复用链接

- **问题**：Owner 要把 TG「查看图表」链接放到周一触价列表的币种名称上；实现却继续扩展为自定义协议和本机桥接。
- **死胡同**：围绕客户端接管增加安装程序、权限排查和菜单自动化，扩大了操作成本；程序被唤起也没有证明目标图表已加载。Owner 用两张截图明确要求直接复用原地址。
- **有效路径**：撤掉本次新增的协议程序与相关代码，恢复与 `monday_fib.py` 通知相同的 HTTPS 图表 URL；刷新 Owner 当前页面，逐项核对 419 个币种链接均为对应 OKX 永续与 interval=15，15 项定向前端测试通过。
- **通用规则**：当 Owner 指定已有入口作为参照，先取出其真实 URL 并验证目标元素的 href；不要把普通链接搬移升级为系统集成。链接一致和客户端成功切图是两个不同的验收结论。
- **牵连**：`yoyo/monitor/static/monday-fib.js`、`yoyo/monitor/monday_fib.py`、`tests/monitor/frontend_monday_fib.test.cjs`。已撤销中转实现，未把客户端切图宣称为成功；其他页面原有桌面桥接保持原样。
