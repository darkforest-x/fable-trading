# 交付审核图必须按复合渲染器重放，不能拿裸画布尺寸验收

- **问题**：模型裸输入是 742×1280，但交付检测图会在上方追加 86 像素审核信息，因此成品是 828×1280。独立验证器把裸画布高度硬编码成了交付图高度，导致 52 个月的榜单、输入像素、语义与去重全部重放通过后，在首张交付图处误报尺寸漂移。
- **危险捷径**：把常量从 742 改成 828 后只验尺寸和记录内 SHA。尺寸只能证明外壳相同，记录内 SHA 又可能与错误产物一起生成，二者都不能独立证明标题、原始检测框和裸输入的组合像素正确。
- **有效路径**：验证时按月重载冻结 K 线，对每条最终事件调用正式 `render_exact_model_input`，再把重放结果与交付 PNG 做逐像素相等比较；文件 SHA 仍作为传输完整性检查保留。期望尺寸由正式复合渲染器自然产生，不再维护第二个手写常量。
- **通用规则**：凡是由“模型输入 + 标题/框/图例”组成的审核资产，验收对象必须是完整复合渲染函数的输出。裸模型画布规格与人审交付规格应明确区分，不能共享一个没有语义名称的尺寸常量。
- **牵连**：检测图库、审核页、离线 verifier、像素复现声明；不改变模型输入、候选事件、标签、训练资格或生产状态。
