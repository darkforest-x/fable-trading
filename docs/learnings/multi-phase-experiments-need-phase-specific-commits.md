# 多阶段实验必须逐阶段披露提交身份

- **问题**：长时远端扫描固定在较早 commit，而数据隔离修复、训练和报告在后续 commit 执行。只在复现命令里写训练 commit，会让读者误以为快照、候选扫描和训练来自同一个二进制。
- **死胡同**：用“输入哈希一致”代替代码血缘。哈希能证明权重、数据和候选账本没有漂移，却不能说明哪个版本负责生成每个阶段，也无法暴露扫描后发生的下游完整性修复。
- **有效路径**：快照、扫描、数据集和训练各自在终态回执中记录 40 位 commit；报告逐项列出并校验格式，同时解释哪些后续变更只作用于下游。候选账本继续靠原子回执与 SHA-256 连接，不重跑或悄悄替换。
- **通用规则**：跨机器、跨数小时或允许阶段间修复的实验，复现身份是“阶段 → commit”的映射，不是单个仓库 HEAD。
- **牵连**：`scripts/build_15m_ma_launch_l2_global_context_report.py`、各阶段 `*_receipt.json`、远端扫描收集门；不改变候选、特征、标签、阈值或模型结果。
