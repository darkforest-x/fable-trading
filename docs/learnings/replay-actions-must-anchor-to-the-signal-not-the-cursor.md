# 回放识别必须锚定原信号，并明确展示调用状态

- **问题**：Owner 打开 PTB 1H 回放后找不到信号，也无法判断智谱是否调用。游标已在原信号后 52 根，页面只有播放和藏在下方的冻结流程；顶部本地 API 连接状态容易被理解成 AI 已运行。
- **死胡同**：仅给播放控件加说明不能建立信号与识别的联系；直接识别当前游标又会把信号之后的行情送入模型。只把游标倒回也无法消除用户已经看到的未来，不能恢复盲审资格。
- **有效路径**：在图表上方展示原信号收盘、相对位置、AI 调用状态与主按钮。图中原策略箭头锚定收盘对应的开盘时间，只标当前前缀内真实存在的 bar；箭头不进入服务器模型图。服务端按案例时间精确冻结 120 根，不移动游标，随后复用持久化 analyze；已有请求直接读取收据。未来已看的盲审会话显式转为回顾学习观察，保留暴露事实，不允许补独立人标。旧冻结 identity 保持兼容，避免升级后重复调用。
- **通用规则**：验收回放时从“用户选了一个事件，下一步点击什么”走完真实界面；分别核对策略事件、播放游标、模型输入截止和持久请求记录。连接成功、播放成功和模型判断成功是不同状态。
- **牵连**：`yoyo/vision_research/replay.py`、`static/replay.js`、`static/index.html`；工程验证使用隔离 runtime 与模拟 provider，不能冒充真实模型效果。低价资产轴精度也必须从当前已披露价格推导，不能四舍五入成 0.00。
