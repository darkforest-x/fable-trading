# 回放窗口冻结必须遮蔽入场而不是特征

- **问题**：历史回放需要较长预热来计算特征，但如果模拟器直接接收预热期信号，会把窗口前开仓带进评分期；逐流结果也可能在中断后只留下半套文件。
- **死胡同**：先截断输入到评分期起点会让 BB 阈值和连续压缩状态重新冷启动；只在最终汇总时过滤交易则已经允许窗口前仓位影响窗口内退出。
- **有效路径**：完整认证前缀先计算特征与缺口状态，再按信号确认时刻 `[START, END)` 遮蔽全部入场和反向事件；执行器在最后可用 bar 标记未平仓为 censored。每个流在 staging 目录完整写入、写 completion receipt 后原子移动，progress 可从 completion 恢复。
- **通用规则**：固定评估窗时，先区分“特征可见历史”和“允许决策历史”；不要通过截掉预热修复 carry-in。可续跑的流级输出必须有独立完成标识及来源哈希。
- **牵连**：`yoyo/evaluation/spike_v7_v1_compare.py`、`tests/evaluation/test_spike_v7_v1_compare.py`、冻结 V1 两年覆盖收据、BB200/P10 连续就绪规则。
