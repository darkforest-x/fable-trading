# 统一研究入口时，保留实时扫描与离线任务的独立生命周期

- **问题**：信号中心、视觉审核与因子研究分散在不同入口，研究登记和回测证据难以联结；直接合并任务又会增加实时扫描延迟。
- **死胡同**：只把另一个页面嵌进 iframe 无法统一导航与同源交互；把离线重放挂进扫描脉冲则会争用时序预算。首轮同源代理还因路径白名单未允许 `.png`，造成文字正常但所有参考图失败，说明接口 JSON 成功不能替代完整页面验收。
- **有效路径**：复用信号中心外壳，把原视觉组件挂进 Shadow DOM，通过固定回环地址代理原 API；原视觉存储与工作进程继续独立。研究目录读原注册表，新补充记录按版本保存；回测使用单独进程、队列锁和独立运行目录，锁由引擎继承，防止包装进程意外退出后重叠运行。原回测输入、成本、逐笔对照与提交门保持一致。
- **通用规则**：先拆清“同一用户入口”和“同一任务执行器”，再统一页面。验收必须覆盖实际图片、保存后重读、失败/取消、已完成任务和原始证据身份；不能把页面渲染或 HTTP 200 当作完整工作流通过。
- **牵连**：`yoyo/research_workspace/`、`yoyo/monitor/static/research.js`、`yoyo/monitor/static/vision-module.js`、`tests/research_workspace/`；8766 为用户入口，8771 继续服务视觉后台；不增加 forward 脉冲任务，不改变训练/实盘资格。
