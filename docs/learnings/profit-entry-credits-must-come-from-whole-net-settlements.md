# 盈利奖励次数从整笔净结算推导，不从通知或成交回报累加

- **问题**：纪律 App 需要“止盈一单，当日可开次数加一”，但分批止盈、多次轮询和重启都会重复看到同一笔交易。
- **死胡同**：没有采用在每条盈利成交或客户端成功提示上执行 `entries -= 1` 的方案；它会把部分止盈当成整笔盈利，重复返还次数，并破坏已用次数的审计事实。
- **有效路径**：保留真实申请次数，服务端从按持仓 ID 去重的完全平仓记录中，统计北京时间当天实际结算净盈利的笔数。总额度为基础次数加奖励；交易所结算晚到仍归实际平仓日。旧规则缺字段默认不奖励，另由明确的本机迁移激活。
- **通用规则**：奖励应从权威终态派生，不能因重试增加；额度增加不清除日亏锁或冷静期。
- **牵连**：`yoyo/discipline_app/book.py`、`policy.py`、`tests/discipline_app/test_profit_entry_bonus.py`。纸面分批/完整结算、净亏、跨日、重启、重复记录、停手优先和虚拟交易所结算均有测试。
