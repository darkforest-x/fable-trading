# 切换信号版本并清空历史，必须同时阻止历史重新入库

- **问题**：Owner 要求前端和 Bark 切换 V9，并清空之前的信号。监控重启会用保存的行情重新计算完整指标序列，只删除事件表会让旧信号再次出现。
- **死胡同**：只改前端标题会保留 V1 算法；只换通知版本只能防补发，不能防旧信号重新显示。V1 的通知与 YOLO 派生事件还写死多头，单独替换检测器会丢失 V9 空头通知。
- **有效路径**：复用已冻结的 V9 准入算法；给原始与 YOLO 事件、通知策略各自设置 V9 身份。停止唯一写者并取得服务锁，私有备份后在同一事务内清空事件及其队列、候选和展示缓存，保存新的交换所时钟切点。扫描器和数据库插入端都拒绝切点之前的原始信号；YOLO 按原始信号时间检查。保留纯行情缓存作预热，重启不移动切点。方向从原始 V9 事件传递到确认事件。
- **通用规则**：先列出会恢复旧数据的所有生产者，再设计删除。版本切换必须同时核对算法、不可变身份、方向、展示和发送边界，使用合成信号验证重启不会复活或补发历史。
- **牵连**：`yoyo/monitor/v9_signals.py`、`v9_worker.py`、`v9_migration.py`、`store.py`、`policy.py`、`model_gate.py`。仅监控状态清理，不触及独立研究影子账本、`forward_log` 或订单。V9 卡片显示确认收盘风险参考，不沿用 V1 持仓路径 R。
