# 手机导航弹窗要按可见视口布局，并默认进入浏览状态

- **问题**：全局“更多”沿用桌面分组网格与搜索聚焦，手机上两列组高不一致产生大块空白；键盘又压缩可用高度。模拟盘独立的 SPIKE 导航还缺少同一入口。
- **死胡同**：仅增大按钮或给列表加 overflow 不够：外层与列表各自按固定 vh 减常量，仍可能被键盘挤出屏幕。把新增入口转点隐藏的全局按钮，会让关闭后的焦点回到不可见控件。
- **有效路径**：用同一个原生 dialog 与路由注册表，懒加载入口委托给全局控制器；关闭回到所在 details 的 summary。手机默认聚焦关闭按钮，搜索由主动点击触发；标题/搜索/底栏固定，中间单列列表独立滚动，visualViewport 高度与偏移约束弹窗。实色背景复用 glass-opaque-sheet，而不是含透明度的 surface。
- **通用规则**：手机弹窗验收同时检查长列表最末项、搜索、缩小可见高度、关闭焦点及桌面键盘路径。主题验收排除浏览器深色扩展干扰；缩小桌面视口不等于已验证真实手机软键盘。
- **牵连**：`workspace-command.js`、`glass-system.css`、`index.html`、两处周一页面导航及 `frontend_glass_navigation.test.cjs`。Stitch 项目 `8978791379095391159` / 画板 `215c57c7d83c405bb2192e3690d2534d`；本轮 15 项导航测试与 Chrome/IAB 响应式验收通过，未运行真实 iPhone 键盘测试。
