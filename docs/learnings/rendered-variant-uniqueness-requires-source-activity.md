# 渲染变体的唯一性必须先由源行情活动度保证

- **问题**：同一个负事件按不同 `pre/post` 位置生成多张训练图时，文件名、样本 ID 和截窗都不同，但停牌或退市后的冻结 OHLC 会让这些变体渲染成完全相同的像素；归一化后，不同币种的恒定水平线甚至也可能撞成同一个哈希。
- **死胡同**：在全量渲染后按图片 SHA 删除重复项，会破坏每个正事件固定的 2 hard + 1 easy 配对、位置分布和 1:3 类别合同；仅检查事件区间不重叠也发现不了“不同源数据生成相同像素”的退化。
- **有效路径**：保留全量像素哈希作为最终拒绝门，同时在负事件选择前对最宽依赖窗口增加最低活动度合同：至少 4 个不同 close，且至少 4 根 `high > low`。候选不满足就整体换事件，再从头物化和复核，而不是事后删图。
- **通用规则**：凡是一个时序事件会派生多个位置/尺度变体，先在原始序列层验证有效变化，再在最终文件层验证哈希唯一；两层都要过，且任何失败都回到事件选择阶段重建。
- **牵连**：`yoyo/datasets/ma_launch_owner_grade_a_negatives.py`、`scripts/build_15m_ma_launch_owner_grade_a_neg24000.py`、`scripts/verify_15m_ma_launch_owner_grade_a_neg24000.py`；约束包括逐事件 2:1 hard/easy、逐位置 1:3 正负配对、时间 split、候选禁入区和 holdout 零读取。
