# 匹配随机对照必须排除全部前序信号而非仅最终成交

- **问题**：动态止损实验复用前序决策账本时，首版控制池只排除了最终接受的 100 笔入场附近，遗漏了同一检测器产生但被经济门、冷却或选择规则拒绝的信号附近时点。
- **死胡同**：把 `accepted == true` 当成“信号全集”。这会让控制组混入形态检测器已经判定为信号、只是后来未成交的时点，使所谓随机非信号对照的语义失真；它还让基线匹配超额看起来比严格版本更乐观。
- **有效路径**：从冻结前序 decision ledger 提取每一个信号时点，不论最终是否成交，在匹配前统一排除其 `horizon + 1` 邻域；然后对所有止损策略重新生成相同月 × UTC 时段 × ATR 桶的精确控制，并核对每笔控制数量。修正后 100/100 仍各有 3 个精确控制，但基线超额回到 -0.457bp/笔。
- **通用规则**：控制池的排除集合由“上游检测器认为是事件的全集”定义，不由下游成交集合定义。复用决策账本时先明确 `candidate`、`signal`、`accepted` 三个层级，并给排除全集写产物测试。
- **牵连**：`build_control_specs()`、前序 two-stage K2 decision ledger、49 根排除邻域、严格匹配随机对照、所有复用候选/成交分层账本的实验。
