# Floating chart controls need separate pointer ownership

- **问题**：全屏 K 线上的悬浮模块既要能移动，也要保留图表平移、缩放和模块里的选币、搜索操作。
- **死胡同**：把整块模块都当作拖动区域，会让按钮、搜索输入和图表争抢指针；单纯降低白色卡片透明度，在背后没有图形的区域也不容易看到玻璃效果。初版 79% 白底被 Owner 指出过于实。
- **有效路径**：只在专用把手上捕获 Pointer Events，位移超过阈值才开始拖动；移动过程中直接跟手，松手才持久化。取消、失焦和离开页面恢复未提交的位置。玻璃采用低透明度渐变、背景模糊和边缘高光，实际拖到 K 线上核对通透效果。
- **通用规则**：先明确每个手势归谁处理，再实现动画。布局坐标与选币、行情、图表缩放状态独立；按桌面和手机分别存储归一化位置，并在窗口变化时限界。验收必须包含实际拖动、刷新恢复、越界和复位。
- **牵连**：`yoyo/monitor/static/monday-fib.js`、`monday-fib.css`；`tests/monitor/frontend_monday_fib_layout.test.cjs`。不改变交易、触价或 Telegram 服务状态。
