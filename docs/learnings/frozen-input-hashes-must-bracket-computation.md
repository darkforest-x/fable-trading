# 冻结输入哈希需要夹住计算过程

- **问题**：source-first研究运行在共享可变工作区，开始时核对过文件SHA，不代表随后实际读到的内容仍是同一版本。
- **死胡同**：只在首次读前验SHA，后续只比时钟、形状或内部语义；另一写者若把OHLC与衍生结构一起替换，所有内部parity仍可能通过，产物却继承旧来源哈希。
- **有效路径**：V25在计算前验证输入与已提交源码，在写输出表/冻结检查点前再次验证同一输入与源码收据。任一变化保留失败记录，不生成成功冻结结果；并用合成mock验证第二次校验变化的失败路径。
- **通用规则**：共享工作区的来源封存要用前后两次身份校验包住计算；结构一致性不是文件版本一致性。严格并发写场景仍应采用不可变快照或文件锁，双重哈希不能保证探测瞬时改动后恢复。
- **牵连**：`yoyo/evaluation/hourly_impulse_structure_event_research.py` 与runner测试；不改变策略参数或实际支持结果。
