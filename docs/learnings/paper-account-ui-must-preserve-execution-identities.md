# 模拟账户扩展必须沿用成交身份，不能只添加切换按钮

- **问题**：60/5 双轨界面接入 v3/v3add 时，路由、预加载、统计、价格标签和加仓阶段具有不同契约。snapshot 用 `v3`/`v3add`，analytics 返回 `1060`/`2060`，加仓持仓内部为 `2061`，仍属于 v3add 账户。
- **死胡同**：只把两按钮改成四按钮会使统计格式校验失败，并将 v3 的分档目标误称为周一高低点。待成交加仓的 `notional=0` 不是影子持仓；按该值显示计划金额或将它拼入持仓都会改变语义。旧前端把所有保护线画在入场价，不能表达新 `be_price`，尤其加仓共用主单保护价时。
- **有效路径**：从 snapshot、analytics 和撮合源代码核对身份映射；统计响应精确匹配所选账户；预加载与路由同样支持四个键。待成交单单列，计划本金上限关联主单原始本金，注明实际成交受额度约束。止盈价格使用持仓记录，名称依据冻结规则；保护线使用已记录 `be_price`，旧单为空时才沿用原入场价；兜底线在保本启用的实际时刻结束。
- **通用规则**：增加策略视图时先核对账户、交易腿和生命周期三种身份，再检查全部读取入口与可见标签。不可把“未成交”“影子”“已结束”合并为一个数组后仅靠外观区分。验收必须包含不同账户数据、待成交加仓、已成交加仓及旧单保护价。
- **牵连**：`yoyo/monitor/static/monday-reclaim-paper.js`、`reclaim-analytics.js`、`reclaim-chart.js`、`reclaim-close.js`、`startup-hints.js`；后端契约源 `monday_reclaim_paper.py`。Stitch `571f390de49b49fcbf11ae0c054d3c95`。本次仅扩展显示，不修改账户、费用、仓位或撮合逻辑。
