# 交互图表与全局参考图必须在识别时冻结

- **问题**：SPIKE 视觉工作台的三栏布局挤压图表，固定深色 PNG 与浅色主题割裂；临时参考图无法跨刷新复用。替换为 TradingView 交互图表后，缩放和主题切换还会改变输入像素。
- **死胡同**：仅调大字体或修改卡片配色仍保留小图主体和固定图片底色。把旧后端 PNG 悄悄发送给模型，会让用户看到的交互图与模型实际输入不同；只在浏览器存参考图，又不能保证跨页面使用的是同一版本。
- **有效路径**：界面和 TradingView 共享语义颜色与统一系统字体；候选数据只暴露到信号收盘的 OHLC/MA。识别时用组件截图冻结当前可见图表，立即显示该快照，后端保存像素、源数据和哈希。参考图存入本机 SQLite，以版本号校验并逐请求保存快照。修改全局配置不追改历史识别。
- **通用规则**：交互预览、实际推理像素和可变全局配置分别有版本与生命周期；每次请求必须明确冻结哪份输入。源数据哈希并不能证明浏览器截图中的像素来自该数据，所以保留 `pixel_attestation=unverified`，不把前端截图当金标或实盘资格。
- **牵连**：`yoyo/vision_research/static/chart.js`、`app.js`、`styles.css` 以及本模块的 source/server/store/schemas；现有扫描器只读复用。49 项后端行为测试覆盖因果边界、参考图重启保留、历史快照不随全局修改、陈旧版本拒绝。浏览器隔离实例使用模拟模型验证上传、保存、刷新及图表截图提交；不构成 Google 真实推理成功证据。
