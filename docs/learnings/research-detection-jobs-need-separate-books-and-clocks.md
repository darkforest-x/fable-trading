# 研究检测任务要有独立账本与可知时间

- **问题**：把已有 Grade-A 模型用于历史检测、当前观察和全币种定时巡检，既要支持真实后台运行，也要能解释每个框何时才可知。
- **死胡同**：仅复用生产 detector 开关会被空 ACTIVE 契约挡住；把确认级检测挂到 forward 脉冲，又会混淆核心位置与信号可知时间，并挤占生产节拍。直接默认最新训练产物也无法证明它是推荐版本。
- **有效路径**：独立队列、进程锁与 SQLite 观察账本固定模型/渲染器/参数及输入来源；扫描时冻结已收盘截止点，结果分开保存核心时间、完整输入收盘时间与首次观察时间。复用已确认行情缓存但不新增行情写者；精确输入从保存的 OHLC/MA 重建并校验像素，后台中断保留已完成结果。推荐版本依据既有误触与召回证据固定，候选版本可手动选择。
- **通用规则**：研究可用性、检测精度和生产资格分别验收。全市场任务成功只证明工作流可运行，不能证明精度或盈利；定时任务须保留失败、取消、重叠跳过与重启状态。
- **牵连**：`yoyo/yolo_workbench/`、`tests/yolo_workbench/`；Grade-A Close/HL2 为现有研究模型，无训练、promote 或实盘切换。5m、30m、1H、4H、日线仍是跨周期研究。
