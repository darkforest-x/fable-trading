# 图表叠加线必须共用价格基准，收益显示必须保留原单位

- **问题**：轮动界面的日线走势已把首点归一到 100，叠加的 4 小时平台线却仍是真实价格；前端把平台价除以归一化的 100，导致价位线位置错误，十万级价格还会压扁走势。相对 BTC 收益比率同时被误标为收益之差与百分点。
- **死胡同**：归一化点值与真实价格都是浮点数，类型检查无法区分其坐标系；把它们交给同一绘图函数并不能使单位自动一致。RS 数字乘 100 后也不能任意选择 `%` 或 `pp`，展示单位由后端公式决定。
- **有效路径**：用真实日线末价和归一化首末值比还原首价，再把平台价投影到同一基准。例如首价 50、末价 60、走势 100→120，平台价 58 应落在 116；真实价格整体放大 2,000 倍时，整张图的坐标保持不变。缺少真实末价时不绘价位线。RS 公式 `(1+币种收益)/(1+BTC收益)-1` 统一显示为百分比，并在表头、板块和详情说明。
- **通用规则**：所有叠加层先明确原单位、变换基准和目标坐标系，再画到同一轴上。跨价格尺度的不变性测试能抓到“正常币看似没问题，高价币被压平”的错误；金融比率也必须连同定义一起传到展示层。
- **牵连**：`yoyo/rotation/web/app.js`、`yoyo/rotation/web/index.html`、`tests/test_rotation_web_static.py`。Node 模拟 DOM 测试同时检查中文原因、衍生品独立事件时间和单位，以及不使用 HTML 注入；未读取真实行情。
