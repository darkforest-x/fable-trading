# 路径清单的完整校验可以按完全相同的条目复用语法结果

- **问题**：2026-09-21 清理过期临时路径清单，数百个文件约 70 GB；相邻清单只增减少量路径，但仍需完整核验后才能删除。
- **死胡同**：只按整文件 SHA 缓存语法结果，任意一条路径变化都会导致重新验证整份清单。逐条重复做 UTF-8 解码、控制字符和路径分段检查，会把大量时间花在已经验证过的相同字节上。直接抽样则不能证明剩余内容仍只是路径清单。
- **有效路径**：每个文件仍全量读取、计算 SHA、验证结束符和条目数，并检查读取前后的文件身份。在固定的允许根目录集合和语法规则下，使用有容量限制的 `set[bytes]` 缓存已完整通过语法校验的路径；完全相同的字节条目可复用检查，新条目仍完整验证。文件级验证失败必须先拒绝，不能因 SHA 缓存命中覆盖失败状态。删除者独立复查文件身份、年龄和打开句柄，按已原子落盘的逐文件证明分批操作。
- **通用规则**：缓存的是“固定上下文下某段确切字节通过语法检查”，不是“某个文件仍安全可删”。语法上下文改变要失效缓存；身份、年龄、占用和完整文件摘要不能缓存跳过。大文件的完整校验不等于每次重复所有字符串计算。
- **牵连**：本机 `~/.local/state/disk-cleanup/20260921/certify_stale_tmp.py`、`certified-stale-temp-preflight.json` 和 `delete_certified_stale_tmp.py`；没有读取清单所指向的数据。此优化只减少核验开销，不修复临时文件生成或残留的源头。相关原则见 [清理证明必须绑定内容与身份](temp-cleanup-proof-must-bind-content-and-file-identity.md)。
