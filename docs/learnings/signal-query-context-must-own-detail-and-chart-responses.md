# 信号查询上下文必须拥有详情与图表响应

- **问题**：实时信号切换到历史回放和 4H 时，左侧已显示回放集合，右侧却短暂保留旧实时详情；旧图表请求也可能在新选择之后才返回。
- **死胡同**：只在筛选结果完成后检查 selected 是否仍存在，无法阻止一个先发出的实时请求在 source 已变更后写回状态；单独 abort 图表请求也不能隔离信号列表请求。
- **有效路径**：把 source、timeframe 和递增 revision 作为一次信号查询上下文。上下文变化立刻清空列表/详情并使旧请求失效；进行中的同步完成后丢弃不匹配的结果，再排队读取当前上下文。图表响应还必须与当前选中的 id、source、confirmation 和 bar 时刻完全相同。
- **通用规则**：任何会改变数据语义的筛选（实时/历史、周期、账户或环境）都应先使旧上下文失效，再允许结果进入详情；不能把上一上下文的缓存渲染成新上下文事实。
- **牵连**：`yoyo/monitor/static/app.js` 的 source/timeframe 筛选、详情选择和 `/api/chart`/`/api/replay/chart` 异步响应；`tests/monitor/frontend_cards.test.cjs`。
