# 图表加仓候选不能冒充已接受的加仓

- **问题**：把已选定的两次滚仓接入 SPIKE V12.6 时，旧版本已经有一句“加仓提示”，但并没有成交腿或仓位会计；完整 V0.4 又使用另一套结构保护规则。
- **死胡同**：仅复制“最多两次”或早期草案的 2R/4R、固定比例，无法复现后来选定的规则。把图上两次结构突破写成两次成功加仓，还会跳过下一开盘的利润保留、保证金、数量规格和维持保证金拒绝路径。本轮在源码核对阶段排除了这种接法，没有执行成交试验。
- **有效路径**：先从 V0.4 CLI 追到实际 V0.3 引擎，确认两次上限约束的是成功成交，第二次仍用初始 2R。Owner 选择先做图表提示后，明确计数的是候选，只添加独立的小时结构状态与参考线；用完整父版源码还原证明原信号和退出没有改变。
- **通用规则**：移植管理策略时，分开列出结构机会、资金准入、实际成交和退出状态。缺少账户信息的图表只能声明它真正计算的层级；显示出的保护参考也不能悄悄变成原策略的生效止损。高周期事件必须标在实际可知的图表 K 线，不能为了视觉整齐回填。
- **牵连**：`docs/profitable_roll_v04.md`、`yoyo/evaluation/profitable_roll_v03.py`、`yoyo/evaluation/pine/spike_burst_v12_6.pine`、新 `spike_burst_v12_8.pine` 与对应源码还原测试。V12.8 是 Owner 选择的提示版，不是完整 V0.4 成交移植；新旧研究均没有新增盈利或实盘准入证明。
