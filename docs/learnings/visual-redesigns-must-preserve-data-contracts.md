# 视觉改版必须与数据契约隔离

- **问题**：需要把已有实盘看板改造成参考图的空间卡片 UI，同时保留全部真实数据、路由和操作；后续还要把深色参考风格转换成白色主题。
- **死胡同**：按截图重写一个独立页面或把数值写死，虽然能更快接近静态画面，却会丢失现有 DOM id、事件绑定、API 加载态和实盘真实性。把新视觉写成深色专用的颜色字面量也会让主题反转变成大面积返工。
- **有效路径**：保留 `index.html` 的业务节点和 `app.js` 的数据渲染契约，只重排总览层级并追加最后加载的视觉样式层；空间卡片仍由真实概览 payload 生成，首屏使用语义明确的加载卡。主题颜色用 `theme-light` / `theme-dark` 作用域隔离，交互只切换 body class 和图表配色。
- **通用规则**：改造有状态看板时，第一步先列出必须保持的 DOM id、事件入口和 API payload；视觉层应后置并可撤销。任何可能被切换的主题都应从第一版开始用作用域或 token 表达，避免颜色字面量散落在业务选择器里。
- **牵连**：`src/webapp/static/index.html`、`src/webapp/static/app.js`、`src/webapp/static/clauseos.css`、浏览器路由/主题/响应式 QA；不得改动交易逻辑、阈值或实盘状态。
