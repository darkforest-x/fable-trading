# 通知去重必须覆盖“已经发出但没有收到回执”

- **问题**：全市场监控会重复检查同一收盘 bar；网络超时和进程重启又会使 Telegram 发送结果不确定。
- **死胡同**：只在发送成功后写去重文件，会在“服务端收到了消息、客户端回执超时”时重复推送；一律重试不能保证恰好一次。Bot API sendMessage 没有调用方幂等键。
- **有效路径**：事件与 outbox 同事务落库，稳定身份包含协议、币种、周期、收盘时刻、事件类型和方向。发送前原子认领；明确 429 按 retry_after 延迟；超时、5xx 和重启中断的 sending 记为 unknown，不自动补发。历史事件不会在下轮扫描升级成待发送消息。
- **通用规则**：把“未发送”“明确失败”“发送结果未知”分开；无法保证 exactly-once 时，公开选择避免重复的代价，并保留前端事件与状态供核对。
- **牵连**：`yoyo/monitor/store.py`、`yoyo/monitor/telegram.py`、`tests/monitor/test_runtime.py`。新鲜窗口为 30 分钟，与本监控前端/TG/扫描共用常量；不改既有 VPS 执行门。
