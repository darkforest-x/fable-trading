# 数据集容量必须在最终事件去重后衡量

## 问题

15 分钟均线密集形态扩充到 10,000 张时，全量严格扫描先得到 12,244 个唯一核心端点。这个数字看似超过目标，但按冻结规则执行“同币、同方向、固定一小时事件簇只保留最相似一个”后，多头只剩 4,494 个，达不到 5,000 个方向配额。若用去重前数量估算容量，会把同一波行情的相邻核心误当成多个独立样本。

## 诊断方法

1. 先冻结形态门、相似度阈值、核心宽度和事件 NMS，不在容量不足后改口径。
2. 全量扫描后依次报告：粗筛数、形态门通过数、距离门通过数、唯一核心端点数、事件 NMS 后方向数。
3. 只用最后一层的方向计数判断能否满足目标；任何较早阶段的数字都只是中间池容量。
4. 若不足，优先增加互不重叠的安全历史覆盖；不能靠缩短 NMS、放宽阈值或重复同一事件补数。

## 修复

本轮第一次构建按 fail-closed 停在选择前，没有渲染图片。随后只增加同一官方数据源、同一冻结币种宇宙的更早非重叠历史区间（2021-09 至 2023-06）；其余形态和去重规则保持不变，并把失败计数和补数原因写入预注册修订记录。

## 验证

- 第一次扫描：最终严格唯一核心端点 12,244。
- 最终一小时事件 NMS 后：LONG 4,494，低于 5,000，构建器抛错并在渲染前退出。
- 退出时没有生成部分图片、训练标签或训练任务，也没有读取 holdout。

## 可复用规则

任何带相邻窗、重叠框或事件簇去重的数据集，容量承诺一律使用“全部硬约束和最终去重之后”的最小类别计数。容量不足时扩数据域，不改标签语义和独立事件定义。
