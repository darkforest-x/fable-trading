# 按主题重组章节时，阅读单元与原章节需要独立身份

- **问题**：任务 #56 将 92 个原章节重组为 31 个图解单元。沿用原章节翻页和 URL 时，点击下一章只改变原章，深度单元没有变化；刷新也丢失单元位置。
- **死胡同**：把单元编号塞进 chapter 或复用旧进度键，会让原文映射、旧笔记和新单元完成状态互相覆盖。仅更改目录文字不能解决这些状态错误。
- **有效路径**：原章节 ID 保留；新增 `study-*` 单元 ID 和显式 `chapter_ids` 映射。笔记仍用书籍 ID 加内容 ID，但单元键与旧章键不重叠。URL 分别存 chapter、unit、mode；单元翻页只驱动单元，原文返回依映射选择单元。旧章节页继续使用原翻页器。
- **通用规则**：改变内容组织粒度时，先定义实体映射和状态归属，再改 UI。源文覆盖、学习进度和策略验证是不同状态，不能因重组而相互继承。
- **牵连**：`yoyo/monitor/static/trading-books.js`、`trading-books-study.js` 与相关前端测试。23 项测试通过；实页确认新笔记刷新、旧 XXIV 笔记保留、单元 URL 恢复、原文往返及导入导出。证据在 `output/playwright/task56/deep-study/`。
