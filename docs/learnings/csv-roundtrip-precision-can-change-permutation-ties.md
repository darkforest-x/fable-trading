# CSV 读回精度会改变置换检验的临界计数

- **问题**：ETH 4h 后段只有 12 笔，多笔保本退出收益接近相等；同种子排序检验在内存为 p=0.488051，默认 CSV 读回后变成 p=0.503450，经济指标几乎不变。
- **死胡同**：仅核对净收益和账户余额到 1e-12，会漏掉置换检验中 >= 比较对浮点末位的敏感性；两个 p 值同为不显著，也不能忽略不一致。
- **有效路径**：保持原始 CSV 字节和种子不变，用 pandas `float_precision="round_trip"` 读取；两段排序 p 精确恢复原始值，月簇 p 也不变。保留初次复核产物，最终报告使用精度恢复后的统计。
- **通用规则**：冻结浮点账本不仅要保存足够有效位，还要检查读回解析模式；统计含阈值比较或近似并列值时，必须逐项核对统计量和尾部计数。
- **牵连**：`yoyo/evaluation/pine_allin_eth4h_verify.py`、本轮 `results/precision_reconciliation.json`。没有改交易、成本、阈值或重跑市场回测。
