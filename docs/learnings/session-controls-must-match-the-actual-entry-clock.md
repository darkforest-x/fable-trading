# 时段实验的真实交易与随机对照必须共用实际开仓时钟

- **问题**：把同一ICT时间段应用到3分钟至4小时周期时，信号K线开盘与可执行的下一开盘不是同一时刻，跨小时、月份或DST边界会改变分组。
- **死胡同**：只筛真实交易的开仓时间，却继续按信号bar开盘小时匹配随机对照，会把不同会话的行情当成同条件对照；直接筛旧已成交清单还会保留被删仓位造成的占仓影响。
- **有效路径**：两边都以`frame.index[signal_i+1]`作实际计划开仓时间，先筛机会再准入。UTC月、纽约小时、纽约周末状态从该时间共同派生；波动桶仍只读取信号收盘及此前120bar，不因日历匹配引入未来价格。
- **通用规则**：先写明交易决策时刻、可成交时刻、K线标签和匹配分组时钟，再做时段结果。用跨边界的合成时间戳验证，不依赖恰好没有跳空的历史数据掩盖错误。
