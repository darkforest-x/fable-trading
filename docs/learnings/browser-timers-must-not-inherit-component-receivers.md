# 浏览器定时器不能继承组件实例作为接收者

- **问题**：首页账户概览的轮询器将 `setTimeout` / `clearTimeout` 保存到实例后，以 `this.set()` / `this.clear()` 调用。Node 测试通过，但浏览器加载时报 `Illegal invocation`，阻断整个行情工作台。
- **死胡同**：只用 Node 的计时器与注入的模拟调度器验证生命周期，遗漏了浏览器原生计时器对调用接收者的约束。测试通过不等于浏览器集成通过。
- **有效路径**：默认调度器使用箭头函数包装全局计时器，避免将 Feed 实例传作原生函数的 `this`。补充拒绝组件接收者的回归用例，并在真实浏览器验证首次加载、切页返回和窄屏布局。
- **通用规则**：将浏览器原生函数保存为组件方法时，先确认其接收者要求；通过包装函数保留原有调用语义。涉及生命周期的纯逻辑测试不能替代一次真实页面加载。
- **牵连**：`yoyo/monitor/static/market-accounts.js`、`tests/monitor/frontend_market_accounts.test.cjs`。轮询仍须按账户独立、离页取消、拒绝旧请求回写，不改变交易执行与账户权限。
