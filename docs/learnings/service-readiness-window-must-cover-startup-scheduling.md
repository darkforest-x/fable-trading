# 就绪检查时间必须覆盖服务管理器的启动调度

- **问题**：工作台连续两次重启时，管理命令报 HTTP 未就绪，但随后接口正常、日志没有退出错误。
- **死胡同**：把启动命令超时直接当成服务启动失败，会误报前端不可用；重复重启又会破坏正在建立的可用状态。
- **有效路径**：分别检查 launchd 是否已加载、进程启动日志和实际 HTTP 响应。原检查仅等待5秒，而配置允许10秒调度节流；将就绪探测窗口延长到20秒，保留有限等待和真实失败出口。
- **通用规则**：启动状态和请求就绪是两件事；就绪超时至少覆盖已配置的调度延迟，不要用过短探测窗口制造假故障。
- **牵连**：`yoyo/vision_research/manage.py` 的启动探测；未改变扫描器、通知、行情源或模型调用超时。
