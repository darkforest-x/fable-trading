# 冻结后台数据前先解除自动重试

- **问题**：Owner 决定现有样本已足够时，采集、评分和自动重试监督器分别运行。只停采集会让监督器误判故障并补抓；只把进度标为结束可能使评分器在旧快照末尾退出，遗漏刚完成的源收据。
- **死胡同**：杀掉整个进程组会中断尚未落收据的评分；只改前端状态或取消定时通知又不会停止真实采集。把未采集股票计入“待重试”也违背新的任务范围。
- **有效路径**：先暂停监督器与采集进程树，保存 Owner 指令、已完成源收据 SHA 和未采集名单，终止采集及旧重试监督器但保留当前评分进程。收尾监督器先等待旧评分器退出，再按哈希复用已完成流，处理冻结清单余项；采集入口发现停止收据直接拒绝。最终将覆盖、取数失败、评估隔离、未采集分别核对到完整分母。
- **通用规则**：用户缩小后台任务范围时，首先找出哪些上游会自动重启工作。停止动作和最终统计应共享一个持久、可校验的范围收据，进程退出不等于数据覆盖完成。
- **牵连**：独立 LaunchAgent、`spike_ashare_background`、`spike_ashare_data`、`owner_stop.json`、最终报告与前端覆盖说明；不影响实时监控或已完成评分。
