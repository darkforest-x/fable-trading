# 全历史覆盖不能用同屏绘图预算代替

- **问题**：信号中心山寨币不能越过初始 K 线窗口；Pine 为性能而保留最近 60 周/60 框，让用户向左回看时区间和信号消失。
- **死胡同**：只把 60 改大仍会同时撞到内部 120 条截断、12H 请求 2400 根窗口和低周期数据深度；只删除绘图数量上限又会触及 TradingView 每类 500 个对象的硬限制。最初只使用 5m 证据也无法还原更早的纽约周一。
- **有效路径**：分开数据、计算和显示三个范围。网页全部有效永续按需翻页，短页仍继续，成功空页才作为交易所边界。Pine 保留全部可用周/计划，使用完整 5m、30m 或 1h 对同一纽约日分片，重叠高低点不一致时拒绝较粗数据；当前视野只决定绘图对象，不决定信号资格。原生 BTC 核对 358 个完整周、103 个计划，并实际回到 2020 年，不能只看最新一屏。
- **通用规则**：遇到“历史只有几个月”，先逐层检查初始窗口、分页准入/终点、缓存截断、低周期覆盖、计算保留和显示预算。缓存容量是性能约束，不应变成永久历史边界；平台缺数据与代码截断分别说明。按视野重绘会触发 Pine 重算，需要保留日历缓存及仅更新未结束计划，不能宣称平移完全不重算。
- **牵连**：`yoyo/monitor/static/chart-history.js`、`yoyo/monitor/monday_chart_history.py`、`yoyo/evaluation/pine/spike_signal_cloud_v1_4.pine`；原始验证 `output/full-cloud-history-20261103/`。TV 数据/订阅及对象上限仍适用，完整日分片没有补造缺失行情。本次没有交易收益研究。
