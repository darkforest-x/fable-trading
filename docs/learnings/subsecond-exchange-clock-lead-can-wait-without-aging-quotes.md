# 交易所小幅时钟领先应等待重检，而不是伪造时间戳

- **问题**：手动预览提示报价过期，实际GET测量event仅10.887秒，ticker比响应本机时钟领先571毫秒，后续public/time领先1.871秒，触发年龄非负门。
- **死胡同**：单看总请求耗时会误以为60秒预览到期；把负年龄截零或放宽新鲜度窗口会隐藏时钟错误，且无法保证最终发单时有效。
- **有效路径**：仅手动报价在领先不超过原preflight容差5秒时有限等待，随后重取本机时钟，仍核验原0–5000毫秒年龄和原60秒截止；较大领先或等待后过期继续拒绝。没有修改信号中心30分钟门或系统时钟。
- **通用规则**：同时保留请求/响应/报价时间和业务期限，以它们的差值定位过期；修复不能改写证据或延长已确认条件。
