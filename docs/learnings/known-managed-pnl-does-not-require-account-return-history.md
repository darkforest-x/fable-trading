# Known managed PnL does not require account return history

- **Problem**: The live statistics API returned realized and floating PnL but deliberately cleared cumulative PnL together with the unavailable account return. Meanwhile, the mobile view replaced managed floating PnL with whole-account equity minus cash whenever a newer overview arrived, introducing external positions into an App-only total.
- **Dead end**: Missing deposit/withdrawal history prevents a defensible cumulative account return denominator, but does not erase the managed ledger's known PnL. Adding realized App PnL to account-wide floating PnL would cross ownership scopes; mixing a newer floating value into an older cumulative snapshot would also break the displayed sum.
- **Effective path**: Reuse `LiveBook.managed_pnl` for the monetary total, retain null initial equity and return fraction, and render realized, floating and total from the same statistics response. Keep current exchange equity separate, label live PnL as App-managed, and hide an unavailable percentage. Regression tests cover full history beyond 30 trades, period filters, partially closed trades, long/short remaining quantities, external floating PnL, capital transfers, empty accounts and read-only behavior.
- **General rule**: Treat ownership scope, time snapshot and return denominator as separate metric contracts. One unknown contract must not null a different known metric or license a substitute from another scope.
