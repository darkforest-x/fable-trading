# 启动框的横向上下文与纵向价格区可以来自不同 K 线区间

- **问题**：Owner 的启动样例框明显比六均线包络框宽，但启动后的大 K 又从红框顶部或底部穿出。若按普通目标检测框理解为“框内所有 K 线的完整外接矩形”，就无法同时复现这两个特征。
- **死胡同**：先把框定义成最密 4–7 根六均线的包络，只会得到很薄的 MA-only 框；再把同一横向区间内所有 K 线 high/low 与六均线取并集，又会被确认大 K 拉成巨框。两种做法都错误地假设 x/y 必须使用同一批 bar。
- **有效路径**：先放大 Owner 原图，确认确认大 K 确实穿框，再把几何拆成两个 span：启动前核心 4–7 根负责纵向 full-wick + 六均线价格区，随后 3 根只扩展横向确认范围而不参与纵向极值。用固定 transform 对确认段 OHLC/MA 做强干预，200/200 个候选框的纵向坐标保持零变化，证明代码契约与语义一致。
- **通用规则**：遇到“框太窄/太高”时，第一步不是加像素下限或统一扩大，而是分别问清 x 轴想保留哪些时间证据、y 轴想标哪一个价格区。若两者答案不同，数据结构和测试必须显式保存两个 span，并用干预测试证明非目标 span 不会污染对应坐标。
- **牵连**：`yoyo/datasets/ma_launch_transition_box_review.py`、`tests/test_ma_launch_transition_box_review.py`、`experiments/active/exp-15m-ma-launch-transition-box-review50-v2/`；确认样例只能作协议参考，不能把含未来的审核截图混入训练图或直接升级成全量 Gold。
