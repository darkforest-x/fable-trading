# 关闭周期必须撤销持久待办，不能只换扫描列表

- **问题**：Owner 把 Spike 的5m通知改为30m。旧5m启动通知和YOLO待确认任务已经写入SQLite，程序重启后仍可能被发送器或模型线程取出。
- **死胡同**：仅换前端按钮或行情周期白名单，会留下旧队列；把停止监控标成结构失效，也会把用户的配置操作冒充行情结论。
- **有效路径**：启动时只退休被移除周期的未完成工作，Bark pending标skipped、模型pending/error标disabled；发送与推理入口再次拒绝禁用周期。已发送、未知回执和原事件保留，30m两阶段各有新的首次启用时间。
- **通用规则**：动态范围收缩时，沿“扫描→持久候选→队列→最终发送”逐层撤销资格，并测试重启后的行为。范围扩展需新启用边界；范围收缩不能删除历史或改写为策略失败。
- **牵连**：`yoyo/monitor/service.py`、`store.py`、`notification_policy.py`、`model_gate.py`、前端disabled文案。Pine自动30m背景为2H，增加原生2H行情流；30分钟新鲜度和执行配置未改。
