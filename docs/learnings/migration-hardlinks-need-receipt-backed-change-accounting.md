# 迁移硬链接时要用收据解释链接数变化

- **问题**：两个待迁图像目录共用本机硬链接；先迁完一个目录并释放其本机副本后，另一目录的 4,853 个文件只变了 `nlink` 与 `ctime`，原先严格比较全部元数据的复制队列因此停止。
- **死胡同**：把一切 `ctime` 变化当作数据写入会阻塞合法迁移；完全忽略 `ctime/nlink` 又会掩盖来源不明的变化。仅凭“可能是硬链接”也不是证据。
- **有效路径**：仍要求路径集合、类型、大小、权限、修改时间与 inode 全部不变。针对每个减少的链接，按 inode 在本轮完成收据的原始快照中找到已删除别名，数量必须恰好对应，当前 `ctime` 必须落在相应已记录删除时间段。无法逐个解释就停止，验收记录保留对应关系。
- **通用规则**：迁移会改变与其他目录共享的文件元数据，稳定性检查需要识别自身产生的变化，不能只比较两个静态快照；统计逻辑迁出字节时也不能等同于物理释放空间。
- **牵连**：本轮 `source_stability.py`、`copy_metadata.py`、`cutover_bulk.py` 与 `hardlink-stability-validation.json`。Owner 明确取消内容哈希，本检查没有增加内容哈希。
